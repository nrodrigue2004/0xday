Tearing Down wg2: An HTTP RAT in Ghidra

2026-11-07Nathan#malware #reverse-engineering #ghidra

For my reverse engineering course I took apart wg2, a 32-bit Windows RAT, function by function in Ghidra. This is the condensed version of my annotated decompilation: how it hides its C2, how it talks home, and the eleven commands it gives an attacker.

Ghidra's FUN_ names are kept so you can follow along in your own copy. The C2 domain is defanged.

First look

format     PE32, 4 sections (.text .rdata .data .rsrc)
language   C++ (connection object with a vtable)
network    WinINet, HTTP and HTTPS
built      2011-11-17 (and it tells you: see "version")

Call graph, in the order I walked it

entry()
 └─ FUN_0040297d  WinMain: decode C2, name the victim, beacon loop
     └─ FUN_00401406  command_and_control  (the heart)
         ├─ FUN_0040101c  build connection object
         ├─ FUN_004010c0  connect (InternetOpen/Connect/OpenRequest)
         ├─ FUN_004012c5  POST data + SSL bypass
         └─ switch → shell, list, kill, getf/putf, start, pidrun, geturl ...

Hiding the C2 with one bit

The C2 hostname sits in .data obfuscated: every byte was shifted left by one. Decoding is a right shift and a mask.

for (i = 0; i < len; i++)
    url[i] = (enc[i] >> 1) & 0x7F;
// -> stratos[.]mcafeepaying[.]com

That's not encryption, it's just enough to keep the domain out of strings. Note the domain itself pretending to be an antivirus vendor.

It then builds a URL path from the victim's hostname via GetComputerNameA (/VICTIM-PC/), so the C2 knows exactly which machine is calling. The main loop calls the C2 handler, then sleeps sleep_scalar × 60000 ms, until a global stop flag is set.

Talking home

FUN_0040101c builds a C++ connection object (about 0x28 bytes): three WinINet handles, a one-hour timeout, the URL path, hostname, a Mozilla/4.0 User-Agent, extra headers, and an HTTPS flag.

+0x00 vtable      +0x14 url path     +0x20 headers
+0x04 hInternet   +0x18 hostname     +0x24 https flag
+0x08 hConnect    +0x1C user-agent
+0x0C hRequest    +0x10 timeout (3,600,000 ms)

FUN_004010c0 is textbook WinINet: InternetOpenA → set send/connect/receive timeouts → InternetConnectA on port 80 or 443 → HttpOpenRequestA. The headers include Pragma: no-cache and a custom Computer: header with the hostname. That custom header is a great network IOC.

The SSL bypass

FUN_004012c5 POSTs data to the C2. If HttpSendRequestA fails with 12045 (ERROR_INTERNET_INVALID_CA), it doesn't give up:

if (GetLastError() == 12045) {               // 0x2F0D: bad cert
    InternetQueryOptionA(h, 31, &flags, &n);  // INTERNET_OPTION_SECURITY_FLAGS
    flags |= SECURITY_FLAG_IGNORE_UNKNOWN_CA;
    InternetSetOptionA(h, 31, &flags, 4);
    // ...and retry
}

So the operator can run HTTPS C2 on a self-signed certificate and still get encrypted traffic past anyone not doing TLS inspection.

The C2 loop

FUN_00401406 connects (five tries, 60 s apart), creates two anonymous pipes for a future shell, changes its working directory to C:\Windows\tasks to blend in, and announces itself with "<hostname> Connected!". Then it loops: POST pending output, read the reply, split it on spaces, and match the first token against a command table (8-byte entries starting at 0x0040402C).

case  command  what it does
0     shell    hidden cmd.exe, stdin/stdout/stderr over pipes
1     list     /p processes  /s services  /d drives
2     kill     /p PID        /s stop service
3     getf     fetch a file from the C2 and write it to disk
4     putf     read a local file, POST it to the C2 in 128 KB chunks
5     start    /p process (hidden window)  /s service
6     whoami   GetUserNameExA, DOMAIN\user
7     sleep    change the beacon interval
8     version  returns "20111117"
9     pidrun   run a command with another process's token
10    geturl   URLDownloadToFileA from any URL
-     other    piped to the shell, or "Start shell first."

Shell and token theft

FUN_00401BA9 finds cmd.exe via %ComSpec% (falling back to System32), sets STARTF_USESTDHANDLES | STARTF_USESHOWWINDOW with SW_HIDE, and wires the pipes in. If a PID is given, it escalates instead:

h = OpenProcess(PROCESS_ALL_ACCESS, 0, pid);
OpenProcessToken(h, TOKEN_QUERY | TOKEN_DUPLICATE | TOKEN_ASSIGN_PRIMARY, &tok);
CreateProcessAsUserA(tok, NULL, "cmd.exe", ...);   // shell as that user

pidrun (FUN_004027A8 / FUN_00402817) reuses the same three calls to run any command under a stolen token. Point it at a SYSTEM process and a low-privilege foothold becomes SYSTEM.

Everything else

  • list: CreateToolhelp32Snapshot + Process32First/Next for processes (the same APIs I saw in anti-VM checks), EnumServicesStatusExA called twice (size, then data) for services, GetLogicalDrives + GetDriveTypeA + GetVolumeInformationA for drives.
  • kill / start: TerminateProcess, or the Service Control Manager with ControlService / StartServiceA, with friendly error messages for 0x420, 0x424 and 0x426.
  • getf / putf: runs in its own thread with its own connection and a different User-Agent (Mozilla/5.0), strips HTTP headers at the \r\n\r\n boundary.
  • geturl: a one-liner around URLDownloadToFileA, which lets the operator stage more tools from anywhere.

IOCs and detection ideas

network   stratos[.]mcafeepaying[.]com
          HTTP header "Computer: <hostname>"
          GET /<HOSTNAME>/ then POSTs, User-Agent Mozilla/4.0 and 5.0
host      process with cwd C:\Windows\tasks
          hidden cmd.exe whose parent isn't explorer.exe
          CreateProcessAsUser from a non-service process
strings   "Start shell first."  "Shell started successfully!"
          "Syntax error! Usage: GetUrl URL FileName"  "20111117"

What I took away

  • Twelve malicious behaviors, zero exploits. It's all documented Windows API, which is exactly why API-sequence detection beats signature matching.
  • Reading order matters. Starting from entry() and following the calls made a 600-line decompile readable in an afternoon.
  • Naming things in Ghidra as you go (initialize_array, send_get, create_shell) is most of the work. Once the struct offsets had names, the C2 loop basically read itself.
