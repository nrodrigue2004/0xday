Patching Out Anti-VM Checks in Malware Samples

2026-09-28Nathan#malware #reverse-engineering #ghidra

Some malware refuses to run when it detects a virtual machine, which is a problem when a VM is exactly where you want to analyze it. In my malware analysis labs I ran into samples using the old SIDT, SLDT and STR tricks.

How the checks work

These instructions return the locations of CPU descriptor tables. On older hypervisors those locations differ from bare metal in predictable ways, so the sample compares the result against a known value and bails out if it looks virtual.

Patching

Using IDA Pro and Ghidra, I found the comparison after each check and patched the conditional jump so the sample always takes the "real hardware" path.

; before
sidt  [esp+idtr]
cmp   byte ptr [esp+idtr+5], 0FFh
je    looks_like_vm
; after: je -> nop nop
