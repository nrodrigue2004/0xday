01 simple // the idea in plain words

A data structure is a way of holding data so a certain question is cheap to answer. Choosing the right one is most of the skill. The five worth knowing cold, with a security use for each:

  • List / array: ordered, indexed. The lines of a log in order.
  • Dictionary (hash map): key to value, near-instant lookup. IP address to failure count.
  • Set: unique items, near-instant "is it in here?". The blocklist, or the IPs already seen.
  • Stack: last in, first out. Undo history, nested brackets, a call stack.
  • Queue: first in, first out. Jobs waiting for a worker, events in arrival order.
$ python3 -c "ips=['a','b','a','c','a']; print(len(set(ips)), 'unique', ips.count('a'), 'times')"

"Is this IP on the blocklist?" in a list means checking every entry. In a set it is one step. With 500,000 entries and a million log lines, that choice is the difference between a second and an afternoon.

Which one?

Need order and position: list. Need to count or group by a key: dictionary. Need uniqueness or membership: set. Need the most recent first: stack. Need the oldest first, or a moving window: queue.

02 mid // how it's actually used

Counting with dictionaries

from collections import Counter, defaultdict
fails = Counter(ip for ip in ips)            # ip -> count
by_user = defaultdict(set)                    # ip -> set of usernames tried
for ip, user in pairs: by_user[ip].add(user)
spray = [ip for ip, us in by_user.items() if len(us) >= 4]

defaultdict(set) creates the empty set for a new key automatically. A scanner that tries many usernames is a spray; one that tries many passwords on one user is a brute force. Different data structure question, different alert.

Sets for membership and comparison

a & b (in both), a | b (either), a - b (in a, not in b). "IPs that failed and later succeeded" is failed_ips & success_ips, one line, and it is the shape of most correlation rules.

Queues and the sliding window

Detection usually means "N things within T seconds". Keep a deque of recent timestamps per key: add the new one on the right, drop old ones from the left, and check the length.

from collections import deque
window = deque()
for ts in times:
    window.append(ts)
    while window and ts - window[0] > 30:   # older than 30 s
        window.popleft()
    if len(window) >= 5:
        print("alert at", ts)

deque.popleft() is O(1). list.pop(0) is O(n), because it shifts every element, which is why you do not use a plain list as a queue.

Stacks

The call stack, an undo list, matching ( with ): append to push, pop to take the last. A stack is also how a depth-first search over a directory tree or an attack graph works.

Patterns you will reuse

  • Dedup a stream: seen = set(); if x in seen: continue; seen.add(x). Memory grows with distinct items, so cap it or use a Bloom filter when it will not fit
  • Top-k: heapq.nlargest(10, counts.items(), key=...) is O(n log k), better than sorting everything when k is small
  • Rate limiting / detection: the per-key deque above, or a token bucket: a counter that refills over time
  • Graphs: hosts and connections are nodes and edges. A dict of sets ({host: {neighbours}}) plus breadth-first search answers "how far can an attacker get from this machine", the lateral-movement question
  • Trie / prefix tree: match a log line against thousands of indicator prefixes at once
  • Memory versus time: a bigger dict can answer faster. Streaming a log with fixed-size state is how you handle logs larger than RAM

The honest rule of thumb: reach for dict, set and deque first. They cover most of it, and the katas in the Python dojo drill each one.
