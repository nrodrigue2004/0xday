PowerShell passes objects, not text, so pulling failed logons out of the Windows event log takes four short stages. Practice with Get-WinEvent, Group-Object and Invoke-RestMethod.

1simple2mid3complex4hands-on+ref

01 simple // the idea in plain words

In bash a pipe passes text. In PowerShell a pipe passes objects with properties, so you filter on .Status instead of cutting column 7. That makes admin chores short:

  • Get-Service returns service objects
  • Where-Object keeps the ones you want
  • Select-Object picks properties
  • Sort-Object, Group-Object and Measure-Object order and count
$ Get-Process | Sort-Object CPU -Descending | Select-Object -First 5

Commands are named Verb-Noun (Get-, Set-, New-, Remove-). Get-Command *event* finds commands by keyword and Get-Help Get-WinEvent -Examples shows how to use one. Get-Member shows what properties an object has, which is the key to every pipeline.

A $_ inside a script block means "the object currently in the pipeline". Where-Object { $_.Id -eq 4625 } reads "keep objects whose Id is 4625".

Why it matters for security

Windows logs everything as structured events. Event ID 4625 is a failed logon, 4624 a successful one, 4688 a new process. PowerShell reads them as objects, so you never parse text.

02 mid // how it's actually used

Failed logons, step by step

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddHours(-24)}

The -FilterHashtable form filters inside the log service, which is far faster than pulling everything and using Where-Object afterwards. Filter early, shape late.

The event's useful fields (account, source address) sit in the message. Many people export to CSV first, or use Import-Csv on an export, and then everything is a property:

$ Import-Csv .\4625.csv | Group-Object TargetUserName | Sort-Object Count -Descending | Select-Object -First 5 Name,Count
$ Import-Csv .\4625.csv | Where-Object TargetUserName -eq 'svc-backup' | Group-Object IpAddress | Sort-Object Count -Descending

Output you can hand to someone

  • Export-Csv -NoTypeInformation out.csv for a spreadsheet
  • ConvertTo-Json and ConvertFrom-Json for APIs and configs
  • Format-Table -AutoSize for the screen only (it produces formatting objects, so do not pipe it onward)

Calling an API

Invoke-RestMethod does the request and parses the JSON in one step:

$key = $env:VT_API_KEY
$r = Invoke-RestMethod -Uri "https://www.virustotal.com/api/v3/ip_addresses/203.0.113.77" `
       -Headers @{ "x-apikey" = $key } -TimeoutSec 10
$r.data.attributes.last_analysis_stats.malicious

Same rules as Python: the key comes from an environment variable, there is a timeout, and results are cached.

03 complex // what the pros do

Write functions, not one-offs

function Get-FailedLogons {
    [CmdletBinding()]
    param([int]$Hours = 24, [int]$Threshold = 10)
    $since = (Get-Date).AddHours(-$Hours)
    Get-WinEvent -FilterHashtable @{ LogName='Security'; Id=4625; StartTime=$since } |
        Group-Object { $_.Properties[5].Value } |
        Where-Object Count -ge $Threshold |
        Select-Object Name, Count
}
  • Parameters with types and defaults make a function safe to reuse. [CmdletBinding()] adds -Verbose, -ErrorAction and friends for free
  • Return objects, not formatted strings, so the caller can pipe the result
  • Error handling: try { ... } catch { ... } only catches terminating errors; add -ErrorAction Stop to turn a cmdlet's non-terminating errors into catchable ones
  • Remoting: Invoke-Command -ComputerName srv01,srv02 -ScriptBlock { ... } runs it on many machines at once (needs WinRM and permission)
  • Scheduling: Register-ScheduledTask runs a script on a timer; run it as a least-privileged service account, never your admin account
  • Execution policy is a guardrail against accidents, not a security boundary. Sign scripts that others will run, and review any script before -ExecutionPolicy Bypass
  • Logging: turn on Script Block Logging (event 4104); it is how defenders see what PowerShell actually ran, and why attackers' obfuscated scripts show up in the log anyway
  • Complexity: Group-Object builds a hash table (O(n)); calling Where-Object once per item inside another loop is O(n times m). Build the lookup once

Compare the same idea in bash and Python. More reps in the PowerShell dojo.
