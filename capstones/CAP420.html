CAP420 Build and publish a security tool

Ship a small, useful security tool to a public repo with tests, docs and a release.

needs: SEC100, CS240 · 17 checklist items · ~20 h · not started · self-study, not an accredited course

# brief

Build one small tool that solves a real problem you have run into, finish it, and publish it. Finished and small beats ambitious and half done. A recruiter reading your repo should understand what it does in thirty seconds.

Write it in a language you can defend in an interview (Python is a fine default). Do not commit secrets, real logs, or anything from a real employer or customer.

# checklist

1. Pick and scope

~/learn: Git and GitHub ~/learn: Python

  1. Choose an idea from the list below or your own, and write a one-sentence purpose
  2. Write three user stories: who runs it, with what input, and what they get
  3. Define done: the smallest version that is still useful, and what is explicitly out of scope
  4. Create the repo with a license, a .gitignore and a README stub

2. Build

~/learn: bash scripting ~/learn: cryptography (applied)

  1. Implement the core feature end to end before adding options
  2. Validate all input and fail with clear error messages
  3. Keep secrets and paths out of code; use arguments or environment variables
  4. Commit in small steps with messages that say why

3. Test and secure

OWASP cheat sheet series

  1. Write automated tests for the core logic and at least three bad-input cases
  2. Run a linter or static analyzer and fix what it finds
  3. Scan dependencies for known vulnerabilities and pin versions
  4. Write a short threat model: what could an attacker do with your tool, and what do you do about it

4. Document and publish

~/bullets: resume bullets ~/careers: career paths

  1. README with purpose, install, usage examples with sample output, and limitations
  2. A demo: a short GIF or pasted terminal session
  3. Set up CI that runs the tests on every push
  4. Tag a release with a changelog
  5. Add the project to ~/projects and a bullet to your resume

# rubric

Grade yourself honestly before you tick the last item.

  • It runs from a clean checkout following only the README
  • Tests pass in CI
  • No secrets or personal data in the history
  • You can explain every design choice out loud
  • Limitations are stated honestly

# idea starters

  • Log parser that flags brute-force logins and prints a summary
  • Port and banner scanner with JSON output
  • File integrity checker that hashes a folder and reports changes
  • Password audit tool that checks a list against rules and a breach-hash file
  • Phishing header analyzer: SPF, DKIM, DMARC and mismatched domains
  • Sigma-style rule runner over JSON logs
  • IOC extractor that pulls IPs, domains and hashes out of text and de-duplicates them
  • Subnet and CIDR calculator with a study mode
