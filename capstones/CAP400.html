CAP400 Blue capstone: investigate a breach

Work a full simulated intrusion from the raw evidence to a written incident report.

needs: BLU300, BLU310 · 25 checklist items · ~12 h · not started · self-study, not an accredited course

# brief

You are the on-call analyst at a fictional company, Brightwater Logistics. At 12:09 UTC the SOC isolated a file server after a ransomware precursor fired. Your job is to find out how the attacker got in, what they touched, what left the network, and what to change so it does not happen again.

The evidence is a case file of email, proxy, endpoint, authentication, DNS and firewall logs. Everything in it is invented and uses reserved example domains and documentation IP ranges. Work it like a real ticket: build a timeline first, form hypotheses, and only then write conclusions.

Do the investigation before opening the answer key at the bottom of the case file. The report is the deliverable, not the answers.

[ open the case file ]

# checklist

1. Triage and scope

~/learn: incident response ~/learn: log analysis

  1. Read the whole case file once without taking notes, then list every host, account and external address that appears
  2. Write a one-paragraph problem statement: what was detected, when, and what you are trying to prove
  3. Pick a timestamp convention (UTC) and record it at the top of your timeline

2. Build the timeline

~/drills: parse logs with pipes ~/drills: regex for logs ~/learn: phishing analysis

  1. Merge every log source into one timeline sorted by time, one line per event, with the source named
  2. Mark the first malicious event (initial access) and the last one you can see
  3. Identify patient zero: the first host and account that were compromised
  4. Calculate dwell time from initial access to containment

3. Analyze the attack

~/learn: network traffic analysis ~/learn: memory forensics ~/learn: SIEM and Security Onion

  1. Explain the initial access vector and show the evidence for it
  2. Identify the command-and-control infrastructure (domains and IPs) and the beacon interval
  3. Show how credentials were stolen and which account was abused afterwards
  4. Trace lateral movement hop by hop, naming the protocol used for each
  5. Identify persistence on any host
  6. Quantify data exfiltration: destination, volume, and which host it came from
  7. Describe the impact that was attempted and whether it succeeded

4. Map and extract indicators

MITRE ATT&CK ~/drills: Security Onion intrusion hunt

  1. Map each stage of the attack to a MITRE ATT&CK technique ID
  2. Write an indicator list (domains, IPs, file names, hashes, service names) in a table
  3. Write at least two detection ideas: one log query or rule that would have fired earlier

5. Write the report

~/report: write-up template ~/harden: hardening checklists

  1. Executive summary a non-technical manager can read in two minutes
  2. Timeline table with times, hosts, events and evidence source
  3. Root cause and contributing factors
  4. Impact assessment: systems, accounts and data affected
  5. Containment, eradication and recovery steps, in order
  6. Recommendations ranked by effort and payoff
  7. Lessons learned: what worked, what was missing, what to rehearse
  8. Compare your findings with the answer key and note anything you missed or got wrong

# rubric

Grade yourself honestly before you tick the last item.

  • A reader who was not there could follow the attack from your report alone
  • Every claim points at a specific log line
  • Timeline is in UTC and sorted
  • Findings and recommendations are separate sections
  • You say what you do not know instead of guessing
