Hardening means removing everything an attacker could use before they show up. Learn baselines, least privilege and the usual misconfigurations on Linux and Windows, then audit a server and find its backdoor account.

1simple2mid3complex4hands-on

01 simple // the idea in plain words

A fresh install is built to *work*, not to be *safe*: default passwords, extra services, broad permissions. Hardening is shrinking the attack surface:

  • remove or disable what you don't need (services, software, ports, accounts)
  • change every default password, and enforce strong ones
  • patch, and keep patching
  • give every user and service only the access it needs (least privilege)
  • turn on logging and a host firewall

Start by seeing what the box exposes. Which services are listening?

$ cat ~/audit/listening.txt

The CIS Benchmarks and DISA STIGs are free, detailed hardening checklists for almost every OS and app. Hardening is mostly working through one.

02 mid // how it's actually used

Linux: accounts and SSH

/etc/passwd has one line per account: name:x:UID:GID:comment:home:shell. Only root should have UID 0. Service accounts should have a nologin shell. Pull the fields you care about with awk -F::

$ awk -F: '{print $1, $3, $7}' ~/audit/etc/passwd

SSH is the front door. Check the settings that matter: no root login, no passwords (keys only), no empty passwords:

$ grep -E "^(PermitRootLogin|PasswordAuthentication|PermitEmptyPasswords)" ~/audit/etc/ssh/sshd_config

Windows: the same ideas, different tools

Group Policy enforces baselines across a domain. Typical wins: disable SMBv1 and LLMNR, enforce account lockout, turn on Windows Defender and the firewall, deploy LAPS (a unique local admin password per machine), and remove users from the local Administrators group.

$ cat ~/audit/windows-baseline.txt

03 complex // what the pros do

Privilege escalation is a hardening checklist in reverse

Attackers who land as a normal user look for exactly the misconfigurations hardening removes:

  • SUID binaries that let anyone run something as root (find / -perm -4000)
  • sudo rules that are too broad ((ALL) NOPASSWD: ALL, or sudo on editors and interpreters that can spawn a shell)
  • world-writable files run by root (cron scripts, services)
  • extra UID 0 accounts, weak file permissions on /etc/shadow
$ cat ~/audit/suid.txt
$ grep -v "^#" ~/audit/etc/sudoers | grep -v "^$"

GTFOBins lists how almost every common binary can be abused when it's SUID or allowed via sudo. If find, vim or python3 is on that list, it's a root shell.

Baselines and drift

Harden once, then keep it that way: define a baseline (CIS level 1), apply it with automation (Ansible, GPO, Intune), and scan for drift regularly (OpenSCAP, Lynis, Microsoft Security Compliance Toolkit).
