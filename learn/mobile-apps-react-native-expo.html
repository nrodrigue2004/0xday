React Native builds real phone apps from React and TypeScript, and Expo makes running them painless. Learn components, state, navigation and talking to an API, then find why a screen keeps re-rendering.

1simple2mid3complex4hands-on+ref

01 simple // the idea in plain words

React Native lets you build iOS and Android apps in TypeScript using React. Instead of HTML elements you use native building blocks: View (a box), Text, Image, TextInput, Pressable, FlatList. They draw real native widgets, not a web page.

Expo is the toolkit around it: one command starts the project, a phone app (Expo Go) runs it by scanning a QR code, and ready-made modules cover camera, notifications, secure storage and more.

$ cat ~/rn/App.tsx
$ cat ~/rn/package.json

The core idea: components and state

A component is a function that returns what a piece of the screen looks like. State (useState) is data the component remembers. When state changes, React re-runs the function and updates the screen.

const [likes, setLikes] = useState(0);
<Pressable onPress={() => setLikes(likes + 1)}><Text>{likes}</Text></Pressable>

Words to know

  • Props: inputs a parent passes to a child component
  • Hook: a function like useState or useEffect that components call
  • Style: a JavaScript object (StyleSheet.create), flexbox by default, column direction

02 mid // how it's actually used

Project layout (Expo Router)

Files under app/ become screens: app/index.tsx is the home screen, app/post/[id].tsx is a screen with a parameter, app/_layout.tsx wraps them (tabs or a stack). Navigation is router.push("/post/7").

Lists

Use FlatList for feeds: it only renders rows on screen. Give it data, a renderItem and a stable keyExtractor (item => item.id). A .map() inside a ScrollView renders everything at once and gets slow.

Effects and data loading

useEffect(() => { ... }, [dependencies]) runs after render. Typical use: fetch from your API when a screen opens.

useEffect(() => {
  fetch(`${API}/api/posts`).then(r => r.json()).then(setPosts);
}, []);

The [] means "only once". Leave it off and the effect runs after every render; if it sets state, that triggers another render, and you get an infinite loop.

Talking to a backend

Call your REST API (see the Spring Boot guide) with fetch, send the JWT in an Authorization header, and show loading, error and empty states. On a real phone localhost is the phone, not your computer: use your computer's LAN IP or a tunnel while developing.

Where to keep things

  • screen-local values: useState
  • shared values (current user): React Context or a small store
  • secrets such as tokens: expo-secure-store (keychain/keystore), not AsyncStorage, which is plain text
  • API keys: never ship a real secret in the app bundle; anything in the app can be extracted

Running and shipping

npx expo start for development, eas build produces installable builds, and eas submit sends them to the stores. Over-the-air updates can fix JavaScript bugs without a store review.

03 complex // what the pros do

Rendering and performance

Components re-render when their state or props change, and when their parent does. Slowness usually has one of these causes: a huge list without FlatList, a new object or function created each render and passed to a memoized child, expensive work during render (move it into useMemo), or an effect that sets state on every run. Use React DevTools' profiler and remove the cause, instead of wrapping everything in memo.

TypeScript the useful way

Type your props and API responses (type Post = { id: string; text: string }). Then a wrong field name is a red underline instead of a blank screen. Validate data from the network at runtime too (the types can't know what the server really sent).

Security on a mobile client

The device is untrusted. Assume users can read the bundle, intercept traffic and tamper with the app, so enforce rules on the server. Use HTTPS only, keep tokens in secure storage with a short lifetime, validate deep links before acting on them, don't log tokens or personal data, and review each Expo module's permissions. OWASP's Mobile Top 10 is the checklist, and the applied-cryptography and Flutter/Firebase guides cover the neighbors.

React Native vs Flutter

Both build one codebase for iOS and Android. React Native uses JavaScript/TypeScript and native widgets and fits web developers; Flutter uses Dart and draws its own UI with a consistent look. I've used both, which makes the concepts (components, state, navigation, backend calls) the lasting skill.

Testing and tooling

jest with @testing-library/react-native for components, tsc --noEmit and ESLint for types and mistakes, Expo's dev menu for reload and element inspector, and npx expo-doctor when versions disagree.
