Every attack and every defense travels over a network. Learn the OSI and TCP/IP layers, how DNS, ARP and the TCP handshake really work, then read a capture to catch ARP spoofing on a LAN.

01 simple // the idea in plain words

A network is devices agreeing on rules (protocols) to send data to each other. The idea everything else builds on is layers: each layer does one job and hands off to the next.

The OSI model has 7 layers. Remember them bottom-up with "Please Do Not Throw Sausage Pizza Away": 1. Physical: cables, radio, bits 2. Data link: MAC addresses, switches, Ethernet, Wi-Fi frames 3. Network: IP addresses, routers 4. Transport: TCP (reliable) and UDP (fast), ports 5. Session, 6. Presentation, 7. Application: HTTP, DNS, SSH, SMTP

$ cat ~/notes/ports.txt
$ grep -w 53 ~/notes/ports.txt

When something "doesn't work", troubleshoot bottom-up: link light, IP address, gateway ping, DNS, then the app.

Layers as a story

When you open a web page: the browser asks DNS for the IP (application), opens a TCP connection (transport), wraps data in IP packets with source and destination (network), puts them in frames for the next device using MAC addresses (data link), and sends bits over Wi-Fi or Ethernet (physical). Each layer wraps the one above in its own header, called encapsulation, and the receiver peels them off in reverse.

Remember the OSI layers: Physical, Data link, Network, Transport, Session, Presentation, Application ("Please Do Not Throw Sausage Pizza Away"). TCP/IP squeezes them into four: link, internet, transport, application.

02 mid // how it's actually used

Addressing at each layer

  • MAC (layer 2): burned into the NIC, only meaningful on the local network
  • IP (layer 3): logical, routable across networks
  • Port (layer 4): which program on that host (443 = HTTPS)

ARP connects layer 3 to layer 2: "who has 10.0.10.1? tell 10.0.10.44", and the owner replies with its MAC. DNS turns names into IPs (A, AAAA, MX, CNAME, TXT records).

$ cat ~/notes/arp-table.txt
$ dig +short updates.corp.example

TCP vs UDP

TCP opens a connection with the three-way handshake (SYN, SYN-ACK, ACK), numbers every byte and resends what's lost. UDP just sends: DNS queries, VoIP, video, games. A TCP RST slams a connection shut, which is also what a closed port answers to a SYN.

$ grep -E "Flags \[S\]|Flags \[S\.\]" ~/caps/handshake.txt

Devices and what layer they work at

Hub (1, repeats everything), switch (2, forwards by MAC), router (3, forwards by IP between networks), firewall (3 to 7), load balancer (4 or 7), access point (1 and 2). A collision domain is where devices share a wire; a broadcast domain is everyone who hears a broadcast, which VLANs and routers split up.

DNS record types

A (name to IPv4), AAAA (IPv6), CNAME (alias), MX (mail server), NS (name server), TXT (free text, used for SPF and verification), PTR (reverse lookup), SOA (zone info), SRV (service location). Resolution: the stub resolver asks a recursive resolver, which walks root, TLD, then the authoritative server and caches the answer for the TTL.

HTTP and TLS in a minute

HTTP is request and response: method (GET, POST), path, headers, optional body, then status code and body back. TLS wraps it: the client says hello and the server name, the server presents a certificate, they agree on keys, then everything is encrypted. Status codes: 2xx success, 3xx redirect, 4xx client error, 5xx server error.

03 complex // what the pros do

Layer 2 attacks

Switches and ARP were designed to trust everyone on the LAN:

  • ARP spoofing / poisoning: an attacker sends unsolicited ARP replies saying "the gateway's IP is at *my* MAC". Victims send their traffic to the attacker, who forwards it (on-path / man-in-the-middle). Sign: one MAC claiming several IPs, or the gateway's MAC suddenly changing
  • MAC flooding: overflow the switch's CAM table so it floods frames to every port
  • VLAN hopping, rogue DHCP servers, rogue access points

Defenses: Dynamic ARP Inspection and DHCP snooping on managed switches, port security (limit MACs per port), 802.1X network access control, and encryption everywhere (TLS, SSH) so an on-path attacker sees nothing useful.

$ grep "is-at" ~/caps/lan.txt
$ grep "is-at" ~/caps/lan.txt | awk '{print $NF}' | sort | uniq -c

DNS attacks

Cache poisoning, DNS tunneling (data hidden in long subdomains), and hijacked records. Watch for very long or random-looking query names and a host making thousands of TXT queries.

Wireless basics

2.4 GHz reaches farther and is crowded, 5 and 6 GHz are faster at shorter range. WPA2-Personal uses a shared passphrase that can be attacked offline from a captured handshake, so use a long one; WPA3 resists that. WPA-Enterprise (802.1X/RADIUS) gives each user their own credentials. Disable WPS, and put guests and IoT on separate networks.

Network attacks to be able to explain

ARP spoofing (man-in-the-middle on a LAN), DHCP starvation and rogue DHCP, DNS spoofing and cache poisoning, VLAN hopping, SYN flood, MAC flooding, and smurf-style amplification. For each, know the layer, what the attacker gains, and the defense (dynamic ARP inspection, DHCP snooping, DNSSEC, port security, rate limiting, 802.1X).

Tools for the layers

ping and traceroute (3), arp -a (2/3), dig (7 DNS), curl -v (7 HTTP/TLS), nc -vz host port (4 connectivity test), ss/netstat (4 sockets), Wireshark/tcpdump (all layers).
