Every attack and every defense travels over a network. Learn the OSI and TCP/IP layers, how DNS, ARP and the TCP handshake really work, then read a capture to catch ARP spoofing on a LAN.

01 simple // the idea in plain words

A network is devices agreeing on rules (protocols) to send data to each other. The idea everything else builds on is layers: each layer does one job and hands off to the next.

The OSI model has 7 layers. Remember them bottom-up with "Please Do Not Throw Sausage Pizza Away": 1. Physical: cables, radio, bits 2. Data link: MAC addresses, switches, Ethernet, Wi-Fi frames 3. Network: IP addresses, routers 4. Transport: TCP (reliable) and UDP (fast), ports 5. Session, 6. Presentation, 7. Application: HTTP, DNS, SSH, SMTP

$ cat ~/notes/ports.txt
$ grep -w 53 ~/notes/ports.txt

When something "doesn't work", troubleshoot bottom-up: link light, IP address, gateway ping, DNS, then the app.

02 mid // how it's actually used

Addressing at each layer

  • MAC (layer 2): burned into the NIC, only meaningful on the local network
  • IP (layer 3): logical, routable across networks
  • Port (layer 4): which program on that host (443 = HTTPS)

ARP connects layer 3 to layer 2: "who has 10.0.10.1? tell 10.0.10.44", and the owner replies with its MAC. DNS turns names into IPs (A, AAAA, MX, CNAME, TXT records).

TCP vs UDP

TCP opens a connection with the three-way handshake (SYN, SYN-ACK, ACK), numbers every byte and resends what's lost. UDP just sends: DNS queries, VoIP, video, games. A TCP RST slams a connection shut, which is also what a closed port answers to a SYN.

$ grep -E "Flags \[S\]|Flags \[S\.\]" ~/caps/handshake.txt

03 complex // what the pros do

Layer 2 attacks

Switches and ARP were designed to trust everyone on the LAN:

  • ARP spoofing / poisoning: an attacker sends unsolicited ARP replies saying "the gateway's IP is at *my* MAC". Victims send their traffic to the attacker, who forwards it (on-path / man-in-the-middle). Sign: one MAC claiming several IPs, or the gateway's MAC suddenly changing
  • MAC flooding: overflow the switch's CAM table so it floods frames to every port
  • VLAN hopping, rogue DHCP servers, rogue access points

Defenses: Dynamic ARP Inspection and DHCP snooping on managed switches, port security (limit MACs per port), 802.1X network access control, and encryption everywhere (TLS, SSH) so an on-path attacker sees nothing useful.

$ grep "is-at" ~/caps/lan.txt
$ grep "is-at" ~/caps/lan.txt | awk '{print $NF}' | sort | uniq -c

DNS attacks

Cache poisoning, DNS tunneling (data hidden in long subdomains), and hijacked records. Watch for very long or random-looking query names and a host making thousands of TXT queries.
