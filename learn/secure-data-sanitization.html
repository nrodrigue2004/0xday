Deleting a file doesn't erase it, and the wrong wipe can leave a whole drive readable. Learn NIST 800-88's clear, purge and destroy, which method fits which media, then catch the drive that was handled wrong.

1simple2mid3complex4hands-on+ref

01 simple // the idea in plain words

When you delete a file, the OS just marks its space as free. The data stays until something overwrites it, which is how forensic tools recover deleted files. Sanitization means making data unrecoverable before a device is reused, sold or thrown out.

The standard is NIST SP 800-88, which defines three levels:

  • Clear: overwrite with standard tools so normal recovery fails (fine for reuse inside the company)
  • Purge: methods that defeat even lab-level recovery: firmware secure erase / sanitize, cryptographic erase, degaussing (magnetic only)
  • Destroy: shred, disintegrate, pulverize, incinerate
$ cat ~/attachments/sanitization-matrix.txt

Why it matters

Old laptops, phones, copiers and USB sticks carry business secrets and personal data. Bad disposal is a breach: stolen or resold drives with readable data have caused real fines and lawsuits. A written process, applied every time, proves you did the right thing.

The three NIST 800-88 levels

  • Clear: overwrite with standard tools. Defeats ordinary recovery. Good when the device stays inside your organization.
  • Purge: stronger methods that resist lab recovery, such as cryptographic erase, ATA Secure Erase or Sanitize, or degaussing for magnetic media.
  • Destroy: physical destruction, shredding, disintegration or incineration. Used when media is too sensitive or broken.

02 mid // how it's actually used

Media type changes everything

  • HDDs (magnetic platters): overwriting works; degaussing works (and destroys the drive)
  • SSDs and NVMe: wear leveling and spare blocks mean overwriting the visible drive misses data. Use the drive's own ATA Secure Erase, NVMe Sanitize/Format or crypto erase. Degaussers do nothing to flash
  • Self-encrypting drives: crypto erase throws away the key, making all data unreadable in seconds
$ grep -i "nvme\|ssd" ~/attachments/sanitization-matrix.txt

Proof

Every wipe needs a record: asset tag, serial, method, tool, operator, date and verification result. Vendors that destroy drives give a certificate of destruction. Without the record, you can't prove it happened.

Matching method to media

  • HDD: a single overwrite pass is enough with modern drives; degauss is an alternative; shred for the highest sensitivity.
  • SSD / NVMe / flash: overwriting is unreliable because of wear-leveling and spare blocks. Use the drive's Secure Erase / Sanitize or cryptographic erase (destroy the encryption key of a self-encrypting drive or fully encrypted disk), and destroy if that is not available.
  • Phones and tablets: encrypt, then factory reset, remove accounts first (Activation Lock, FRP) and the SIM and SD card.
  • Printers and copiers: have internal storage, wipe through the manufacturer menu.
  • Optical and tape: shred or disintegrate.
  • Cloud: delete data and keys, check retention and backups, request provider attestation.

Paperwork

A sanitization record shows: asset tag, serial number, media type, method and tool, date, operator, verification result and the destination (reuse, resale, recycle). A certificate of destruction from a vendor lists the serials destroyed. Check legal holds first: never destroy anything subject to litigation or an investigation.

03 complex // what the pros do

Verifying a wipe

Sanitization isn't done until it's verified: sample the drive (or read it fully) and confirm no original data remains. Tools like Blancco produce signed reports. A secure-erase command that returns "success" on a drive with a buggy firmware is a known failure mode, so verification matters.

Common mistakes

  • using a multi-pass overwrite on an SSD and calling it purged
  • degaussing an SSD
  • formatting (quick format only rewrites the file system tables)
  • forgetting other storage: printers, copiers, phones, network gear, USB sticks and the SD card in a camera
  • wiping before checking for a legal hold that requires keeping the data
$ cat ~/attachments/legal-holds.txt

Verification

Sample-check wiped drives by trying to read them with a recovery tool and confirming that no data of value appears. For cryptographic erase, confirm that the drive was truly encrypted from the start; encrypting after data is already on it does not protect old blocks.

Planning for sanitization from day one

Full-disk encryption on every laptop makes disposal easy: destroy the key and the data is unreadable. Keep an asset inventory so nothing leaves unrecorded, store removed drives in a locked container, and make destruction vendors sign a contract that covers chain of custody and liability. Treat remote wipe (MDM) as a loss-response tool, not a disposal procedure.

ref reference // commands and terms, also on the cheatsheet

linux tools

shred -vzn 1 /dev/sdX
overwrite a disk once, then zeros
dd if=/dev/zero of=/dev/sdX bs=1M status=progress
zero a disk
hdparm -I /dev/sdX
check if Secure Erase is supported and not frozen
hdparm --user-master u --security-set-pass p /dev/sdX
set a temporary password before secure erase
hdparm --security-erase p /dev/sdX
ATA Secure Erase
nvme format /dev/nvme0n1 -s 1
NVMe format with user-data erase
blkdiscard /dev/sdX
TRIM the entire SSD
cryptsetup luksErase /dev/sdX
destroy LUKS keyslots, making data unreadable

windows tools

cipher /w:C:\
overwrite free space on a volume
diskpart → clean all
zero a whole disk
Reset this PC → Remove everything
consumer reset, clear-level only
Manage-bde -off C:
decrypt BitLocker if required (not a wipe)

verification

sha256sum /dev/sdX
hash proves a zero or pattern fill if you know the expected value
xxd /dev/sdX | head
look at the start of the disk
photorec
try recovery on a wiped disk as a spot check
