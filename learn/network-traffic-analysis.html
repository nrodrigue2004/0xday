Every attack crosses the network. Learn to read packet captures like a story: who talked to whom, what they said, and what looks wrong, then catch data leaving through DNS.

1simple2mid3complex4hands-on

01 simple // the idea in plain words

Computers talk in packets: small chunks of data with a source address, a destination address, a protocol and a payload. A packet capture (pcap) records every packet that crossed a network interface, and tools like Wireshark, tshark and tcpdump let you read it.

The lab's captures have been exported as text, one packet per line, which is exactly what tshark -r file.pcap prints. Each line reads: time, source -> destination, protocol, details.

$ ls ~/captures
$ head -5 ~/captures/dns.txt

Start every capture with three questions: which hosts are talking, which protocols, and what's unusual for this network.

02 mid // how it's actually used

Conversations and protocols

The fastest overview is who talks to whom. Pull the source and destination columns and count them, the text version of Wireshark's *Statistics > Conversations*:

$ awk '{print $2, $4}' ~/captures/tcp.txt | sort | uniq -c | sort -rn | head

Spotting a port scan

A scan looks like one source sending SYN packets to many ports on one target, with almost nothing else. Count distinct destination ports per target:

$ grep SYN ~/captures/tcp.txt | grep 10.0.20.60

Plain-text protocols leak

HTTP, FTP, Telnet and SMTP without TLS send everything readable, including passwords:

$ grep -i "pass" ~/captures/http.txt

In Wireshark these are display filters: tcp.flags.syn==1 && tcp.flags.ack==0, http.request.method=="POST", dns.qry.name contains "corp".

03 complex // what the pros do

DNS: the protocol everyone allows

Almost every network lets DNS out, so attackers use it as a covert channel. Data gets chunked, encoded (base64 or hex) and stuffed into subdomains: <chunk>.attacker-domain.com. The attacker's name server logs every query and reassembles the data. Signs of it:

  • Long, random-looking subdomain labels, often numbered so they can be reordered
  • Lots of unique subdomains under one rarely-seen domain
  • One internal host making most of those queries

List every domain queried, then look for the odd one out by counting the registered domain (the last two labels). Reversing the string makes "last two" into "first two", which cut can grab:

$ awk '{print $NF}' ~/captures/dns.txt | rev | cut -d. -f1-2 | rev | sort | uniq -c | sort -rn

Beyond the capture

Full pcaps are huge, so SOCs also keep flow data (NetFlow/Zeek conn logs: who, when, how many bytes) for weeks and full packets for days. Long-lived connections with regular timing are beaconing (malware checking in with its C2 server). Encrypted traffic still leaks metadata: SNI hostnames, certificate details and JA3/JA4 fingerprints.
