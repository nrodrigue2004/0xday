Kali is a toolbox, not a skill. Learn what's in it, how to run it safely in a homelab, and how to keep your own attack box from becoming the easiest target on the network.

1simple2mid3complex4hands-on

01 simple // the idea in plain words

Kali Linux is a Debian-based distribution that comes with hundreds of security tools preinstalled: scanners, web proxies, password auditors, forensics and wireless tools. It's what pentesters, CTF players and students boot into.

In a homelab, Kali usually runs as a VM on a separate network segment, so practice traffic never touches your real network. Its default user is kali and tools live in the menu by category, or are just commands:

$ cat /etc/os-release
$ cat ~/tool-categories.txt

Kali is for authorized testing on systems you own or have permission to test. The tools are legal; using them on other people's systems isn't.

02 mid // how it's actually used

Keeping it current

Kali is a rolling release: tools update constantly. Update before every engagement, and install extra tools from its repositories with apt:

$ apt list --upgradable
$ apt search gobuster

Know where things live

  • Wordlists: /usr/share/wordlists/ (rockyou is gzipped by default)
  • Nmap scripts: /usr/share/nmap/scripts/, Metasploit: msfconsole
  • Web: Burp Suite, ZAP, gobuster/feroxbuster, sqlmap, nikto
$ ls /usr/share/wordlists

Organize your work

Make a folder per target with nmap/, loot/, notes.md, and save every scan with -oA. A pentest is only as good as its report, and the report is only as good as your notes.

03 complex // what the pros do

Your attack box is a target too

A Kali VM full of credentials, client data and open services is attractive. Harden it like any server:

  • change the default password, or better, disable password SSH login entirely
  • don't leave services like SSH, a Python web server or a reverse-shell listener running and exposed after you're done
  • keep client data encrypted and delete it when the engagement ends
  • snapshot a clean baseline and revert between engagements
$ cat ~/audit/ss-tulpn.txt

Safe homelab layout

Put Kali and vulnerable targets on an isolated internal network (a pfSense LAN or Proxmox bridge with no route to your home LAN), and give the lab internet only when you need updates. That way a vulnerable VM never sits on the same network as your family's devices.
