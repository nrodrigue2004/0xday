01 simple // the idea in plain words

A data structure is a way to organize data; an algorithm is a recipe that works on it. The basics:

  • Array: items side by side in memory, instant access by index (a[5])
  • Linked list: each item points to the next; easy inserts, slow lookups
  • Stack (last in, first out: undo, the call stack) and queue (first in, first out: print jobs, packet buffers)
  • Hash table (dictionary, map): key to value in about one step
  • Tree and graph: items connected by links (folders, networks, social graphs)

Big-O describes how the work grows with input size *n*: O(1) constant, O(log n) halving each time, O(n) look at everything once, O(n²) compare everything with everything.

What a data structure is for

Choose a structure by what you do most. Array/list: fast access by position. Hash table (dict, set): fast lookup by key. Stack: last in, first out (undo, call stack). Queue: first in, first out (job processing, BFS). Linked list: cheap insert in the middle, slow to search. Tree: hierarchical data and sorted lookup. Heap: always gives the smallest or largest next. Graph: networks and relationships (hosts, users, attack paths).

Big-O describes how work grows with input size: O(1) constant, O(log n) halving, O(n) one pass, O(n log n) good sorting, O(n²) nested loops, O(2ⁿ) trying everything.

02 mid // how it's actually used

Binary search

On a sorted array, look at the middle: if it's too small, throw away the left half, if too big, the right half. Each step halves what's left, so a million entries take about 20 steps: O(log n). Linear search would take up to a million.

Sorting

Merge sort and quicksort are O(n log n); bubble sort is O(n²). You usually call the language's built-in sort, but you need to know that binary search only works on sorted data.

Hash tables

A hash function turns the key into a bucket number. Average O(1) lookup, which is why blocklists, caches and password-cracking wordlists use them. Collisions (two keys, same bucket) are handled with chaining or probing.

Complexity cheat table

Array index O(1), array search O(n), sorted array binary search O(log n), hash lookup average O(1), insert into a balanced tree O(log n), sort O(n log n), nested loops over the same list O(n²). Space matters as well as time: a hash set trades memory for speed.

Patterns that solve most problems

  • Hash map for counting and lookup: count occurrences, find duplicates, two-sum.
  • Two pointers / sliding window: pairs in sorted data, longest substring without repeats.
  • Stack: matching brackets, parsing, undo.
  • BFS (queue): shortest path in an unweighted graph, nearest neighbor.
  • DFS (stack or recursion): explore everything, find connected components, detect cycles.
  • Sorting first: many problems get easy once the data is ordered.
  • Binary search: not just arrays, any monotonic yes/no question.

Recursion

A recursive function needs a base case and a step toward it. Each call uses stack space, so deep recursion overflows; convert to a loop when depth is large. Memoization (cache results) turns exponential recursion like Fibonacci into linear.

03 complex // what the pros do

Off-by-one errors

The most common algorithm bug. Binary search has three places to get it wrong: the initial hi (n or n - 1), the loop condition (< or <=), and the updates (mid or mid ± 1). They must agree. With hi = n - 1 (inclusive), the loop must be while (lo <= hi), otherwise the last remaining candidate is never checked.

$ break 16
$ continue

$ print hi

Algorithms in security

  • Hash flooding DoS: send keys that all collide, turning O(1) lookups into O(n). Languages now use randomized (keyed) hash functions like SipHash
  • Regex DoS (ReDoS): badly written patterns take exponential time on crafted input
  • Graphs: BloodHound models Active Directory as a graph and runs shortest path to find the quickest route from a normal user to Domain Admin
  • Bloom filters: tiny probabilistic sets, used to check "is this password in a breach list?" without storing the list
  • Tries and Aho-Corasick: match thousands of IDS signatures in one pass

Dynamic programming in one paragraph

When a problem breaks into overlapping subproblems (shortest edit distance, knapsack, longest common subsequence), store each subproblem's answer in a table so it is computed once. Define the state, the transition, the base case and the order of filling.

Graphs in security

Hosts and connections form a graph: BFS finds the shortest path an attacker could take, BloodHound is a graph of Active Directory permissions, dependency trees are graphs (supply chain), and firewall rule analysis is reachability. Trie and bloom filters power fast blocklist lookups, hashing powers integrity checks, and rate limiting uses queues and sliding windows.

Algorithmic attacks

Hash collision attacks degrade a hash table to O(n) per lookup (a denial of service), catastrophic regex backtracking (ReDoS) takes exponential time on crafted input, and unbounded recursion or allocation exhausts memory. Know the worst case, not just the average case, for anything that handles untrusted input.
