Metasploitable 2, DVWA and WebGoat are machines and apps built to be broken, so you can practice safely. Learn how to run them without exposing them, what each one teaches, and how to read the vulnerable code.

1simple2mid3complex4hands-on+ref

01 simple // the idea in plain words

A vulnerable-by-design target is software with known holes, made for practice. Attacking something you own, in an isolated lab, is legal and the best way to learn. Attacking anyone else's system is not.

The three in the homelab:

  • Metasploitable 2: a whole Linux VM full of old services (FTP, SMB, Tomcat, a backdoored vsftpd). Practice: scanning, service exploits, Metasploit
  • DVWA (Damn Vulnerable Web App): a PHP/MySQL site with SQL injection, XSS, command injection, file upload and more, with security levels low, medium, high and impossible
  • WebGoat: a Java teaching app that walks you through lessons (injection, broken access control, JWT, XXE) with hints and a check for each one

$ ls ~/targets/dvwa

Rule one: keep them contained

These machines are meant to be compromised. Put them on an isolated lab subnet (a pfSense interface with no route to your home network, no port forwarding, no bridged adapter). Never expose them to the internet: scanners will own them within hours and use your IP.

02 mid // how it's actually used

Setting them up

  • Metasploitable 2: import the VM into Proxmox/VirtualBox, give it a host-only or isolated lab network, log in with the credentials printed on its banner, and snapshot it before you start
  • DVWA: run it in Docker (docker run -p 127.0.0.1:8080:80 vulnerables/web-dvwa) or on a Linux VM; open /setup.php, click create database, log in, then set DVWA Security from the menu
  • WebGoat: java -jar webgoat-*.jar or the Docker image; browse to port 8080 /WebGoat, register a local account (nothing leaves your machine)

Always bind to localhost or the lab network only. Take a snapshot so you can reset in a minute.

What to practice on each

  • Metasploitable: nmap -sV the host, search each version in searchsploit, try Metasploit modules (vsftpd 2.3.4, Samba usermap, distcc), read the resulting logs from the defender's side in Security Onion
  • DVWA: SQL injection (' OR '1'='1), reflected and stored XSS, command injection (; id), file inclusion and upload. Use Burp Suite or the browser dev tools to see the requests
  • WebGoat: follow the lessons in order; they teach the idea, then make you exploit it

Read the source at every level

DVWA lets you view the source of each page. Compare low (no checks), medium (a weak filter that can be bypassed), high (stronger but quirky) and impossible (parameterized queries, tokens). Seeing why impossible is safe is worth more than the exploit.

Think like both sides

Every attack you run leaves a trail. After each success, look at what the web server log, the pfSense log and Security Onion saw. A good lab note says: what I did, what the log showed, and the control that would have stopped it.

03 complex // what the pros do

Lab hygiene and safety

  • Separate VLAN/subnet per purpose: attacker (Kali), targets, monitoring, management; allow attacker to targets only
  • pfSense default-deny with explicit rules; log blocked traffic, since a blocked attempt is a lesson too
  • Snapshots before and after each exercise; revert to a clean state
  • Never reuse a real password on a deliberately weak machine; treat anything typed into it as public
  • Keep the lab off a work or school network, and disable shared folders and clipboard in the VM

Mapping exercises to real frameworks

Tag each practice with the OWASP Top 10 category (A01 Broken Access Control, A03 Injection, A07 Identification and Authentication Failures) and, for the whole-network exercises, the MITRE ATT&CK technique (T1190 exploit public-facing app, T1059 command interpreter). It turns a weekend of poking at DVWA into interview answers.

Sample write-up shape

  1. Target and version, date, network location
  2. Recon: ports and services, with the command
  3. Finding: the flaw, where it is, how you confirmed it
  4. Impact: what an attacker gets
  5. Evidence: request, response, screenshot (redact nothing sensitive because it is a lab)
  6. Fix: the code or config change, and the detection that would catch it

Beyond the basics

Move on to other practice platforms (TryHackMe rooms, Hack The Box, VulnHub machines, OWASP Juice Shop, bWAPP) when these feel easy. The skill is the method: enumerate, form a hypothesis, test it, write down what happened.
