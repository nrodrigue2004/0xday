Databases are where the valuable data lives. Learn tables, keys, normalization, transactions and indexes, then run real SQLite in your browser to find the account whose balance was tampered with.

01 simple // the idea in plain words

A relational database stores data in tables: rows (records) and columns (fields). Each table has a primary key that uniquely identifies a row, and a foreign key in one table points at the primary key of another, which is how tables relate.

SQL is how you ask questions. The sandbox runs real SQLite (the first run downloads it once):

$ sqlite3 bank.db ".tables"
$ sqlite3 bank.db "SELECT * FROM accounts;"

The four basic operations are CRUD: Create (INSERT), Read (SELECT), Update (UPDATE), Delete (DELETE).

Other databases (PostgreSQL, MySQL, SQL Server) use the same SQL with small differences. MongoDB and Redis are NoSQL: documents or key-value pairs instead of tables.

02 mid // how it's actually used

Relationships and JOINs

One customer has many transactions: a one-to-many relationship. A JOIN combines tables on the key that links them, and GROUP BY + SUM / COUNT turns many rows into one per group:

$ sqlite3 bank.db "SELECT a.owner, COUNT(*) FROM accounts a JOIN txns t ON t.account_id = a.id GROUP BY a.owner;"

Normalization

Store each fact once. If the owner's name is copied into every transaction row, changing it means updating hundreds of rows, and some will be missed. Normal forms (1NF, 2NF, 3NF) are rules for splitting tables so data can't contradict itself.

Transactions and ACID

A transaction groups changes so they all happen or none do (moving money: subtract here, add there). ACID = Atomic, Consistent, Isolated, Durable.

03 complex // what the pros do

Integrity as a security control

The I in the CIA triad. Databases protect it with constraints (NOT NULL, UNIQUE, CHECK (balance >= 0), foreign keys), transactions, and audit trails. A classic check: does a stored total match the sum of the records it's supposed to summarize? If not, someone changed one without the other.

$ sqlite3 bank.db "SELECT account_id, SUM(amount) FROM txns GROUP BY account_id;"

Indexes and performance

An index is a sorted lookup structure (usually a B-tree) on a column, turning a full table scan into a quick search. It speeds up reads and slows down writes. EXPLAIN QUERY PLAN shows whether a query uses one.

Database security

  • SQL injection: always parameterized queries (? placeholders), never string concatenation
  • Least privilege: the web app's DB user can't DROP TABLE or read the HR schema
  • Encryption at rest (TDE) and in transit (TLS), tokenization or masking for card numbers
  • Backups tested by actually restoring them, and database activity monitoring
