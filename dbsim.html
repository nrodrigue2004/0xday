~/dbsim database design and performance tools

Three tools for CS230: find keys and normal forms, see why an index helps (and when it does not), and test whether a set of overlapping transactions is serializable.

Functional dependencies and normal forms

One dependency per line, like order_id product_id -> qty. The tool finds every candidate key, the prime attributes and the highest normal form, and lists what violates the next one. Extra attributes with no dependency go in the second box. Closure asks: from these columns, what can I derive?

Index versus table scan

A simplified cost model counted in page reads. The B-tree walk costs its height, then one table page for every matching row. A scan reads every page. Slide the table size, then raise the rows returned and watch the planner give up on the index.

Schedule serializability

Write a schedule as r1(x) w2(x) ... (transaction number, item). The tool draws the precedence graph as a list of edges and says whether the schedule is conflict-serializable, with an equivalent serial order if so.
