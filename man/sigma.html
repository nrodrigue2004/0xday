SIGMA(7)0xDay Field ManualSIGMA(7)

sigma - Sigma rule fields, modifiers and conditions, plus ATT&CK tactic names

SECTIONS ATT&CK vocabulary Detection terms rule fields modifiers pySigma tactics hunting patterns hypothesis template

ATT&CK vocabulary

tactic
the attacker's goal at that step, such as Persistence
technique (T1059)
a way to reach a tactic, with a numeric ID
sub-technique (T1059.001)
a specific variant, here PowerShell
procedure
how one named actor or tool performs the technique
data source
the log type that shows the behavior, such as Process Creation

Detection terms

true positive
alert fired on real malicious activity
false positive
alert fired on benign activity
false negative
malicious activity that produced no alert
detection-as-code
rules stored, tested and deployed like software
pyramid of pain
hashes < IPs < domains < artifacts < tools < TTPs, in how hard they are for an attacker to change

rule fields

title / id / status
name, UUID, experimental|test|stable
logsource
category (process_creation), product (windows), service
detection
named selections plus a condition
condition
selection and not filter / 1 of selection_* / all of them
tags
attack.<tactic> and attack.tNNNN[.NNN] mapping
level
informational, low, medium, high, critical

modifiers

contains / startswith / endswith
substring tests (case-insensitive)
all
every value in the list must match
re
regular expression match
cidr
IP is in the range
base64offset
match a string in its base64 forms

pySigma

sigma convert -t splunk -p sysmon rule.yml
convert a rule to a Splunk query
sigma check rules/
validate rule syntax
sigma list targets
show supported SIEM backends

tactics

attack.initial-access | attack.execution
attack.persistence
attack.privilege-escalation | attack.defense-evasion
attack.credential-access
attack.discovery | attack.lateral-movement
attack.collection
attack.command-and-control | attack.exfiltration
attack.impact

hunting patterns

stacking
count values of a field and examine the rare end
beaconing
regular connection intervals to one destination
parent-child
which process started which: Office -> cmd is suspicious
first seen
a user, host or binary doing something for the first time
long tail
very low-frequency values in a large dataset

hypothesis template

Hypothesis
If <attacker action> happened, we would see <artifact> in <log>
Data
which sources and what time range
Result
malicious / benign (why) / inconclusive (what is missing)
Output
new rule, new logging, or no action
