rev - Reverse engineering and exploitation: triage commands, dynamic-analysis tools, checksec and gdb

SECTIONS windows dynamic analysis linux dynamic analysis ioc terms packer triage packer terms x86 patterns reversing commands format string conversions finding and fixing checksec fields commands gadget terms

windows dynamic analysis

procmon.exe
log file, registry, process and network events
procexp.exe
process tree with handles, DLLs and strings
autoruns.exe
everything configured to start automatically
regshot
diff the registry before and after
wireshark
capture the sample's network traffic
fakenet-ng
fake DNS, HTTP and other services for the sample
x64dbg
debugger: breakpoints on API calls

linux dynamic analysis

strace -f -e trace=file,network,process ./s
system calls: files, sockets, processes
ltrace ./s
library calls
inetsim
fake internet services for the sample
gdb ./s
debugger
tcpdump -i eth0 -w cap.pcap
capture traffic

ioc terms

IOC
indicator of compromise: hash, domain, IP, path, key, mutex
mutex
named lock malware uses to run only once; a good IOC
beacon
regular check-in to the C2 server
dropper
malware whose job is to write and run the next stage
persistence
how it survives a reboot

packer triage

pecheck / pe-bear
list sections, entropy, imports
diec file.exe
Detect It Easy: packer and compiler guess
upx -d file.exe
unpack a UPX-packed file
strings -n 8 file
readable strings (few = packed)
xxd file | head
look at the raw bytes
ent file
entropy of a file (0 to 8)

packer terms

stub
the small program that unpacks the real one
OEP
original entry point: where the real program starts
tail jump
the jump from the stub to the OEP
entropy
randomness per byte, 0 to 8; above 7 is packed or encrypted
UPX0 / UPX1
UPX section names
import rebuild
repairing the import table after dumping
PEB walk
stub finds API functions by looking at loaded modules

x86 patterns

xor eax, eax
set register to 0
cmp a, b / jne L
if (a != b) goto L
test eax, eax / jz L
if (eax == 0) goto L
movzx eax, byte [p+i]
eax = p[i] (one byte)
xor al, K
al ^= K
inc ecx / dec ecx
i++ / i--
call f
call a function; result in eax/rax
ret
return

reversing commands

objdump -d -M intel bin
disassemble in Intel syntax
gdb -q ./bin
start the debugger
break *0x401136
breakpoint at an address
x/8bx $rsp
examine 8 bytes in hex
info registers
all registers
python3 -c 'print(...)'
quick decoder calculations

format string conversions

%p
print the next argument as a pointer (leak)
%x / %lx
print as hex (4 or 8 bytes)
%s
read text at the pointer in the next argument
%n
write the number of characters printed so far (dangerous)
%7$p
read the 7th argument directly
%c
print one character

finding and fixing

printf("%s", s)
the safe form: s is data, not format
gcc -Wformat-security
warn on non-literal format strings
gcc -D_FORTIFY_SOURCE=2 -O2
runtime checks that reject unsafe %n
grep -n "printf *([a-z_]*)" *.c
find printf(var) calls
checksec --file=./bin
see if canary, PIE, RELRO and NX are enabled

checksec fields

Partial RELRO / Full RELRO
GOT writable until / read-only after startup
No canary found
stack overflows are not detected on return
NX enabled
stack and heap are not executable
No PIE
program loads at a fixed address
PIE enabled
program address randomized each run
FORTIFY
libc calls checked at run time

commands

checksec --file=./bin
show the protections of one binary
checksec --dir=/usr/bin
check a whole directory
cat /proc/sys/kernel/randomize_va_space
2 means full ASLR
ldd ./bin
run twice to see library addresses change under ASLR
gcc -fstack-protector-strong
add canaries to risky functions
gcc -fPIE -pie
position-independent executable
gcc -Wl,-z,relro,-z,now
full RELRO
gcc -fsanitize=address
catch memory errors in test builds

gadget terms

gadget
a few instructions ending in ret
chain
a list of gadget addresses and values on the stack
pop rdi; ret
puts the next stack value into the first-argument register
ret2libc
return into a library function with chosen arguments
ret2win
return into a function that already prints the flag (CTF)
CET shadow stack
hardware check that every ret goes where its call came from
