appsec - STRIDE, common scanner commands and CI security gates

SECTIONS STRIDE DFD elements SAST tools DAST tools terms scanners

STRIDE

Spoofing
pretending to be someone else -> authentication
Tampering
modifying data -> integrity
Repudiation
denying an action -> logging and non-repudiation
Information disclosure
leaking data -> confidentiality
Denial of service
exhausting a resource -> availability
Elevation of privilege
gaining rights -> authorization

DFD elements

external entity
user or system outside your control
process
code that handles data
data store
database, file, bucket, queue
data flow
data moving between elements
trust boundary
where trust level changes; check every crossing

SAST tools

semgrep --config auto .
run Semgrep with community rules on the current folder
bandit -r src/
Python security linter
codeql database create db --language=python
build a CodeQL database
gitleaks detect
scan a repo and its history for secrets

DAST tools

zap-baseline.py -t URL
passive OWASP ZAP scan
zap-full-scan.py -t URL
active scan (staging only)
nikto -h URL
quick web server checks

terms

CWE
Common Weakness Enumeration, catalog of bug types (CWE-89 is SQL injection)
false positive
a finding that is not a real vulnerability
taint analysis
tracking untrusted input from source to dangerous sink
baseline
the set of existing findings you accept for now

scanners

npm audit
check Node dependencies against advisories
pip-audit
check Python dependencies
osv-scanner -r .
scan a folder against the OSV database
grype dir:.
vulnerability scan using an SBOM or folder
syft dir:. -o cyclonedx-json
generate an SBOM
trivy fs .
scan files, images and IaC for vulnerabilities and misconfig
gitleaks detect
scan git history for secrets
