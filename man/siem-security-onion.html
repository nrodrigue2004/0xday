siem-security-onion - SIEM / Security Onion commands and terms

SECTIONS roles and logs zeek fields worth knowing hunting queries (patterns) triage verdicts command line

roles and logs

Suricata
signature-based IDS/IPS, writes alerts
Zeek
passive network analyzer, writes conn, dns, http, ssl, files, notice logs
Stenographer
full packet capture you can pull by IP, port and time
Elastic
stores and searches all events
Alerts page
the triage queue of IDS and other detections
Hunt page
query and group events to look for what no rule caught
PCAP
pivot from an event to the raw packets

zeek fields worth knowing

id.orig_h / id.resp_h
source and destination IP
id.resp_p
destination port
conn_state
S0 no reply, SF normal finish, REJ rejected, RSTO reset by originator
orig_bytes / resp_bytes
bytes sent by each side, large outbound can mean exfiltration
query / qtype_name
DNS question, long or random names suggest tunnelling or DGA
uid
connection ID that ties together entries across logs

hunting queries (patterns)

event.dataset:conn AND destination.port:22
all SSH connections
event.dataset:dns AND dns.query.name:*.top
DNS lookups ending in a suspicious TLD
rule.category:"Attempted Administrator Privilege Gain"
alerts of that class
source.ip:10.0.30.20
everything one host did
groupby source.ip destination.port
stack to see who talks to what

triage verdicts

True positive
real malicious activity, escalate and contain
Benign true positive
rule worked, behavior is authorized (scanner, pentest)
False positive
rule fired but behavior is not what it describes, tune it
Undetermined
not enough data, collect more and note what is missing

command line

so-status
health of all Security Onion services
so-allow
open the firewall for a new analyst or sensor
sudo so-rule-update
refresh the Suricata ruleset
so-test
replay sample traffic to check alerting
