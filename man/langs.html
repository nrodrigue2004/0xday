langs - Languages and compilers: grammar notation, types, parsing terms and Python idioms for interpreters

SECTIONS paradigm terms type terms python type commands scope terms functional python toolchain commands compiler terms lexer terms python re for lexers grammar notation parser terms interpreter terms python introspection automata terms regex basics computability terms

paradigm terms

pure function
same input gives same output, no side effects
side effect
any visible change outside the function: I/O, globals, mutation
referential transparency
a call can be replaced by its value without changing the program
encapsulation
callers use methods, not internals
polymorphism
one call, behavior chosen by the object's type
composition
an object holds another instead of inheriting from it
declarative
state the result you want, not the steps (SQL, regex)
invariant
a fact that stays true on every loop iteration
strict vs lazy
arguments evaluated before the call vs only when used

type terms

static typing
types checked before the program runs
dynamic typing
types checked at runtime
strong typing
the language refuses to mix types silently
weak typing
the language converts types silently
type inference
the compiler works out types you did not write
generics
one definition parameterized over types
sum type
a value that is one of several shapes
product type
a record with several fields at once
sound
the checker's guarantees actually hold

python type commands

type(x)
the runtime type of a value
isinstance(x, int)
check a type at runtime
int("443")
convert text to a number (raises ValueError if it is not one)
mypy file.py
static type check of the hints
x: int = 5
a type hint (ignored when the program runs)

scope terms

local
visible only inside its function
global
visible everywhere in the file
LEGB
Python lookup order: Local, Enclosing, Global, Built-in
closure
a function plus the variables it captured
nonlocal x
assign to a variable of the enclosing function
global x
assign to a module-level variable
late binding
closures see a variable's latest value, not its value when made
shadowing
an inner name hides an outer one
lexical scope
meaning decided by where code is written
lifetime
how long a value exists (not the same as where its name is visible)

functional python

[f(x) for x in xs if p(x)]
map and filter in one comprehension
(f(x) for x in xs)
lazy generator expression, one item at a time
map(f, xs)
apply f to each item (lazy)
filter(p, xs)
keep items where p is true (lazy)
functools.reduce(f, xs, init)
fold a list into one value
sum(xs) / max(xs, key=f)
common folds
sorted(xs, key=f)
sort by any function of the item
functools.partial(f, a)
fix the first argument of f
functools.lru_cache
memoize a pure function
itertools.groupby(xs, key=f)
group consecutive items (sort first)

toolchain commands

gcc -E file.c
preprocess only
gcc -S file.c
compile to assembly (file.s)
gcc -c file.c
assemble to an object file
gcc -O0 / -O2
no optimization / standard optimization
gcc -g
include debug symbols
gcc -fstack-protector-strong
add stack canaries
objdump -d bin
disassemble a binary
nm bin
list symbols
readelf -S bin
list ELF sections
strip bin
remove symbol names
ldd bin
list shared libraries a binary needs

compiler terms

token
smallest meaningful piece of source (name, number, symbol)
AST
tree of how the code nests
IR
simple intermediate form between source and machine code
SSA
each value assigned exactly once, makes optimization easier
basic block
straight-line code with one entry and one exit
CFG
graph of basic blocks joined by branches
JIT
compile hot code while the program runs
linker
joins object files and libraries, resolves symbols

lexer terms

token
a kind plus the text it came from
lexeme
the actual text of a token
longest match
the lexer takes the longest string a pattern allows
keyword
a reserved name such as if, while, return
whitespace
skipped between tokens

python re for lexers

re.compile(p)
compile a pattern once
(?P<NAME>pattern)
a named group
m.lastgroup
name of the group that matched
m.start() / m.end()
position of the match
re.finditer(p, s)
iterate over all matches
\d+ / \w+ / \s+
digits / word characters / whitespace

grammar notation

rule := a b | c
symbols after := define the rule on the left
a | b
choose a or b
a*
zero or more a
a+
one or more a
a?
optional a
"+"
a literal token

parser terms

AST
tree of the program's structure
recursive descent
one function per grammar rule
precedence
which operator binds tighter
associativity
grouping of equal operators: (a-b)-c is left
left recursion
rule that starts with itself, loops in LL parsers
ambiguous grammar
one string, two trees
fuzzing
feeding a parser mutated input to find crashes

interpreter terms

environment
table mapping names to values
AST-walking interpreter
evaluates the tree directly
bytecode VM
compiles to simple instructions, runs them in a loop
expression
produces a value
statement
does something, usually changes state
call stack
frames for active function calls
step limit
counter that stops runaway programs

python introspection

import dis; dis.dis(f)
show the bytecode of a function
ast.parse(src)
build Python's own AST
ast.dump(tree)
print an AST
compile(src, "f", "exec")
compile source to a code object
eval / exec
run Python text (never on untrusted input)

automata terms

state
a node: all the machine remembers
transition
which state to go to on a given input symbol
accepting state
ending here means the string is accepted
DFA
exactly one move for each state and symbol
NFA
may have several moves or empty moves
regular language
what a DFA or regex can recognize
pumping lemma
proof tool for showing a language is not regular
ReDoS
regex that takes exponential time on crafted input
Aho-Corasick
automaton that finds many fixed strings in one pass

regex basics

.
any character
[abc] / [^abc]
one of / none of those
a* / a+ / a?
zero or more / one or more / optional
a{2,4}
between 2 and 4
(x|y)
alternation
^ and $
start and end of the string
\d \w \s
digit, word character, whitespace

computability terms

regular language
recognized by a finite automaton or regex
context-free language
recognized by a pushdown automaton (adds a stack)
Turing machine
finite controller plus unbounded tape: the model of a computer
decidable
a program always halts with the right answer
halting problem
undecidable: no program can predict halting for all programs
Rice's theorem
every non-trivial question about program behavior is undecidable
P
solvable in polynomial time
NP
answers can be checked in polynomial time
NP-complete
hardest problems in NP
reduction
showing one problem is at least as hard as another
SAT / SMT solver
tools that attack hard logic problems in practice
