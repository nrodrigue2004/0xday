~/dojo/sql 6 katas

Threat hunting in SQL. Every kata runs against the same small SOC database: users, login events, hosts and alerts. Your result set is compared with the reference query's.

[runs in your browser] runtime: SQLite 3 compiled to WebAssembly (sql.js); a fresh database for every run

Tables: users(id, name, dept, is_admin), logins(id, user_id, ts, ip, success), hosts(id, hostname, os), alerts(id, host_id, ts, severity, rule). ts is ISO-8601 text, success and is_admin are 0/1, severity is 1-5. Column names in your output don't have to match, but column count and values do.

0/6 solved

  1. List the name of every admin user (is_admin = 1), alphabetically.

  2. For every user with at least one failed login (success = 0), return name and the number of failures, most failures first, then by name.

  3. Which hosts have never raised an alert? Return their hostname.

  4. A password spray is one source IP failing against many different accounts. Return each ip with failed logins against 3 or more distinct users, plus that user count, highest first.

  5. The scary pattern: 3 or more failed logins for a user from an IP, followed later by a successful login for the same user from the same IP. Return name, ip and the ts of that success. If there are several successes, return the first one. Sort by ts.

  6. For each host that has alerts, return hostname, the rule of its most recent alert, and how many alerts it has in total. Sort by hostname. Window functions make this clean: ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...).

Keys inside the editor: Tab indents, Ctrl+Enter runs the tests, Esc leaves the editor. Progress is saved in this browser only.
