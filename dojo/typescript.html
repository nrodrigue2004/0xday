~/dojo/typescript 5 katas

Types as a design tool. Every kata is type-checked with --strict before the tests run, so a type error fails the kata just like a wrong answer.

[runs in your browser] runtime: the real TypeScript 5.4 compiler (tsc --strict) in a Web Worker, then your browser's JS engine

0/5 solved

  1. Write first<T>(xs: T[]): T | undefined that returns the first element, or undefined for an empty array. It must be generic: first(["a"]) has type string | undefined, not any.

  2. Given the union below, write area(s: Shape): number. Use a switch on s.kind, and in the default branch assign s to a variable of type never, so adding a new shape later becomes a compile error until you handle it. Round nothing; tests compare with a small tolerance.

    type Shape =
  | { kind: "circle"; r: number }
  | { kind: "rect"; w: number; h: number }
  | { kind: "tri"; base: number; height: number };

  3. Define interface LogEntry { ts: string; level: "INFO" | "WARN" | "ERROR"; msg: string } and write parseLine(line: string): LogEntry | null for lines like 2026-11-07T10:00:00Z [WARN] disk 91% full. Return null if the line doesn't match or the level isn't one of the three. No any, no as casts allowed on the level. Narrow it with a type guard instead.

  4. Write groupBy<T, K extends string>(xs: T[], key: (x: T) => K): Record<K, T[]>. The return type should know the keys: grouping alerts by a "low" | "high" field gives a Record<"low" | "high", Alert[]>. Only keys that actually occur appear in the object.

  5. Errors as values. Define type Result<T> = { ok: true; value: T } | { ok: false; error: string }. Then write:

    • parsePort(s: string): Result<number>: ok for a whole number 1-65535, else an error string
    • all<T>(rs: Result<T>[]): Result<T[]>: ok with every value if all are ok, otherwise the **first** error

    The compiler must stop you from reading .value without checking .ok first.
