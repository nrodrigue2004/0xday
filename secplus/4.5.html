SY0-701domain 4.0 · Security Operations4.5

4.5 Given a scenario, modify enterprise capabilities to enhance security

key ideas

  • Firewall: rules, access lists, ports/protocols, screened subnets. IDS/IPS: trends, signatures.
  • Web filter: agent-based, centralized proxy, URL scanning, content categorization, block rules, reputation.
  • OS security: Group Policy, SELinux. Secure protocols, DNS filtering, email security (DMARC, DKIM, SPF, gateway).
  • File integrity monitoring, DLP, NAC, EDR/XDR, user behavior analytics.

study notes

Objective 4.5 is "modify enterprise capabilities to enhance security": which tool fits which problem, and how you tune it. Expect scenario questions that ask what to change.

Firewalls

  • Rules use source, destination, port, protocol, and action. Evaluated top to bottom, first match wins, with an implicit deny at the end. Place specific rules first; remove stale rules.
  • Access control list (ACL) is the rule set. Screened subnet (DMZ) hosts public services between two firewalls/interfaces.
  • Ports and protocols: allow only what's needed (443, 22, 53...); block risky ones (Telnet, SMBv1, RDP from the internet).
  • Types: stateless, stateful, next-generation (NGFW) with application awareness, user identity and TLS inspection, UTM, WAF, host-based.
  • Inbound vs outbound rules: egress filtering stops malware from calling out and data leaving.
  • Logging firewall decisions feeds the SIEM.

Web filtering

  • Agent-based: software on the endpoint enforces policy anywhere (good for roaming laptops).
  • Centralized proxy / secure web gateway (SWG): all web traffic passes through one place for filtering, malware scanning and logging.
  • URL scanning / categories: allow or block by site category (gambling, adult, malware).
  • Content categorization, block rules, reputation scores for domains, and DNS filtering that refuses to resolve known-bad domains.
  • TLS inspection lets the filter see inside HTTPS but requires certificates and has privacy implications.

Operating system security

  • Group Policy (Windows domain): centrally enforce settings such as password rules, disabled services, firewall settings and application restrictions across thousands of computers.
  • SELinux (and AppArmor): Linux mandatory access control that limits what a process can do even if compromised.
  • Patching, local firewall, least privilege, secure boot, disabling legacy protocols.

Email security

  • SPF (Sender Policy Framework): a DNS record listing the mail servers allowed to send for a domain.
  • DKIM (DomainKeys Identified Mail): the sending server signs messages; receivers verify with a DNS public key. Proves the message came from the domain and wasn't altered.
  • DMARC (Domain-based Message Authentication, Reporting and Conformance): tells receivers what to do when SPF/DKIM fail (none, quarantine, reject) and sends reports back. Builds on SPF and DKIM.
  • Gateways: spam filters, attachment sandboxing, link rewriting, anti-phishing, DLP, encryption (S/MIME, PGP, TLS).
  • Mailbox protections: MFA, disable legacy protocols, external sender banners, user reporting button.

Monitoring data

  • Log sources: operating systems, firewalls, IPS, applications, network devices, cloud, endpoints.
  • SIEM correlation and dashboards; NetFlow; packet captures; DLP alerts.
  • Tune rules and thresholds to cut false positives; add new detections as threats change.
  • Archive and protect log integrity (send off-host, restrict deletion).

Endpoint security

  • Antivirus/anti-malware: signature-based detection of known threats.
  • EDR (endpoint detection and response): continuous behavior monitoring, investigation and response on endpoints. XDR extends across endpoints, network, cloud and email.
  • Host-based firewall and HIPS.
  • Application allow list and device control (block USB storage).
  • DLP agents, full-disk encryption, patch management, mobile device management.
  • Configuration enforcement and compliance checks.
  • Network access control (NAC) and posture assessment before connecting.

More detail from the lessons

Firewalls

  • A network firewall sits inline and can also be a VPN endpoint (site-to-site or remote access) and a layer 3 router/NAT device at the ingress/egress point. NGFW (also application layer gateway, stateful multilayer inspection, deep packet inspection) classifies each application, which takes more analysis than ports.
  • Same service, two views. Traditional: web = TCP 80/443, SSH = TCP 22, RDP = TCP 3389, DNS = UDP 53, NTP = UDP 123. NGFW recognizes the application itself (while still allowing port matching). NGFW rule fields: name, source and destination zone, IPs, services (ports), user, application, web category and URL list.
  • Rule order: top to bottom, first match wins, specific rules high and broad ones low, and an implicit deny at the end. The rule base is an ACL.
  • Lesson rule table example: accept inbound TCP 22 (SSH), 80 (HTTP), 443 (HTTPS), 3389 (RDP), UDP 53 (DNS), UDP 123 (NTP), and deny ICMP (ping), followed by implicit deny.
  • Screened subnet: a third firewall interface for services that must be reachable from the internet; internet traffic goes to the screened subnet and back out, and cannot reach the internal network with confidential data.
  • IPS rules: usually inside the NGFW, with signatures (the lesson shows one for the Conficker worm), and can also detect anomalies such as generic database injection with no specific signature. Thousands of signatures can be grouped (block every database-injection rule). Customize to balance security against false positives. Sample rules: malware names with ports, and an FTP login worm.

Web filtering

  • A content filter (URL filter, website category filter) controls the data in and out and is like parental controls at home. Some block known-bad sites (malware, viruses). URL lists have allow lists and block lists; URLs are grouped into categories (auction, hacking, malware, travel, recreation and 50+ more such as adult, educational, gambling, government, home and garden). Example policy: educational allowed; home and garden allowed but logged or alerted; gambling blocked.
  • Standalone URL filters are now commonly built into NGFWs, but that assumes users are behind the firewall. Agent-based filters on the device work anywhere and are centrally managed, but the agents and category lists need regular updates.
  • Proxy: requests on the user's behalf, then inspects the response; can cache, perform access control (by username/password or IP), URL filter and malware check. Explicit proxy needs client config; transparent proxy does not. A forward (internal) proxy serves internal users, with the organization controlling its configuration.
  • Reputation filtering: levels such as trustworthy, low risk, medium risk, suspicious, high risk; usually automated by scanning sites, with manual override allowed. Block high-risk, allow trustworthy.
  • DNS filtering: the DNS server will not return the IP of known-bad domains (updated by real-time threat intelligence, commercial or public lists). Users get a default IP or none. It also breaks malware calling its command and control server by name.

Operating system security

  • Active Directory: central, redundant database of computers, devices, users, file shares, printers and security groups. Single source of authentication and permissions, assignable to users or groups. Group policy (Group Policy Management Editor) overlays settings: login scripts, QoS-type network configuration, security parameters for users and devices.
  • Linux default is discretionary access control (DAC) where users set permissions; high-security environments use mandatory access control (MAC) with a central administrator. SELinux (open source, installable on many distributions) supports least privilege so a breach or malicious code has limited scope.

Secure protocols

  • Telnet, FTP, SMTP and IMAP are cleartext. Use packet capture to see: headers visible, payload should be encrypted. DEFCON's wall of sheep shows people sending IMAP, HTTP and POP3 insecurely. Replace Telnet with SSH, HTTP with HTTPS, IMAP with IMAPS, FTP with SFTP. If you cannot use a secure protocol, better not to use the app.
  • Port 80 usually means HTTP and 443 HTTPS, but a port number does not guarantee encryption; check server settings and confirm with a packet capture. Network-level options: WPA3 on wireless, or a VPN (encrypted tunnel to a concentrator, though it needs client software and your own concentrator or a third-party service).

Email security

  • Email protocols have little built-in checking, so spoofing is common. The mail gateway (on-premises in a screened subnet, or cloud-based) decides inbox, spam or discard.
  • SPF: a TXT record in DNS listing servers authorized to send for the domain (example: mailgun.org). DKIM: the sending mail server signs messages in transit; the signature is in the headers and receivers verify with the public key in a DNS TXT record. Note: this is not a signature the user adds to a message.
  • DMARC: a TXT record (DMARC1) saying what to do when SPF/DKIM fail: accept (none), spam folder/quarantine, or reject, and where to send compliance reports. The reports show how many messages validated and how many were spoofed.

Monitoring data

  • File integrity monitoring (FIM) watches files that should not change. Windows SFC (System File Checker) checks critical OS files on demand and replaces bad ones. Linux Tripwire gives real-time monitoring. A host-based IPS can do FIM too.
  • DLP deployment types: endpoint DLP watches data in use; network DLP (inside an NGFW or standalone appliance) watches data in motion; server-resident DLP covers data at rest; cloud DLP blocks sensitive uploads and malware to cloud apps.
  • USB blocking: November 2008, the US Department of Defense had the agent.btz worm spread via a USB drive, so USB storage was banned/blocked by local DLP agents until restrictions lifted in February 2010.
  • Email DLP: inbound (suspicious keywords, spoofed or imposter mail, quarantine) and outbound (fake wire transfer emails, W-2 data with Social Security numbers). Boeing, November 2016: an employee emailed a seemingly blank spreadsheet to a spouse with hidden fields holding data for 36,000 employees; email DLP would have stopped it.

Endpoint security

  • Endpoints (desktops, laptops, phones, tablets) need defense in depth. The edge firewall rules are fairly static. Access control rules can use user or group, location, data location and application, and can change with posture.
  • Posture assessment at connect or login: is the device trusted (a company certificate), is antivirus installed, running and updated, are required apps present and current, is there full disk encryption. Agent types: persistent agent (always installed, can run any time, needs updates), dissolvable agent (runs at login then removes itself), and agentless NAC (integrated with Active Directory, only runs at login and logoff). Failing devices can be quarantined on their own VLAN with remediation instructions, then reassessed.
  • More than a million malware variants a day makes signatures alone inadequate. EDR adds behavior analysis, machine learning, process monitoring and root-cause analysis and can automatically isolate, quarantine and roll back. XDR adds data from many systems and the network, correlates it, reduces false positives and speeds investigation. Data sources include user behavior analytics which builds baselines of normal users, devices, traffic and repositories, then flags abnormal events using rules, pattern matching or statistics.

Exam traps

  • SPF = who may send; DKIM = signature that proves authenticity/integrity; DMARC = policy plus reporting.
  • Implicit deny is the last rule in a firewall.
  • EDR watches behavior and can respond; plain antivirus relies on signatures.
  • SFTP runs over SSH (port 22); FTPS runs FTP over TLS (990/989).
  • SELinux is mandatory access control on Linux; Group Policy manages Windows settings.
