SY0-701domain 4.0 · Security Operations4.5

4.5 Given a scenario, modify enterprise capabilities to enhance security

key ideas

  • Firewall: rules, access lists, ports/protocols, screened subnets. IDS/IPS: trends, signatures.
  • Web filter: agent-based, centralized proxy, URL scanning, content categorization, block rules, reputation.
  • OS security: Group Policy, SELinux. Secure protocols, DNS filtering, email security (DMARC, DKIM, SPF, gateway).
  • File integrity monitoring, DLP, NAC, EDR/XDR, user behavior analytics.

study notes

Objective 4.5 is "modify enterprise capabilities to enhance security": which tool fits which problem, and how you tune it. Expect scenario questions that ask what to change.

Firewalls

  • Rules use source, destination, port, protocol, and action. Evaluated top to bottom, first match wins, with an implicit deny at the end. Place specific rules first; remove stale rules.
  • Access control list (ACL) is the rule set. Screened subnet (DMZ) hosts public services between two firewalls/interfaces.
  • Ports and protocols: allow only what's needed (443, 22, 53...); block risky ones (Telnet, SMBv1, RDP from the internet).
  • Types: stateless, stateful, next-generation (NGFW) with application awareness, user identity and TLS inspection, UTM, WAF, host-based.
  • Inbound vs outbound rules: egress filtering stops malware from calling out and data leaving.
  • Logging firewall decisions feeds the SIEM.

Web filtering

  • Agent-based: software on the endpoint enforces policy anywhere (good for roaming laptops).
  • Centralized proxy / secure web gateway (SWG): all web traffic passes through one place for filtering, malware scanning and logging.
  • URL scanning / categories: allow or block by site category (gambling, adult, malware).
  • Content categorization, block rules, reputation scores for domains, and DNS filtering that refuses to resolve known-bad domains.
  • TLS inspection lets the filter see inside HTTPS but requires certificates and has privacy implications.

Operating system security

  • Group Policy (Windows domain): centrally enforce settings such as password rules, disabled services, firewall settings and application restrictions across thousands of computers.
  • SELinux (and AppArmor): Linux mandatory access control that limits what a process can do even if compromised.
  • Patching, local firewall, least privilege, secure boot, disabling legacy protocols.

Secure protocols

Use encrypted versions and retire cleartext ones:

Choose the protocol when the question mentions confidentiality, plus port knowledge when asked which port to open or close. Also use DNSSEC, NTP with authentication, and TLS 1.2+.

Email security

  • SPF (Sender Policy Framework): a DNS record listing the mail servers allowed to send for a domain.
  • DKIM (DomainKeys Identified Mail): the sending server signs messages; receivers verify with a DNS public key. Proves the message came from the domain and wasn't altered.
  • DMARC (Domain-based Message Authentication, Reporting and Conformance): tells receivers what to do when SPF/DKIM fail (none, quarantine, reject) and sends reports back. Builds on SPF and DKIM.
  • Gateways: spam filters, attachment sandboxing, link rewriting, anti-phishing, DLP, encryption (S/MIME, PGP, TLS).
  • Mailbox protections: MFA, disable legacy protocols, external sender banners, user reporting button.

Monitoring data

  • Log sources: operating systems, firewalls, IPS, applications, network devices, cloud, endpoints.
  • SIEM correlation and dashboards; NetFlow; packet captures; DLP alerts.
  • Tune rules and thresholds to cut false positives; add new detections as threats change.
  • Archive and protect log integrity (send off-host, restrict deletion).

Endpoint security

  • Antivirus/anti-malware: signature-based detection of known threats.
  • EDR (endpoint detection and response): continuous behavior monitoring, investigation and response on endpoints. XDR extends across endpoints, network, cloud and email.
  • Host-based firewall and HIPS.
  • Application allow list and device control (block USB storage).
  • DLP agents, full-disk encryption, patch management, mobile device management.
  • Configuration enforcement and compliance checks.
  • Network access control (NAC) and posture assessment before connecting.

Exam traps

  • SPF = who may send; DKIM = signature that proves authenticity/integrity; DMARC = policy plus reporting.
  • Implicit deny is the last rule in a firewall.
  • EDR watches behavior and can respond; plain antivirus relies on signatures.
  • SFTP runs over SSH (port 22); FTPS runs FTP over TLS (990/989).
  • SELinux is mandatory access control on Linux; Group Policy manages Windows settings.
