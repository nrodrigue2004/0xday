1.4 Explain the importance of using appropriate cryptographic solutions

key ideas

  • Symmetric (AES, one shared key, fast) vs asymmetric (RSA/ECC, public+private keys, used for key exchange and signatures).
  • Hashing (SHA-256) is one-way, for integrity. Salting stops rainbow tables; key stretching (bcrypt, PBKDF2) slows brute force.
  • PKI: CA signs certificates; CRL and OCSP check revocation; a CSR requests a cert. Wildcard certs cover *.domain.
  • Encryption levels: full-disk, partition, volume, file, database, record. Transport: TLS, VPN (IPsec).
  • Hardware: TPM (on the motherboard), HSM (dedicated appliance), secure enclave, key management system.
  • Obfuscation: steganography, tokenization, data masking. Blockchain is a distributed, append-only ledger.

study notes

Cryptography protects confidentiality (encryption), integrity (hashing) and authenticity/non-repudiation (signatures and certificates). This objective is heavy on vocabulary and on choosing the right tool for a scenario.

Public key infrastructure (PKI)

PKI is the people, policies and software that create, distribute, store and revoke digital certificates.

  • Public key / private key: a mathematically linked pair (asymmetric). The public key is shared; the private key never leaves its owner.
  • Key escrow: a trusted third party holds a copy of a key so it can be recovered (for example, a lost key or a legal request). Raises trust and security concerns, so access must be tightly controlled.
  • Certificate authority (CA): issues and signs certificates. Trust chains up to a root CA.
  • Registration authority (RA): verifies identity requests before the CA issues a certificate.
  • Certificate signing request (CSR): what you send a CA with your public key and details.
  • CRL (certificate revocation list) and OCSP (online certificate status protocol): ways to check whether a certificate has been revoked.
  • Key management: generation, storage, rotation, backup, revocation and destruction of keys.

Encrypting data at different levels

  • Full-disk and partition encryption (BitLocker, FileVault, LUKS): protects a stolen or lost device.
  • File encryption (EFS, GPG): protects individual files.
  • Volume encryption: protects a logical volume.
  • Database encryption: whole database, or record/column level for specific fields such as card numbers.
  • Transport/encryption in transit: TLS, VPNs (IPsec) protect data between systems. Data at rest, in transit and in use are the three states you must protect.
  • Transparent data encryption (TDE): encrypts database files with no application change.

Symmetric vs asymmetric

KeysOne shared secretPublic + private pair
SpeedFast, good for bulk dataSlow
WeaknessSafely sharing the keyComputationally expensive

Typical useEncrypting files, disks, VPN tunnelsKey exchange, digital signatures, certificates
  • Hybrid: asymmetric crypto exchanges a symmetric session key, then fast symmetric encryption protects the data. This is what TLS does.
  • Key length: longer keys are stronger. Longer symmetric keys (AES-256) resist brute force; asymmetric keys are much longer for comparable strength (RSA 2048+). ECC reaches the same strength with much shorter keys, good for mobile and IoT.

Key exchange

  • Out-of-band exchange: send the key by another channel (in person, phone call).
  • In-band exchange: send it over the network, but it must be protected, usually by asymmetric encryption.
  • Diffie-Hellman lets two parties build a shared secret over an untrusted network without sending the secret itself. Ephemeral variants (DHE, ECDHE) create a new key per session, which gives perfect forward secrecy: stealing a server's private key later cannot decrypt past recorded sessions.

Encryption technologies

  • Trusted Platform Module (TPM): a chip on the motherboard that generates and stores keys, holds disk-encryption keys and checks boot integrity (measured boot).
  • Hardware security module (HSM): a hardened device (card, appliance or cloud service) built to generate, store and use keys, often for CAs and payment systems. Faster and more tamper-resistant than a TPM; usually a shared enterprise resource.
  • Key management system (KMS): central service to create, rotate, store and audit keys, including cloud services.
  • Secure enclave: a protected processor area where sensitive operations run isolated from the rest of the OS (phones, modern CPUs).

Obfuscation

Hiding meaning without being true encryption:

  • Steganography: hide data inside another file (image, audio, video, packet padding). Cover medium plus hidden payload. Detectable with statistical analysis.
  • Tokenization: replace sensitive data (card number) with a meaningless token. The real value lives in a protected vault. Common for payments, and it reduces PCI scope.
  • Data masking: hide part of the value (****-****-****-1234) for display or test data.

Hashing and digital signatures

  • A hash turns any input into a fixed-length digest. One-way, same input always gives the same output, any change gives a totally different output, and collisions should be practically impossible.
  • Common hashes: SHA-256 and SHA-3 (strong), SHA-1 and MD5 (broken for security, still seen for quick checks).
  • Uses: file integrity checks, password storage (with a salt and a slow hash such as bcrypt/PBKDF2/Argon2), digital signatures.
  • Salting: random value added before hashing so identical passwords produce different hashes and rainbow tables fail.
  • Key stretching: repeat hashing many times to slow guessing.
  • Digital signature: hash of the message encrypted with the sender's private key. Gives integrity, authentication and non-repudiation (see 1.2).
  • Collision: two different inputs with the same hash. A collision attack breaks the algorithm's integrity guarantee, which is why MD5 and SHA-1 are retired.

Blockchain

A public ledger shared across many computers. New data goes into a block, each block contains a hash of the previous one, and the chain is verified by many participants. Altering an old block changes every later hash, so tampering is obvious. Used for cryptocurrency, supply chains, contracts, identity and record keeping.

Certificates

A digital certificate binds a public key to an identity and is signed by a CA. The X.509 standard defines the format.

  • Root of trust and certificate chain: root CA signs intermediate CAs which sign end-entity certificates. A browser trusts a site because the chain ends at a root it already trusts.
  • Self-signed certificate: signed by its own key, not a CA. Fine for internal labs, untrusted by browsers.
  • Third-party (public) CA: trusted by default in devices.
  • Wildcard certificate (*.example.com): covers all subdomains one level down. Convenient but a stolen private key exposes every subdomain.
  • Subject alternative name (SAN): lists multiple host names on one certificate.
  • Types by validation: domain validated (DV), organization validated (OV), extended validation (EV).
  • Certificate formats: PEM (Base64 text), DER (binary), PFX/P12 (certificate + private key in one password-protected file), CER/CRT.
  • Certificate lifecycle: request (CSR), issue, install, renew before expiry, revoke if compromised.
  • Revocation checking: CRL (downloaded list) or OCSP (live query). OCSP stapling has the server include a signed, recent OCSP response so clients don't contact the CA.
  • Certificate pinning ties a service to a known certificate or key so a rogue CA cannot impersonate it.

More detail from the lessons

PKI and the two key types

  • PKI is a broad term: policies, procedures, hardware and software that create, distribute, manage, store and revoke digital certificates. It is also used to tie a certificate to a person or device through a CA, so you can trust that they are who they claim.
  • Symmetric is also called a secret key algorithm or shared secret. Its weakness is scale: past about ten people or devices, sharing and tracking which key belongs to whom gets painful. It stays popular because it is fast with low overhead, so real systems use both types together.
  • Asymmetric keys are created at the same time and are mathematically related, yet you cannot work out the private key from the public key. Generation uses randomness and very large prime numbers. Individuals do it once (for example with PGP or GPG), publish the public key (website, social media), and store the private key locally, often protected by a password.
  • Flow: Bob writes plaintext, encrypts it with Alice's public key to get ciphertext, anyone can see the ciphertext, and only Alice's private key turns it back into the same plaintext. Even holding the ciphertext and the public key does not help an attacker.
  • Key escrow in practice: with hundreds of users, a third party (or you) stores private keys so data can still be decrypted when an employee leaves or moves, or when two organizations (for example a government agency and a partner) both need access. Handing over a private key is controversial but sometimes needed for availability.

Encrypting at each level

  • At rest: full disk or volume encryption (BitLocker on Windows, FileVault on macOS). File level: EFS, built into NTFS (File or folder Properties, Advanced, "Encrypt contents to secure data"). Third-party tools exist for macOS, Linux and Windows.
  • Database: transparent encryption uses a symmetric key over everything, but then every search needs decryption overhead. Column level encryption encrypts only the sensitive columns (for example the SSN column) so IDs and names stay searchable quickly. You only decrypt the column or record you need.
  • In transit: HTTPS in the browser; a VPN creates an encrypted tunnel. Client VPNs commonly use SSL/TLS, and site-to-site VPNs commonly use IPsec.
  • Both sides must use the same algorithm. DES (64-bit blocks) cannot be decrypted with AES. You do not need the block diagrams for the exam.
  • Algorithms are public, keys are secret (like a door lock: everyone knows how locks work, but you still need the key). Public algorithms are more trustworthy because the math can be examined. Keys feed encryption, hashing and signatures, so protecting the private key is everything.
  • Brute force is answered with length: symmetric keys of 128 bits or larger are common, and asymmetric keys of 3072 bits or larger are now common. Keys grow over time as processors improve.
  • Key stretching (key strengthening): hash the password, then hash the hash, and so on. This multiplies the work an attacker must do per guess.

Key exchange

  • Out of band (courier, phone call, in person; the handcuffed suitcase) is too slow for the web. In band sends information over the network, usually by encrypting a symmetric key with asymmetric crypto.
  • Session keys are ephemeral: the client makes a random symmetric key, encrypts it with the server's public key, and the server decrypts it with its private key. Use it for the session, throw it away, repeat next time.
  • Key exchange algorithms: Bob combines his private key with Alice's public key, and Alice combines her private key with Bob's public key. The math gives both sides the same symmetric key without it ever crossing the network. Nothing is encrypted or hashed in this step.

Hardware and key management

  • TPM: a standardized chip on the motherboard that generates random numbers and keys, has persistent memory for keys unique to that machine, and stores disk encryption keys (for example BitLocker's). It is password protected and resists brute force and dictionary attacks. It serves one device.
  • HSM: serves hundreds or thousands of devices, such as a thousand web servers' keys. Large installs are clustered with redundant power and network. Often has dedicated plug-in cards or cryptographic accelerators for fast real-time encryption. Built to store keys safely and block unauthorized access.
  • Key management system: one console (on-premises or cloud) for all keys such as TLS/SSL, SSH, Active Directory and BitLocker keys. It keeps keys separate from the data they protect, associates keys with users, supports automatic key rotation, and gives logging and reporting (key names, fingerprints, expiry dates, active vs inactive, usage).
  • Secure enclave: a separate security processor (phones, laptops, desktops), not the main CPU. It has its own boot ROM, monitors the boot process, has a true random number generator, does real-time memory encryption, holds built-in unchangeable keys as a root for other crypto, and does AES in hardware. It keeps data private even if the device falls into someone else's hands.

Obfuscation

  • Obfuscation makes something hard to understand, and if you know the method you can reverse it. It is hiding in plain sight, so it counts as security through obscurity, which is not real security.
  • Steganography ("concealed writing" in Greek): the file holding the hidden data is the covertext. It works in images, audio, video, and even network traffic (messages in TCP packets sent a few bits or bytes at a time). Printers add near-invisible yellow dots called machine identification codes that can trace a page to the printer.
  • Tokenization replaces sensitive data with a token while a server keeps the mapping. Mobile payments: registering the card gets a batch of tokens from a token service server onto your phone. At checkout, NFC sends a one-time token, the merchant sends it to the token service for a reverse lookup, the card is validated, then the token is thrown away and the next one is used. The token has no mathematical relationship to the card number, so it needs no encryption or hashing to be sent.
  • Data masking hides part of a value (receipt showing only the last four digits, a support agent seeing "ending in 2512"). You can also mask by rearranging or replacing digits reversibly.

Hashing, salts and signatures in detail

  • A hash is also a message digest or fingerprint. It is not encryption and cannot be reversed. Uses: confirm a download matches the site (Linux ISO hashes), password storage, digital signatures.
  • SHA-256 gives 256 bits shown as 64 hexadecimal characters. Changing a single character (period to exclamation mark) gives a completely different hash. A collision is two different inputs giving the same hash. MD5 had a collision problem found in 1996, so use something else.
  • Passwords: never store plaintext, and do not encrypt them (they could be decrypted). Store a salted hash. Login hashes what you type and compares. A rainbow table is a precomputed set of inputs and their hashes; it cracks unsalted hashes in seconds, while brute forcing a salted one can take days or weeks. Each user gets a different random salt, so even if five users share the password "dragon", the database shows five different hashes.
  • Digital signature gives integrity, authentication and non-repudiation. The process is almost the opposite of encrypting data. Alice's mail client hashes "You're hired, Bob" and encrypts the hash with her private key. The message itself still travels in plaintext, and the signature rides along. Bob's client decrypts the signature with Alice's public key to get a hash, hashes the received message itself, and if both hashes match, the message is unchanged and came from Alice. If verification fails, something changed and you cannot trust it.

Blockchain

  • A distributed, public ledger where participants each keep a copy. A transaction (a Bitcoin transfer, a backup record, a house title) is sent to everyone, collected into a block, and the block gets a hash for integrity before copies go out. If someone edits an old transaction, the hash no longer fits, other ledger holders reject the block, and the tampering is exposed. Uses: payments, digital identity, supply chain tracking, digital voting.

Certificates in detail

  • A certificate is a file with a public key and a digital signature, like a digital ID card. Trust comes from a CA signing it. A web of trust is the decentralized alternative: people sign each other's certificates. Inside an organization you can use built-in tools such as Windows Certificate Services or software like OpenCA.
  • X.509 is the standard format, which is why your browser can show certificate details for any site. Fields include serial number, version, signature algorithm, issuer, subject (holder), public key and more.
  • Root of trust: an inherently trusted component, in hardware (HSM, secure enclave), software, firmware or a CA. Browsers ship with hundreds of trusted CAs. When you buy a certificate you are really buying the CA's validation process (proving you own the site), not the signature itself. If a CA skips validation, none of its certificates can be trusted.
  • CSR process: create the key pair, put the public key plus server and organization details into a CSR, send it to the CA, the CA validates ownership and signs with its private key, and returns the certificate.
  • Internal CA: for internal apps, install your own CA software and push the CA's public certificate to every computer's trusted store. Works exactly like a public CA for your devices. Common in medium and large organizations.
  • Subject Alternative Name (SAN) lists many DNS names. A wildcard entry such as *.example.com covers www, ftp, mail and so on, making one certificate easy to deploy across many hosts.
  • Revocation when decommissioning a server or after a compromise. The big example is Heartbleed (April 2014), a vulnerability in the OpenSSL library that could leak a web server's private key, which forced everyone to patch OpenSSL, revoke old certificates and issue new ones.
  • CRL: list kept at the CA. The certificate's CRL Distribution Points field holds URIs; the browser downloads the list and checks whether the cert is on it. Inefficient because it is one big file.
  • OCSP asks about one certificate instead of downloading a list. OCSP stapling has the web server attach the CA-signed status response to the TLS handshake, so the client does not have to contact the CA, and the CA's signature stops the server from lying. Very old browsers may lack OCSP, and some claim support but do not check properly, so test your browser.

Exam traps

  • Encryption provides confidentiality; hashing provides integrity; neither one alone proves who sent it.
  • Sign with private, verify with public. Encrypt with public, decrypt with private.
  • TPM is on a device; HSM is a dedicated key-protection device used by many systems.
  • Salts defeat rainbow tables; key stretching slows brute force.
  • Tokenization replaces data; masking hides it; encryption transforms it reversibly with a key.
