2.3 Explain various types of vulnerabilities

key ideas

  • Application: memory injection, buffer overflow, race conditions (TOCTOU), malicious updates.
  • Web: SQL injection, cross-site scripting (XSS). OS-based, hardware (firmware, end-of-life, legacy).
  • Virtualization: VM escape, resource reuse. Cloud-specific, supply chain (service/hardware/software providers).
  • Cryptographic weaknesses, misconfiguration, mobile (sideloading, jailbreaking), zero-day.

study notes

A vulnerability is a weakness an attacker can exploit. Objective 2.3 lists the families you must recognize in a scenario. For each one, learn what it is, how it shows up, and the mitigation.

Application vulnerabilities

Memory injection: malicious code is placed into a running process's memory (often by a malicious DLL or code injection into a trusted process), so it runs with that process's privileges and hides inside a legitimate name. Mitigation: endpoint protection, memory protections, application control, patching.

Buffer overflow: the program writes more data into a fixed-size buffer than it can hold, spilling into adjacent memory. The attacker can crash the program or overwrite a return address to run their own code. Mitigations: input validation and bounds checking, safe languages, ASLR (random memory layout), DEP/NX (data pages can't execute), stack canaries, patching. Seen as a crash or unexpected behavior after oversized input.

Race condition: the outcome depends on timing between operations. The classic is time-of-check to time-of-use (TOCTOU): the program checks a condition, then acts on it, and an attacker changes the state in between. Related: time-of-use errors and file/temp-file races. Mitigation: atomic operations, locks, minimize the gap, secure coding.

Malicious update: an attacker poisons a software update channel or fake update prompt to deliver malware (this is also a supply chain risk). Mitigation: update only from the vendor, verify digital signatures and hashes, use trusted repositories, test updates, application control.

SQL injection (SQLi): user input is placed into a SQL statement, letting the attacker change the query (for example ' OR 1=1 --). Impact: read, change or delete data, bypass login. Mitigations: parameterized queries / prepared statements, input validation, stored procedures, least-privilege database accounts, web application firewall. Don't rely on blocklists of bad characters.

Cross-site scripting (XSS): the attacker gets script to run in another user's browser in the context of a trusted site.

Impact: steal session cookies, redirect users, act as the user. Mitigations: output encoding, input validation, Content Security Policy, HttpOnly cookies, frameworks that escape by default. Contrast with CSRF, which makes a logged-in browser send an unintended request (see 2.4).

Operating system vulnerabilities

Unpatched flaws, privilege escalation bugs, insecure default settings, unneeded services, outdated or end-of-life OS versions. Mitigation: patch management, hardening baselines, remove unused components, endpoint protection, vulnerability scanning.

Hardware vulnerabilities

  • Firmware flaws (BIOS/UEFI, network device firmware, printers): hard to patch and invisible to most tools.
  • End-of-life hardware that no longer receives updates.
  • Legacy devices that can't support modern security.
  • Speculative execution CPU flaws (Meltdown, Spectre) that let one process read another's data.
  • Mitigations: firmware updates, retire unsupported hardware, secure boot, supply chain verification, isolation.

Virtualization vulnerabilities

  • VM escape: code running in a guest breaks out to the hypervisor or other VMs. Rare but severe, because the hypervisor controls everything.
  • VM sprawl: unmanaged, forgotten virtual machines that never get patched or monitored.
  • Resource reuse: memory or storage from one VM leaking into another.
  • Mitigations: patch the hypervisor, limit who can manage it, inventory and decommission VMs, segment management networks, separate sensitive VMs.

Cloud-specific vulnerabilities

Misconfigured storage buckets, overly broad IAM roles, exposed management consoles and APIs, weak keys, lack of logging, and misunderstanding the shared responsibility model (the provider secures the cloud itself; the customer secures their data, access and configuration). Mitigations: CSPM tools, least privilege IAM, encryption, MFA, logging, regular configuration review.

Supply chain vulnerabilities

Compromise through a service provider, hardware provider or software provider: a tainted firmware, a backdoored library, a compromised MSP. Mitigations: vendor due diligence, software bills of materials, signed code, limit vendor access, monitor third-party connections, validate hardware sources.

Misconfiguration vulnerabilities

  • Open permissions (world-readable files and shares), unsecured admin accounts, default accounts and passwords, open ports and unneeded services, insecure protocols (Telnet, FTP, HTTP), weak encryption settings, verbose error messages that leak details.
  • Mitigations: secure baselines and hardening guides, configuration management, change control, automated audits, vulnerability scans.

Mobile device vulnerabilities

  • Jailbreaking / rooting removes OS protections and lets unsigned code run.
  • Sideloading installs apps outside the official store, skipping its review.
  • Outdated OS, malicious apps, unencrypted data, insecure Wi-Fi, lost devices.
  • Mitigations: MDM, app allow lists, enforce updates and encryption, block jailbroken devices.

Zero-day vulnerabilities

A flaw unknown to the vendor (and so unpatched) that attackers are already exploiting or could. The vendor has had "zero days" to fix it. Mitigations: defense in depth, segmentation, EDR/behavior detection, rapid response, virtual patching (WAF/IPS rules), threat intelligence. Once a patch exists it is no longer a zero-day, only a known unpatched vulnerability.

More detail from the lessons

Memory and buffer attacks

  • Nothing runs unless it is loaded from disk into memory. Malware can run as its own process or inject itself into an existing process between that process's start and end addresses. Benefits: it dodges tools looking for a malicious process and inherits that process's rights, which is a quick privilege escalation.
  • DLL injection: get a malicious DLL onto storage, then put its path into the target process. When the process reaches that reference it loads the DLL into memory and the malware runs.
  • Buffer overflow: writing more than the area expects (the developer should do bounds checking, for example only 8 bytes). Overflow is hard to exploit reliably because it can just crash the app, so attackers look for one that is repeatable and always gives an advantage.
  • Lesson example: variable A holds 8 bytes, variable B (2 bytes, value 1979) controls permissions, under 2000 means user and over 24,000 means admin. Typing the 9-character word "excessive" into A spills the ninth character e (hex 65) into B and changes it to 25,856, so the attacker is admin without credentials.

Race conditions

  • Two events happen at nearly the same time and the application did not plan for it. TOCTOU (time of check to time of use): the app reads a value, something else changes it before the app uses it.
  • Bank example: two users each transfer $50 from account A to B, both starting at $100 each. Deposits update instantly but withdrawals are not shown immediately, so after both withdraw, user 2 still sees A with $50 when it really should be $0 and B ends up with $200.
  • Real cases: the Mars rover Spirit (2004) looped on reboots because of a file system error each boot, fixed by sending code to bypass it. Pwn2Own Vancouver 2023: a TOCTOU in the Tesla Model 3 infotainment system via Bluetooth gave root on that system and a $100,000 prize plus the car.

Updates and OS

  • Updates are effectively new installs, so they can carry malware. Best practices: backup first, use trusted sources, ideally download from the developer, and prefer digitally signed updates. A random "update Chrome" pop-up after clicking a search result is suspect, while one at browser launch is more trustworthy. Built-in app updaters verify signatures automatically.
  • That trust is not total: SolarWinds Orion (reported December 2020). Attackers got into the development system months before and their code was rolled into a normal, digitally signed update that auto-distributed to customers. Hundreds of large government agencies and companies were hit and attackers pivoted to other systems. Rare, but shows a trusted process distributing malware.
  • OS updates: operating systems are huge (Windows 11 has tens of millions of lines of code), so unknown vulnerabilities exist. Microsoft releases patches on Patch Tuesday, the second Tuesday of each month. May 2023 had almost 50 patches (8 elevation of privilege, 4 security feature bypass, 12 remote code execution and others); April 2023 had almost 100. The Microsoft Security Response Center (MSRC) lists them. Once a flaw is public, attackers reverse engineer the patch, so patch fast. In large environments, test first, expect some patches to need a reboot, and keep a backup for rollback.

SQL injection

  • Code injection types include HTML, SQL and XML. SQL is the usual way apps talk to databases. Normal query: SELECT * FROM users WHERE name = 'Professor'. Injected: ... name = 'Professor' OR 1=1, which is always true and returns everything. If you ever see 1=1 in a request, think SQL injection.
  • It needs no extra software and no victim clicks, just typing into an existing input field. Impact: view, change or delete everything, or take the database down.
  • Demo: WebGoat (webgoat.org), an intentionally vulnerable app. Input of employee name Smith and a transaction authentication number; injecting ' or '1'='1 into the number field returned every record.

Cross-site scripting

  • Abbreviated XSS because CSS already means cascading style sheets. Named for early browser flaws where info from one site leaked to another. It abuses the browser's trust of websites, usually with JavaScript.
  • Reflected (non-persistent): attacker sends a link containing a script (email, text). The victim clicks, lands on a legitimate trusted site that echoes the script from the input (for example a search box), and the script quietly sends cookies and session IDs to the attacker, giving the same access as the victim. Demo: script pasted into a credit card number field showing an alert with the session ID cookie; a real attacker would silently send it.
  • Stored (persistent): the payload is saved on a site such as a social network post. Everyone viewing it runs the script, and it can even include code to re-share itself so it spreads.
  • Subaru (June 2017, researcher Aaron Guzman): the login token never expired and let you do any service request, and you could add your email to someone else's account to manage their car too. Combined with XSS, a stolen token would work forever. Reported by the researcher and fixed.
  • Defenses: do not click untrusted links (type trusted domains yourself), limit or disable JavaScript (limited protection, breaks sites), keep the browser patched, and developers must validate all inputs.

Hardware, firmware and EOL

  • Embedded devices (thermostats, HVAC controllers, time clocks, stoves, fridges, garage doors, door locks, IoT) run a hidden OS called firmware that only the manufacturer can update. Makers often do not prioritize security: Trane ComfortLink II thermostats were reported vulnerable in April 2014, first patch April 2015, another January 2016, while desktop OS vendors patch within about a month.
  • EOL (end of life): manufacturer announces it will stop selling the product, but support and patches may continue for a while. EOSL (end of service life): no more security patches (maybe paid premium support). EOSL is the date that matters most; replace gear once it hits it.
  • Legacy platforms (old OS, old application, old middleware) that are critical to the mission cannot be turned off easily. Compare the risk of keeping versus replacing, add mitigations such as extra firewall rules to limit who can reach it and extra IPS signatures for older OSes, and build a plan to replace it.

Virtualization

  • Cloud VMs get created and torn down constantly with varying CPUs, memory and storage, which makes posture management harder. Apply the same OS best practices to VMs. Virtual-specific issues include local privilege escalation, command injection and information disclosure.
  • VM escape: normally a VM cannot reach another VM on the same hypervisor, but flaws let an attacker hop between them, and a hypervisor may host tens or hundreds. March 2017 Pwn2Own: a bug in the Microsoft Edge JavaScript engine reached the Edge sandbox, then a Windows 10 kernel bug gave full guest control, then a VMware hardware-simulation bug let them hop to another VM. It was first demonstrated at the contest, so VMware had time to patch.
  • Resource reuse: the hypervisor can overcommit (three VMs with 2 GB each on a 4 GB host). With a hypervisor memory-management bug, one VM can write to a memory area another VM reads. Fix: update the hypervisor.

Cloud

  • Stats from the lesson: roughly 76% of organizations did not use MFA on the central cloud console, and up to 63% of code in the cloud was unpatched, some with CVSS 7 or higher. Public cloud means anyone can try to connect, so expect DoS/DDoS, authentication bypass from weak or misconfigured auth, directory traversal (moving around the web server folder structure) and remote code execution on unpatched systems. Examples: Log4j and Spring Cloud Function, easy to exploit and giving full control. Also XSS from missing input validation, out-of-bounds write (writing to memory you are not authorized to, causing RCE or a crash) and SQL injection against cloud-hosted databases.

Supply chain

  • The chain runs from raw materials through suppliers, manufacturers and distributors to customers; compromise at any point matters. Service providers (network, utilities, cleaning, payroll, accounting, cloud) can expose sensitive data, so contracts often include the right to audit and ongoing security audits.
  • Target, November 2013: over 40 million cards stolen. An HVAC firm in Pennsylvania got malware through an email, it was a Target supplier with access to Target's HVAC systems, and the HVAC and cash register networks were not segmented, so attackers reached every register. They stayed in for months. Lesson: non-IT providers count, and segmentation matters.
  • Hardware: treat new gear as untrusted out of the box. Use a short list of trusted vendors and procurement and implementation policies. July 2022: the DHS arrested the head of a reseller of counterfeit Cisco products (over a billion dollars, about 30 companies, selling since 2013, mostly made in China). Devices failed and some caught fire. Verify hardware before production.
  • Software: check digital signatures, think about auto-updates, and note that open source can also be changed maliciously. SolarWinds Orion: about 18,000 customers including Fortune 500 and US federal agencies; malicious code signed and shipped in March and June 2020, detected only in December 2020, reaching Microsoft, Cisco, Intel, the Pentagon, Homeland Security and Treasury.

Misconfigurations

  • Open data: attackers scan for unsecured cloud storage. June 2017: 14 million Verizon records sat in an open Amazon S3 bucket left by a third party; found by a researcher, not an attacker.
  • Unsecured admin accounts: Linux root, Windows Administrator (the superuser accounts). Weak passwords such as 123456, ninja and football are brute-forced. Best practice: disable direct root/administrator login, log in as a normal user and elevate with su/sudo or Windows Run as administrator, and keep admin accounts very few.
  • Insecure protocols: Telnet, FTP, SMTP and IMAP are cleartext. A Wireshark capture of HTTP shows browser version, referring URLs and cookies. Use SSH, SFTP, HTTPS and so on. The "wall of sheep" at DEFCON 22 displayed credentials captured from HTTP, IMAP and POP3.
  • Default credentials: the Mirai botnet tries 60+ default username/password pairs on IoT devices (cameras, routers, doorbells, garage openers). It is open source, so researchers and attackers both use it.
  • Open ports: each inbound service opens a port. Firewall rule sets are large and it is easy to accidentally expose something, so audit the rule base regularly.

Mobile

  • Small, always moving, always online, holding personal and corporate data. Rooting is Android and jailbreaking is iOS: replacing the OS with a third-party one, which defeats MDM controls. Sideloading is installing apps outside the approved store or company app library, easily done once rooted or jailbroken. Policies (AUP, employee handbook) forbid this and violations can lead to dismissal.

Zero-day

  • Researchers and attackers both hunt for flaws; attackers keep theirs secret, so the vendor has no idea and there is no patch. Exploiting an unpatched, unknown flaw is a zero-day attack. Track vulnerabilities at CVE (cve.mitre.org). Examples in the lesson: April 2023 Chrome zero-day (memory corruption and sandbox escape); May 2023 Microsoft patch for self-signed code running during the UEFI boot despite secure boot; May 2023 Apple iOS/iPadOS fixes for a sandbox escape, an information disclosure and arbitrary code execution, some already used in the wild.
