SY0-701domain 4.0 · Security Operations4.1

4.1 Given a scenario, apply common security techniques to computing resources

key ideas

  • Secure baselines: establish, deploy, maintain. Hardening targets: mobile, workstations, switches, routers, cloud, servers, ICS/SCADA, embedded, RTOS, IoT.
  • Wireless: site surveys and heat maps; WPA3, RADIUS, AAA. Cryptographic protocols and authentication protocols.
  • Application security: input validation, secure cookies, static code analysis, code signing. Sandboxing. Monitoring.
  • Mobile solutions: MDM; deployment models BYOD, COPE, CYOD; connection methods cellular, Wi-Fi, Bluetooth.

study notes

Objective 4.1 is about configuring things securely from the start and keeping them that way. It covers baselines, hardening for each kind of device, wireless and mobile security, and application security.

Secure baselines

A secure baseline is the documented, approved set of security settings for a type of system (a Windows workstation, a Linux web server, a switch). It follows three steps:

  1. Establish: define the baseline from vendor guidance, CIS benchmarks, STIGs or your own policy.
  2. Deploy: apply it consistently (group policy, configuration management, golden images, automation).
  3. Maintain: monitor for drift, update the baseline for new threats and patches, and re-apply it.

Baselines make systems consistent, make audits easier, and give you a known-good reference to detect unauthorized change.

Hardening targets

For every device class, the same ideas apply: remove what you don't need, change defaults, patch, restrict access, log. The exam tests what is *special* about each class.

TargetHardening focus
WorkstationsPatching, endpoint protection/EDR, host firewall, full-disk encryption, least privilege, remove bloatware, disable unneeded services
ServersMinimal installed roles, remove unneeded services/accounts, restrict admin access, patching, logging, secure remote admin
Switches and routersChange default credentials, disable unused ports, use SSH not Telnet, secure management access (dedicated VLAN), update firmware, port security, disable unused services
Cloud infrastructureLeast privilege IAM, MFA, private storage by default, encryption, security groups, logging, scan IaC templates
Mobile devicesMDM policy, screen lock, encryption, patching, app control, remote wipe
ICS/SCADAIsolate from IT networks, strict access control, monitor, compensating controls because patching is hard and availability/safety come first
Embedded systems and RTOSLimited patch options, so isolate, restrict network exposure, vendor lifecycle awareness
IoTChange default passwords, separate VLAN, disable unneeded features, firmware updates

Hardening also includes: encryption, minimal software, secure configuration, disable unused ports and protocols, restrict admin rights, enable logging.

Wireless device installation considerations

  • Site survey: measure signal and interference to plan access point placement.
  • Heat map: visual map of coverage strength and dead zones.
  • Channel selection to avoid overlap and interference, AP placement (not near external walls so the signal doesn't leak far outside), power levels.
  • Plan for capacity and for connecting wired backhaul.

Mobile solutions

Mobile device management (MDM) enforces policy on phones and tablets: require a PIN, encryption, remote wipe, app allow lists, geofencing, block jailbroken devices, push updates and certificates. Mobile application management (MAM) controls just the apps/data, which suits personal devices. Unified endpoint management (UEM) covers all endpoint types.

Deployment models:

ModelWho owns the deviceTrade-off
BYOD (bring your own device)EmployeeCheapest; hardest to control, privacy and data separation issues
COPE (corporate-owned, personally enabled)CompanyMore control, personal use allowed
CYOD (choose your own device)CompanyEmployee picks from an approved list
Corporate-ownedCompanyMaximum control

Connection methods: cellular, Wi-Fi, Bluetooth (pairing risks, bluejacking/bluesnarfing), NFC, USB. Containerization / work profiles separate work data from personal data. Geofencing restricts features by location. Remote wipe erases a lost device.

Wireless security settings

  • WPA3 (current): uses SAE (simultaneous authentication of equals) instead of PSK handshake, protecting against offline password guessing, and adds forward secrecy and stronger encryption. WPA2 uses AES-CCMP; WPA TKIP; WEP is broken.
  • Personal vs Enterprise: Personal uses a shared password. Enterprise uses 802.1X with a RADIUS server so each user authenticates individually (different credentials, revocable per user).
  • Authentication protocols (EAP family): EAP-TLS (certificates on both sides, strongest), PEAP (TLS tunnel protecting a password exchange), EAP-TTLS, EAP-FAST.
  • Captive portals for guest access. Guest networks should be separate from the internal network.
  • Open networks have no encryption; WPA3 OWE (enhanced open) encrypts without a password.
  • Disable WPS, change default SSID/password, hide nothing in the name of security (hiding SSID is weak).
  • Rogue AP and evil twin detection through WIDS/WIPS.

Application security

  • Input validation: check all input for type, length, range and format, on the server side. Prevents injection and overflows.
  • Secure cookies: set Secure (HTTPS only), HttpOnly (not readable by scripts), SameSite (limits cross-site sending).
  • Static application security testing (SAST): analyze source code without running it. Dynamic testing (DAST): test the running app. Code review, fuzzing (random/malformed input).
  • Code signing: digitally sign code so users can verify the publisher and that it wasn't altered.
  • Sandboxing: run code in an isolated environment so damage is contained.
  • Software composition / package monitoring: track third-party libraries for known vulnerabilities.
  • Secrets management: no passwords or keys in code or repos.
  • Secure development lifecycle: security built into each phase.

Exam traps

  • EAP-TLS is strongest because it needs certificates on client and server.
  • WPA3-Personal protects against offline dictionary attacks via SAE.
  • BYOD = employee owns; COPE = company owns, personal use allowed.
  • Baselines: establish → deploy → maintain.
  • SAST examines code; DAST tests running software.
