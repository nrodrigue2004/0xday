SY0-701domain 4.0 · Security Operations4.1

4.1 Given a scenario, apply common security techniques to computing resources

key ideas

  • Secure baselines: establish, deploy, maintain. Hardening targets: mobile, workstations, switches, routers, cloud, servers, ICS/SCADA, embedded, RTOS, IoT.
  • Wireless: site surveys and heat maps; WPA3, RADIUS, AAA. Cryptographic protocols and authentication protocols.
  • Application security: input validation, secure cookies, static code analysis, code signing. Sandboxing. Monitoring.
  • Mobile solutions: MDM; deployment models BYOD, COPE, CYOD; connection methods cellular, Wi-Fi, Bluetooth.

study notes

Objective 4.1 is about configuring things securely from the start and keeping them that way. It covers baselines, hardening for each kind of device, wireless and mobile security, and application security.

Secure baselines

A secure baseline is the documented, approved set of security settings for a type of system (a Windows workstation, a Linux web server, a switch). It follows three steps:

  1. Establish: define the baseline from vendor guidance, CIS benchmarks, STIGs or your own policy.
  2. Deploy: apply it consistently (group policy, configuration management, golden images, automation).
  3. Maintain: monitor for drift, update the baseline for new threats and patches, and re-apply it.

Baselines make systems consistent, make audits easier, and give you a known-good reference to detect unauthorized change.

Hardening targets

For every device class, the same ideas apply: remove what you don't need, change defaults, patch, restrict access, log. The exam tests what is *special* about each class.

TargetHardening focus
WorkstationsPatching, endpoint protection/EDR, host firewall, full-disk encryption, least privilege, remove bloatware, disable unneeded services
ServersMinimal installed roles, remove unneeded services/accounts, restrict admin access, patching, logging, secure remote admin
Switches and routersChange default credentials, disable unused ports, use SSH not Telnet, secure management access (dedicated VLAN), update firmware, port security, disable unused services
Cloud infrastructureLeast privilege IAM, MFA, private storage by default, encryption, security groups, logging, scan IaC templates
Mobile devicesMDM policy, screen lock, encryption, patching, app control, remote wipe
ICS/SCADAIsolate from IT networks, strict access control, monitor, compensating controls because patching is hard and availability/safety come first
Embedded systems and RTOSLimited patch options, so isolate, restrict network exposure, vendor lifecycle awareness
IoTChange default passwords, separate VLAN, disable unneeded features, firmware updates

Hardening also includes: encryption, minimal software, secure configuration, disable unused ports and protocols, restrict admin rights, enable logging.

Wireless device installation considerations

  • Site survey: measure signal and interference to plan access point placement.
  • Heat map: visual map of coverage strength and dead zones.
  • Channel selection to avoid overlap and interference, AP placement (not near external walls so the signal doesn't leak far outside), power levels.
  • Plan for capacity and for connecting wired backhaul.

Mobile solutions

Mobile device management (MDM) enforces policy on phones and tablets: require a PIN, encryption, remote wipe, app allow lists, geofencing, block jailbroken devices, push updates and certificates. Mobile application management (MAM) controls just the apps/data, which suits personal devices. Unified endpoint management (UEM) covers all endpoint types.

Deployment models:

ModelWho owns the deviceTrade-off
BYOD (bring your own device)EmployeeCheapest; hardest to control, privacy and data separation issues
COPE (corporate-owned, personally enabled)CompanyMore control, personal use allowed
CYOD (choose your own device)CompanyEmployee picks from an approved list
Corporate-ownedCompanyMaximum control

Connection methods: cellular, Wi-Fi, Bluetooth (pairing risks, bluejacking/bluesnarfing), NFC, USB. Containerization / work profiles separate work data from personal data. Geofencing restricts features by location. Remote wipe erases a lost device.

Wireless security settings

  • WPA3 (current): uses SAE (simultaneous authentication of equals) instead of PSK handshake, protecting against offline password guessing, and adds forward secrecy and stronger encryption. WPA2 uses AES-CCMP; WPA TKIP; WEP is broken.
  • Personal vs Enterprise: Personal uses a shared password. Enterprise uses 802.1X with a RADIUS server so each user authenticates individually (different credentials, revocable per user).
  • Authentication protocols (EAP family): EAP-TLS (certificates on both sides, strongest), PEAP (TLS tunnel protecting a password exchange), EAP-TTLS, EAP-FAST.
  • Captive portals for guest access. Guest networks should be separate from the internal network.
  • Open networks have no encryption; WPA3 OWE (enhanced open) encrypts without a password.
  • Disable WPS, change default SSID/password, hide nothing in the name of security (hiding SSID is weak).
  • Rogue AP and evil twin detection through WIDS/WIPS.

Application security

  • Input validation: check all input for type, length, range and format, on the server side. Prevents injection and overflows.
  • Secure cookies: set Secure (HTTPS only), HttpOnly (not readable by scripts), SameSite (limits cross-site sending).
  • Static application security testing (SAST): analyze source code without running it. Dynamic testing (DAST): test the running app. Code review, fuzzing (random/malformed input).
  • Code signing: digitally sign code so users can verify the publisher and that it wasn't altered.
  • Sandboxing: run code in an isolated environment so damage is contained.
  • Software composition / package monitoring: track third-party libraries for known vulnerabilities.
  • Secrets management: no passwords or keys in code or repos.
  • Secure development lifecycle: security built into each phase.

More detail from the lessons

Baselines

  • A baseline covers firewall settings, patch levels, the underlying OS, file permissions and application configuration. Each time an application instance is deployed, its baseline goes with it, and you keep checking that settings still hold; if not, make a plan to correct it quickly.
  • Sources: the application developer, the OS manufacturer (Microsoft), and appliance makers. Windows 10 has over 3,000 group policy settings (only a subset matter for security). Microsoft publishes baselines for Windows and Windows Server and the Security Compliance Toolkit (SCT) to deploy them.
  • Deploy through a central console, Active Directory group policy, or an MDM for mobile; automate it for hundreds or thousands of devices. Updates are needed for new vulnerabilities, app updates, or a new OS. Two vendors' baselines can conflict, so choose the better one. Test before deploying and audit afterward.

Hardening targets (lesson specifics)

  • Default configs are rarely secure. Look for manufacturer hardening guides, otherwise ask the vendor or look for third-party guides.
  • Mobile: patches (often security fixes), segment company data from personal data, manage with an MDM.
  • Workstations (Windows, macOS, Linux): patches for the OS, apps and firmware; vendors bundle monthly so you can test once. Remove unused software.
  • Network infrastructure: switches, routers and firewalls run embedded OSes, so change default credentials, use local or central authentication, and check the manufacturer for rare updates, treating a security release as a significant event.
  • Cloud management workstation: has broad access to cloud systems so it must be secure. Use least privilege for cloud apps and devices, install EDR, back up (ideally to a different cloud provider).
  • Servers: security patches and service packs, minimum password length and complexity, least privilege, disable unused accounts, limit which devices can reach the server (policy or firewall), plus EDR, antivirus or anti-malware.
  • SCADA/ICS: distributed control with real-time monitoring and control, often on an isolated, air-gapped network with no internet access.
  • Embedded (smartwatches, TVs, appliances): hard to upgrade and patches are rare, so install them as soon as they appear, and consider a separate network with a firewall.
  • RTOS: deterministic (processes have expected time frames) for industrial, military and automotive. Isolate, run minimum services, and add a separate firewall or host-based security if it must talk to the network.
  • IoT: makers are not security experts, so prioritize patches and segment IoT devices on their own network.

Wireless and mobile

  • Site survey: learn which access points are nearby (yours and others), the spectrum in use and the best channels, then repeat periodically because neighbors change. A heat map shows coverage (red/yellow strong, blue weak). Tools: built-in OS utilities, NetSpot, and survey tools listing SSIDs, BSSID, channel and band. A spectrum analyzer shows every signal on a frequency, including non-Wi-Fi devices.
  • MDM capabilities: push policies and required apps, disable the camera at headquarters and re-enable it outside, create a business partition separate from personal data, force screen locks and PIN/password. BYOD (also "bring your own technology") needs modern devices that can be managed, privacy for the user, and a process for when the phone is sold or traded in. COPE: company buys it, personal use allowed, with corporate data partitioned so one partition can be wiped. CYOD: user chooses from corporate-owned options.
  • Cellular (4G/5G, divided into cells): worry about traffic monitoring and location tracking; keep devices patched. Wi-Fi: use VPN or other encryption on untrusted networks (coffee shop, hotel), because attackers nearby can do on-path or interference attacks. Bluetooth is a PAN; use the formal pairing process and do not auto-connect to unknown devices.

Wireless security settings

  • Wireless is over the air, so encrypt and authenticate. A message integrity check (MIC) ensures frames arrive unchanged.
  • WPA2 problem: the four-way handshake carries a hash tied to the pre-shared key. Capture it, then brute force it offline with GPU or cloud cracking in days.
  • WPA3: GCMP (Galois Counter Mode Protocol) provides confidentiality plus integrity through a Galois message authentication code. The handshake is replaced by SAE (simultaneous authentication of equals), based on Diffie-Hellman, with mutual authentication and session keys created on each end rather than sent across. Each user gets a different session key even with the same PSK. Also known as the dragonfly handshake.
  • Network modes: open/none, WPA3-Personal (PSK), and WPA3-Enterprise (802.1X) tied to RADIUS, LDAP or TACACS+.
  • AAA: identification (username), then authentication, authorization (what you can access) and accounting (login time, data sent and received, logout). RADIUS (remote authentication dial-in user service) is widely supported for routers, switches, servers and VPNs. A central AAA server lets you disable one account when someone leaves.
  • 802.1X (NAC) works on wired and wireless. EAP is the flexible framework inside it. Roles: supplicant, authenticator, authentication server. Flow: authenticator blocks and asks for identity, supplicant sends an EAP response with its name, authenticator asks the server whether to continue, supplicant gives credentials, server validates and allows.

Application security

  • Input validation: check every field against the expected format (a ZIP code has a set length and character set, and formats differ by country) and prompt for correction. Fuzzing automates random input to see how the app behaves.
  • Cookies are data files, not executables, but hold useful info. Secure cookies have an attribute requiring HTTPS. Anything in a cookie can be read, so never store sensitive data in one.
  • SAST (static application security testing): analyzers find buffer overflows and injections in code, but miss problems like how cryptography is implemented, and produce false positives to triage. Example output: filetest.c line 32 using gets with no overflow check, recommend fgets.
  • Code signing answers whether the code changed and whether it truly came from that developer. A CA signs the developer's key, the developer signs code, and the OS checks during install and warns if validation fails.
  • Sandboxing: the app only reaches the data it needs. Development sandboxes keep a new app away from production; VMs are isolated; mobile OS sandboxes mean a browser cannot reach your camera roll.
  • Monitoring: built-in logging reveals SQL injection attempts, unusual file transfers or rising client access.

Exam traps

  • EAP-TLS is strongest because it needs certificates on client and server.
  • WPA3-Personal protects against offline dictionary attacks via SAE.
  • BYOD = employee owns; COPE = company owns, personal use allowed.
  • Baselines: establish → deploy → maintain.
  • SAST examines code; DAST tests running software.
