2.4 Given a scenario, analyze indicators of malicious activity

key ideas

  • Malware: ransomware, trojan, worm (self-spreading), spyware, bloatware, virus, keylogger, logic bomb, rootkit.
  • Physical: brute force, RFID cloning. Network: DDoS (amplified, reflected), DNS attacks, wireless, on-path, credential replay, malicious code.
  • Application: injection, buffer overflow, replay, privilege escalation, forgery (CSRF/SSRF), directory traversal.
  • Crypto: downgrade, collision, birthday. Password: spraying (one password, many accounts) vs brute force.
  • Indicators: account lockout, concurrent session usage, blocked content, impossible travel, resource consumption/inaccessibility, out-of-cycle logging, missing logs, published/documented.

study notes

Objective 2.4 is a scenario objective: you are shown symptoms or logs and must name the attack or malware. Learn each item as what it does, how it looks, how to stop it.

Malware

Malware is software built to harm or take control of a system. Infection routes: email attachments, drive-by downloads, malicious updates, removable media, trojanized apps, exploited vulnerabilities.

Signs of ransomware: files renamed/encrypted, a ransom note, backups deleted or encrypted. Signs of a worm: unusual network traffic and many hosts failing at once. Signs of rootkit: security tools disabled, strange behavior that scans can't find.

Physical attacks

  • Brute force (physical): forcing locks, doors or enclosures.
  • RFID cloning: copying the data from an access card or fob to make a duplicate. Defend with encrypted/mutual-auth cards and shielded wallets.
  • Environmental attacks: heat, cooling failure, power loss, water, fire against infrastructure.
  • Skimming: a device on a card reader steals card data.
  • Malicious USB cables and devices that inject keystrokes.

Network attacks

#### Denial of service

  • DoS: one source overwhelms a service. DDoS: many sources (usually a botnet). Impact is on availability.
  • Amplified: a small request produces a large reply (DNS, NTP). Reflected: spoofed source address sends the replies to the victim. Combined: reflection + amplification.
  • Application-layer attacks target a web app (HTTP floods, Slowloris). Operational technology (OT) DoS can affect physical processes.
  • Mitigation: upstream DDoS scrubbing/CDN, rate limiting, redundancy, anycast, ISP help, WAF.

#### DNS attacks

  • DNS poisoning / cache poisoning: false records get cached so users are sent to the attacker's address.
  • Domain hijacking: attacker takes over the domain registration or registrar account.
  • URL redirection and DNS tunneling (data hidden in DNS queries to exfiltrate or run C2).
  • Domain reputation matters: monitoring newly registered, look-alike domains.
  • Mitigation: DNSSEC (signed records), registrar lock and MFA, restrict zone transfers, DNS filtering and logging.

#### Wireless attacks

  • Rogue access point: unauthorized AP plugged into the network.
  • Evil twin: rogue AP imitating a legitimate SSID so users connect to it (often paired with a captive portal). Defense: 802.1X/WPA3-Enterprise with certificate validation, VPN on public Wi-Fi.
  • Deauthentication: forged frames disconnect clients (used to force reconnects/capture handshakes). 802.11w (management frame protection) mitigates it.
  • Jamming: radio noise blocks the signal.
  • WPS PIN attacks, Bluetooth attacks (bluejacking sends unwanted messages, bluesnarfing steals data), NFC relay and war driving.

#### On-path and replay

  • On-path (formerly man-in-the-middle): attacker sits between two parties, reading or altering traffic. ARP poisoning is a common local technique. SSL stripping downgrades HTTPS to HTTP. Defense: encryption (TLS), HSTS, certificate validation, Dynamic ARP Inspection.
  • Browser on-path (man-in-the-browser): malware in the browser alters transactions.
  • Replay attack: capture a valid message (authentication token, session) and resend it. Defense: timestamps, nonces, one-time session tokens, sequence numbers, MFA. Pass-the-hash replays a captured hash instead of a password.
  • Session hijacking: stealing a session ID/cookie to impersonate a logged-in user.

Application attacks

  • Injection: SQL, command, LDAP, XML. Untrusted input is interpreted as commands. Fix: validation, parameterization, least privilege.
  • Buffer overflow: too much data overwrites memory (see 2.3).
  • Privilege escalation: gaining more rights. Vertical (user to admin) or horizontal (to another user's data).
  • Forgery: CSRF (a logged-in browser sends an unintended request; defended with anti-CSRF tokens, SameSite cookies) and SSRF (the server is tricked into making requests to internal systems or cloud metadata).
  • Directory traversal: ../../ sequences read files outside the web root. Fix: canonicalize and validate paths.
  • Replay, race conditions and cross-site scripting also appear here.
  • API attacks and XML external entity (XXE) may appear in scenarios.

Cryptographic attacks

  • Downgrade attack: force the use of a weaker protocol or cipher (forcing TLS 1.0, export ciphers). Disable old versions.
  • Collision attack: find two inputs with the same hash (breaks MD5/SHA-1 signatures).
  • Birthday attack: exploits the math of collisions; needs far fewer tries than brute force. Use longer hashes.
  • Key-related: weak keys, key reuse, stolen keys, brute force against short keys.
  • Side-channel attacks (timing, power) leak keys from the way hardware behaves.

Indicators of compromise (IOC)

An IOC is evidence that a system is or was compromised. Look for:

  • Account lockout or administrative disable that nobody requested. Attackers may lock an account to trigger a help-desk password reset they can social-engineer.
  • Concurrent session usage: one account active in two places at once.
  • Blocked content: AV or update sites suddenly unreachable because malware blocks security tools.
  • Impossible travel: logins from distant places within a time too short to travel (Omaha and Sydney minutes apart).
  • Resource consumption: CPU, bandwidth or disk use spikes, especially unusual traffic at 3 a.m. (data exfiltration).
  • Resource inaccessibility: a server crashes after exploitation attempts, data suddenly encrypted, or an account locked from brute force.
  • Out-of-cycle logging: events at times they should not happen (patches installing at an odd hour, transfers at 3 a.m.).
  • Missing logs: attackers delete logs, so alert when expected logs stop.
  • Published or documented: your private data appears publicly or on leak sites, often tied to ransomware extortion.

More detail from the lessons

Malware overview

  • Malware types work together: a worm exploits a known vulnerability, drops a backdoor, the attacker connects and installs more. Infection ways: an email click, a pop-up, a drive-by download (downloads with no click, rare), or a worm using a known vulnerability. Data is valuable (personal archives, planning documents, employee and financial data), either to steal or to hold for ransom.
  • Ransomware is a business model: encrypt everything in your personal folders but leave the OS working so you can read the ransom note, then demand cryptocurrency for the key. Defenses: offline backups (so the ransomware cannot find and encrypt them), OS and app patches, and up-to-date antimalware signatures. Backups plus updates are the two basics.

Viruses and worms

  • A virus needs a human to start it (click a link or run an executable), then spreads through the file system or network shares. Some sit quietly. Types: program viruses, boot sector viruses (run at boot), script viruses, macro viruses (Office) and fileless viruses.
  • Fileless: never writes malicious code to disk, so signature-based AV that watches disk writes misses it. Typical chain: user clicks a malicious link, the site exploits a flaw (Flash, Java, a known Windows bug), the code launches PowerShell, downloads more scripts and runs them in memory, exfiltrates data, and adds an autostart entry in the Windows registry to survive reboot.
  • Worms self-replicate without user action, spread at network speed, and can strike any time. Stop them with network firewalls, personal firewalls and IPS that have the right signatures. Example: WannaCry used EternalBlue (an SMB v1 flaw) to infect a vulnerable system, install a backdoor, pull ransomware, and keep scanning for more victims.

Spyware, keyloggers and bloatware

  • Spyware watches everything: ads, stolen info, affiliate fraud, browsing habits. It arrives via peer-to-peer software, fake security software or email links, often installs a keylogger, and is hard to uninstall. Use anti-malware (the lesson names Malwarebytes), research what you install, and keep a known good backup.
  • Bloatware is manufacturer-installed (paid) software: takes space, runs at startup, and can have vulnerabilities on a brand-new device. Remove via the OS app list, the app's own uninstaller, or as a last resort third-party uninstaller software.
  • Keyloggers capture keystrokes (URLs, passwords, card numbers), but also the clipboard, screenshots, chats and search queries, and they send the log to the attacker about once a day. Typing is not encrypted, so encryption elsewhere does not help. The lesson's demo tool is DarkComet, a RAT with a keylogger that even recorded the delete key.

Logic bombs and rootkits

  • Logic bomb: waits for a date/time or event (a particular user logging in). Usually custom-made, so no antivirus signature exists. South Korea, March 20, 2013 at 2:00 PM: a Trojan delivered by email to banks and broadcasters (March 19) wiped storage and the master boot record, so machines and the bank's ATMs rebooted with the message "Boot device not found." Defense: limit and monitor changes to core OS files, and enforce least privilege so nobody casually has admin rights.
  • Rootkit: "root" is from the Unix superuser. It hides in the kernel, so it is part of the OS, does not show in process lists and evades normal AV. Not every rootkit is in the kernel; those running as ordinary processes can still be caught. Use standalone removal tools after infection. Secure boot (UEFI) checks the OS signature and kernel before booting so the rootkit cannot load.

Physical

  • Whoever physically touches a computer can bypass the OS, and "door locks only keep out honest people". Brute force a door or window. RFID cloning: cloners cost under $50, copy a badge in seconds, and can even work by brushing someone on a train. MFA (PIN, biometrics) beats a cloned badge.
  • Environmental: cut power (possible from outside the building), attack the HVAC control system so equipment overheats and shuts down, or trigger the fire suppression system to cause denial of service.

Denial of service

  • Motives: competitive advantage, a smokescreen for another attack, or simple vulnerabilities. Easy methods include pulling power. Self-inflicted DoS examples: a network loop from plugging two switches together twice with no spanning tree, saturating a small DSL line downloading a big Linux ISO, and a water line over a data center ceiling breaking.
  • DDoS uses botnets under one command. The Zeus botnet reached over 3.6 million computers. It is an asymmetric threat: the attacker with few resources defeats a larger target.
  • Amplification uses services where a small request gets a big answer (NTP, DNS, ICMP). The lesson's example: a dig ANY isc.org query of about 15 characters returned about 1,300 characters, roughly 86x. Attack flow: the botnet's command and control tells bots to query open DNS resolvers with the source address spoofed to the victim, so the large responses hit the victim web server.

DNS attacks

  • DNS maps names to IPs. Methods to redirect: edit the client's hosts file (needs local access and usually elevated rights; the file is checked before DNS), on-path interception of DNS queries, or modify the DNS server itself (attacker at 100.100.100.100 changes the record so user 2 gets the attacker's IP). Servers are usually well protected.
  • Domain hijacking: take over the registration through brute force, social engineering, or leaked credentials, then change the DNS settings. October 22, 2016: 36 domains of a Brazilian bank (over 5 million customers, about $27 billion in assets) were altered for about six hours, so the attackers effectively became the bank's IP address and could collect credentials.
  • URL hijacking / typosquatting / brandjacking: look-alike domains for ad revenue, to sell back to the owner, to redirect to a competitor, to phish logins, or to drop ransomware or botnet code. Variants: misspell a letter (messor), drop a letter, add a letter (messers), or use a different top-level domain (.org).

Wireless

  • Deauthentication: management frames in older 802.11 are sent in the clear and unauthenticated, so an attacker can forge them. Lesson demo: find the AP BSSID and the victim's MAC with airodump-ng (monitor interface wlan0mon), then aireplay-ng -0 to send deauth frames; the victim keeps dropping. Fix: the 802.11w / 802.11ac-and-newer updates encrypt management frames like disassociate, authenticate and channel switch announcements. Beacons, probes, authentication and association still must be in the clear.
  • RF jamming lowers the signal-to-noise ratio. Everyday jammers: microwave ovens and fluorescent lights on 2.4 GHz. Deliberate jam signals can be constant, random data, many legitimate frames, random-time, or reactive (only when someone transmits). The attacker must be nearby, so hunt it with a directional antenna ("fox hunt") and an attenuator to triangulate.

On-path

  • Also called man-in-the-middle; invisible to both sides; can read and modify. ARP poisoning works on the local subnet because ARP has no authentication: the attacker sends an unsolicited ARP reply claiming to be 192.168.1.1 with the attacker's MAC; the victim's ARP cache updates (the same trick on the router), and traffic flows through the attacker. Normal ARP: broadcast asking who has the IP, reply with the MAC, cache it for some minutes.
  • On-path browser (man-in-the-browser): a Trojan on the victim's device acts as a proxy, so it sees data even if the network traffic is encrypted, waits for a banking login, grabs credentials and starts hidden sessions to move money.

Replay

  • The attacker needs something to replay and gets it via a physical network tap, ARP poisoning, or malware. Replay is not itself on-path, though on-path is often used to collect the data.
  • Pass the hash: capture the username and hashed password during authentication, replay it to the server. Counter: encryption, plus salting so each authentication uses a different salt and hash, with the server refusing to accept the same hash twice.
  • Cookies are not executable, but hold session IDs and tracking data. Session hijacking / sidejacking: steal the session ID after the victim logs in, and the server treats you as the logged-in user. Collected via packet capture (Wireshark, Kismet), XSS, or header tampering with tools like Tamper, Firesheep and Scapy, plus browser cookie editors. Fix: encrypt end to end with HTTPS (browser extensions can force HTTPS), or at least a VPN to a concentrator.

Malicious code in the news

  • Scripts, macros, executables and Trojans together require layered defense: anti-malware, firewall, patching, and user training. WannaCry: SMBv1 vulnerability allowing arbitrary code execution, then ransomware. British Airways: 22 lines of malicious JavaScript on the checkout pages (XSS-style), about 380,000 victims' cards at risk. Estonian Central Health Database: SQL injection exposed health records of the whole country.

Application attacks

  • Injection types: SQL, HTML, XML, LDAP. Buffer overflows usually just crash the app unless repeatable. Privilege escalation: vertical to admin or horizontal (user A gets user B's access). Mitigations: patch, update AV signatures, data execution prevention (DEP), and ASLR (randomized memory locations). Example: CVE-2023-29336, Win32k elevation of privilege (May 2023) giving SYSTEM, the highest Windows privilege.
  • Cross-site request forgery (CSRF, "sea surf", one-click attack, session riding): pages load content from many servers (client side HTML/JavaScript and server side code like PHP). The attacker abuses the server's trust of your authenticated browser, such as a bank transfer link sent by email, or posting on your Facebook. Defense: a cryptographic anti-forgery token per request.
  • Directory traversal: a web server misconfiguration or software bug lets requests reach outside the web root. A log line with ../../windows/system.ini is the tell, and ../ moves up one directory.

Cryptographic attacks

  • Attackers go after the implementation, not the algorithm, because public algorithms have withstood scrutiny.
  • Birthday attack: among 23 people there is about a 50% chance two share a birthday; at 30 people about 70%. Applied to hashes, finding any two inputs with the same hash is far easier than matching a specific hash. Counter: larger hash output.
  • MD5 was published April 1992, collisions found in 1996, and in December 2008 researchers made a forged CA-signed certificate that validated via MD5, so the industry moved off MD5.
  • Downgrade / SSL stripping: on-path attacker strips HTTPS. The victim's first request is HTTP, the attacker proxies it and opens its own HTTPS session to the server, then sends everything to the victim in HTTP. The victim's username and password are readable, and the attacker relays them over HTTPS. Everything after is in the clear between victim and attacker. Defense: HSTS and HTTPS-only.

Password attacks

  • Never store plaintext. Store hashes (fixed-length output, different inputs give very different hashes, no way back). A one-character change (123456 vs 1234567) yields completely different SHA-256 hashes.
  • Spraying: try the few most common passwords (123456, 123456789, qwerty, password, 1234567) against each account, about 3 attempts, then move to the next so no lockout or alarm fires.
  • Brute force: try every combination (aaaaa, aaaab, ...) and compare hashes to the stolen hash. Online is slow and triggers lockout. In practice the attacker downloads the credential file and brute forces offline with unlimited time, limited only by computing power and hash strength and password length.

Indicators of compromise

  • An IOC is evidence you are highly confident means compromise: large unusual traffic, changed file hashes, traffic from unexpected countries, changed DNS records, odd login patterns, files read far more than normal.
  • Account lockout you did not cause (or an administrative disable nobody ordered). The attacker may do it on purpose to call the help desk and get a password reset, so use strong reset procedures.
  • Concurrent session usage: one account in two places (but legit multi-device use and service logins exist; check login reports, like Gmail's activity list).
  • Blocked content: malware disables AV updates, so failure to reach security sites or patches is an IOC.
  • Impossible travel: login from Omaha, Nebraska and minutes later from Australia. Check authentication logs.
  • Resource consumption: unusual traffic at 3:00 AM from file transfer or exfiltration, visible in firewall flow logs. Some breaches were noticed only by one small transfer at an odd time.
  • Resource inaccessibility: crashed server (from exploitation attempts), network disruption used as a diversion, data encrypted, or an account locked by brute force.
  • Out-of-cycle logging: events outside the expected schedule (patches installing off the regular patch time, firewall logs showing transfers at odd hours).
  • Missing logs: attackers delete logs, so alert when expected log data disappears.
  • Published/documented: data appears on the internet, often because ransomware gangs steal data first (double extortion) and then leak it if you do not pay. Researchers then trace the source and notify the owner.

Exam traps

  • Virus needs user action; worm spreads on its own.
  • Spraying = one password across many accounts; brute force = many passwords on one account.
  • Evil twin imitates a known network; rogue AP is any unauthorized AP.
  • Replay resends valid captured data; on-path intercepts live.
  • Rainbow tables are defeated by salts.
  • Logic bomb waits for a trigger; backdoor gives hidden access.
