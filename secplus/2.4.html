study --objective 2.4

SY0-701domain 2.0 · Threats, Vulnerabilities & Mitigations2.4

2.4 Given a scenario, analyze indicators of malicious activity

key ideas

  • Malware: ransomware, trojan, worm (self-spreading), spyware, bloatware, virus, keylogger, logic bomb, rootkit.
  • Physical: brute force, RFID cloning. Network: DDoS (amplified, reflected), DNS attacks, wireless, on-path, credential replay, malicious code.
  • Application: injection, buffer overflow, replay, privilege escalation, forgery (CSRF/SSRF), directory traversal.
  • Crypto: downgrade, collision, birthday. Password: spraying (one password, many accounts) vs brute force.
  • Indicators: account lockout, concurrent session usage, blocked content, impossible travel, resource consumption/inaccessibility, out-of-cycle logging, missing logs, published/documented.

study notes

Objective 2.4 is a scenario objective: you are shown symptoms or logs and must name the attack or malware. Learn each item as what it does, how it looks, how to stop it.

Malware

Malware is software built to harm or take control of a system. Infection routes: email attachments, drive-by downloads, malicious updates, removable media, trojanized apps, exploited vulnerabilities.

TypeDefining behaviorNotes

Signs of ransomware: files renamed/encrypted, a ransom note, backups deleted or encrypted. Signs of a worm: unusual network traffic and many hosts failing at once. Signs of rootkit: security tools disabled, strange behavior that scans can't find.

Physical attacks

  • Brute force (physical): forcing locks, doors or enclosures.
  • RFID cloning: copying the data from an access card or fob to make a duplicate. Defend with encrypted/mutual-auth cards and shielded wallets.
  • Environmental attacks: heat, cooling failure, power loss, water, fire against infrastructure.
  • Skimming: a device on a card reader steals card data.
  • Malicious USB cables and devices that inject keystrokes.

Network attacks

#### Denial of service

  • DoS: one source overwhelms a service. DDoS: many sources (usually a botnet). Impact is on availability.
  • Amplified: a small request produces a large reply (DNS, NTP). Reflected: spoofed source address sends the replies to the victim. Combined: reflection + amplification.
  • Application-layer attacks target a web app (HTTP floods, Slowloris). Operational technology (OT) DoS can affect physical processes.
  • Mitigation: upstream DDoS scrubbing/CDN, rate limiting, redundancy, anycast, ISP help, WAF.

#### DNS attacks

  • DNS poisoning / cache poisoning: false records get cached so users are sent to the attacker's address.
  • Domain hijacking: attacker takes over the domain registration or registrar account.
  • URL redirection and DNS tunneling (data hidden in DNS queries to exfiltrate or run C2).
  • Domain reputation matters: monitoring newly registered, look-alike domains.
  • Mitigation: DNSSEC (signed records), registrar lock and MFA, restrict zone transfers, DNS filtering and logging.

#### Wireless attacks

  • Rogue access point: unauthorized AP plugged into the network.
  • Evil twin: rogue AP imitating a legitimate SSID so users connect to it (often paired with a captive portal). Defense: 802.1X/WPA3-Enterprise with certificate validation, VPN on public Wi-Fi.
  • Deauthentication: forged frames disconnect clients (used to force reconnects/capture handshakes). 802.11w (management frame protection) mitigates it.
  • Jamming: radio noise blocks the signal.
  • WPS PIN attacks, Bluetooth attacks (bluejacking sends unwanted messages, bluesnarfing steals data), NFC relay and war driving.

#### On-path and replay

  • On-path (formerly man-in-the-middle): attacker sits between two parties, reading or altering traffic. ARP poisoning is a common local technique. SSL stripping downgrades HTTPS to HTTP. Defense: encryption (TLS), HSTS, certificate validation, Dynamic ARP Inspection.
  • Browser on-path (man-in-the-browser): malware in the browser alters transactions.
  • Replay attack: capture a valid message (authentication token, session) and resend it. Defense: timestamps, nonces, one-time session tokens, sequence numbers, MFA. Pass-the-hash replays a captured hash instead of a password.
  • Session hijacking: stealing a session ID/cookie to impersonate a logged-in user.

Application attacks

  • Injection: SQL, command, LDAP, XML. Untrusted input is interpreted as commands. Fix: validation, parameterization, least privilege.
  • Buffer overflow: too much data overwrites memory (see 2.3).
  • Privilege escalation: gaining more rights. Vertical (user to admin) or horizontal (to another user's data).
  • Forgery: CSRF (a logged-in browser sends an unintended request; defended with anti-CSRF tokens, SameSite cookies) and SSRF (the server is tricked into making requests to internal systems or cloud metadata).
  • Directory traversal: ../../ sequences read files outside the web root. Fix: canonicalize and validate paths.
  • Replay, race conditions and cross-site scripting also appear here.
  • API attacks and XML external entity (XXE) may appear in scenarios.

Cryptographic attacks

  • Downgrade attack: force the use of a weaker protocol or cipher (forcing TLS 1.0, export ciphers). Disable old versions.
  • Collision attack: find two inputs with the same hash (breaks MD5/SHA-1 signatures).
  • Birthday attack: exploits the math of collisions; needs far fewer tries than brute force. Use longer hashes.
  • Key-related: weak keys, key reuse, stolen keys, brute force against short keys.
  • Side-channel attacks (timing, power) leak keys from the way hardware behaves.

Indicators of compromise (IOC)

An IOC is evidence that a system is or was compromised. Look for:

  • Account lockout or administrative disable that nobody requested. Attackers may lock an account to trigger a help-desk password reset they can social-engineer.
  • Concurrent session usage: one account active in two places at once.
  • Blocked content: AV or update sites suddenly unreachable because malware blocks security tools.
  • Impossible travel: logins from distant places within a time too short to travel (Omaha and Sydney minutes apart).
  • Resource consumption: CPU, bandwidth or disk use spikes, especially unusual traffic at 3 a.m. (data exfiltration).
  • Resource inaccessibility: a server crashes after exploitation attempts, data suddenly encrypted, or an account locked from brute force.
  • Out-of-cycle logging: events at times they should not happen (patches installing at an odd hour, transfers at 3 a.m.).
  • Missing logs: attackers delete logs, so alert when expected logs stop.
  • Published or documented: your private data appears publicly or on leak sites, often tied to ransomware extortion.

Exam traps

  • Virus needs user action; worm spreads on its own.
  • Spraying = one password across many accounts; brute force = many passwords on one account.
  • Evil twin imitates a known network; rogue AP is any unauthorized AP.
  • Replay resends valid captured data; on-path intercepts live.
  • Rainbow tables are defeated by salts.
  • Logic bomb waits for a trigger; backdoor gives hidden access.
