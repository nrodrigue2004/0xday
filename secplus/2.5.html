SY0-701domain 2.0 · Threats, Vulnerabilities & Mitigations2.5

2.5 Explain the purpose of mitigation techniques used to secure the enterprise

key ideas

  • Segmentation, access control (ACLs, permissions), application allow lists, isolation, patching, encryption, monitoring.
  • Least privilege; configuration enforcement; decommissioning.
  • Hardening: install endpoint protection, host-based firewall, HIPS, disable ports/protocols, change default passwords, remove unnecessary software.

study notes

Mitigation techniques are the practical ways to shrink risk. The exam wants you to match a problem to the control that actually fixes it.

Segmentation and access control

  • Segmentation: splitting the network into separate zones (VLANs, subnets, firewalls) so an intruder in one area can't move freely. Limits lateral movement and contains incidents. Examples: separate guest Wi-Fi, a DMZ for public servers, isolated OT/IoT networks.
  • Access control list (ACL): rules on a router, firewall or file system that allow or deny based on source, destination, port, user. Network ACLs filter traffic; file system ACLs control who can read/write files.
  • Permissions: least privilege on files, folders, databases and cloud resources.
  • Application allow list (whitelist): only approved programs may run. Strongest application control, but takes maintenance. A deny list (blocklist) blocks known bad software and misses new threats.
  • Isolation: a compromised or untrusted system is cut off from the network (quarantine VLAN, network access control).
  • Decommissioning: remove unused systems, accounts and services, and securely wipe data.

Mitigation techniques

  • Patching: apply vendor fixes promptly, after testing. Emergency patching for actively exploited flaws.
  • Encryption: protects data at rest, in transit and in use.
  • Monitoring: logging, SIEM, alerts, and review to detect problems early.
  • Least privilege: only the access needed for the job, for the time needed.
  • Configuration enforcement: automated checks that systems keep their secure baseline (group policy, configuration management, compliance scanning).
  • Decommissioning and hardening (below) reduce the attack surface.
  • Defense in depth: layers so one failure doesn't expose everything.

Hardening techniques

Hardening means removing or locking down everything that isn't required.

More detail from the lessons

Segmentation reasons

  • Segment physically (separate devices), logically (VLANs on switches), or virtually (cloud and VM architectures). Reasons: performance (a dedicated subnet for a high-bandwidth app), security (users talk to an application server, only the application server talks to the database server, enforced by a firewall or ACL), and mandates (PCI DSS may require card data kept completely separate from the rest of the network).
  • ACL criteria: source IP, destination IP, port numbers, time of day, or user. Example rules from the lesson: Bob can read files on a resource, Fred can access the network, James can reach 192.168.1.0/24 only on TCP 80, 443 and 8088. Operating system file and folder permissions and group membership are ACLs too. Take care not to write an ACL that locks you out of managing the device.
  • Application allow/deny lists: allow list means nothing runs unless approved (restricted); deny list means everything runs except named items. Antivirus is a deny list. Windows rules can identify an application by hash (a change in the file breaks the match), by digital signature/certificate (allow anything signed by Microsoft, Adobe or Google and block unsigned), by path (only run from a specific directory), or by network zone (private vs public).

Mitigation details

  • Patching also improves stability. Home OSes patch themselves; large organizations test first then push, with emergency patches when attackers are actively exploiting a hole.
  • Encryption limits what an attacker can take: EFS for files and folders, FDE for devices that leave the building (BitLocker on Windows, FileVault on macOS), and application-level encryption so data stays protected regardless of the file system.
  • Monitoring comes from switches, routers, sensors, firewalls, IPS and OS authentication logs, and a SIEM consolidates them for reports.
  • Least privilege: ideally nobody runs as admin; elevate temporarily and drop back. This limits an attack to what that one user can see.
  • Configuration enforcement / posture assessment at login checks OS version and patches, EDR version and signatures, local firewall and EDR turned on, and a device certificate. A failing device goes to quarantine or a private VLAN to fix itself, then retries.
  • Decommissioning: remove or wipe storage (SSD, hard drive, USB) before retiring equipment. Reuse the drive internally after formatting, or destroy it if sensitive data may remain.

Hardening details

  • OS hardening: apply monthly security updates, set a password policy (the lesson's example: at least 8 characters with upper, lower, numbers and special characters), keep accounts to least privilege, limit which IP address range can reach the server, run antivirus, anti-malware or endpoint detection, and encrypt (EFS for files, FDE, VPN and HTTPS for traffic).
  • Endpoint hardening: attacks can be inbound, and an infected device can be a launch point against others. Different platforms (desktop, laptop, tablet, phone) need different tools, layered as defense in depth.
  • EDR: over a million malware variants appear daily, so signatures alone do not scale. EDR adds behavioral analysis, machine learning, process monitoring, root-cause analysis, and automatic response (isolate the system, quarantine the threat, roll back to a previous config) through an API, reporting to a central console without waiting for a ticket.
  • Host-based firewall: software firewall on the OS, controls inbound and outbound by process, sees traffic before/after encryption, can block unknown processes until approved, and is centrally manageable.
  • HIPS: usually built into EDR or anti-malware. It uses signatures, heuristics and behavior. Because it runs on the OS it can detect a buffer overflow, a registry change, or modified files in the core Windows folder and then alert and block.
  • Open ports: close as many as possible, using the host or a firewall (a next-generation firewall can control the service, not only the port number). Installers sometimes ask to open ports 0 to 65535 just so the vendor avoids support calls; that is not actually needed. Check with Nmap.
  • Default passwords: change them on routers, switches, firewalls, access points and application consoles, even when the device does not prompt you. Add MFA or centralized authentication where possible.
  • Remove unused software: every app has its own update process and its own bugs, so the easiest fix is to delete what you do not use.

Exam traps

  • Allow list beats deny list for application control.
  • Segmentation limits spread; it does not remove the vulnerability.
  • Isolation is a containment action; patching is the real fix.
  • If the question says "least effort and still effective", look for disabling unused services, changing defaults and patching.
