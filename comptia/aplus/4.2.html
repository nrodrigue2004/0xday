4.2 Client-side Virtualization

study notes

Client-side Virtualization

  • Run several OSes at once on one machine; each guest sees its own CPU, RAM and storage but they share the hardware. A hypervisor (virtual machine manager) allocates resources and manages networking and security. IBM mainframes did this in the 1960s. On a desktop it runs on top of your OS; on a server it hosts many VMs.
  • Uses: legacy software on an old OS next to a new one; different OSes without rebooting or partitioning; cost and time saving; sandboxing/testing (isolated VM, snapshot, roll back, mirror production safely).
  • Requirements: CPU hardware support (Intel VT, AMD-V; enable in BIOS), plenty of RAM, disk space per VM (many GB), and correct guest network configuration.
  • Security: VM escape (malware reaches the hypervisor and hops to other VMs, especially risky on shared hosting). VMs still need host firewalls, antivirus, patches. Never trust downloaded pre-built VMs (could contain malware); build your own.
  • VM networking: shared (NAT): VM uses a private IP and NATs through the host's address; bridged: VM gets its own IP on the LAN (like a physical device, via DHCP); private (host-only): VM can talk only to other VMs, not outside.

flashcards

self-check

1. Hypervisor won't start a 64-bit guest. First thing to check?

  • a) VT/AMD-V enabled in BIOS
  • b) Printer language
  • c) PSU wattage
  • d) DDR type
answer

a) Hardware virtualization support must be on.

2. You need a VM that is reachable by other LAN devices with its own address. Network mode?

  • a) Private
  • b) NAT
  • c) Bridged
  • d) Disabled
answer

c) Bridged gets its own IP.

short lab: Safe test VM

Set up a throwaway VM to test a risky installer. List four safety steps.

walkthrough

Build the VM yourself, take a snapshot, use private/host-only or NAT networking, no shared folders or clipboard, then revert to the snapshot afterward.
