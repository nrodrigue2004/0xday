4.3 Network Security Features

study notes

Device Security

  • Close unused ports/services: every listening service is an entry point (ports 0 to 65,535). Check with nmap; use a firewall to limit who can reach the ones you keep.
  • Change default credentials on every switch, router and firewall; default admin logins are public.
  • Port security (switches): limit the number of MACs per port or pin specific MACs; a violation usually shuts the port down and alerts the admin. Stops someone swapping in their own device.
  • Disable unused interfaces (wall jacks, conference rooms) until needed.
  • NAC / 802.1X: require authentication before a port or Wi-Fi network works.
  • MAC filtering: allow or block by MAC. Weak, security through obscurity: MACs are easy to sniff and change.
  • Key management: central console to create, track expiry, renew, revoke and report on certificates, SSL keys and SSH keys per user or service.

Security Rules

  • ACL: allow/deny list matching source and destination IP, port, protocol, time or application. Found on routers, firewalls and operating systems.
  • Firewall rules are read top to bottom, first match wins: put specific rules first, general ones last. If nothing matches, the implicit deny blocks the traffic. Sample rule base: allow TCP 22, 80, 443, 3389 in; allow UDP 53 and 123 out; deny ICMP; implicit deny at the end.
  • URL filtering: allow or block specific URLs or categories; combine with firewall rules so users can't bypass. Content filtering goes further: inspect content for leaked documents or financial data, unsafe content, malware (antivirus). Next-generation firewalls include both.
  • Screened subnet (DMZ): separate network for public services (web, mail) so the internet reaches them but not the internal LAN.
  • Zones: group networks into trusted/untrusted, or inside, internet, server, database and screened subnet zones. Rules reference zones rather than IPs ("trusted to untrusted: allow", "untrusted to trusted: deny"). This is a zone-based firewall.

flashcards

self-check

1. Traffic from the internet matches no firewall rule. What happens?

  • a) Allowed
  • b) Implicit deny
  • c) Logged only
  • d) Sent to the DMZ
answer

b) Unmatched traffic is dropped by default.

2. A public web server should be reachable but not expose the internal LAN. Where do you place it?

  • a) Inside the trusted zone
  • b) Screened subnet
  • c) On the management VLAN
  • d) Behind a hub
answer

b) Screened subnet isolates public services.

3. Someone plugs a personal laptop into a wall jack and gets network access. Best control?

  • a) 802.1X with port security
  • b) More DNS servers
  • c) Longer lease times
  • d) NTP
answer

a) Authenticate and limit devices per port.

short lab: Order the rules

A firewall has: (1) deny all, (2) allow TCP 443 to web server, (3) deny TCP 443 from 203.0.113.5. Put them in a working order so that the bad host is blocked and others reach the site.

walkthrough

Deny 203.0.113.5 to 443 first (specific), then allow TCP 443 to the web server, then deny all (explicit version of the implicit deny) last.
