3.1 Processes and Procedures

study notes

Network Documentation

  • Physical network map: devices, cables and connections as built (you could follow the cable in the room), made in Visio, OmniGraffle, Gliffy. Logical map: high-level connectivity (sites joined across a WAN cloud) without ports and cables, good for planning new sites.
  • Rack diagram: front view of a rack by unit number ("go to U15 in row 3, rack W and reboot that server") for remote hands. Cable map: floor plan with numbered drops that correspond to patch panel ports, vital for tracing faults. Layered diagrams overlay layer 1 (ports/cables), layer 2 (MAC addresses) and layer 3 (IP addresses).
  • Asset management: tag every device (barcode or RFID) and keep one database tying tag, components, user, location, purchase date, warranty and installed software (license counts). Tags also let tickets refer to "router 42" and support depreciation.
  • IPAM (IP address management): plan and track subnets, DHCP scopes and who held which IP at what time (key with dynamic addressing), spot shortages, IPv4 and IPv6 in one console.
  • SLA (service level agreement): contract with a provider defining minimum service, for example 99.99 percent uptime or no more than 4 hours of unscheduled downtime.
  • Site survey: map the wireless environment (all APs including neighbors, frequencies in use) to minimize interference. A heat map shows signal strength across the building. Repeat in shared buildings.

Life Cycle Management

  • EOL (end of life): vendor stops selling and improving the product (may still patch). EOS (end of support): no more patches or updates at all, a serious security risk. EOL means plan and budget a replacement, EOS means act now.
  • Patching: OS and app updates are often monthly on a schedule with out-of-band emergency fixes (zero-days). Updates also change security configuration (password rules, firewall settings, anti-malware). Firmware (software embedded in hardware: printers, modems, thermostats) must be updated too, often by hand. Keep old firmware images so you can roll back. Vendors can be slow: some IoT firmware bugs took more than a year to fix, so security must decide whether to keep a device.
  • Decommissioning: sanitize or destroy media before disposal, respect legal retention requirements (keep in secure storage until allowed), never throw gear in the trash.
  • Change management: defined process with allowed change windows, approvals, install procedure and a rollback plan. Service requests: a help desk ticketing system for triage, assignment, resolution and closing.

Configuration Management

  • Production configuration: the tested standard for a device class including hardware revisions, firmware, drivers and software versions. Test in a lab first.
  • Backup before every change (copy the config file, or a VM snapshot) so you can revert. Record changes so a system can be rebuilt after a disaster.
  • Baseline / golden configuration: the certified known-good complete config of an application deployment (workstations, firewall, servers). Compare production against it for integrity checks: either fix production to match, or approve the change and update the baseline to a new version.

flashcards

self-check

1. A vendor announces that no more security patches will ever ship for your core switch. Which milestone?

  • a) EOL
  • b) EOS
  • c) SLA
  • d) IPAM
answer

b) End of support means no updates at all.

2. Before a router upgrade, the first thing to do is?

  • a) Reboot it
  • b) Back up the configuration and keep the old firmware
  • c) Change the SLA
  • d) Decommission it
answer

b) Backup and rollback path first.

List six pieces of documentation you would hand to a new network admin on day one.

walkthrough

Physical and logical network maps, rack diagrams, cable map with drop numbers, IPAM export with DHCP scopes, asset database with warranty and firmware versions, SLA contracts plus golden configs and the change management policy.
