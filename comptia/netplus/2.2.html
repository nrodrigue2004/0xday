2.2 Switching Technologies

study notes

VLANs and Trunking

  • A LAN is one broadcast domain. A VLAN carves one physical switch into several separate broadcast domains (defined by number, per interface). Devices on different VLANs cannot talk without a router. Saves power, rack space and management versus one switch per network.
  • Spanning several switches: one cable per VLAN does not scale, so use a trunk (802.1Q, "dot1q"). The switch tags each frame with a 12-bit VLAN ID (inserted after the source MAC), so a single link carries up to 4,094 usable VLANs; the far switch reads the tag, strips it and delivers to the right VLAN. ISL was Cisco's old proprietary trunking, rarely seen now.
  • Default VLAN (usually VLAN 1): where every port starts. Native VLAN: the one VLAN sent untagged on a trunk (for devices that do not speak 802.1Q and some management traffic). It must match on both ends or you get log errors.
  • Layer 3 switch: switching plus routing in one box. Routing between VLANs uses SVIs (switched virtual interfaces), and routing may need to be enabled (sometimes a reload). Less capable than a real router ("a switch should switch, a router should route"), fine for small sites.
  • Voice and data: VoIP phones and PCs share one cable (PC plugs into the phone). Put voice in its own VLAN (say 200) and data in another (100) so bursty data does not hurt call quality; the switch separates them with tagging.

Interface Configurations

  • Speed must match on both ends or there is no link at all. Duplex mismatch (one half, one full) still links but performs terribly. Auto-negotiate on both sides is the norm. First check on a bad Ethernet link: speed and duplex, then IP config (address, mask, gateway, DNS must match what the admin assigned).
  • Link aggregation (LAG / port bonding): bundle several ports into one logical link (four 1 Gb links = 4 Gb throughput) without causing a loop. LACP negotiates it automatically.
  • MTU: normal Ethernet payload is 1500 bytes. Fragmenting is slow and one lost fragment forces resending everything. Path MTU discovery is automatic but firewalls can break it, so you may need to set MTU by hand. Jumbo frames raise MTU up to about 9,000 to 9,216 bytes (6x fewer frames), but every device in the path must support them or the frames are dropped.

Spanning Tree Protocol

  • A cable loop between switches makes frames circulate forever (Ethernet has no hop counter), creating a broadcast storm within seconds. STP (802.1D) prevents loops by blocking redundant ports.
  • Port states: blocking (no forwarding), listening (clears tables, hears neighbors), learning (builds MAC table), forwarding, plus disabled (admin down). Roles: one root bridge is elected; each switch has a root port (best path to the root), designated ports (forward traffic) and blocked ports (the loop breakers). If a link fails, STP recalculates and unblocks a backup port.
  • RSTP (802.1w, Rapid STP): same idea, converges in about 6 seconds versus 30 to 50 seconds for classic STP, and is backward compatible.

flashcards

self-check

1. Two switches are connected with two cables and the network goes down within seconds. What would normally prevent this?

  • a) LACP or STP
  • b) DHCP snooping
  • c) NAT
  • d) MTU
answer

a) STP blocks one path; LACP bundles the links into one logical link. Both avoid a loop.

2. A link between a PC (auto) and a switch port forced to 100/half is slow but up. Fix?

  • a) Change the cable category
  • b) Match duplex and speed settings (set both to auto)
  • c) Add a VLAN
  • d) Increase MTU
answer

b) Duplex mismatch causes collisions and poor throughput.

3. Two ends of a trunk disagree about the native VLAN. What do you see?

  • a) Nothing
  • b) Log errors and misdelivered untagged traffic
  • c) Link down
  • d) STP disabled
answer

b) Native VLAN must match.

short lab: Configure a trunk on paper

Switch A and B each have VLAN 100 (data) and VLAN 200 (voice). Describe the single link setup and the router-on-a-stick option for routing between them.

walkthrough

One cable between A and B, both ends set to 802.1Q trunk allowing VLANs 100 and 200, same native VLAN. To route: either an SVI per VLAN on a layer 3 switch, or a router with a trunk to the switch and subinterfaces (for example g0/0.100 and g0/0.200) each with an IP in its VLAN as the gateway.
