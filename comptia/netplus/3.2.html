3.2 Network Monitoring

study notes

SNMP

  • SNMP lets a management station query and manage devices from any vendor. Devices hold values in a MIB (management information base), each value addressed by an OID (object identifier, a dotted number path such as 1.3.6.1.2.1...). Standard values live in MIB-2; vendors add their own OIDs and provide MIB files to load into the console. Polling uses UDP 161.
  • Versions: v1 original, clear text. v2/v2c: bulk retrieval, still clear text. v3: encryption, integrity and real authentication (username and password hash).
  • Community strings (v1/v2c) are simple shared passwords, for example read-only "public" and read-write "private" (change the defaults!). A MIB walker (MIB browser) enumerates everything on a device.
  • Polling only finds a problem at the next poll, so devices can send traps (unsolicited alerts, UDP 162), such as a CRC error threshold, which can trigger tickets or scripts. Poll results over time become graphs of utilization and errors.

Logs and Monitoring

  • NetFlow: summary statistics of traffic flows (who talked to whom, ports, bytes). A probe (inline tap or switch SPAN/mirror port) summarizes packets and exports to a collector with reports: top conversations, top endpoints, top applications by port.
  • Protocol analyzer (Wireshark etc.): see raw frames, wired or wireless, with drill-down. Some places store full packet captures long term.
  • Baseline: what "normal" looks like (utilization, per device). Compare current numbers to the baseline to decide if something is wrong.
  • Syslog (UDP 514) forwards logs from any device to a SIEM (security information and event manager), which records the sending device, facility (originating program) and severity of each message. Dashboards and alerts show failed logins, devices going offline, and reports across time. Tune the severity captured so you do not store everything. Example query: records containing "fail" and "password" reveal brute force or spraying and support forensics.
  • API integration: manage hundreds of devices by script (send commands, query config) rather than logging in by hand to each.
  • Port mirroring (SPAN) or a network tap copies traffic to a monitoring device (IDS/IPS, NetFlow collector), even across switches.

Network Solutions

  • Discovery: LLDP (open standard link layer discovery) and CDP (Cisco discovery protocol) show neighbors. Ping scans, port scans and SNMP discover hosts. Nightly scans give an inventory.
  • Traffic analysis: firewall logs list timestamp, protocol, ports, client and server IP, application and bytes, useful for reports and forensics.
  • Performance (utilization, errors) from SNMP, NetFlow, protocol analysis or agents. Availability monitoring: up/down status (green/red) with alerts, tickets and uptime reports.
  • Configuration monitoring: back up and restore device configs (a config may need matching firmware, so keep the old software), compare identical devices, alert on unapproved changes via change control.

flashcards

self-check

1. You want an alert the instant a router's CRC errors spike, without waiting for polling. Which?

  • a) SNMP trap
  • b) MIB walk
  • c) NetFlow report
  • d) LLDP
answer

a) Traps are device-initiated notifications.

2. Which tool tells you which apps use the most bandwidth by port, summarized?

  • a) Wireshark
  • b) NetFlow
  • c) CDP
  • d) TFTP
answer

b) Flow summaries rank applications and endpoints.

short lab: Find the brute force

Your SIEM shows 4,000 "failed password" events for user admin from one external IP between 02:00 and 02:10. What do you do?

walkthrough

Brute force. Check the source IP reputation and geolocation, verify no success after the failures, block the IP, lock or monitor the account, enforce MFA and account lockout, and add an alert rule for repeated failures in a short window.
