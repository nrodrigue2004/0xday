3.4 IP Services

study notes

DHCP

  • History: manual config, then BOOTP, then DHCP. The four-step DORA exchange: Discover (client, source 0.0.0.0, broadcast to 255.255.255.255, UDP 68 to 67), Offer (server, broadcast, UDP 67 to 68), Request (client picks one offer, broadcast), Acknowledge (server confirms, client applies the settings). Everything is broadcast because the client has no IP yet.
  • Broadcasts do not cross routers, so central DHCP servers use a DHCP relay / helper on the router. The relay turns the broadcast into a unicast to the DHCP server (source becomes the router's interface IP) and turns the reply back into a broadcast on the client subnet.

Configuring DHCP

  • A scope (per subnet): the address pool/range, exclusions, subnet mask, lease duration and options (DNS servers, default gateway, VoIP call server). Servers remember MAC-to-IP pairings and will often give you the same address back.
  • Reservation (static DHCP, IP reservation): bind a MAC address to a fixed IP in the server, so printers and servers always get the same address and are still managed centrally.
  • Lease timers: T1 = 50 percent of the lease: client tries to renew with the original server. T2 = 87.5 percent (7/8): if that failed, the client rebinds with any DHCP server. Example, 8-day lease: T1 at 4 days, T2 at 7 days. Clients release their address on shutdown.
  • DHCP options: numbered fields (up to 254) for extra settings, for example option 129 call server IP, option 135 HTTP proxy. The server must support the option.

IPv6 and SLAAC

  • DHCPv6 exists, but IPv6 hosts can also self-configure (stateless, no leases, no server). NDP (neighbor discovery protocol) replaces ARP and uses multicast, not broadcast. SLAAC steps: host sends a router solicitation (RS), router answers with a router advertisement (RA) (the 64-bit prefix, prefix length, DNS and other parameters; routers also send unsolicited RAs). The host builds the last 64 bits (interface ID) from its MAC address (modified EUI-64: insert ff:fe in the middle) or randomizes it. Duplicate address detection (DAD) checks nobody else uses it. Result: a unique, routable address.

An Overview of DNS

  • DNS translates names to IPs. Hierarchy: root (., 13 server clusters, over 1,000 servers), TLDs (.com, .org, .net, country codes like .us .uk), domains, hosts. A full name is an FQDN (www.example.com). Use redundant servers: primary (holds the editable zone) and secondary (read-only copy).
  • Local resolution: the hosts file (Windows: C:\Windows\System32\drivers\etc\hosts, usually needs write permission changed) overrides DNS for testing or fixes. Some apps ignore it.
  • Forward lookup: name to IP (dig www.example.com, nslookup). Reverse lookup: IP to name (dig -x 1.2.3.4). The reverse name can differ from the forward name (for example a CDN's name).
  • Authoritative server = owns the zone. Non-authoritative = answered from a cache or secondary copy. TTL (seconds) controls how long caches keep an answer (300 = 5 minutes).
  • Recursive resolution: the client (resolver) asks its local DNS server, which asks a root server (points to the .com servers), then the TLD server (points to the domain's name server), then the authoritative server (gives the IP), caches it and answers the client.
  • Security: DNS is clear text and unauthenticated. DNSSEC digitally signs responses (authenticity and integrity, not secrecy). DNS over TLS (DoT) encrypts on TCP 853. DNS over HTTPS (DoH) encrypts inside HTTPS on TCP 443 (looks like web traffic, many browsers use it by default).

DNS Records

  • SOA start of authority (zone info, serial, refresh/retry/expire). A hostname to IPv4. AAAA (quad-A) hostname to IPv6. CNAME alias to another name (needs a second lookup). MX mail exchanger for the domain (points at a name that needs an A record). TXT free text, used for SPF (which servers may send mail for you) and DKIM (public key to verify mail signatures). NS the domain's name servers. PTR reverse lookup (IP to name, stored in a reverse zone such as 23.168.192.in-addr.arpa).

Time Protocols

  • NTP (UDP 123): clients sync to servers; accurate to milliseconds (about 10 ms from a local server). Servers do not set their own time, a client component syncs them upstream. Many orgs run an internal NTP server. Critical for log correlation, and Kerberos fails if clocks differ by more than 5 minutes (feeding wrong time is a denial of service).
  • NTS (network time security) authenticates NTP: TLS handshake with an NTS key exchange server gets a cookie that the client includes in NTP requests. PTP (precision time protocol): hardware-based, nanosecond accuracy, for industrial uses.

flashcards

self-check

1. A client has an 8-day lease. When does it first try to renew?

  • a) 1 day
  • b) 4 days
  • c) 7 days
  • d) 8 days
answer

b) T1 is 50 percent of the lease.

2. Clients on a remote VLAN get 169.254.x.x though the DHCP server is on another subnet. Likely missing piece?

  • a) NAT
  • b) DHCP relay on the router
  • c) PTR record
  • d) RPO
answer

b) Broadcasts need a relay to reach the remote server.

3. Users reach the old IP of a site for 10 minutes after a DNS change. Cause?

  • a) NTP
  • b) TTL caching of the old record
  • c) DNSSEC
  • d) SLAAC
answer

b) Resolvers keep the answer until TTL expires.

short lab: Dig it

Interpret dig www.example.com: answer section shows www.example.com. 300 IN A 93.184.216.34. What do 300, IN, A mean and when will other resolvers see a change?

walkthrough

300 = TTL seconds, IN = Internet class, A = IPv4 address record. Caches may keep the old value for up to 5 minutes, so a change propagates within about that time.
