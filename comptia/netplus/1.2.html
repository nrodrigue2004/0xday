1.2 Network Appliances and Applications

study notes

Networking Devices

  • Router: layer 3, moves traffic between IP subnets (rooms apart or continents apart), joins LANs to WANs, over copper or fiber. A layer 3 switch adds routing inside a switch chassis.
  • Switch: layer 2, forwards on MAC address, mostly in hardware chips (ASIC). Enterprise switches add PoE (power over the Ethernet cable) and VLANs.
  • Firewall: filters by port; a next-generation firewall (NGFW) identifies the application itself and allows or blocks it. Firewalls commonly also do VPN termination, routing (sitting at the inside/outside edge) and NAT, and often speak dynamic routing protocols.
  • IDS vs IPS: both spot known attacks (exploits against OS and apps: buffer overflow, cross-site scripting and so on). IDS only alerts, IPS also blocks, so IPS is the usual choice inline. Much of this is now built into NGFWs.
  • Load balancer: spreads requests over a farm of servers so a site stays up. It notices a dead server and removes it from rotation. Extras: TCP offload, SSL/TLS offload (the balancer encrypts/decrypts instead of the servers), caching, QoS prioritizing and application-aware routing (certain pages to certain servers). Users see one address.
  • Proxy: sits in the middle and makes the request for the client, then checks the answer for malware before handing it back. Gives caching, authentication (login to reach the internet), URL and content filtering. Explicit proxies need client configuration, transparent proxies do not.
  • NAS vs SAN: NAS gives file-level access (move the whole file to change it, over a normal network share). SAN gives block-level access like a local disk (change only the modified blocks, efficient for huge files). Both usually sit on their own isolated, high-bandwidth network.
  • Access point (AP): wireless to wired bridge, a layer 2 device. Offices use many dedicated APs, not the home all-in-one "wireless router". A wireless LAN controller (WLC) centrally configures, monitors and updates all APs and handles roaming policy. Usually vendor-specific.

Networking Functions

  • CDN (content delivery network): copies of content cached at regional points so users fetch from nearby. Faster and spreads load. Video sites and most large sites use one.
  • VPN: encrypted tunnel across an untrusted network. The central endpoint is a VPN concentrator / head-end, usually dedicated hardware (high-speed crypto) or a feature of the NGFW. Small setups can use software concentrators and the VPN client built into Windows, macOS and Linux.
  • QoS (traffic shaping): give real-time voice and video priority over bulk file transfers. Configured on routers, switches and firewalls, often with built-in application lists.
  • TTL (time to live): a countdown that kills runaway things. In an IP packet, TTL counts hops: every router subtracts one and drops the packet at zero, which stops routing loops. Typical start values: 64 for Linux/macOS, 128 for Windows. A traceroute bouncing between the same two routers is a routing loop. In DNS, TTL is in seconds: how long a resolver may cache the answer (for example 300 s = 5 minutes), so changing a record takes about that long to spread. Caches use TTL the same way.

flashcards

self-check

1. A web farm of 6 servers must stay online when one crashes. Which device provides this?

  • a) Proxy
  • b) Load balancer
  • c) IDS
  • d) WLC
answer

b) Load balancers detect failures and route around them.

2. You changed an A record but some users still hit the old IP for up to an hour. What is the likely cause?

  • a) IP TTL
  • b) DNS TTL caching
  • c) Spanning tree
  • d) PoE budget
answer

b) Resolvers cache the old answer until its DNS TTL (seconds) expires.

short lab: Reason about a routing loop

A traceroute shows 10.1.10.1, 10.2.10.2, 10.1.10.1, 10.2.10.2 repeating. What is wrong, what stops it eventually, and where do you look?

walkthrough

A routing loop: each router thinks the other is the next hop (often one wrong static route). The IP TTL decrements at each hop and the packet is discarded at zero, so the loop is not infinite. Fix by checking the routing tables (show route) on both routers for the bad next hop.
