5.3 Troubleshooting Network Services

study notes

Switching Issues

  • Ethernet frames have no TTL, so a switching loop circulates forever and broadcast/multicast storms kill the network. Spanning Tree Protocol (STP) prevents them.
  • STP switches exchange BPDUs (MAC multicast, hello every 2 seconds). Missing three hellos = link down and the topology is recomputed. A root bridge is elected: lowest bridge ID wins (settable from 0 to 61,440 in steps; ties broken by lowest MAC). Others pick a root port toward the root; designated ports forward; blocked/discarding ports break loops. Port states: blocking/discarding, listening, learning, forwarding, disabled (admin). Failures unblock ports automatically.
  • VLAN issues: device has an IP but can't reach neighbors? Check the access port's VLAN ID on the switch.
  • ACLs: if routing and VLANs look right but packets disappear, check ACLs on the path. Like firewall rules: first match, specific entries first, implicit deny, so an empty ACL on an interface blocks everything. Be careful editing ACLs on the interface you are managing through (you can lock yourself out).

Routing and IP Issues

  • Check the routing table on every router along the path and the return path. No route = packet dropped, often with ICMP destination/host unreachable. Compare with a network map.
  • Gateway of last resort = default route, 0.0.0.0/0, usually static (ip route 0.0.0.0 0.0.0.0 10.10.50.2). Routing table sources: directly connected, static, learned (RIP, OSPF, etc.).
  • Address pool exhaustion: clients get APIPA 169.254.x.x (local only, nonroutable). Check the DHCP server or IPAM, enlarge the pool, shorten the lease on transient networks.
  • Incorrect IP, mask or gateway: verify with the admin, packet capture, or other devices. Test in order: ping self, ping gateway, ping beyond the gateway (and traceroute).
  • Duplicate IPs: static device inside a DHCP pool, overlapping scopes on two servers, or a rogue DHCP server. Modern OSes warn on conflict. Ping the address before assigning; if it answers, find it: ping, then ARP table for the MAC, then switch MAC table for the port. Capture DHCP offers to catch duplicate servers.

flashcards

self-check

1. Network comes to a halt after someone adds a second cable between two switches. Missing feature?

  • a) STP
  • b) DHCP relay
  • c) NTS
  • d) PoE
answer

a) A loop without STP floods the network.

2. A PC gets 169.254.12.7. Likely cause?

  • a) DNS cache
  • b) DHCP unavailable or pool exhausted
  • c) Wrong VLAN trunk
  • d) NTP drift
answer

b) APIPA means no DHCP lease.

3. Router 1 sends traffic to 10.3.10.0/24 but pings get "destination unreachable." What do you check?

  • a) Routing tables, in both directions
  • b) The hosts file
  • c) Port security
  • d) Cable category
answer

a) Missing route on the path or return.

short lab: Chase the conflict

Windows reports an IP conflict for 192.168.1.50. Write the commands to find the other device.

walkthrough

ping 192.168.1.50, then arp -a to read its MAC, then on the switch show mac address-table address <mac> to find the port. Remove or fix that device, then renew leases.
