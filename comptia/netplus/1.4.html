1.4 Ports and Protocols

study notes

Introduction to IP

  • Encapsulation picture: the network is the road, IP is the truck, TCP/UDP are the boxes, application data is inside. An Ethernet frame is header + IP packet + trailer; the IP packet is IP header + TCP/UDP segment; that holds the application data.
  • TCP: connection-oriented (formal setup and teardown), acknowledgments and numbered segments so lost data is resent and only the lost part, plus flow control (the receiver can tell the sender to slow down). "Reliable".
  • UDP: connectionless, no setup, no acknowledgments, no retransmit, no flow control. "Unreliable" means no delivery guarantee, not that it fails more. Low overhead, good for real-time voice and video and simple queries.
  • Both layer 4 protocols do multiplexing: many apps share one IP pair, told apart by port numbers (the "room in the house").
  • A socket = IP address + protocol + port. Server side uses a fixed port, client side a random one. Replies simply swap source and destination.
  • Well-known (non-ephemeral) ports are 0 to 1023. Ephemeral client ports are 1024 to 65535. Not a hard rule. Range overall: 0 to 65535.
  • TCP port 80 and UDP port 80 are different things. Changing a port is not security, you still need a firewall. If a server moves off the default port, clients must be told.

Other Useful Protocols

  • ICMP: its own IP protocol (not TCP/UDP). Used by ping, and for messages such as "destination unreachable" and "time exceeded" (TTL hit zero).
  • GRE: tunnels packets inside IP, but no encryption. Pair with a VPN protocol.
  • IPsec: standard encrypted tunnel, vendor-neutral. Gives confidentiality, packet signatures (integrity) and anti-replay. Parts: AH (authentication/integrity only, data in clear) and ESP (encrypts and authenticates, the usual choice). IKE sets up the security association (SA): phase 1 uses Diffie-Hellman over ISAKMP, UDP 500 to agree a shared secret, phase 2 negotiates the ciphers and key sizes for each direction. Transport mode encrypts only the payload and leaves the original IP header visible. Tunnel mode encrypts the whole original packet and adds a new IP header, which is what site-to-site VPNs use.

Network Communication

  • Unicast: one to one (web, email, file transfer). Multicast: one to a subscribed group, efficient for video, market feeds, routing updates, needs multicast-aware gear and stays inside a network. Anycast: one to the nearest of many identical hosts (for example anycast DNS). Broadcast: one to everyone in the local broadcast domain (ARP, some routing). IPv6 has no broadcast; it uses multicast.

flashcards

self-check

1. An admin sends router logs to a central collector. Which port by default?

  • a) UDP 161
  • b) UDP 514
  • c) TCP 389
  • d) UDP 123
answer

b) Syslog uses UDP 514.

2. Which is true about IPsec tunnel mode?

  • a) Original IP header stays visible
  • b) Entire original packet is encrypted and a new IP header is added
  • c) Only AH is allowed
  • d) It uses TCP 22
answer

b) That is why it is used for site-to-site VPNs.

3. A switch pings 8.8.8.8 and gets "TTL expired in transit". Which protocol reported that?

  • a) TCP
  • b) ICMP
  • c) SNMP
  • d) GRE
answer

b) ICMP time exceeded.

short lab: Name that port

In a capture you see: UDP 53, TCP 3389, UDP 123, TCP 445, UDP 162, TCP 636. Name each protocol and what it tells you about the traffic.

walkthrough

DNS lookups, RDP remote desktop session (Windows), NTP time sync, SMB file share/Windows file access, SNMP trap from a device, secure LDAP directory queries. Together: a Windows host doing remote desktop, name lookups and file access, with a monitored device sending traps.
