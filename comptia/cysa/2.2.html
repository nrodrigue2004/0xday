CS0-004domain 2.0 · Vulnerability Management2.2

2.2 Given a scenario, analyze output from vulnerability assessment tools

study notes

Tools and their lane

  • Network scanning: Angry IP Scanner (simple GUI sweep), Masscan (internet-scale, very fast port scanner).
  • Multipurpose: Nmap (hosts, ports, services, OS, scripts via NSE), Metasploit (exploit framework used to validate), Maltego (link-analysis OSINT graphs), Recon-ng (modular OSINT framework).
  • Web app scanners: Burp Suite (intercepting proxy), ZAP (free proxy and scanner), Nikto (quick web server checks).
  • Vulnerability scanners: Nessus, OpenVAS (open source), Nuclei (template-based, fast, great for specific CVEs).
  • Cloud: ScoutSuite and Prowler audit cloud accounts for misconfigurations, Trivy scans container images and IaC, Checkov scans IaC (Terraform etc.) before deployment.
  • Breach and attack simulation: Atomic Red Team (small tests mapped to ATT&CK), Caldera (automated adversary emulation). They test whether your detections work.

Reading output

  • Nmap states: open, closed (reachable, nothing listening), filtered (firewall dropped it). -sV versions, -sC default scripts, -O OS guess, -p- all ports, -sS SYN scan.
  • A finding has: title/plugin, CVE, severity (CVSS), host/port, evidence, solution. Validate: read the evidence, check the version and whether the vulnerable feature is on, then confirm with a second tool or manual test.
  • Beware: banner says Apache 2.4.49 but a distro back-patched it (false positive), or a scan with no credentials missed a missing patch (false negative).

answer

2. Nmap shows port 443 "open" and 8443 "filtered". What do you infer about 8443?

  • a) A service is listening and responding
  • b) Something is blocking probes, state unknown
  • c) Port is closed with RST
  • d) UDP only
answer

b) Filtered means no definitive answer due to filtering.

short lab: Triage a scan finding

A scanner reports "Apache 2.4.49 path traversal (CVE-2021-41773), critical" on a Debian host. apache2 -v shows 2.4.49-1+deb10u1 patched build. Real or false positive?

walkthrough

Likely false positive: the distro maintains security fixes via package revisions without changing the upstream version string. Confirm with the vendor security tracker/changelog (apt changelog apache2) and a safe proof-of-concept request. Document and mark as a false positive so it stops resurfacing.
