study --objective 1.2 --exam CS0-004

CS0-004domain 1.0 · Security Operations1.2

1.2 Given a scenario, analyze indicators of potential malicious activity

study notes

The job here is pattern recognition: a single odd event is noise, several in a chain are an incident.

Network indicators

  • Rogue devices: unknown MACs, a rogue AP or DHCP server. Compare against the asset inventory.
  • Enumeration: many connection attempts across hosts or ports in a short time (port scans, ping sweeps, SMB or LDAP queries from a workstation).
  • Anomalous activity: beaconing (fixed-interval small callbacks, often with jitter), large outbound transfers, DNS with long random subdomains (tunneling or DGA), traffic at 3 a.m., unusual protocols.
  • Unexpected ports: HTTP on 4444, SSH on 443, high ports to external hosts. Reverse shells often use common ports to slip through.

Host indicators

  • Resource consumption: sustained CPU and GPU use (cryptominer), disk churn (ransomware encrypting), memory spikes.
  • Unauthorized software and unauthorized configuration changes: new services, scheduled tasks, run keys, disabled AV, edited hosts file, new local admin.
  • Suspicious or rogue processes: odd parent-child pairs (Office spawning PowerShell, cmd under a browser).
  • LOLBins: legitimate tools abused so nothing "malicious" is dropped: certutil -urlcache, mshta, rundll32, regsvr32, bitsadmin, PowerShell with -enc, wmic. Detection is behavioral, so hunt the command line.
  • File system changes: new executables in temp or AppData, mass renames, changed extensions, deleted shadow copies (vssadmin delete shadows).
  • Data exfiltration: archives staged then sent out, big uploads to cloud storage, DNS or ICMP tunneling.

Application and cloud

  • Application: service disruption, spikes of 500s, injection strings in logs (' OR 1=1, ../../), new admin users, unusual API calls.
  • Cloud: new access keys, resources created in odd regions (mining), public buckets, disabled logging, privilege escalation in IAM, API calls from unfamiliar IPs.

Social engineering and identity

  • Typosquatting (rnicrosoft.com), URL shorteners that hide the target, lookalike Unicode domains.
  • Impossible travel: logins from two far-apart places faster than a plane could go. Verify first: VPNs and mobile carriers cause false positives.
  • Other identity tells: MFA fatigue (burst of push prompts), new inbox rules forwarding mail, logins at odd hours, many failures then a success (spray or brute force), service accounts logging in interactively.
  • BEC: attacker (or a lookalike domain) impersonates an exec or vendor to redirect payments. Look for reply-to mismatch, changed bank details, urgency, inbox rules that hide replies.

flashcards

self-check

1. An HR laptop shows winword.exe launching powershell.exe -enc JAB... . Most likely?

  • a) Normal macro-free document
  • b) Malicious macro executing an encoded payload
  • c) Windows update
  • d) Printer driver install
answer

b) Office spawning an encoded PowerShell command is a textbook malicious-document pattern.

2. A user signs in from Chicago, and 20 minutes later from Singapore. First step?

  • a) Reset the whole domain
  • b) Verify for VPN/proxy, check device and MFA details, then contain if unexplained
  • c) Ignore it
  • d) Block all of Singapore forever
answer

b) Confirm before disruptive action, but treat as a likely account compromise if nothing explains it.

short lab: Read a suspicious command

Decode and judge: powershell.exe -nop -w hidden -enc SQBFAFgAIAAoAE4AZQB3AC0ATwBiAGoAZQBjAHQA... The flags: -nop skips the profile, -w hidden hides the window, -enc takes base64 UTF-16LE. In your own words, what do those flags tell you before you decode a single byte? Then decode this beginning in a shell: echo 'SQBFAFgA' | base64 -d | iconv -f UTF-16LE.

walkthrough

Hidden window plus encoded command is rarely administrator behavior, so treat as hostile until proven otherwise. The decoded fragment is IEX, the invoke-expression cradle that normally precedes a download-and-run (IEX (New-Object Net.WebClient).DownloadString(...)). Next steps: get the full command, extract the URL, block it, find the parent process and scope other hosts that ran the same command line.
