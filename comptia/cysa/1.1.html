1.1 Explain concepts related to system and network architecture in security operations

study notes

An analyst can only investigate what was logged, so architecture questions are mostly "where does the evidence come from and can I trust it".

Logging

  • Ingestion: agents, syslog forwarders or API pulls ship logs to a central store (a SIEM). Normalize fields (timestamp, host, user, src/dst IP) or correlation breaks.
  • Time sync: every device syncs to NTP. Two hosts five minutes apart make a timeline impossible and can wreck Kerberos too. Store in UTC.
  • Integrity and security: send logs off the box immediately, over TLS, write-once if possible. An attacker with admin deletes local logs first (Windows event 1102 means the Security log was cleared).
  • Retention: set by compliance and by dwell time. Intrusions often sit unnoticed for months, so hot storage for weeks and cold storage for a year or more is common.

Operating system

  • Hardening: remove unused services and software, patch, least privilege, disable default accounts, host firewall, secure baselines (CIS).
  • Critical files: Windows has the registry hives, SAM, System32, startup folders and Windows\Temp. Linux has /etc/passwd, /etc/shadow, /etc/sudoers, /var/log, cron entries and ~/.ssh/authorized_keys. Know what normal looks like so deviations stand out.
  • System processes: lsass.exe, svchost.exe, services.exe and explorer.exe are common impersonation targets. Wrong parent process, wrong path or a misspelling (svch0st) are classic tells.

Infrastructure

  • Cloud native: services built for the cloud. Evidence lives in provider logs (CloudTrail, Azure Activity, VPC flow logs) and you cannot image a managed service.
  • Virtualization: many VMs per host. Snapshots help forensics. VM escape is the rare worst case.
  • Containerization: short-lived, so logs and artifacts vanish when the container does. Ship logs out, scan images, avoid privileged containers.
  • APIs: the glue between tools and a major attack surface. Authenticate, rate-limit, log, and keep keys out of code.

Devices and networks

  • Mobile and endpoint management (MDM/UEM, EDR) lets you enforce policy, wipe lost devices and collect telemetry.
  • ZTNA: no implicit trust from network location, verify each request on identity, device health and context.
  • SASE: network and security services (SWG, CASB, ZTNA, firewall-as-a-service) delivered from the cloud edge for remote users and branches.
  • Hybrid cloud: on-prem plus cloud means two sets of logs and identity to stitch together.

Identity and data

  • PAM: vault admin credentials, check them out per session, record the session, rotate afterwards. Secrets management keeps API keys and passwords in a vault, not in repos.
  • AuthN vs AuthZ: MFA, SSO with SAML/OIDC, OAuth for delegated access, Kerberos in AD.
  • Encryption: AES at rest, TLS in transit, hashing with salt for passwords. Data protection: classification, DLP, masking, tokenization, backups.

Critical infrastructure

OT runs physical processes. ICS is the control system, SCADA supervises many remote sites. These favor availability and safety over confidentiality, run legacy protocols (Modbus, DNP3) with no authentication and cannot be patched casually. Segment them from IT, monitor passively, never active-scan a PLC carelessly.

flashcards

self-check

1. A server's clock is 7 minutes ahead of the rest of the network. What is the most direct security impact?

  • a) Certificates stop working
  • b) Event timelines across systems cannot be correlated reliably
  • c) Packets get dropped
  • d) Logs are encrypted twice
answer

b) Correlation relies on consistent time. (Kerberos also has a skew limit, but the analyst-facing issue is the timeline.)

2. Where should you send logs so an intruder with local admin cannot erase them?

  • a) A second folder on the same disk
  • b) The same server's backup
  • c) A remote, access-controlled log collector
  • d) The user's laptop
answer

c) Off-host, restricted storage preserves integrity.

short lab: Spot the impostor process

A process list shows svchost.exe running from C:\Users\Public\svchost.exe, parent winword.exe. Another shows svchost.exe from C:\Windows\System32\ with parent services.exe. Which is suspicious and what are the three tells? What would you collect next?

walkthrough

The first one. Tells: wrong path (Users\Public instead of System32), wrong parent (an Office app should never spawn it), and it's a well-known name used for camouflage. Next: grab the hash, check it on VirusTotal, pull the Word document and macro, look at network connections from that PID, and isolate the host through EDR.
