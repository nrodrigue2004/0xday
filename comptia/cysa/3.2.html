3.2 Summarize the incident response process

study notes

The phases in order:

  1. Preparation: plan, team, tools, contacts, logging, backups, training. Nothing else works without it.
  2. Detection: alerts, user reports, threat intel.
  3. Analysis: confirm it's real, scope, severity, what systems and data, timeline.
  4. Containment: stop the spread. Short-term (isolate host, disable account, block IP) then long-term (rebuild segments, temporary fixes). Preserve evidence first when you can, and weigh business impact.
  5. Eradication: remove the cause: malware, persistence, bad accounts, patch the hole, reset credentials.
  6. Recovery: restore from clean backups, rebuild, monitor closely, return to production in stages.
  7. Post-incident: lessons learned meeting, after-action report, update plans and detections.

Traps: pulling the plug on a running host loses memory evidence. Eradicating before scoping tips off the attacker and misses persistence. Recovering before eradication re-infects. Order of volatility for evidence: CPU registers/cache, RAM, network state and processes, disk, remote logs, backups.

flashcards

self-check

1. Ransomware spreading across file shares. What is the first priority?

  • a) Write the report
  • b) Containment: isolate affected hosts and shares
  • c) Pay the ransom
  • d) Reimage everything
answer

b) Stop spread before cleanup.

2. Which step comes immediately after eradication?

  • a) Detection
  • b) Recovery
  • c) Preparation
  • d) Analysis
answer

b) Restore operations once the threat is removed.

short lab: Order the steps

Shuffle fixed: reset passwords, isolate host, collect memory, scope via logs, restore backup, review at lessons-learned meeting. Put them in IR order with the phase names.

walkthrough

Scope via logs (analysis) → collect memory (analysis/containment prep) → isolate host (containment) → reset passwords (eradication) → restore backup (recovery) → lessons learned (post-incident).
