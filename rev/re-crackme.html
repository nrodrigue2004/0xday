MAL300 Reverse engineering and malware (extra labs)

Reverse engineering is turning assembly back into the idea behind it. Read a small license-check function line by line, write its logic in Python, and recover the password. Practice for crackmes, CTF reversing and reading malware routines.

1simple2mid3complex4hands-on+ref

01 simple // the idea in plain words

A crackme is a small program written to be reverse engineered: it asks for a password, and your job is to find out what it wants by reading its code, not by guessing. The skill is exactly what you use on malware: read a function and say what it *does* in plain language.

A method that works every time:

  1. Find the decision. Look for the message or the jump that separates success from failure (cmp then je/jne)
  2. Work backward from that jump: what value is being compared, and where did it come from?
  3. Name things. Write i for the counter, len for the length, ok for the result. Names make the pattern visible
  4. Translate to a few lines of Python or C. Once it is in a language you read fluently, the answer is usually obvious
  5. Test your answer by running the program
cmp ecx, 8       ; is the counter 8?
jne .fail        ; if not equal, go to the failure label

That pair reads as if (len != 8) fail;. Learn the handful of patterns (compare-and-jump, loop with a counter, a byte-by-byte comparison against a table) and most check functions are quick.

02 mid // how it's actually used

Reading x86 you meet in checks

PatternMeaning
xor ecx, ecxi = 0 (xor with itself zeroes a register)
cmp byte [rsi+rcx], 0 / jeis s[i] == 0 (end of string)? this is strlen
movzx eax, byte [rdi+rcx]eax = s[i] (load one byte)
xor al, 0x5aal ^= 0x5a, a one-byte XOR with a key
inc ecx / cmp ecx, 8 / jli++; if (i < 8) loop again
mov eax, 1 then retreturn 1 (success); xor eax, eax returns 0

The return value of a function is in eax/rax. A check function usually returns 1 for "good" and 0 for "bad"; the caller tests it and picks which message to print.

Reconstructing the C

int check(const char *s) {
    if (strlen(s) != 8) return 0;
    for (int i = 0; i < 8; i++)
        if ((s[i] ^ 0x5a) != enc[i]) return 0;
    return 1;
}

The password is whatever makes every s[i] ^ 0x5a equal the stored byte. XOR is its own inverse, so s[i] = enc[i] ^ 0x5a. In the lab, compute it with python3 -c.

When it is not an XOR

The same shape handles add/sub (reverse with the opposite), rol/ror (rotate the other way), a lookup table (invert the table) and a running checksum (solve for the last byte). If the transform cannot be inverted (a real hash), you stop reversing and search: a wordlist, or constraint solving (angr, Z3).

Static vs dynamic

You can read the listing, or run the program under gdb, break at the cmp, and look at the register that holds the "expected" value. Doing both catches mistakes: the disassembly says what *should* happen and the debugger shows what *does*.

03 complex // what the pros do

Tooling for scale

  • Ghidra / IDA decompiler gives you C-like pseudocode at once; the habit is to verify it against the disassembly for the one function that matters. Decompilers get loops, integer sizes and signedness wrong sometimes
  • Z3 / angr: describe the constraints (all (s[i] ^ 0x5a) == enc[i], length 8, printable) and let a solver find an input. Essential when the check is a tangle of arithmetic, useless against a crypto hash
  • Patching instead of solving: change the jne to je (or nop it). Fine for a crackme; in malware it is how you force a code path (see patching anti-VM checks)
  • Binary diffing (Ghidra's Version Tracking, BinDiff): compare a patched and an unpatched binary to find what a security update fixed, the starting point of "patch diffing" for n-day analysis

Calling conventions and arguments

On 64-bit Linux the first arguments arrive in rdi, rsi, rdx, rcx, r8, r9; on 64-bit Windows in rcx, rdx, r8, r9. Reading which register holds a pointer to your input is the first thing to establish in any function. On 32-bit x86 the arguments are on the stack. See C and x86 assembly.

What malware does with the same shape

String decryption routines are this loop: for i in range(len): out[i] = in[i] ^ key. Config extractors, API-hash resolvers and C2 protocol encoders are the same idea with different arithmetic. Once you can read this function you can write a decoder script and extract the strings from every sample of the family, which feeds YARA rules and IOC lists. See the XOR lab in malware analysis.

Ethics and legality

Reverse engineering software you own or a crackme for practice is fine. Breaking license checks on commercial software to avoid paying, or analyzing code you were told not to, is a legal problem (DMCA, EULA and contract terms). Do research on your own copies and in an isolated VM.
