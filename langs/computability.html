CS301 Theory of computation (optional)

Optional and light. Context-free grammars add a stack to automata, Turing machines add an unbounded tape, and some questions no program can ever answer. Learn the map of what computers can and cannot do, and why "P vs NP" matters for passwords and crypto.

01 simple // the idea in plain words

Machines come in strengths. Each step up can recognize more:

  1. Finite automaton: fixed memory. Recognizes regular languages (what a regex can do). Cannot count.
  2. Pushdown automaton: a finite automaton plus a stack. Recognizes context-free languages: nested structure like balanced parentheses and the grammar of programming languages.
  3. Turing machine: a finite controller plus an unbounded tape it can read, write and move along. Anything a real computer can compute, a Turing machine can too (and the reverse, given enough memory). This is the formal definition of "computable".

The stack is what lets the second machine check ((())): push on (, pop on ), and the string is balanced if the stack is empty at the end. A finite automaton cannot do this, because it would need a different state for every nesting depth.

def balanced(s):
    stack = []
    for ch in s:
        if ch == "(":
            stack.append(ch)
        elif ch == ")":
            if not stack:
                return False
            stack.pop()
    return not stack

Programming languages are context-free (mostly). That is why a parser needs recursion, and why a regex alone cannot parse code.

02 mid // how it's actually used

Context-free grammars

A grammar with rules like S := "(" S ")" S | "" generates exactly the balanced strings. Each rule rewrites one symbol into others, no matter the neighbors (context-free). Compilers use them for syntax (see grammars and the parser).

Decidable and undecidable

A problem is decidable if some program always halts with the right yes/no answer. Many are: "is this string in the language of this regex?", "does this bracket string balance?". Some are provably not:

  • The halting problem: no program can look at any program and its input and always correctly say whether it finishes. Turing proved this in 1936 by contradiction: assume such a checker H exists, build a program D that asks H about itself and does the opposite
  • Rice's theorem: any interesting question about what a program *does* (does it ever write the file? is it malware?) is undecidable in general

What that means for security

A perfect malware detector that never errs on any program cannot exist. Antivirus and static analysis are therefore heuristics: they accept false positives or false negatives. This is why defenders layer signatures, behavior monitoring, sandboxes and humans, and why an attacker can always keep changing the program until it slips past one fixed check.

Complexity: P and NP

  • P: problems solvable in polynomial time (sorting, shortest path)
  • NP: problems where a proposed answer can be *checked* in polynomial time (factoring a number, a Sudoku, subset sum)
  • NP-complete: the hardest in NP; if one had a fast solution, all would
  • The open question: does P = NP? Almost everyone thinks not. The security consequence: we depend on problems believed hard (factoring for RSA, discrete logarithm for Diffie-Hellman and ECC)

03 complex // what the pros do

Turing machines in a paragraph

A Turing machine has a tape of cells, a head, a finite set of states and a table: "in state q reading symbol a: write b, move left or right, go to state q'". Despite being tiny, with enough tape it can run any algorithm. The Church-Turing thesis says that is what "algorithm" means. A universal Turing machine reads a description of another machine from the tape and runs it, which is a stored-program computer, a CPU running software, in 1936.

Reductions

To show problem B is hard, show that a solver for B would let you solve a known-hard problem A (reduce A to B). It is how undecidability spreads ("if you could decide X you could decide halting") and how NP-completeness is proved. The mindset also helps in practice: a lot of security analysis problems (is this path feasible? does any input reach this sink?) are reductions to SAT or SMT, and symbolic execution and SAT/SMT solvers attack them anyway, because worst-case hard rarely means hard on real programs.

Hash cracking and the brute force wall

Recovering a password from a hash is a search problem with no known shortcut: the cost is the size of the search space. That is why length and randomness beat clever substitutions, and why a work factor in a password hash (bcrypt, Argon2) buys time. It is not an NP-hardness argument; it is an exponential search. See password cracking.

Quantum note

Shor's algorithm factors in polynomial time on a quantum computer, which would break RSA and elliptic curves (not "all of crypto"; symmetric keys and hashes are only weakened). That is the reason post-quantum standards exist.

Where to read more

Sipser's textbook is the standard; the first three chapters are this page done properly. For security-flavored computability, see the Rice's theorem sections of any program-analysis course. This chapter is optional on the way to a security job, and worth an evening for the vocabulary.
