CS310 Compilers

An interpreter walks the tree and does what each node says. Environments hold variables, a loop is a node that evaluates its body repeatedly. Finish the evaluator of a small calculator language and run a program in it.

1simple2mid3complex4hands-on+ref

01 simple // the idea in plain words

Once the parser has built a tree, an interpreter runs it. The idea is a single function that looks at a node and decides what to do:

  • a number node: the value is the number
  • an add node: evaluate the left child, evaluate the right child, add the results
  • a variable node: look the name up in a table of variables
  • an assignment node: evaluate the right side, store it under the name
  • a while node: while the condition is true, run the body

That table of variables is the environment. Evaluate from the leaves up and the whole program runs.

def evaluate(node, env):
    kind = node[0]
    if kind == "num":
        return node[1]
    if kind == "name":
        return env[node[1]]
    if kind == "bin":
        _, op, left, right = node
        a, b = evaluate(left, env), evaluate(right, env)
        return a + b if op == "+" else a * b      # (abridged)

This design is called an AST-walking interpreter. It is slow compared to compiled code, and it is the easiest one to write, read and sandbox. Most "little languages" in tools you use started as one.

02 mid // how it's actually used

Statements vs expressions

An expression produces a value (n * 2). A statement does something (total = total + n, print total, while ...). Statements run in order, and they change the environment. Assignment is the only way the environment changes in this language, which is why the evaluator takes env as a parameter and mutates it.

Environments

env here is a plain dict from name to value. Reading an unknown name is an error, and you should say so clearly: NameError: total is not defined. Real languages chain environments (a local dict whose parent is the enclosing one) to get scope and closures: a function value stores the environment where it was defined.

Short example: a while loop

if kind == "while":
    _, cond, body = node
    while evaluate(cond, env):      # re-evaluate the condition each time
        for stmt in body:
            evaluate(stmt, env)

The loop is just the host language's loop running over the tree. The interpreter's while is Python's while; that borrowing is why an interpreter is short, and why a language with no way to stop (a while 1) hangs the host unless you add a step limit.

Errors at run time

Division by zero, an undefined name, a wrong type: the interpreter raises an error that carries the node (and ideally the source line). Decide which errors are the language's and which are the host's; never let a stack trace from the host leak to a user of your language.

Adding features

Each new feature is a new node kind plus a few lines in the parser and the evaluator: if, comparison, print, functions (a node that stores parameters and a body, a call node that makes a new environment), lists. Try adding if after the lab.

03 complex // what the pros do

From tree-walker to bytecode

Walking a tree repeats a lot of dispatch work. A bytecode virtual machine compiles the tree once into a flat list of simple instructions (PUSH 3, ADD, STORE n, JUMP_IF_FALSE 12) and runs them in a loop over a stack. CPython, the JVM, .NET and Lua all work this way. You can see Python's with the dis module: import dis; dis.dis(f). The step from the VM to a JIT is compiling the hot bytecode to machine code.

Closures and calls

A function call evaluates the arguments, creates a new environment whose parent is the function's defining environment, binds the parameters, runs the body, and returns. Recursion works because each call gets its own environment; the host language's call stack holds them, which is also why deep recursion in your language can crash the host.

Sandboxing an interpreter

Running code you did not write (a rule language, a template, a plug-in script) means the interpreter decides what the code can reach. A good small interpreter is a security feature: no open, no import, no eval of host strings, a step counter to stop infinite loops, and a memory cap. Contrast this with eval() on a Python string, which hands the attacker the entire host language. Template engines that allow attribute walking ({{ ''.__class__.__mro__ }}) are server-side template injection: the "little language" was too powerful.

Malware and interpreters

Interpreted malware (PowerShell, JavaScript, VBA macros, Python) is source-level reverse engineering: obfuscation is string tricks and eval/Invoke-Expression, and deobfuscating often means writing a tiny evaluator for the obfuscator's constant-folding. Some packers ship a custom bytecode VM; analysing one means writing a disassembler for its instruction set, which is the exact skill in this chapter.

Where to go next

Work through the free book *Crafting Interpreters* (first half, in Python or Java). It builds the whole thing step by step. Then look at source to machine code to see what changes when the target is a CPU.
