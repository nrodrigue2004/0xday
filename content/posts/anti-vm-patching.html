Some malware won't run if it detects a virtual machine. That's a problem when a VM is exactly where you want to analyze it. In my malware analysis labs I ran into samples that used the old SIDT, SLDT and STR tricks.

How the checks work

These instructions return the locations of the CPU descriptor tables. On older hypervisors those locations differ from bare metal in predictable ways. The sample compares the result against a known value and quits if it looks virtual.

Patching

In IDA Pro and Ghidra I found the comparison after each check. Then I patched the conditional jump so the sample always takes the "real hardware" path.

; before
sidt  [esp+idtr]
cmp   byte ptr [esp+idtr+5], 0FFh
je    looks_like_vm
; after: je -> nop nop
