ERU was a team project for a software course in fall 2024: a social media app built to put curated, worthwhile posts where doomscrolling usually is. We built a Java backend, a TypeScript frontend and a MongoDB database, and got a working feed, uploads, comments and profiles by the deadline.

Architecture

React Native (Expo, web)  --HTTP/JSON-->  Spring Boot REST API  -->  MongoDB
  feed, upload, explore,                    accounts, posts,
  profile, settings, FAQ                    comments, likes
  • Frontend: TypeScript and React Native via Expo, run in the browser. Components for posts, comments, likes and a nav bar, with pages for the home feed, upload, explore, profile and settings.
  • Backend: Java 21 with Spring Boot, controllers per area (accounts, friends, and so on) and a centralized exception handler that returns consistent error models.
  • Data: MongoDB, wrapped in a single manager class so the rest of the code never touches the driver directly.

The API

GET   /account/{id}            profile
GET   /account/{id}/feed       one user's posts, newest first
GET   /account/feed            home feed, newest first
POST  /account/post            create a post (UUID assigned server-side)
POST  /post/{id}/like          like
POST  /post/{id}/comment       comment

New post IDs are random UUIDs, and the server re-rolls on the (astronomically unlikely) collision. The feed endpoint also fills in each post's author name and picture so the client doesn't need a second call.

On the frontend

The home feed loads posts, tracks which identifiers it has already seen so repeated fetches never duplicate a post, and falls back to defaults for missing captions or profile pictures instead of crashing on incomplete data.

What was unfinished (and honest about it)

  • No login or registration screen. We hardcoded one account ID, so profile pages show that user.
  • The Explore tab shows placeholder images; the recommendation algorithm never got built.
  • The front end talks to localhost addresses, so it's a dev setup and not a deployable one.

Lessons

  • Cutting scope early beats cutting features at the deadline. The unfinished list above is what scope creep looks like.
  • Never commit secrets. The repo's config file shipped with a database connection string. Credentials belong in environment variables or a secrets manager, and anything that has been committed has to be rotated, even if the repo is deleted later.
  • Typed models on both ends (Java classes, TypeScript interfaces) caught a lot of mismatches before runtime.
