:: simple
The shell lets you chain small tools: each does one job and passes its output to the next with a pipe (`|`). Most log questions are the same four stages:

- **Select** the rows you care about: `grep`
- **Extract** the field: `awk '{print $1}'` or `cut`
- **Count** how often each value appears: `sort | uniq -c`
- **Rank** them: `sort -rn | head`

```
$ cut -d' ' -f1 logs/access.log | sort | uniq -c | sort -rn | head -3
$ grep " 404 " logs/access.log | wc -l
```

> `uniq` only collapses neighbours, so it needs `sort` first. Forgetting that is the most common wrong answer from this pipeline.

### Reading it aloud
"Take column 1 of the log, sort it, count the duplicates, sort by count high to low, show the top 3." If you can say it, you can build it one stage at a time. Run the first stage alone, check the output, then add the next.
:: mid
### Fields and filters
```
$ awk '{print $1, $7}' logs/access.log | head -3
$ awk '$9 == 404 {print $1}' logs/access.log | sort | uniq -c | sort -rn | head
$ grep -c "curl/" logs/access.log
```

In a combined-format web log, `$1` is the client IP, `$7` the path, `$9` the HTTP status. `grep -c` counts matching lines, `-v` inverts a match, `-E` allows `a|b` alternatives.

### Distinct versus total
Counting requests per IP is one question. Counting **different paths** per IP is another, and it is the one that finds scanners: a person browses a few pages many times, a scanner hits many pages once. `sort -u` removes duplicate lines, so unique (ip, path) pairs come first:

```
$ awk '{print $1, $7}' logs/access.log | sort -u | cut -d' ' -f1 | sort | uniq -c | sort -rn | head -3
```

### Loops and scripts
```
for f in logs/*.log; do
  echo "$f: $(grep -c ' 404 ' "$f") not-found"
done
```

Put it in a file with `#!/usr/bin/env bash` on the first line, `chmod +x`, run with `./script.sh arg`. `$1` is the first argument, `$#` the count, `$(...)` captures output.
:: complex
### Write scripts that fail loudly
Start every non-trivial script with:

```code
#!/usr/bin/env bash
set -euo pipefail
```

- `-e` stops at the first failing command instead of ploughing on
- `-u` makes an unset variable an error (so `rm -rf "$DIR/"` with an empty `DIR` does not become `rm -rf /`)
- `-o pipefail` makes a pipeline fail if any stage failed, not just the last

Other habits that matter: **quote your variables** (`"$f"`), check arguments (`[ $# -eq 1 ] || { echo "usage: $0 <log>"; exit 2; }`), use `mktemp` instead of fixed `/tmp` names, and `trap 'rm -f "$tmp"' EXIT` to clean up.

### Automate it
- **cron:** `0 2 * * * /home/ops/bin/scan_report.sh /var/log/nginx/access.log > /var/log/scan_report.txt 2>&1` runs it at 02:00 and keeps the output. Cron has a tiny `PATH`, so use absolute paths.
- **systemd timers** are the modern alternative: they log to the journal and can retry
- **Exit codes:** `exit 1` when the report finds something, so a wrapper can alert
- **shellcheck** catches quoting and portability mistakes before they reach production
- **Know when to stop:** past about 50 lines, or once you need a real data structure, move to Python (see the Python chapter)

### Cost of a pipeline
`sort` is O(n log n), so `sort | uniq -c` is dominated by the sort, while a one-pass counter in a dictionary (what Python's `Counter` does) is O(n). For a few hundred megabytes of log either is fine. More reps in the [Bash dojo](../dojo/bash.html), and see [Big-O](../bigo.html) for the cost model.

### log pipelines
cut -d' ' -f1 file | first space-separated column
awk '{print $1, $7}' file | pick columns (IP and path in a web log)
awk '$9 == 404' file | filter on a column value
grep -c PATTERN file | count matching lines
grep -v PATTERN file | everything that does not match
sort | uniq -c | sort -rn | head | frequency table, top N
sort -u | unique lines only
wc -l file | count lines
while read -r line; do ...; done < file | loop over lines safely
for f in logs/*.log; do ...; done | loop over files
set -euo pipefail | stop on errors, unset variables, failed pipes
trap 'rm -f "$tmp"' EXIT | clean up however the script ends
crontab -e | edit scheduled jobs
shellcheck script.sh | lint a script
