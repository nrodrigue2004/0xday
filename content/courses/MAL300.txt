## 0
Q: Which x86-64 register is the stack pointer?
* RSP
- RAX
- RIP
- RBX
? RIP is the instruction pointer, RAX the usual return value register.

Q: What does the call instruction do?
* Pushes the return address and jumps to the target
- Compares two values
- Returns from a function
- Copies memory
? ret later pops that address.

Q: How is the 32-bit value 0x12345678 stored in memory on a little-endian CPU?
* 78 56 34 12
- 12 34 56 78
- 87 65 43 21
- 21 43 65 87
? The least significant byte sits at the lowest address.

Q: What does xor eax, eax do?
* Sets eax to zero
- Doubles eax
- Compares eax with itself and jumps
- Loads the address of eax
? Compilers use it because it is shorter than mov eax, 0.

## 1
Q: Which PE section normally holds executable code?
* .text
- .data
- .rsrc
- .reloc
? .data holds initialized globals and .rsrc holds resources.

Q: What does a PE's import table tell an analyst?
* Which library functions the program uses, hinting at its capabilities
- The author's name
- The compile date only
- The program's source code
? Imports like network or process-injection APIs raise questions.

Q: What does a section with very high entropy suggest?
* The data is packed or encrypted
- The file is empty
- The file is a text document
- The file is signed
? Packers hide the real code until runtime.

Q: Which two bytes begin the header of a PE file?
* MZ
- PE
- ELF
- PK
? "PE" appears later at the PE header offset, and ELF is Linux.

## 2
Q: What is the difference between static and dynamic analysis?
* Static examines the file without running it, dynamic runs it and observes
- Static runs it, dynamic does not
- Static is for Linux, dynamic for Windows
- They are the same
? Static is safer. Dynamic shows behavior the code hides.

Q: What does a decompiler such as Ghidra's produce?
* Pseudo-C approximating the original logic
- The exact original source
- A network capture
- A list of vulnerabilities
? Names and types are guesses until you rename and retype them.

Q: What does the strings tool help you find?
* Readable text in a binary, such as URLs, paths and messages
- Encrypted keys
- The CPU architecture
- Hidden processes
? A quick first look before opening a disassembler.

Q: What does a breakpoint do in a debugger?
* Pauses execution at a chosen address
- Deletes a function
- Hides a process
- Encrypts memory
? It lets you inspect registers and memory at that point.

## 3
Q: Where should unknown malware be run?
* In an isolated VM with a clean snapshot and no real network
- On your daily laptop
- On a USB stick
- On a work server
? Revert to the snapshot after every run.

Q: Which is a common Windows persistence mechanism?
* A Run registry key or scheduled task
- Lowering the screen brightness
- Editing the hosts banner
- Changing the wallpaper
? Autoruns shows most of these.

Q: What is a dropper?
* A program that delivers or installs another payload
- A tool that deletes malware
- A network scanner
- A kind of firewall
? Stage one often does little except fetch stage two.

Q: How might malware try to evade a sandbox?
* By checking for VM artifacts or sleeping until the analysis times out
- By turning off its own code
- By emailing the analyst
- By running faster
? Analysts patch the checks or speed up the clock.

## 4
Q: What is the most important safety rule for dynamic malware analysis?
* Run samples only in a disposable VM with a snapshot, no shared folders and a network that goes nowhere
- Run them on your laptop with antivirus on
- Run them as an administrator on your real network
- Upload every sample to a public sandbox
? Revert to the snapshot after every run.

Q: In a Procmon log a process writes a file, sets a Run registry value to that file and starts it. What is that behavior?
* Dropping a copy of itself and establishing persistence
- Normal Windows Update behavior
- A printer driver install
- Disk defragmentation
? Run keys start the program at every login.

Q: What does FakeNet-NG or INetSim give you?
* Fake internet services so the sample connects and you see what it asks for
- A faster internet connection
- Real DNS records
- Antivirus signatures
? Your analysis network should have no route to the real internet.

Q: A host contacts the same IP and port at a steady one-minute interval. What does that suggest?
* A beacon to a command-and-control server
- A backup job
- A DHCP lease renewal
- A screen saver
? Steady spacing is a tell; record the IP, port and domain as IOCs.

## 5
Q: Which sign suggests an executable is packed?
* Very high entropy in a section and almost no readable strings or imports
- Many readable strings
- A large import table
- A .txt extension
? Entropy above about 7 means compressed or encrypted data.

Q: What is the original entry point (OEP)?
* The first instruction of the real program, reached after the stub finishes unpacking
- The address of the packer's stub
- The start of the resource section
- The first import
? Break on the tail jump to find it.

Q: What does a tail jump look like in an unpack stub?
* A jmp that leaves the stub's section for the newly unpacked code, often right after popad
- A call to ExitProcess
- A loop back to the start
- A ret to the OS
? Jumps that stay inside the stub are just loops and padding.

Q: Is a packed executable always malicious?
* No; many legitimate installers and commercial programs are packed, so packing is a signal, not a verdict
- Yes, always
- Only if it is larger than 1 MB
- Only on Linux
? Combine it with behavior and other evidence.

## 6
Q: In a check function, what does xor ecx, ecx usually do?
* Sets the counter to zero
- Compares two strings
- Doubles the counter
- Calls a function
? Xor of a register with itself is a short way to zero it.

Q: A loop XORs each input byte with 0x5a and compares it to a stored byte. How do you recover the password?
* XOR each stored byte with 0x5a, because XOR is its own inverse
- Hash the stored bytes
- Add 0x5a to each stored byte
- Brute-force all of memory
? The same shape decrypts strings in a lot of malware.

Q: Where does a 64-bit Linux function receive its first argument?
* In the rdi register
- In rax
- In rsp
- In the heap
? Windows x64 uses rcx.

Q: Why verify decompiler output against the disassembly for a critical function?
* Decompilers can get loops, integer sizes and signedness wrong
- Decompilers never run
- Disassembly is always shorter
- It is required by law
? Use both views.
