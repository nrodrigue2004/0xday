## 0
Q: What can a finite automaton NOT do?
* Count to arbitrary depth, such as check that parentheses are balanced
- Check whether a string ends in .exe
- Match a fixed word
- Accept the empty string
? It has only a fixed number of states and no stack.

Q: How many languages does a regular expression describe, compared with finite automata?
* The same ones: regular languages
- Fewer, only fixed strings
- More, including balanced parentheses
- None
? Regexes and finite automata are equivalent in power.

Q: What is ReDoS?
* A regex whose backtracking takes exponential time on crafted input
- A remote code execution via regex
- A DNS attack
- A password reset flaw
? Automaton-based engines like RE2 avoid it.

Q: Why does Aho-Corasick suit intrusion detection?
* It finds many fixed patterns in one pass over the data
- It decrypts traffic
- It compresses packets
- It blocks IP addresses
? One automaton covers thousands of signatures.

## 1
Q: What does adding a stack to a finite automaton give you?
* A pushdown automaton, which recognizes context-free languages
- A Turing machine
- A faster regex
- A DFA
? A stack is enough to match nested structure.

Q: Which language is context-free but not regular?
* Balanced parentheses
- Strings ending in .exe
- The word root
- A fixed list of ports
? Counting nesting depth needs unbounded memory.

Q: Why are programming language grammars written as context-free grammars?
* They express nested structure and can be parsed efficiently
- They are shorter than regexes
- They never have errors
- They run on GPUs
? Parsers like recursive descent follow the grammar rules.

Q: What does it mean for a grammar to be ambiguous?
* Some string has more than one parse tree
- It has no start rule
- It is too long
- It contains numbers
? The dangling else is the classic example.

## 2
Q: What does the halting problem say?
* No program can correctly decide for every program and input whether it halts
- Every program halts eventually
- Loops cannot be analyzed
- Only C programs can loop forever
? Turing proved this in 1936.

Q: What does it imply for antivirus?
* A perfect detector for all malicious programs cannot exist, so detection is heuristic
- Antivirus is useless
- All malware can be found by signatures
- Malware cannot change
? Layered defense accepts false positives and false negatives.

Q: What does NP mean?
* A proposed answer can be checked in polynomial time
- No polynomial algorithm exists
- Not a problem
- Needs a password
? Factoring is easy to check and believed hard to do.

Q: Why do we depend on the hardness of problems like factoring?
* RSA and similar systems are secure only if no efficient algorithm exists to break them
- Because factoring is NP-complete
- Because computers cannot multiply
- Because primes are secret
? A quantum computer running Shor's algorithm would break this assumption.
