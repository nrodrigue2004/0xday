## 0
Q: After fork() succeeds, what does the call return in the child process?
* 0
- The parent's PID
- The child's own PID
- -1
? fork() returns 0 in the child and the child's PID in the parent, which is how one program tells the two copies apart. -1 means the fork failed.

Q: What does exec() do to the process that calls it?
* Replaces its program image with a new one, keeping the same PID
- Creates a new child process running the new program
- Pauses it until the new program exits
- Copies its address space to a new PID
? exec() loads a new program into the existing process. Shells run commands as fork() then exec() in the child.

Q: A process has exited but its parent has not yet called wait(). What is it?
* A zombie
- An orphan
- A daemon
- A thread group leader
? The kernel keeps the exit status in the process table until the parent collects it. An orphan is a live process whose parent died first.

Q: Which of these do threads in the same process share?
* The heap and open file descriptors
- The stack
- The CPU registers
- The program counter
? Each thread has its own stack, registers and program counter. Everything in the address space (heap, globals, code) and the file table is shared, which is why threads need locks.

Q: A running process asks to read from disk and has to wait. Which state does the scheduler move it to?
* Waiting (blocked)
- Ready
- Terminated
- New
? It cannot use the CPU until the I/O finishes, so it leaves the ready queue. When the I/O completes it goes to ready, not straight to running.

Q: How does user code ask the kernel to do something privileged, such as read a file?
* A system call, which traps into kernel mode
- A direct jump to a kernel address
- Editing the page tables
- Setting a bit in the status register
? The syscall instruction switches to kernel mode at a fixed entry point the kernel chose. User code can't jump into the kernel anywhere it likes.

Q: What does the OS save in the process control block during a context switch?
* The CPU registers, including the program counter, plus scheduling and memory info
- The whole contents of RAM
- Only the stack
- Only the open files
? The PCB holds what is needed to resume the process later. The memory itself stays where it is.

## 1
Q: Three jobs arrive together with CPU bursts of 24, 3 and 3 ms, in that order. What is the average waiting time under FCFS?
* 17 ms
- 3 ms
- 10 ms
- 5.7 ms
? Waits are 0, 24 and 27, which sum to 51; 51 / 3 = 17. The two short jobs sit behind the long one.

Q: Same three jobs (24, 3, 3 ms). What is the average waiting time under shortest-job-first?
* 3 ms
- 17 ms
- 6 ms
- 9 ms
? Order 3, 3, 24 gives waits of 0, 3 and 6, which sum to 9; 9 / 3 = 3.

Q: Short jobs stuck behind one long CPU-bound job is called what?
* The convoy effect
- Thrashing
- Priority inversion
- Belady's anomaly
? FCFS suffers from it. Preemptive or shortest-first policies reduce it.

Q: What is the main problem with pure shortest-job-first or strict priority scheduling?
* Starvation of long or low-priority jobs
- Too many context switches
- It needs hardware support
- It cannot run more than one process
? A steady stream of short or high-priority work can keep a job waiting forever. Aging, which slowly raises a waiting job's priority, fixes it.

Q: A round-robin quantum is set far larger than any job's burst. How does the scheduler behave?
* Like FCFS
- Like shortest-job-first
- Like a priority scheduler
- It stops scheduling
? Nobody ever gets preempted, so jobs just run in arrival order. A tiny quantum has the opposite problem: most time goes to context switches.

Q: What is turnaround time?
* Completion time minus arrival time
- Completion time minus burst time
- First run time minus arrival time
- Time spent running on the CPU
? Waiting time is turnaround minus burst. Response time is first run minus arrival.

Q: Which policy gives interactive jobs good response time without knowing job lengths in advance?
* Multilevel feedback queue
- Shortest-job-first
- FCFS
- Longest-job-first
? MLFQ starts jobs at high priority and demotes those that use their whole quantum, so short and I/O-bound jobs stay near the top. SJF needs burst lengths known ahead of time.

## 2
Q: A system uses 32-bit virtual addresses and 4 KiB pages. How many bits are the page offset?
* 12
- 20
- 10
- 32
? 4 KiB is 2^12 bytes, so the low 12 bits pick a byte within the page. The remaining 20 bits are the virtual page number.

Q: With the same 32-bit addresses and 4 KiB pages, how many entries does a single-level page table need per process?
* 2^20 (about one million)
- 2^12
- 2^32
- 2^10
? 32 - 12 = 20 bits of page number, so 2^20 entries. Multi-level page tables avoid allocating most of them.

Q: What does the TLB cache?
* Recent virtual-to-physical page translations
- Recently used disk blocks
- Recently executed instructions
- Page fault handlers
? Without it every memory access would need extra memory accesses to walk the page table.

Q: A process touches a valid page that is not currently in RAM. What happens?
* A page fault; the OS loads the page from disk, then the instruction retries
- The process is killed with a segmentation fault
- The CPU reads zeros
- The TLB fetches it from the cache
? That is demand paging. A segmentation fault comes from touching an address that isn't mapped at all or violates permissions.

Q: Reference string 1,2,3,4,1,2,5,1,2,3,4,5 with FIFO replacement. Going from 3 frames to 4 frames changes the page faults from 9 to 10. What is this called?
* Belady's anomaly
- Thrashing
- The convoy effect
- Internal fragmentation
? More memory made FIFO worse. LRU and OPT never do this because they are stack algorithms.

Q: Which page replacement algorithm gives the fewest faults but cannot be built, because it needs the future?
* OPT (Belady's optimal)
- LRU
- FIFO
- Clock
? OPT evicts the page whose next use is farthest away. It is the yardstick the real algorithms are measured against.

Q: The system spends most of its time swapping pages in and out and little time computing. What is this?
* Thrashing
- A deadlock
- A race condition
- A convoy
? The combined working sets exceed RAM. Fixes are more RAM, fewer running processes or smaller working sets.

Q: Which mitigation randomizes where the stack, heap and libraries load so an exploit can't hard-code addresses?
* ASLR
- NX bit
- Stack canary
- Secure Boot
? NX marks data pages non-executable and a canary detects stack smashing; ASLR is about unpredictability of addresses.

## 3
Q: What does a Unix inode store?
* File metadata (owner, permissions, size, timestamps) and pointers to data blocks
- The file name and its data
- Only the file name
- The directory path
? Names live in directory entries, which map a name to an inode number. That is why one inode can have several names.

Q: What is the difference between a hard link and a symbolic link?
* A hard link is another name for the same inode; a symlink is a small file holding a path
- A hard link can cross filesystems; a symlink cannot
- A symlink shares the inode; a hard link does not
- They are the same thing
? Hard links need the same filesystem and keep the data alive until the link count hits zero. A symlink breaks if its target is removed.

Q: What actually happens when you delete (unlink) a file on ext4 or NTFS?
* The directory entry goes and the blocks are marked free, but the data usually stays until overwritten
- Every block is zeroed immediately
- The inode is encrypted
- Nothing, the file is only hidden
? That is why forensic tools can recover deleted files and why secure wiping tools overwrite the data.

Q: What does a journaling filesystem protect against?
* An inconsistent filesystem after a crash or power loss
- Malware
- Disk failure
- Slow reads
? Changes are written to a log first, so after a crash the OS replays or discards the log instead of scanning the whole disk.

Q: An inode has 12 direct pointers and the block size is 4 KiB. How much data can the direct pointers address?
* 48 KiB
- 12 KiB
- 4 MiB
- 48 MiB
? 12 x 4 KiB = 48 KiB. Single, double and triple indirect blocks cover larger files.

Q: With 4 KiB blocks and 4-byte block pointers, how much can one single-indirect block address?
* 4 MiB
- 4 KiB
- 1 MiB
- 1 GiB
? 4096 / 4 = 1024 pointers, and 1024 x 4 KiB = 4 MiB.

Q: Unused space between the end of a file's data and the end of its last block is called what?
* Slack space
- Swap space
- A superblock
- A journal
? It can hold leftover data from earlier files, which is why forensic examiners look there.

Q: A file has mode rwxr-x---. Who can read it?
* The owner and the group
- Only the owner
- Everyone
- The group only
? The first triplet is the owner (rwx), the second the group (r-x), the third others (---).

## 4
Q: Two threads each run counter++ on a shared variable 1000 times. Why might the result be under 2000?
* counter++ is load, add, store, so one thread can overwrite the other's update
- The CPU skips instructions under load
- The compiler removes one loop
- The OS limits threads to 1000 updates
? That is a race condition. The final value depends on how the threads interleave.

Q: What is a critical section?
* Code that touches shared state and must not run in two threads at once
- Code that runs in kernel mode
- The most CPU-heavy function
- A section of memory that cannot be paged out
? A lock or semaphore around it enforces mutual exclusion.

Q: A binary semaphore used as a lock should start at which value?
* 1
- 0
- -1
- 2
? wait() decrements it (blocking at 0) and signal() increments it. Starting at 1 lets exactly one thread in.

Q: In the bounded-buffer producer/consumer problem, which counting semaphore tracks how many slots are free?
* empty, starting at the buffer size
- full, starting at the buffer size
- mutex, starting at 0
- items, starting at 1
? The producer waits on empty before adding, the consumer waits on full before removing, and a mutex protects the buffer itself.

Q: When is a spinlock a better choice than a sleeping mutex?
* When the lock will be held only very briefly, such as short kernel critical sections on multicore
- When the lock is held a long time
- On a single-core machine always
- When you want fairness
? Spinning burns CPU, but sleeping and waking costs a context switch. For tiny critical sections spinning is cheaper.

Q: A program checks that a file is safe with access(), then opens it. An attacker swaps the file with a symlink in between. What is this bug?
* TOCTOU (time-of-check to time-of-use)
- A buffer overflow
- A deadlock
- Priority inversion
? It is a race condition with security impact. Fix it by acting on one file descriptor instead of re-resolving the name, or by using atomic operations.

Q: What does compare-and-swap (CAS) provide?
* An atomic update that only succeeds if the value is still what you expected
- A way to swap two processes
- Automatic deadlock avoidance
- A faster malloc
? Lock-free data structures are built on CAS: read, compute, CAS, retry on failure.

## 5
Q: Which of these is NOT one of the four conditions needed for deadlock?
* Preemption
- Mutual exclusion
- Hold and wait
- Circular wait
? The fourth is no preemption: resources can't be forcibly taken away. Break any one condition and deadlock can't happen.

Q: Thread A locks X then wants Y while thread B locks Y then wants X. What is the simplest prevention?
* Make every thread acquire locks in the same global order
- Add more RAM
- Use a larger scheduling quantum
- Run them on separate cores
? A fixed lock order removes circular wait.

Q: Banker's algorithm is an example of what?
* Deadlock avoidance, by only granting requests that keep the system in a safe state
- Deadlock detection after it happens
- Deadlock prevention by removing hold-and-wait
- A page replacement policy
? It needs each process's maximum demand declared in advance.

Q: Available = (3,3,2). P1 has maximum need (3,2,2) and holds (2,0,0), so its remaining need is (1,2,2). What can be said?
* P1 can run to completion now
- P1 would deadlock
- P1 must wait for another process to finish
- The state is unsafe
? Need (1,2,2) fits inside available (3,3,2). When P1 finishes it returns its allocation, which grows what is available for the others.

Q: What does a cycle in a wait-for graph (when each resource has one instance) mean?
* A deadlock
- A safe state
- A race condition
- Starvation
? Detection algorithms look for cycles. Recovery means killing processes or preempting resources.

Q: Two threads keep releasing a lock and retrying in lockstep, so neither progresses, but neither is blocked. What is this?
* Livelock
- Deadlock
- Thrashing
- A convoy
? In deadlock the threads are blocked; in livelock they're running but making no progress.

## 6
Q: Why does the CPU have separate user and kernel modes?
* So untrusted code can't run privileged instructions or touch kernel memory directly
- To make programs run faster
- To save power
- To allow more than one core
? The kernel can enforce isolation only if user code can't execute privileged instructions or edit the page tables.

Q: What is the risk with a setuid-root program?
* It runs with root's privileges, so a bug in it can give an attacker root
- It can't be updated
- It always runs in kernel mode
- It ignores file permissions for other users' files only
? Privilege escalation hunts often start with `find / -perm -4000`. Keep the list small and patched.

Q: Which Linux features are the building blocks of containers?
* Namespaces and cgroups
- Hypervisor and VT-x
- SELinux and AppArmor only
- Swap and journaling
? Namespaces limit what a process can see, cgroups limit what it can use. Containers share the host kernel, unlike VMs.

Q: What is the difference between DAC and MAC?
* In DAC owners set permissions; in MAC a central policy decides and owners can't override it
- DAC is for networks, MAC for files
- DAC is encrypted, MAC is not
- There's no difference
? Normal Unix permissions are DAC. SELinux and AppArmor add MAC.

Q: Which defense places a random value before a function's return address and checks it before returning?
* A stack canary
- ASLR
- The NX bit
- A TLB
? A buffer overflow that overwrites the return address has to trample the canary first, which is detected.

Q: A rootkit is installed in the kernel. Why can a normal antivirus running as a user process struggle to find it?
* The kernel can lie to user-mode tools about what files and processes exist
- It uses encryption
- It runs outside RAM
- User processes can't read files
? That's why memory forensics and offline scans from trusted media are used.
