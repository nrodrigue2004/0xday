## 0
Q: In ATT&CK, what does a tactic describe?
* The attacker's goal at that stage, such as Persistence
- A specific tool a group uses
- A vulnerability ID
- A detection rule format
? Tactics are the "why"; techniques are the "how".

Q: What does the ID T1059.001 identify?
* A sub-technique: PowerShell under Command and Scripting Interpreter
- A tactic
- A CVE number
- A malware family
? The dot marks a sub-technique of T1059.

Q: A rule needs the full command line of process starts, but only process names are logged. What is the right first fix?
* Turn on command-line logging, because no data means no detection
- Write a longer rule
- Lower the rule severity
- Block the process by name
? A rule is only as good as the data source behind it.

Q: Which indicator is hardest for an attacker to change, according to the pyramid of pain?
* Tactics, techniques and procedures (behavior)
- File hashes
- IP addresses
- Domain names
? Behavior-based detections survive tool changes.

Q: A detection fires on benign admin activity again and again. What is it called, and what should you do?
* A false positive; add a narrow, documented filter or tune the logic
- A true positive; ignore it
- A false negative; delete the data source
- A tactic; remap it
? Too much noise makes analysts ignore the rule.

Q: Why store detection rules in git with tests?
* So they get review, version history and automated checks like any software
- So attackers cannot read them
- Because SIEMs require git
- To make them run faster
? This practice is called detection-as-code.

## 1
Q: What is Sigma?
* A vendor-neutral YAML format for log detection rules
- A malware sandbox
- A packet capture format
- A SIEM product
? Sigma rules are converted to each SIEM's query language.

Q: In a Sigma selection, several fields listed together are combined with which logic?
* AND
- OR
- XOR
- NOT
? A list of values under a single field is OR instead.

Q: What does `CommandLine|contains: 'x'` do?
* Matches when the command line includes x (case-insensitive)
- Requires an exact match
- Matches only the start
- Runs x on the host
? Modifiers change how the value is compared.

Q: A rule searches for ` -enc ` with a trailing space but the attacker typed `-EncodedCommand`. What happens?
* The rule misses it, because the longer flag does not contain that text
- The rule fires
- Sigma converts it automatically
- The SIEM corrects the flag
? Match both short and long forms and test with real samples.

Q: Where do ATT&CK mappings go in a Sigma rule?
* In the tags field, such as attack.t1059.001
- In the logsource
- In the condition
- In the title only
? Tags make coverage reporting possible.

Q: What is the best way to exclude a known-good parent process?
* A named filter selection with `and not filter` in the condition
- Delete the rule
- Lower the level to informational
- Add the parent to the title
? Visible filters make the tuning auditable.

## 2
Q: What does a YARA rule match against?
* Files or process memory, using strings, hex patterns and conditions
- Network flows only
- Event log IDs
- Passwords
? YARA describes malware by content.

Q: What does `uint16(0) == 0x5A4D` check?
* The file starts with "MZ", so it is a Windows executable
- The file is 5A4D bytes long
- The file is a script
- The file is encrypted
? 0x5A4D is "MZ" read as a little-endian 16-bit value.

Q: Why use `ascii wide` on a string?
* To match both 1-byte and UTF-16 forms, common in Windows malware
- To encrypt the string
- To make the rule faster
- To ignore case
? Windows programs often store text as UTF-16.

Q: Which makes a better YARA string?
* A custom mutex name unique to the malware family
- The API name CreateFileA
- The text kernel32.dll
- The word http
? Common strings also appear in clean software.

Q: What should you do before deploying a YARA rule widely?
* Scan a clean goodware corpus and confirm no hits
- Nothing, rules cannot misfire
- Only scan malware
- Delete the meta section
? A rule that hits clean files is an outage waiting to happen.

Q: Why scan memory with YARA in addition to files?
* Packed malware reveals its strings only after unpacking in memory
- Memory is slower to scan
- Files cannot be scanned
- YARA only works on memory
? Memory scans catch unpacked payloads.

## 3
Q: What should every threat hunt start with?
* A specific, testable hypothesis
- A random search for bad things
- An alert from the SIEM
- A vulnerability scan
? "Find bad stuff" cannot be proved or disproved.

Q: What does stacking (frequency analysis) do?
* Counts values of a field so the rare end can be examined
- Merges log files
- Encrypts the logs
- Sorts alerts by severity
? Rare is a lead, not a verdict.

Q: Connections to one domain every 60 seconds with the same small size suggest what?
* Possible beaconing by automated malware
- Normal web browsing
- DNS poisoning
- A broken switch
? Human traffic is irregular; automation is regular.

Q: What is the best output of a successful hunt?
* A new detection rule, logging fix or documented finding
- A deleted log
- Nothing, hunts are one-off
- A bigger budget
? Hunting should feed detection engineering.

Q: A hunt finds an active intruder. What next?
* Hand off to incident response and preserve evidence
- Keep hunting alone and quietly
- Reboot the host
- Delete the suspicious files
? Switch to the IR process.

Q: Why record hunts that found nothing?
* They show which techniques were checked and over what period
- They never matter
- To pad the report
- Because a law requires it
? Negative results document coverage.
