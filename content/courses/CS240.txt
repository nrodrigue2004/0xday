## 0
Q: In the test pyramid, which kind of test should you have the most of?
* Unit tests
- End-to-end tests
- Manual tests
- Load tests
? Unit tests are fast and precise. E2E tests are slow and flaky, so you keep only a few.

Q: A rule says "free shipping at 50 dollars or more". Which inputs best test the boundary?
* 49.99, 50 and 50.01
- 10, 20 and 30
- 100, 200 and 300
- Only 50
? Off-by-one and comparison-operator bugs hide exactly at the boundary.

Q: What is the difference between a stub and a mock?
* A stub returns canned data; a mock also records calls so you can assert on them
- A stub is slower
- A mock is a real database
- There is no difference
? Use test doubles for slow or random dependencies like networks, clocks and payment APIs.

Q: A team has 95% line coverage. What does that guarantee?
* Only that the lines ran during tests, not that the behavior was checked
- The software has no bugs
- Every branch was asserted
- All security flaws are covered
? Coverage finds untested code but cannot tell if assertions are meaningful. Mutation testing checks test quality.

Q: In test-driven development what is the correct order?
* Write a failing test, make it pass, then refactor
- Write the code, then the test
- Refactor, then test, then code
- Write all the tests at the end
? Red, green, refactor.

## 1
Q: Which SOLID principle says a class should have only one reason to change?
* Single responsibility
- Open/closed
- Interface segregation
- Dependency inversion
? Mixing unrelated duties in one class makes every change risky.

Q: You have an if/else chain choosing between pricing rules and keep adding rules. Which pattern fits?
* Strategy
- Singleton
- Observer
- Facade
? Put each rule behind a common interface and pass the chosen one in; adding a rule means adding a class.

Q: Why are singletons often called an anti-pattern?
* They are hidden global state, which is hard to test and unsafe under concurrency
- They use too much memory
- They cannot be subclassed
- They need reflection
? Prefer creating one instance and passing it in (dependency injection).

Q: Which pattern lets many objects react when one object changes state?
* Observer
- Adapter
- Builder
- Proxy
? Event handlers and pub/sub systems are observers.

Q: What does the Liskov substitution principle require?
* A subclass must work anywhere its parent class is expected
- Classes must be final
- Every class needs an interface
- Functions must be pure
? If Square extends Rectangle but breaks code that sets width and height independently, the hierarchy violates it.

## 2
Q: What is the main difference between continuous delivery and continuous deployment?
* Delivery keeps every change releasable with a human approval; deployment releases passing changes automatically
- Delivery has no tests
- Deployment only works for mobile apps
- They are the same
? Both rely on CI; the difference is the manual release step.

Q: In GitHub Actions, which key makes the deploy job wait for the test job?
* needs
- on
- steps
- runs-on
? `needs: [test]` orders the jobs and skips deploy if test fails.

Q: Which deployment strategy sends a small percentage of traffic to the new version first?
* Canary release
- Blue/green switch
- Big-bang release
- Rolling restart with no monitoring
? Watch error rate and latency, then widen the rollout or roll back.

Q: Which practice keeps a compromised third-party GitHub Action from silently changing?
* Pin the action to a full commit SHA
- Use the latest tag
- Run it as root
- Disable CI
? Tags can be moved; commit SHAs are immutable.

Q: Why build an artifact once and promote it through environments?
* So exactly what you tested is what ships to production
- To save disk space
- Because staging cannot run code
- To avoid versioning
? Rebuilding per environment can produce different binaries. Keep configuration outside the artifact.

## 3
Q: Which is a non-functional requirement?
* 95% of requests complete in under 300 ms
- A user can reset a password
- The page has a login button
- Admins can export reports
? Non-functional requirements describe how well the system does it: performance, security, availability.

Q: In Scrum, who decides the order of the product backlog?
* The product owner
- The scrum master
- The tester
- The manager of each developer
? The product owner owns value and priority; the scrum master coaches the process.

Q: What does a WIP limit on a Kanban column do?
* Limits work in progress so the team finishes items before starting more
- Limits who may use the column
- Sets the sprint length
- Caps story points
? Smaller queues mean shorter cycle times.

Q: What is technical debt?
* Shortcuts that make future changes slower, which accrue interest
- Money owed to vendors
- Code that has tests
- Unused servers
? Track it, pay it down regularly and explain it in terms of risk and delivery speed.

Q: What is the goal of a blameless postmortem?
* Learn how the system allowed the failure and fix it, not blame a person
- Decide who gets fired
- Avoid writing anything down
- Assign story points
? People report problems honestly when they are not punished for them.

## 4
Q: What is a sensible default architecture for a small team starting a new product?
* A well-structured monolith
- Fifty microservices
- A separate database for every function
- Only serverless functions
? Split out services only for clear reasons like team boundaries or independent scaling.

Q: Why must servers be stateless to scale horizontally?
* Any server must be able to handle any request, so state lives in a shared store
- Stateless servers use less CPU
- Load balancers require it by law
- Databases cannot store sessions
? Session data goes in a database or cache such as Redis, not in one server's memory.

Q: What does the S in STRIDE refer to?
* Spoofing
- Scaling
- Storage
- Sanitizing
? STRIDE: spoofing, tampering, repudiation, information disclosure, denial of service, elevation of privilege.

Q: A client retries a payment request after a timeout. Which property prevents charging twice?
* Idempotency, for example via an idempotency key
- Encryption
- Caching
- Compression
? The server recognizes the repeated request and returns the original result.

Q: During which SDLC phase is threat modeling cheapest to do?
* Design
- After release
- During incident response
- Only during penetration testing
? Changes cost far less before code is written.

## 5
Q: You must explain what happens between `git push` and production. Which answer is best?
* CI builds and tests, scans, packages an artifact, deploys to staging, then promotes to production with monitoring and rollback
- The code is copied to the server
- Someone emails the release
- The database is updated by hand
? Show you know the stages, the gates and the safety nets.

Q: A test fails randomly in CI but passes locally. What is the best response?
* Find the cause (shared state, timing, order, environment) instead of just adding retries
- Delete the test
- Ignore CI
- Rerun until green
? Flaky tests destroy trust in the pipeline; quarantine only temporarily.

Q: You review a pull request. What should you check besides style?
* Correctness, tests, security (validation, authorization, secrets) and design
- Only variable names
- Only that the build passes
- The author's seniority
? Reviews are one of the cheapest ways to find defects, including security flaws.

Q: When a bug is reported, what is the first good step to fix it?
* Write a failing test that reproduces it
- Change code until it goes away
- Add a retry
- Close the ticket
? The test proves the fix and prevents regression.

Q: A coworker asks why not use five design patterns in a 100-line script. What is a good answer?
* Patterns solve specific recurring problems; extra abstraction adds complexity without payoff
- Patterns are illegal
- Scripts cannot use classes
- More patterns always means better code
? Use a pattern when it removes real duplication or makes change easier, not for its own sake.
