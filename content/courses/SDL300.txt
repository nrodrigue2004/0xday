## 0
Q: What is a trust boundary in a data flow diagram?
* A line where the level of trust changes between components
- A firewall rule
- A database table
- A network cable
? Most threats sit where data crosses a boundary.

Q: What does the S in STRIDE stand for?
* Spoofing
- Scanning
- Sniffing
- Signing
? Spoofing violates authentication.

Q: A threat where a user denies doing an action because nothing was logged is which STRIDE letter?
* Repudiation
- Tampering
- Information disclosure
- Elevation of privilege
? Audit logging addresses repudiation.

Q: When should you threat model?
* Early in design, and again when the architecture changes
- Only after a breach
- Only at launch
- Never, scanners cover it
? It finds design flaws no scanner can.

Q: Which is a good threat model output?
* A testable statement such as "a caller cannot read another tenant's invoices"
- "Encrypt everything"
- A diagram nobody reads
- A list with no owners
? Concrete items can be tested and tracked.

## 1
Q: What does SAST analyze?
* Source code or bytecode without running the application
- A running application over HTTP
- Network packets
- User behavior
? DAST attacks the running app.

Q: Which is DAST best at finding?
* Missing security headers and reflected XSS in a running app
- Dead code
- Hard-coded variable names
- Memory leaks in a compiler
? DAST sees runtime behavior but not source lines.

Q: Which flaw do both SAST and DAST usually miss?
* Broken access control and business-logic abuse
- SQL injection by string concatenation
- Missing headers
- Weak hash calls
? These need human-written tests and review.

Q: The first step when triaging a SAST finding is?
* Check whether untrusted input can reach that code
- Close it as noise
- Suppress the rule
- Escalate to critical
? Reachability and exploitability decide whether it is real.

Q: Why gate a CI build on only new findings?
* Failing on the whole backlog blocks everything and gets the tool turned off
- New findings are always worse
- Old findings are fixed already
- It is faster
? Baseline the existing findings and track burn-down.

Q: Where should an active DAST scan run?
* Against a staging copy with agreed scope
- Against production
- Against any site
- Only locally on the laptop
? Active scans send attack payloads and create data.

## 2
Q: What is a transitive dependency?
* A dependency of one of your dependencies
- A dependency you wrote
- A dev-only tool
- A dependency with no license
? Most vulnerable packages arrive transitively.

Q: What is an SBOM used for?
* A machine-readable inventory of components, so you can answer "are we affected?"
- Encrypting builds
- Scanning for open ports
- Signing emails
? CycloneDX and SPDX are common formats.

Q: Dependency confusion is when?
* A public package overrides a private one with the same name
- Two teams use different editors
- A package is unlicensed
- A lockfile is missing
? Scope and proxy internal packages.

Q: A secret was committed to git. What is the first step?
* Rotate the secret, then clean up
- Delete the commit and move on
- Make the repo private
- Rename the file
? Assume anything pushed has been copied.

Q: Why pin CI actions to a full commit SHA?
* A mutable tag can be moved to malicious code
- SHAs run faster
- Tags are not allowed
- It saves storage
? Pinning protects the build pipeline.

Q: Which signal helps prioritize a CVE?
* Whether it is exploited in the wild (KEV) and reachable in your code
- The alphabetical order of the package
- The package's star count
- The CVE year only
? Not every critical CVE is equally urgent.

## 3
Q: The best fix for SQL injection is?
* Parameterized queries
- Blacklisting quote characters
- Hiding error messages
- Longer passwords
? Parameters keep data separate from the query.

Q: Stored XSS happens when?
* Malicious input is saved and later served to other users' browsers
- A cookie is encrypted
- A server reboots
- A form is empty
? Output encoding is the main defense.

Q: Which is a good defense against CSRF on state-changing requests?
* Anti-CSRF tokens and SameSite cookies
- Using GET for everything
- Hidden form fields with no secret
- Longer URLs
? Tokens prove the request came from your own page.

Q: Where must authorization be enforced?
* On the server for every request
- Only in the client app
- Only in JavaScript
- Only at login
? Clients can always be modified.

Q: What is the OWASP Cheat Sheet Series?
* Short practical guidance on securing specific features
- A malware list
- A scanner
- A certification
? Use it as a reference during development.
