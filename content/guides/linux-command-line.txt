:: simple
The **shell** is a text interface: you type a command, press Enter, it prints a result. Everything in Linux is a file in one tree that starts at `/`. Your home directory is `~`.

The first five commands you need:

```
$ pwd
$ ls
$ cat notes.txt
$ cd projects
$ ls -l
```

- `pwd` where am I, `ls` what's here, `cd` go somewhere (`cd ..` goes up, `cd` alone goes home)
- `cat` prints a file, `head` / `tail` print the start or end
- Files starting with `.` are **hidden**. `ls -a` shows them

```
$ cd ~
$ ls -a
```

> Press Tab to autocomplete names and the Up arrow to reuse commands. It works in this sandbox too.

### How to read a command
Almost every command follows the same shape: `command -options arguments`. Options (flags) change *how* it works, arguments say *what* to work on. `ls -l /etc` is "list, in long format, the directory /etc". Short flags stack, so `ls -la` is `ls -l -a`. Long flags use two dashes: `ls --all`.

- **Absolute path** starts at `/` and works from anywhere (`/etc/passwd`). **Relative path** starts from where you are (`projects/servers.txt`).
- `.` is "here", `..` is "one level up", `~` is your home directory.
- Quoting matters: `"$HOME"` expands the variable, `'$HOME'` does not, and unquoted names break at spaces.
- Stuck? `man ls` is the full manual (press `q` to leave), `ls --help` is the short one, and `whatis ls` is a single line.

### The directories worth knowing
- `/etc` configuration files (`/etc/passwd` users, `/etc/ssh/sshd_config`, `/etc/hosts`)
- `/var/log` logs (`auth.log` logins, `syslog` general, `nginx/` web server)
- `/home` one directory per user, `/root` is the admin's home
- `/tmp` anyone can write here, which is why attackers like it
- `/usr/bin`, `/bin` programs, `/proc` live system info that looks like files
:: mid
### Finding things
`find` searches by name, type or size, and `grep` searches inside files. `-r` makes grep search a whole directory tree, `-i` ignores case, `-l` lists only file names:

```
$ find ~ -name "*.txt"
$ grep -ril "password" ~
```

### Pipes
The `|` sends one command's output into the next command's input. Small tools chained together are the Unix way:

```
$ cat ~/projects/servers.txt | sort | uniq
$ ls ~/projects | wc -l
```

### Redirection
`>` writes output to a file (overwriting), `>>` appends:

```
$ echo "checked $(date)" >> ~/log.txt
$ cat ~/log.txt
```

### Seeing and measuring files
`wc -l file` counts lines, `head -n 20` and `tail -n 20` show the ends, and `tail -f /var/log/auth.log` follows a log live as new lines arrive. `less file` lets you scroll and search (`/word`, `n` for next, `q` to quit). `file mystery.bin` tells you what a file really is regardless of its name, `stat file` shows size, owner and timestamps, and `du -sh *` shows how big each item in a folder is.

### Searching smarter
- `grep -n` shows line numbers, `-v` inverts (lines that do NOT match), `-c` counts matches, `-E` allows extended regex such as `grep -E "fail|error"`
- `find / -type f -perm -4000 2>/dev/null` lists SUID files. `2>/dev/null` throws away the "permission denied" noise
- `find . -mtime -1` finds files changed in the last day, `-size +10M` finds files over 10 MB, `-user bob` finds files owned by bob

### Variables, history and quick wins
```
export TARGET=10.0.0.5
echo "$TARGET"
history | grep ssh
!!
```
`export` sets a variable for child programs, `history` lists what you ran, `!!` repeats the last command and `sudo !!` repeats it as root. `Ctrl+R` searches your history as you type, `Ctrl+C` stops a runaway command.

### Streams
Every program has three streams: **stdin** (0, input), **stdout** (1, normal output) and **stderr** (2, errors). `command > out.txt` redirects stdout, `command 2> err.txt` redirects stderr, `command > all.txt 2>&1` sends both to one file, and `command 2>/dev/null` discards errors.
:: complex
### Permissions
`ls -l` starts every line with something like `-rwxr-x---`: file type, then three groups of read/write/execute for the **owner**, the **group** and **everyone else**. As numbers, r=4, w=2, x=1, so `750` is `rwxr-x---`.
- `chmod 600 key.pem` only the owner can read/write (what SSH demands for private keys)
- `chown user:group file` changes the owner
- A directory needs `x` to be entered and `r` to be listed

Security-relevant special bits: **SUID** (`s` in the owner execute spot) runs a program as its owner, often root; the **sticky bit** on `/tmp` stops users deleting each other's files.

### Text-processing power tools
`cut` picks columns, `sort -n` sorts numbers, `uniq -c` counts duplicates, `tr` swaps characters, `awk` handles columns and conditions. Combined, they answer most "how many / which one / who" questions about logs without writing a script:

```
$ cut -d, -f2 ~/projects/servers.txt | sort | uniq -c | sort -rn
```

### Users, groups and sudo
`id` shows who you are and which groups you belong to. `sudo command` runs one command as root; `sudo -l` lists what you are allowed to run, which is the first thing to check after landing on a box. `/etc/passwd` lists accounts (a line per user, seven colon-separated fields) and `/etc/shadow` holds the password hashes, readable only by root. A user with UID 0 *is* root, whatever the name says.

### Processes and the network
```
ps aux
ps aux | grep sshd
top
ss -tulpn
kill 1234
```
`ps aux` lists every process, `top` is the live view, `ss -tulpn` shows listening TCP/UDP sockets and the process behind each (`netstat` is the older tool), `kill PID` asks a process to stop and `kill -9 PID` forces it.

### Scheduled jobs and startup
`crontab -l` lists your scheduled jobs, and `/etc/crontab` plus `/etc/cron.d/` hold system ones. A cron line is `minute hour day month weekday command`. Persistence often hides here, or in `~/.bashrc`, `~/.ssh/authorized_keys` and systemd units.

### Archives and moving data
`tar -czf backup.tgz folder/` packs and compresses, `tar -xzf backup.tgz` unpacks, `scp file user@host:/path` copies over SSH, and `sha256sum file` gives a checksum to prove a file was not altered.

:: solution

A few decoy files contain the word "flag" in other places, which is why anchoring the search with `^` (start of line) helps. The flag is **FLAG{h1dd3n_1n_pl41n_s1ght}**.
