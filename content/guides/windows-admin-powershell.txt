tagline: PowerShell is how Windows admins and attackers both get work done. Learn cmdlets, objects and the pipeline, then use exported service data to find malware disguised as a Windows service.
sheet: powershell
:: simple
**PowerShell** is Windows' shell and scripting language. Its commands are **cmdlets** named `Verb-Noun`: `Get-Process`, `Get-Service`, `Stop-Service`, `Get-ADUser`. `Get-Help <cmdlet>` explains any of them, and `Get-Command *service*` finds them.

```
$ Get-Service
$ Get-Process | Sort-Object CPU -Descending | Select-Object -First 5
```

> The big difference from bash: PowerShell pipes **objects**, not text. `Get-Process` sends process objects with properties (Name, Id, CPU), so the next cmdlet can filter on a property instead of parsing columns.

### Cmdlets and the pipeline
PowerShell commands (**cmdlets**) are named `Verb-Noun`: `Get-Process`, `Stop-Service`, `New-Item`. The pipeline passes **objects**, not text, so you can sort or filter by a property name without cutting columns. `Get-Command *service*` finds commands, `Get-Help Get-Service -Examples` shows examples, and `Get-Member` lists the properties of whatever is flowing through.

```
Get-Process | Sort-Object CPU -Descending | Select-Object -First 5 Name, CPU
```
Aliases like `ls`, `cat`, `ps` and `?` exist for speed; use full names in scripts so they stay readable.
:: mid
### Filter, sort, select
- `Where-Object` keeps objects matching a condition: `Where-Object Status -eq 'Running'`
- `Sort-Object` sorts by a property, `Select-Object` picks properties or the first N
- `Format-Table` / `Export-Csv` for output

```
$ Get-Service | Where-Object Status -eq 'Stopped'
$ Get-LocalUser | Where-Object Enabled
```

### Remote and at scale
`Invoke-Command -ComputerName PC01,PC02 { Get-Service spooler }` runs on many machines at once over WinRM. Admins export results to CSV and analyze them anywhere, which is what this lab does: the exports are text, so `grep`, `cut` and `sort` in the sandbox work on them.

```
$ head -3 ~/exports/services.csv
```

### Variables, loops and conditions
```
$svcs = Get-Service
foreach ($s in $svcs) { if ($s.Status -eq 'Stopped') { $s.Name } }
Get-Service | ForEach-Object { $_.DisplayName }
Get-Process | Where-Object { $_.WorkingSet -gt 200MB }
```
Comparison operators are words: `-eq`, `-ne`, `-gt`, `-lt`, `-like` (wildcards), `-match` (regex), `-contains`. `$_` is the current object in the pipeline.

### Files, registry and output
`Get-ChildItem -Recurse -Filter *.log`, `Get-Content file -Tail 50 -Wait`, `Select-String -Path *.log -Pattern "failed"` (grep for Windows), `Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Run` for autostart entries. Send results with `Export-Csv`, `ConvertTo-Json`, `Out-File` or `Format-Table -AutoSize` for the screen.

### Execution policy is not security
`Set-ExecutionPolicy` only stops accidental script runs; anyone can bypass it with `-ExecutionPolicy Bypass`. Treat it as a seatbelt, not a lock. Real control comes from code signing, AppLocker or WDAC, and constrained language mode.
:: complex
### Hunting with PowerShell
Malware loves to hide as a **service**: it survives reboots and runs as SYSTEM. Real Windows services run from `C:\Windows\System32` (or `Program Files` for apps), are signed by Microsoft or a known vendor, and have sensible names. Red flags: a binary in `C:\Users\...\AppData`, `C:\ProgramData` or `Temp`, a name that's *almost* a real one, an unsigned binary.

```
$ Get-CimInstance Win32_Service | Select-Object Name, PathName, StartMode
$ grep -viE "C:\\\\Windows\\\\|Program Files" ~/exports/services.csv
```

### Logging and security
Attackers use PowerShell too (downloading payloads, running in memory, `-EncodedCommand` to hide scripts). Defend with **Script Block Logging** (event 4104 records the decoded script), **Constrained Language Mode** and AMSI, and by alerting on `-enc`, `IEX` and `DownloadString`.

```
$ grep -i "4104" ~/exports/powershell-events.txt
```

### Admin automation patterns
- Wrap work in functions with parameters and `try/catch`, and use `-ErrorAction Stop` so errors are caught.
- Use `Invoke-Command` for many machines, `Get-CimInstance` (not the old `Get-WmiObject`) for hardware and OS data.
- Support `-WhatIf` and `-Confirm` on destructive scripts.
- Store secrets in the SecretManagement module or a vault, never in the script.

### Security-relevant logs
Enable script block logging (event 4104), module logging (4103) and transcription through Group Policy. Process creation (4688 with command line, or Sysmon 1) shows `powershell -enc ...`. Encoded commands decode with `[Text.Encoding]::Unicode.GetString([Convert]::FromBase64String($b64))`. Attackers use PowerShell because it is already there, which is why defenders watch for download cradles (`IEX (New-Object Net.WebClient).DownloadString(...)`), hidden windows and AMSI bypass attempts.

:: hint

:: hint
Cross-check the remaining binaries against `signatures.csv`. Which one is NotSigned?
:: solution
Filtering services by path leaves two: the real Defender (its normal home is under ProgramData) and **WinDefendUpdate**, display name "Windows Defender Update Service", running as LocalSystem from `C:\ProgramData\WinDef\wdupdate.exe`. Real Defender is `WinDefend`, running `MsMpEng.exe` from `C:\ProgramData\Microsoft\Windows Defender\Platform\...` and signed by Microsoft. `signatures.csv` shows `wdupdate.exe` is **NotSigned**, and `powershell-events.txt` has a 4104 entry where the service was created with `New-Service` from an encoded command. The malicious service is **WinDefendUpdate**. Contain the host, then `Stop-Service` / `sc.exe delete`, preserve the binary for analysis, and hunt for the same hash on other machines.
