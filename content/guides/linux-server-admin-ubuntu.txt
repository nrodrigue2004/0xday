tagline: Running a Linux server means keeping services up, patched and logged. Learn systemd, journals, packages, users and the firewall on Ubuntu, then figure out why a web server won't start.
:: simple
A **server** is just a computer whose job is to run **services** (web, database, SSH) for other machines. On Ubuntu, services are managed by **systemd** with the `systemctl` command:

```
$ systemctl status nginx
$ systemctl list-units --type=service --state=running
```

- `systemctl start|stop|restart nginx` control a service now
- `systemctl enable nginx` start it automatically at boot
- Software is installed with `apt`: `sudo apt update && sudo apt upgrade` patches everything

> Most admin commands need root. Use `sudo` for one command at a time instead of logging in as root.
:: mid
### When a service fails, read the journal
systemd captures every service's output in the **journal**. `journalctl -u <service>` shows one service's log, `-e` jumps to the end, `-f` follows live, `--since "1 hour ago"` filters by time:

```
$ journalctl -u nginx --no-pager | tail -8
```

### Configuration and checks
Config lives in `/etc`. Many services can validate their config before you restart, which avoids taking the site down with a typo:

```
$ nginx -t
$ ls /etc/nginx/sites-enabled
```

### Firewall: ufw
Ubuntu's `ufw` is a friendly front end for the kernel firewall. Default deny incoming, then allow only what the server serves:

```
$ ufw status verbose
```
:: complex
### Ports, processes and conflicts
Only one program can listen on a given IP and port. "Address already in use" means something else got there first. `ss -tlpn` shows every listening port and which process owns it:

```
$ ss -tlpn
```

### Hardening a fresh Ubuntu server
- create a normal admin user, add it to `sudo`, disable root SSH login and password auth (keys only)
- `ufw default deny incoming`, allow 22 (ideally only from your admin network), 80, 443
- enable `unattended-upgrades` for security patches
- install `fail2ban` to block repeated failed logins
- ship logs off the box (rsyslog to a SIEM), since an attacker with root can edit local logs

### Users and groups
`adduser`, `usermod -aG sudo name`, `passwd -l name` (lock). `/etc/passwd` lists accounts, `/etc/group` groups, and `id name` shows a user's groups.

:: brief
After last night's maintenance, **nginx won't start** on web02 and the company site is down.

Use `systemctl`, `journalctl` and `ss` to find out why. Something else is holding the port nginx needs.

Submit the **name of the service** you need to stop or disable so nginx can start, e.g. `submit mysql`.
:: answer
apache2
apache2.service
:: hint
Start with `systemctl status nginx` and `journalctl -u nginx`. What error does nginx give?
:: hint
"Address already in use" on port 80. Which process is listening on 80? `ss -tlpn`
:: solution
`journalctl -u nginx` ends with `bind() to 0.0.0.0:80 failed (98: Address already in use)`. `ss -tlpn` shows `apache2` listening on `*:80`, and `systemctl status apache2` shows it was **installed and enabled during maintenance** (it came in as a dependency of a PHP package). Fix: `sudo systemctl disable --now apache2`, then `sudo systemctl start nginx`. The answer is **apache2**. Better long-term: remove the package if nothing needs it, and add a check for this to the maintenance runbook.
