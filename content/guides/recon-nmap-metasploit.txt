tagline: You can't attack or defend what you haven't mapped. Learn host discovery, port and version scanning with Nmap, how Metasploit turns a finding into access, then find the one vulnerable box on a lab network.
:: simple
**Reconnaissance** is mapping a target before touching it hard: which hosts are alive, which ports are open, and what software is listening. **Nmap** is the standard tool for this.

Only scan networks you own or have written permission to test. Here, `10.10.10.0/24` is a lab network built for practice.

The first question is simply *who's there?* A **ping sweep** (`-sn`) finds live hosts without port scanning them:

```
$ nmap -sn 10.10.10.0/24
```

Then ask one host which ports are open:

```
$ nmap 10.10.10.5
```

> An **open** port has a program listening. **Closed** means the host answered but nothing's there. **Filtered** means a firewall ate the probe.
:: mid
### Finding versions
Knowing port 21 is open is a start; knowing it's **vsftpd 2.3.4** is a finding. `-sV` probes each open port to identify the service and version, and `-sC` runs the default safe scripts (banners, titles, anonymous login checks):

```
$ nmap -sV -sC 10.10.10.5
```

### Scan types and speed
- `-sS` SYN scan (default as root): sends SYN, reads the reply, never completes the handshake
- `-sT` full TCP connect (no root needed, noisier)
- `-sU` UDP (slow, but finds DNS, SNMP, TFTP)
- `-p-` all 65,535 ports, `--top-ports 100` the most common ones
- `-T4` faster timing, `-oA name` save output in every format

```
$ nmap -p- --min-rate 1000 10.10.10.7
```
:: complex
### From version to exploit
Once you have a product and version, look it up: CVE databases, vendor advisories, and **searchsploit** (an offline copy of Exploit-DB):

```
$ searchsploit vsftpd 2.3.4
```

### Metasploit in one minute
Metasploit organizes attacks as **modules**: auxiliary (scanners), exploits, payloads (what runs after: a shell or Meterpreter) and post modules. The workflow is always the same: `search`, `use`, `show options`, `set RHOSTS`, `run`.

```
$ msfconsole -q -x "search vsftpd"
```

### Defender's view
Every scan you just ran is visible: a SYN scan is a burst of SYNs to many ports from one IP, and IDS rules (Snort's scan detection, Zeek's `Scan::Port_Scan`) catch it. Reduce what recon finds by closing unused ports, keeping software current, and hiding version banners.

:: solution
The sweep finds 10.10.10.1, .5, .7 and .9. Version scans show: .1 a router (SSH, HTTPS admin), .5 vsftpd **3.0.5** and OpenSSH, .7 nginx and PostgreSQL, and .9 **vsftpd 2.3.4**. `searchsploit vsftpd 2.3.4` returns *vsftpd 2.3.4 - Backdoor Command Execution* (CVE-2011-2523), and Metasploit has `exploit/unix/ftp/vsftpd_234_backdoor`, which opens a root shell. The vulnerable host is **10.10.10.9**. In the report: upgrade or remove vsftpd on .9, and restrict FTP to the hosts that need it.
