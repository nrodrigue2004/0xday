## 1.1 The OSI Model
labs: networking-tcp-ip-dhcp-nat-subnets, network-traffic-analysis
@notes
### Understanding the OSI Model
The OSI model is a seven-layer vocabulary for describing where something happens on a network. It is not a protocol suite and real traffic is TCP/IP, but "that's a layer 2 problem" means the same thing to everyone. One layer holds many protocols, and several layers often collapse into one in practice.

Top to bottom: **7 Application, 6 Presentation, 5 Session, 4 Transport, 3 Network, 2 Data link, 1 Physical** (mnemonic: All People Seem To Need Data Processing).

| layer | nickname | what lives here | troubleshooting hint |
|---|---|---|---|
| 1 Physical | signals | cables, fiber, radio, adapters, hubs | bad cable or fiber, interference, loopback tests, cable testers |
| 2 Data link | switching, MAC layer | Ethernet frames, MAC (EUI-48/EUI-64) addresses, switches, bridges, access points (802.11 to 802.3) | MAC table, port problems, VLANs |
| 3 Network | routing | IP addresses, subnet masks, routers, fragmentation | wrong IP/mask/gateway, routing |
| 4 Transport | post office | TCP and UDP, port numbers, segmenting and reassembly | firewall port blocks, ports not listening |
| 5 Session | control | setting up, maintaining, ending and restarting sessions, tunneling and control protocols | |
| 6 Presentation | formatting | character encoding, encryption and decryption (TLS) | |
| 7 Application | what you see | HTTP/HTTPS, FTP, DNS, POP3 and the app itself | the application's own errors |

- **Any hardware address, switch behavior or frame is layer 2.** Anything with an IP or a subnet mask is layer 3. Anything with a TCP/UDP port is layer 4.
- A **Wireshark decode** reads bottom-up through the layers: frame summary (L1), Ethernet II with MAC addresses (L2), IP (L3), TCP with ports (L4), then TLS and the application (L5-7 together). Destination port 443 tells you it is HTTPS.
- Layers 5-7 are often lumped together because TLS-wrapped applications blur them.

## 1.2 Network Appliances and Applications
labs: firewalls-pfsense, virtualization-proxmox
@notes
### Networking Devices
- **Router**: layer 3, moves traffic between IP subnets (rooms apart or continents apart), joins LANs to WANs, over copper or fiber. A **layer 3 switch** adds routing inside a switch chassis.
- **Switch**: layer 2, forwards on MAC address, mostly in hardware chips (**ASIC**). Enterprise switches add **PoE** (power over the Ethernet cable) and VLANs.
- **Firewall**: filters by port; a **next-generation firewall (NGFW)** identifies the application itself and allows or blocks it. Firewalls commonly also do **VPN** termination, routing (sitting at the inside/outside edge) and **NAT**, and often speak dynamic routing protocols.
- **IDS vs IPS**: both spot known attacks (exploits against OS and apps: buffer overflow, cross-site scripting and so on). IDS only alerts, IPS also blocks, so IPS is the usual choice inline. Much of this is now built into NGFWs.
- **Load balancer**: spreads requests over a farm of servers so a site stays up. It notices a dead server and removes it from rotation. Extras: **TCP offload**, **SSL/TLS offload** (the balancer encrypts/decrypts instead of the servers), caching, **QoS** prioritizing and application-aware routing (certain pages to certain servers). Users see one address.
- **Proxy**: sits in the middle and makes the request for the client, then checks the answer for malware before handing it back. Gives caching, authentication (login to reach the internet), URL and content filtering. **Explicit** proxies need client configuration, **transparent** proxies do not.
- **NAS vs SAN**: NAS gives **file-level** access (move the whole file to change it, over a normal network share). SAN gives **block-level** access like a local disk (change only the modified blocks, efficient for huge files). Both usually sit on their own isolated, high-bandwidth network.
- **Access point (AP)**: wireless to wired bridge, a layer 2 device. Offices use many dedicated APs, not the home all-in-one "wireless router". A **wireless LAN controller (WLC)** centrally configures, monitors and updates all APs and handles roaming policy. Usually vendor-specific.

### Networking Functions
- **CDN (content delivery network)**: copies of content cached at regional points so users fetch from nearby. Faster and spreads load. Video sites and most large sites use one.
- **VPN**: encrypted tunnel across an untrusted network. The central endpoint is a **VPN concentrator / head-end**, usually dedicated hardware (high-speed crypto) or a feature of the NGFW. Small setups can use software concentrators and the VPN client built into Windows, macOS and Linux.
- **QoS (traffic shaping)**: give real-time voice and video priority over bulk file transfers. Configured on routers, switches and firewalls, often with built-in application lists.
- **TTL (time to live)**: a countdown that kills runaway things. In an **IP packet**, TTL counts hops: every router subtracts one and drops the packet at zero, which stops routing loops. Typical start values: 64 for Linux/macOS, 128 for Windows. A traceroute bouncing between the same two routers is a routing loop. In **DNS**, TTL is in seconds: how long a resolver may cache the answer (for example 300 s = 5 minutes), so changing a record takes about that long to spread. Caches use TTL the same way.

@lab
Reason about a routing loop
A traceroute shows 10.1.10.1, 10.2.10.2, 10.1.10.1, 10.2.10.2 repeating. What is wrong, what stops it eventually, and where do you look?
@answer
A routing loop: each router thinks the other is the next hop (often one wrong static route). The IP TTL decrements at each hop and the packet is discarded at zero, so the loop is not infinite. Fix by checking the routing tables (`show route`) on both routers for the bad next hop.

## 1.3 The Cloud
labs: virtualization-proxmox
@notes
### Designing the Cloud
- Cloud traits: **elasticity** (scale up and down with demand), access from anywhere, **multitenancy** (many customers share one infrastructure, which is what makes it cheap).
- **NFV (network function virtualization)**: routers, switches and firewalls become virtual appliances on the hypervisor. Same functions, deployed with a click instead of a truck and a rack.
- **VPC (virtual private cloud)**: a private, isolated chunk of cloud holding your web servers, databases, load balancers and virtual network gear. Big orgs use one VPC per app or business unit.
- **Transit gateway**: a cloud router that links many VPCs. A VPN into the transit gateway gives remote users access to all of them.
- **Internet gateway**: makes a VPC reachable from the public internet. **NAT gateway**: lets private instances reach out to the internet without being reachable from it. **VPC endpoint**: a private connection from a VPC to another service or provider so traffic never crosses the open internet (useful to reach a private subnet).
- **Security lists** (applied to whole subnets/VCNs, coarse) vs **security groups / network security groups** (attached to individual virtual NICs, fine-grained, but more to administer). Rules are protocol + port + source/destination (single IP or CIDR block, IPv4 or IPv6), inbound and outbound, like a stateful firewall in front of the instance. Need more? Add a virtual firewall.

### Cloud Models
- **Deployment**: **public** (anyone, run by a provider), **private** (your own virtualized data center), **hybrid** (both).
- **Service models** (who manages what): **SaaS** the finished app, you just log in and bring data (Gmail, Office 365). **PaaS** the provider gives the platform and tools, you build and maintain the app (Salesforce platform). **IaaS** (HaaS) you get raw compute, storage and network, and you install, patch and secure the software and data. Responsibility moves toward the provider as you go IaaS to PaaS to SaaS, but **you always own your data, accounts and devices**. On-prem is all yours, including the building.

## 1.4 Ports and Protocols
labs: networking-tcp-ip-dhcp-nat-subnets, network-traffic-analysis
@notes
### Introduction to IP
- Encapsulation picture: the network is the road, **IP is the truck**, **TCP/UDP are the boxes**, application data is inside. An Ethernet frame is header + IP packet + trailer; the IP packet is IP header + TCP/UDP segment; that holds the application data.
- **TCP**: connection-oriented (formal setup and teardown), acknowledgments and numbered segments so lost data is resent and only the lost part, plus **flow control** (the receiver can tell the sender to slow down). "Reliable".
- **UDP**: connectionless, no setup, no acknowledgments, no retransmit, no flow control. "Unreliable" means no delivery guarantee, not that it fails more. Low overhead, good for real-time voice and video and simple queries.
- Both layer 4 protocols do **multiplexing**: many apps share one IP pair, told apart by **port numbers** (the "room in the house").
- A **socket** = IP address + protocol + port. Server side uses a fixed port, client side a random one. Replies simply swap source and destination.
- **Well-known (non-ephemeral) ports** are 0 to 1023. **Ephemeral** client ports are 1024 to 65535. Not a hard rule. Range overall: 0 to 65535.
- TCP port 80 and UDP port 80 are different things. Changing a port is **not security**, you still need a firewall. If a server moves off the default port, clients must be told.

### Common Ports (memorize)

### Other Useful Protocols
- **ICMP**: its own IP protocol (not TCP/UDP). Used by `ping`, and for messages such as "destination unreachable" and "time exceeded" (TTL hit zero).
- **GRE**: tunnels packets inside IP, but **no encryption**. Pair with a VPN protocol.
- **IPsec**: standard encrypted tunnel, vendor-neutral. Gives confidentiality, packet signatures (integrity) and anti-replay. Parts: **AH** (authentication/integrity only, data in clear) and **ESP** (encrypts and authenticates, the usual choice). **IKE** sets up the **security association (SA)**: phase 1 uses Diffie-Hellman over **ISAKMP, UDP 500** to agree a shared secret, phase 2 negotiates the ciphers and key sizes for each direction. **Transport mode** encrypts only the payload and leaves the original IP header visible. **Tunnel mode** encrypts the whole original packet and adds a new IP header, which is what site-to-site VPNs use.

### Network Communication
- **Unicast**: one to one (web, email, file transfer). **Multicast**: one to a subscribed group, efficient for video, market feeds, routing updates, needs multicast-aware gear and stays inside a network. **Anycast**: one to the nearest of many identical hosts (for example anycast DNS). **Broadcast**: one to everyone in the local broadcast domain (ARP, some routing). **IPv6 has no broadcast**; it uses multicast.

## 1.5 Transmission Media
labs: hardware-diagnostics-and-repair
@notes
### Wireless Networking
- **IEEE 802.11** is the Wi-Fi standard. The **Wi-Fi Alliance** certifies interoperability (the Wi-Fi logo). Generation names: 802.11n = Wi-Fi 4, 802.11ac = Wi-Fi 5, **802.11ax = Wi-Fi 6** (6E adds the 6 GHz band), 802.11be = Wi-Fi 7. Older a/b/g are rarely used. Bands: 2.4, 5 and 6 GHz. Theoretical link rates rise each generation (antenna and radio counts change the numbers).
- **Cellular**: **4G LTE** (long term evolution, merged GSM and CDMA worlds) about 150 Mbps, LTE-A about 300 Mbps. **5G** (from 2020) target up to 10 Gbps, real-world 100 to 900 Mbps, which makes cellular a realistic wired substitute and enables big IoT deployments.
- **Satellite**: for sites with no terrestrial option. Roughly 100 Mbps down and 5 Mbps up. Needs line of sight, so storms cause **rain fade**. Classic latency is about 250 ms each way, newer low-orbit service (Starlink) advertises about 40 ms and falling.

### Ethernet Standards
- Ethernet is defined by **IEEE 802.3**. Name decoding: **1000BASE-T** = speed (1000 Mbps), BASE = baseband (one frequency, versus broadband), suffix = media. **T** twisted pair copper, **F**/**SX** fiber (SX is short-wavelength light). **10GBASE-T** = 10 Gbps over copper. The name hints at the standard but you must read the standard for the exact details.

### Optical Fiber
- Light over fiber: hard to tap without notice, signal survives far longer than copper (km versus 100 m), immune to radio interference. Parts: light source (LED or laser), **core** (reflective), **cladding** (low reflectivity), buffer coating.
- **Multimode**: wide core, several light modes, cheap LED light source, shorter runs (up to about 2 km). **Single-mode**: tiny core, one mode, laser, very long runs (up to about 100 km without regeneration).

### Copper Cabling
- **Twisted pair**: pairs carry opposite-polarity copies of the signal (TX+/TX-, RX+/RX-); twisting means interference hits both wires and is cancelled at the receiver. Each pair has a different twist rate. A cable has no "speed": the **Ethernet standard** and signal define the speed, and the **category** (Cat 5, 6, 7...) sets the minimum quality (1000BASE-T needs Cat 5 or better).
- **Coax**: center conductor, insulator, shield, jacket, all on one axis. **RG-6** is the cable-TV/cable-modem coax. **Twinax**: two conductors, used for short 10 Gb SFP+ links (about 5 m), cheap and low latency.
- **Plenum**: the air space above a drop ceiling. If it is shared air (no ductwork walls), cables there must be **plenum-rated** (FEP or low-smoke PVC jacket) so a fire does not pump toxic smoke through the building. Stiffer than normal cable.

### Network Transceivers
- A **transceiver** (transmitter + receiver) is a swappable module so one switch port can be copper or fiber, at the speed you need. Must match the switch type (Ethernet versus Fibre Channel).
- **SFP**: small form-factor pluggable, 1 Gbps. **SFP+**: same size, up to 10 Gbps (spec says to about 16). **QSFP**: four SFP channels in a slightly larger module, 4 Gbps. **QSFP+**: four SFP+ channels, 40 Gbps (can be split into four 10G links).

### Fiber Connectors
- **SC** (subscriber/square/standard): push-pull, snaps in. **LC** (local/Lucent/little): smaller, latch clip you press to release, very common now. **ST** (straight tip): round **bayonet**, push and twist. **MPO** (multi-fiber push on, branded MTP): 12 fibers in one push-pull connector, for density. Fibers usually come in pairs, one transmit, one receive.

### Copper Connectors
- **RJ11**: 6 positions, 2 conductors used (6P2C), analog phone and DSL. **RJ45**: 8 positions, 8 conductors, Ethernet. **F-connector**: threaded, coax for cable TV and cable modems (DOCSIS). **BNC**: bayonet-style coax connector (push, twist), named after Neill and Concelman.

## 1.6 Network Topologies
@notes
### Network Topologies
- **Star / hub and spoke**: everything connects to one central device (a switch). Most LANs. All spoke-to-spoke traffic goes through the hub. Hub is a single point of failure.
- **Mesh**: more than one path between locations, so a failed link does not break the connection and load can be shared. Common on WANs. Full mesh costs many links.
- **Hybrid**: a real enterprise mixes star, point-to-point, mesh and others.
- **Spine and leaf**: data center design. **Leaf** switches (one at the top of each rack, "top-of-rack") connect to every **spine** switch. Leaves never connect to each other, spines never connect to each other. Result: any two devices are one leaf-spine-leaf hop apart, cabling stays inside the rack, redundancy is built in. Cost grows with every rack because each needs a switch.
- **Point to point**: one link between two points, old T1/T3 WAN lines and building-to-building campus links.

### Network Architectures
- **Three-tier**: **core** (servers, apps, databases, the fast center), **distribution** (aggregates and redundantly connects access switches to the core), **access** (user-facing switches, usually per floor). Multiple links between layers give redundancy. City analogy: downtown = core, highways = distribution, local roads = access.
- **Collapsed core**: two tiers, core and distribution merged. Cheaper and simpler for small organizations, but less redundancy.
- **Traffic flow in a data center**: **east-west** stays inside the data center (server to server, fast). **North-south** enters or leaves (to or from the internet) and needs a different security posture.

## 1.7 IPv4 Addressing
labs: networking-tcp-ip-dhcp-nat-subnets
@notes
### Binary Math
- A **bit** is 0 or 1; 8 bits = a **byte / octet**. Write the place values right to left, doubling each time: **128 64 32 16 8 4 2 1**. Binary to decimal: add the place values under every 1 (`10000010` = 128+2 = **130**, `11111111` = **255**). Decimal to binary: go left to right and put a 1 whenever the place value still fits in what remains (154 = 128+16+8+2 = `10011010`).
- n bits give 2^n values (2 bits = 4, 3 = 8, 4 = 16, 5 = 32, 6 = 64, 7 = 128, 8 = 256).

### IPv4 Addressing
- IPv4 address: 32 bits, 4 octets, each 0 to 255, written dotted decimal. A **subnet mask** (also 4 octets, never sent on the wire) tells the host which addresses are on its own subnet. Traffic for anything else goes to the **default gateway**, a router address inside your own subnet (often .1).
- **Loopback** 127.0.0.0/8 (127.0.0.1 = this host; ping it to test the local IP stack). **Reserved / class E**: 240.0.0.0 and up. **VIP** (virtual IP): an address not tied to one physical NIC (for example on a VM or a router).
- Manual configuration (address, mask, gateway, DNS) was replaced by **DHCP**. If DHCP fails, the host gives itself an **APIPA / link-local** address **169.254.x.x** (169.254.1.0 to 169.254.254.255 usable), picked after an ARP check for conflicts. It only talks on the local subnet. **Seeing 169.254 means "DHCP did not answer".**
- **Private ranges (RFC 1918)**, not routable on the internet, reached out through **NAT**: **10.0.0.0/8** (10.0.0.0 to 10.255.255.255, 16.7 million), **172.16.0.0/12** (172.16.0.0 to 172.31.255.255, about 1 million), **192.168.0.0/16** (about 65,000). IPv4 public space is exhausted, which is why NAT exists.

### Classful Subnetting (the starting point)
- Classes by first octet: **A 1-126** (mask 255.0.0.0, /8), **B 128-191** (255.255.0.0, /16), **C 192-223** (255.255.255.0, /24), **D 224-239** multicast, **E 240-255** reserved. First bits: A `0`, B `10`, C `110`, D `1110`, E `1111`. Classes were abandoned in 1993 but are still the mental starting point.
- Four numbers to know for any subnet: **network address** (all host bits 0), **first usable** (network + 1), **broadcast** (all host bits 1), **last usable** (broadcast - 1). Example 192.168.4.77/24: network .4.0, first .4.1, broadcast .4.255, last .4.254.

### IPv4 Subnet Masks (CIDR)
- Since 1993: **classless** (CIDR). The mask is a run of 1s then 0s, written as a **prefix length** (/24 = 255.255.255.0). Windows wants the dotted mask, routers and switches usually accept /nn.
- Octet values for a partial mask: **128, 192, 224, 240, 248, 252, 254, 255** (one to eight 1-bits). /26 = 255.255.255.192, /20 = 255.255.240.0, /12 = 255.240.0.0, /19 = 255.255.224.0.

### Calculating IPv4 Subnets and Hosts (VLSM)
- **VLSM** cuts the pizza any way you like. Subnets = **2^(borrowed bits)**. Hosts per subnet = **2^(host bits) - 2** (minus network and broadcast).
- 10.1.1.0/24 (borrowing 16 bits from the /8): 65,536 subnets of 254 hosts. 192.168.11.0/26: 4 subnets of 62 hosts. 172.16.55.0/21: 32 subnets of 2,046 hosts.
- Sizing: need 40 hosts per subnet, 192.168.1.0/24? /27 gives 30 hosts (too few), **/26 gives 62** (right answer, 4 networks). /25 = 126 hosts, 2 networks. /30 = 2 hosts (point to point). /31 and /32 are special (no usable hosts in the classic sense).

### Magic Number Method (no binary)
1. Write the mask in decimal. 2. The **interesting octet** is the one that is neither 255 nor 0. 3. **Magic number = 256 minus the mask value** in that octet (the block size). 4. Network address: copy the IP octets where the mask is 255, put 0 where the mask is 0, and in the interesting octet use the **multiple of the magic number at or below the IP's value**. 5. Broadcast: copy where 255, use 255 where 0, interesting octet = network value + magic number - 1. 6. First = network + 1, last = broadcast - 1.
- Worked: 165.245.77.14 mask 255.255.240.0. Interesting octet is the third (240). Magic = 16. 77 falls in 64-79, so network **165.245.64.0**, broadcast **165.245.79.255**, range .64.1 to .79.254.
- Worked: 10.180.122.244 mask 255.248.0.0. Interesting octet 2, magic 8, 180 is in 176-183, so network **10.176.0.0**, broadcast **10.183.255.255**.
- Worked: 172.16.242.133/27 (255.255.255.224). Magic 32, 133 in 128-159, network **172.16.242.128**, broadcast **.159**, hosts .129 to .158.

### Seven Second Subnetting (chart method)
- Build a table once on the exam whiteboard: for each prefix, the decimal mask, number of subnets (2,4,8...256) and block size (128, 64, 32, 16, 8, 4, 2, 1). Prefix to octet: /9-/16 = second octet, /17-/24 = third, /25-/30 = fourth. Then: network = copy address where mask is 255, 0 where mask is 0, block start in the interesting octet; broadcast = the number just before the next block start (255s where mask is 0). Same answers as magic number, just lookups instead of subtraction.
- Check: 165.245.12.88/26: block size 64, 88 is in 64-127, network .12.64, broadcast .12.127, hosts .65-.126. 160.245.12.88/20: third octet mask 240, blocks of 16, .12 is in 0-15, network x.x.0.0, broadcast x.x.15.255. 18.172.200.77/11: mask 255.224.0.0, blocks of 32, 172 is in 160-191, network 18.160.0.0, broadcast 18.191.255.255.
- Practice tip: pick one method and drill it until it is automatic. On a testing-center whiteboard bring your own fine-tip dry-erase pen if allowed.

## 1.8 Network Environments
labs: virtualization-proxmox, firewalls-pfsense
@notes
### Software Defined Networking
- Every network device has three planes. **Data plane (infrastructure layer)**: the forwarding itself (moving frames between interfaces, trunking, encryption, NAT). **Control plane**: the tables and logic that decide where traffic goes (routing, switching, NAT, firewall rule tables). **Management plane (application layer)**: how admins configure it (SSH, console, web GUI). **SDN** splits these into software so they can be virtualized and centrally controlled.
- **SD-WAN**: a WAN built for cloud-era traffic. It is **application aware** (it knows it is email or a database and sends it straight to the nearest cloud service instead of back through HQ), **transport agnostic** (fiber, 5G, DSL all fine), has **central policy management** (one console pushes policy to all SD-WAN routers) and **zero-touch provisioning** (devices update themselves when services move).

### Virtual Extensible LAN (VXLAN)
- Problem: apps and VMs span multiple data centers (**data center interconnect, DCI**) with different IP schemes and links. VLANs top out around 4,000 networks and are layer 2 only. **VXLAN** supports about **16 million** virtual networks (24-bit VNI) and runs over a **layer 3** network.
- Each data center has a **VTEP** (VXLAN tunnel endpoint, often the top-of-rack switch). Networks are named by a **VNI**. The original Ethernet frame is **encapsulated** in VXLAN inside **UDP** inside IP, routed across, then decapsulated on the far side, so VMs in different sites feel they are on the same LAN.

### Zero Trust
- Edge-only security leaves the inside wide open. **Zero trust**: every user, device and application is untrusted until verified, with authentication, encryption, extra firewalls and monitoring everywhere.
- **Policy-based / adaptive authentication** weighs who, where, from which IP, what connection and what time. Inside HQ in work hours = password; unknown foreign IP over VPN at 3 a.m. = more factors or deny.
- **Authorization** follows: role (help desk can read, the manager can edit), location, whether it is a managed laptop with a valid certificate. **Least privilege**: only the rights the job needs, never admin by default (malware on an admin's box gets admin everywhere).
- **SASE (secure access service edge)**: security in the cloud near the apps, with a client on every device. "Next-generation VPN." Combines networking (QoS, routing) with ZTNA, firewall as a service and DNS security, always on, for users anywhere reaching apps anywhere.

### Infrastructure as Code
- **IaC**: describe servers, networks, firewalls and apps in files and let the platform build them. Rebuild identically in another data center, version changes, redeploy. Cures **configuration drift**, enforces compliance, makes test = production, and documents the build.
- **Playbooks**: scripted response steps (breach investigation, ransomware recovery: remove from network, wipe, reimage, redeploy). Centralized in **SOAR** (security orchestration, automation and response).
- **Source / version control (Git)**: one central repository, tracked changes, **branches** for testing, **merging**, **conflict** detection when two people edit the same line.

### IPv6 Addressing
- IPv4: 32 bits, 4.29 billion addresses, exhausted, extended by NAT. **IPv6: 128 bits**, hexadecimal, eight 16-bit groups separated by colons. Example `fe80::5d18:652:6ffd:8f52`.
- **Compression rules**: drop leading zeros in each group, and replace one run of all-zero groups with `::` (only once per address). `2601:04C3:4002:BE00:0000:0000:0000:0066` becomes `2601:4C3:4002:BE00::66`. `2600:DDDD:1111:0001:0000:0000:0000:0001` becomes `2600:DDDD:1111:1::1`.
- IPv4 and IPv6 cannot talk directly. Bridges: **dual stack** (host runs both, separate routing tables, the common method today), **tunneling** (**6to4**: IPv6 over IPv4, needs a relay, no NAT, removed from Windows. **4in6**: IPv4 over IPv6; both rare now), **NAT64 + DNS64** (DNS64 hands an IPv6-only client a synthesized IPv6 address that points at the NAT64 router, which translates to the real IPv4 server).

## 2.1 Routing Technologies
labs: networking-tcp-ip-dhcp-nat-subnets
@notes
### Static Routing
- A router reads the destination IP, looks it up in its **routing table**, and sends it out the interface toward the **next hop**. Directly connected subnets are known automatically. **If there is no matching route the packet is discarded.**
- **Static route** = admin types it by hand on each router: `destination/prefix via next-hop`. Example: on router 1, send 10.10.20.0/24 to next hop 10.10.40.2 and 10.10.30.0/24 to 10.10.50.2.
- Pros: instant, no CPU or memory overhead, no protocol traffic, predictable and fairly secure, ideal for **stub networks** (one link in and out) or small networks. Cons: does not scale to hundreds of routers, easy to mistype and create a **routing loop**, no automatic rerouting when a link fails.

### Dynamic Routing
- Routers discover routes and tell each other via routing protocols (updates are often multicast). They adapt automatically to added or removed routers. Costs: CPU and memory, plus initial planning and config.
- **EIGRP**: Cisco-centric, easy to set up, converges fast, loop avoiding, efficient updates (admin distance 90).
- **OSPF** (open shortest path first): open standard, multi-vendor, a **link-state** protocol used inside one **autonomous system (AS)** (everything you control). Picks the lowest **cost** (based on bandwidth, link state, delay) and can load-balance equal-cost paths (admin distance 110).
- **BGP** (border gateway protocol): the **exterior gateway protocol** that routes between autonomous systems and runs the internet and WAN/ISP connections ("three napkins protocol").
- **RIP**: old, **hop count** metric (admin distance 120).
- Choose by what decides the best route (link state, hop count, speed), convergence speed, and vendor environment.

### Routing Technologies
- Reading an entry (Cisco style): code letter (**C** connected, **S** static, **R** RIP, **D** EIGRP, **O** OSPF, **B** BGP), destination/prefix, `[AD/metric]`, `via next-hop`, age, outgoing interface.
- **Best-match order**: 1) **longest prefix** (most specific route wins; for 192.168.1.6 a /32 beats /24 beats /16), 2) lowest **administrative distance** (trust of the source: connected 0, **static 1**, EIGRP 90, OSPF 110, RIP 120; lower is better), 3) lowest **metric** within one protocol (RIP = hop count, EIGRP and OSPF use their own calculations; metrics are not comparable across protocols).
- **FHRP (first hop redundancy protocol)**: two routers share a **virtual IP** used as the clients' default gateway. The active router owns it and the standby takes it over if the active router disappears, so clients never change settings (HSRP, VRRP are examples).
- **Subinterfaces**: one physical router interface split into virtual ones (`e1/1.10`, `e1/1.20`) so each VLAN on a **trunk** gets its own IP address ("router on a stick").

### Network Address Translation
- IPv4 ran out, NAT lets many private hosts share public addresses (private ranges in RFC 1918). **Static/dynamic NAT** swaps one private address for one public address (source address rewritten on the way out, destination rewritten on the way back).
- **NAT overload / PAT (port address translation)**: many inside hosts share one public IP, told apart by **translated port numbers** kept in the NAT table (10.10.20.50:3233 becomes 94.1.1.1:1055, the next host gets 94.1.1.1:1056). This is what your home router does.

## 2.2 Switching Technologies
labs: networking-tcp-ip-dhcp-nat-subnets
@notes
### VLANs and Trunking
- A LAN is one **broadcast domain**. A **VLAN** carves one physical switch into several separate broadcast domains (defined by number, per interface). Devices on different VLANs cannot talk without a router. Saves power, rack space and management versus one switch per network.
- Spanning several switches: one cable per VLAN does not scale, so use a **trunk** (**802.1Q**, "dot1q"). The switch **tags** each frame with a **12-bit VLAN ID** (inserted after the source MAC), so a single link carries up to **4,094** usable VLANs; the far switch reads the tag, strips it and delivers to the right VLAN. **ISL** was Cisco's old proprietary trunking, rarely seen now.
- **Default VLAN** (usually VLAN 1): where every port starts. **Native VLAN**: the one VLAN sent **untagged** on a trunk (for devices that do not speak 802.1Q and some management traffic). It must **match on both ends** or you get log errors.
- **Layer 3 switch**: switching plus routing in one box. Routing between VLANs uses **SVIs** (switched virtual interfaces), and routing may need to be enabled (sometimes a reload). Less capable than a real router ("a switch should switch, a router should route"), fine for small sites.
- **Voice and data**: VoIP phones and PCs share one cable (PC plugs into the phone). Put voice in its own VLAN (say 200) and data in another (100) so bursty data does not hurt call quality; the switch separates them with tagging.

### Interface Configurations
- **Speed** must match on both ends or there is **no link** at all. **Duplex** mismatch (one half, one full) still links but performs terribly. Auto-negotiate on both sides is the norm. First check on a bad Ethernet link: speed and duplex, then IP config (address, mask, gateway, DNS must match what the admin assigned).
- **Link aggregation (LAG / port bonding)**: bundle several ports into one logical link (four 1 Gb links = 4 Gb throughput) without causing a loop. **LACP** negotiates it automatically.
- **MTU**: normal Ethernet payload is **1500 bytes**. Fragmenting is slow and one lost fragment forces resending everything. Path MTU discovery is automatic but firewalls can break it, so you may need to set MTU by hand. **Jumbo frames** raise MTU up to about **9,000 to 9,216 bytes** (6x fewer frames), but **every device in the path** must support them or the frames are dropped.

### Spanning Tree Protocol
- A cable loop between switches makes frames circulate forever (Ethernet has no hop counter), creating a **broadcast storm** within seconds. **STP (802.1D)** prevents loops by **blocking** redundant ports.
- Port states: **blocking** (no forwarding), **listening** (clears tables, hears neighbors), **learning** (builds MAC table), **forwarding**, plus **disabled** (admin down). Roles: one **root bridge** is elected; each switch has a **root port** (best path to the root), **designated ports** (forward traffic) and **blocked** ports (the loop breakers). If a link fails, STP recalculates and unblocks a backup port.
- **RSTP (802.1w, Rapid STP)**: same idea, converges in about **6 seconds** versus 30 to 50 seconds for classic STP, and is backward compatible.

## 2.3 Wireless Devices
labs: vpn-tailscale
@notes
### Wireless Technologies
- IEEE 802.11 standards have friendly names: 802.11ac = Wi-Fi 5, 802.11ax = Wi-Fi 6 (6E extends into 6 GHz), 802.11be = Wi-Fi 7.
- **Frequencies and channels**: 2.4, 5 and 6 GHz bands, divided into numbered **channels** (2.4 GHz channel 6 is centered on 2.437 GHz, 5 GHz channel 44 on 5.220 GHz). **Channel width** (bandwidth) 20, 40, 80 or 160 MHz: wider is faster but uses more spectrum. The 2.4 GHz band has only **three non-overlapping channels (1, 6, 11)** at 20 MHz, 5 GHz has many more, 6 GHz even more.
- Older clients may only do 2.4 GHz. **Band steering** makes the AP nudge dual-band clients onto 5 GHz (better throughput) instead of letting them pick by signal strength alone.
- Regulation: the **FCC** in the US allocates spectrum; the ITU coordinates globally. **802.11h** adds interoperability: **DFS (dynamic frequency selection)** moves the AP off channels that conflict with other users (and tells clients), **TPC (transmit power control)** lets the AP tell clients to lower power.

### Wireless Networking
- **IBSS** = ad hoc, device to device with no AP (used when first configuring IoT gear).
- **SSID** = network name. **BSSID** = the AP's radio hardware (MAC) address. **ESSID** = the same SSID shared across multiple APs so clients **roam** seamlessly across the building.
- **Captive portal**: first connection redirects to a page for terms or login; success adds you to an access table for a set time (for example 24 hours).
- **Security modes**: open (no security), **OWE** (opportunistic wireless encryption: encrypts without a password, isolates users), **WEP** (broken), **WPA/WPA2/WPA3 Personal = PSK** (one shared passphrase), **Enterprise / 802.1X** (each person authenticates with their own credentials, so disabling an account cuts access). Enterprises should use 802.1X.
- **Antennas**: **omnidirectional** spreads signal in all directions (put the AP in the middle). **Directional** focuses signal: **Yagi** (high gain, narrow), **parabolic** (dish, collects and focuses, long distance). Gain is in dB: **every +3 dB roughly doubles** power.
- **Autonomous AP**: standalone (home). **Lightweight AP**: the brains live in a **wireless LAN controller** (WLC) managed over **CAPWAP** (control and provisioning of wireless access points), a single pane of glass for deploy, monitor, change, report.

### Network Types
- **Mesh**: APs link to each other and heal themselves if one drops (home mesh). **Ad hoc / IBSS**: two devices directly, no AP. **Point-to-point**: AP-to-AP links over long distance (building to building) needing the right antennas, power and frequency. **Infrastructure**: clients connect to a central AP (most common); some APs offer **client isolation** so wireless devices cannot talk to each other.

### Wireless Encryption
- Wireless needs authentication, **encryption** (confidentiality) and a **message integrity check**. **WEP**: vulnerable cryptography. **WPA**: temporary fix that ran on WEP hardware. **WPA2** (2004): **AES** with **CCMP** (counter mode with CBC-MAC, encryption and integrity together). **WPA3** (2018): AES with **GCMP** (Galois counter mode) and GMAC for integrity. Use the newest your devices support.

## 2.4 Physical Installations
labs: virtualization-proxmox
@notes
### Installing Networks
- A **distribution frame** is where cables are passively terminated (punch-down blocks, patch panels). **MDF** (main distribution frame): the central room (usually the data center) where WAN circuits and internal LAN runs come together and the core gear lives. **IDF** (intermediate distribution frame): a satellite closet per floor or building that connects back to the MDF.
- **Racks**: 19 inches wide, height in **rack units (U)** of 1.75 inches each, typically **42U** tall, depth varies. Lockable cabinets add physical security and need ventilation.
- **Cooling**: an **HVAC** designed for the heat load, with enough power, and tied into the fire system (shuts off if fire). **Hot aisle / cold aisle**: equipment faces so servers pull cold air from the cold aisle and exhaust to the hot aisle (cold air often through a raised floor, hot air drawn out of the ceiling). Cold aisles are often enclosed.
- **Cabling practice**: run one cable from each desk to a patch panel (**110 punch-down block** on the back, **RJ45** jacks on the front) and never touch it again. Moves, adds and changes are done with **patch cables** between the panel and the switch. Fiber panels: respect the **bend radius** and leave a **service loop** of slack for future changes.

### Power
- **Safety**: disconnect power before working, and remember capacitors in CRT monitors and laser printers can still shock you. Never ground yourself to an energized circuit.
- **Units**: **amps** (current, the hose diameter), **volts** (pressure, 120 V or 240 V), **watts = volts x amps** (120 V x 0.5 A = 60 W). **AC** (wall power: 110-120 V at 60 Hz in the US, 220-240 V at 50 Hz in Europe) is converted to **DC** inside device power supplies.
- **UPS**: batteries ride through outages and even out **brownouts** (low voltage) and **surges**. **Offline/standby** (cheapest, tiny gap that can reboot switches), **line-interactive** (boosts during brownouts), **online/double-conversion** (always on battery, no gap, preferred in data centers). Features: auto shutdown, capacity, outlets.
- **PDU**: power distribution unit, rack-mounted, often intelligent: IP-managed with a built-in web server, per-outlet remote power on/off.

### Environmental Factors
- Data centers use about 2 percent of US electricity, much of it for the environment. Ideal **humidity 40 to 60 percent** (too high: condensation, too low: static discharge). Temperature roughly **64 to 81 degrees F**. HVAC with sensors keeps it even.
- **Fire suppression**: no water on live equipment. Use inert gas or chemical agents that smother the fire (clean agent systems), integrated with HVAC shutdown to cut off oxygen.

## 3.1 Processes and Procedures
labs: help-desk-ticketing-osticket
@notes
### Network Documentation
- **Physical network map**: devices, cables and connections as built (you could follow the cable in the room), made in Visio, OmniGraffle, Gliffy. **Logical map**: high-level connectivity (sites joined across a WAN cloud) without ports and cables, good for planning new sites.
- **Rack diagram**: front view of a rack by unit number ("go to U15 in row 3, rack W and reboot that server") for remote hands. **Cable map**: floor plan with numbered drops that correspond to patch panel ports, vital for tracing faults. **Layered diagrams** overlay layer 1 (ports/cables), layer 2 (MAC addresses) and layer 3 (IP addresses).
- **Asset management**: tag every device (barcode or RFID) and keep one database tying tag, components, user, location, purchase date, warranty and installed software (license counts). Tags also let tickets refer to "router 42" and support depreciation.
- **IPAM (IP address management)**: plan and track subnets, DHCP scopes and who held which IP at what time (key with dynamic addressing), spot shortages, IPv4 and IPv6 in one console.
- **SLA (service level agreement)**: contract with a provider defining minimum service, for example 99.99 percent uptime or no more than 4 hours of unscheduled downtime.
- **Site survey**: map the wireless environment (all APs including neighbors, frequencies in use) to minimize interference. A **heat map** shows signal strength across the building. Repeat in shared buildings.

### Life Cycle Management
- **EOL (end of life)**: vendor stops selling and improving the product (may still patch). **EOS (end of support)**: no more patches or updates at all, a serious security risk. EOL means plan and budget a replacement, EOS means act now.
- **Patching**: OS and app updates are often monthly on a schedule with out-of-band emergency fixes (zero-days). Updates also change security configuration (password rules, firewall settings, anti-malware). **Firmware** (software embedded in hardware: printers, modems, thermostats) must be updated too, often by hand. Keep old firmware images so you can roll back. Vendors can be slow: some IoT firmware bugs took more than a year to fix, so security must decide whether to keep a device.
- **Decommissioning**: sanitize or destroy media before disposal, respect legal retention requirements (keep in secure storage until allowed), never throw gear in the trash.
- **Change management**: defined process with allowed change windows, approvals, install procedure and a **rollback plan**. **Service requests**: a help desk ticketing system for triage, assignment, resolution and closing.

### Configuration Management
- **Production configuration**: the tested standard for a device class including hardware revisions, firmware, drivers and software versions. Test in a lab first.
- **Backup before every change** (copy the config file, or a **VM snapshot**) so you can revert. Record changes so a system can be rebuilt after a disaster.
- **Baseline / golden configuration**: the certified known-good complete config of an application deployment (workstations, firewall, servers). Compare production against it for **integrity checks**: either fix production to match, or approve the change and update the baseline to a new version.

## 3.2 Network Monitoring
labs: siem-security-onion, network-traffic-analysis, log-analysis
@notes
### SNMP
- **SNMP** lets a management station query and manage devices from any vendor. Devices hold values in a **MIB** (management information base), each value addressed by an **OID** (object identifier, a dotted number path such as 1.3.6.1.2.1...). Standard values live in **MIB-2**; vendors add their own OIDs and provide MIB files to load into the console. Polling uses **UDP 161**.
- Versions: **v1** original, clear text. **v2/v2c**: bulk retrieval, still clear text. **v3**: encryption, integrity and real authentication (username and password hash).
- **Community strings** (v1/v2c) are simple shared passwords, for example read-only "public" and read-write "private" (change the defaults!). A **MIB walker** (MIB browser) enumerates everything on a device.
- Polling only finds a problem at the next poll, so devices can send **traps** (unsolicited alerts, **UDP 162**), such as a CRC error threshold, which can trigger tickets or scripts. Poll results over time become graphs of utilization and errors.

### Logs and Monitoring
- **NetFlow**: summary statistics of traffic flows (who talked to whom, ports, bytes). A **probe** (inline tap or switch **SPAN**/mirror port) summarizes packets and exports to a **collector** with reports: top conversations, top endpoints, top applications by port.
- **Protocol analyzer** (Wireshark etc.): see raw frames, wired or wireless, with drill-down. Some places store full packet captures long term.
- **Baseline**: what "normal" looks like (utilization, per device). Compare current numbers to the baseline to decide if something is wrong.
- **Syslog** (UDP 514) forwards logs from any device to a **SIEM** (security information and event manager), which records the sending device, **facility** (originating program) and **severity** of each message. Dashboards and alerts show failed logins, devices going offline, and reports across time. Tune the severity captured so you do not store everything. Example query: records containing "fail" and "password" reveal brute force or spraying and support forensics.
- **API integration**: manage hundreds of devices by script (send commands, query config) rather than logging in by hand to each.
- **Port mirroring (SPAN)** or a **network tap** copies traffic to a monitoring device (IDS/IPS, NetFlow collector), even across switches.

### Network Solutions
- **Discovery**: LLDP (open standard link layer discovery) and CDP (Cisco discovery protocol) show neighbors. Ping scans, port scans and SNMP discover hosts. Nightly scans give an inventory.
- **Traffic analysis**: firewall logs list timestamp, protocol, ports, client and server IP, application and bytes, useful for reports and forensics.
- **Performance** (utilization, errors) from SNMP, NetFlow, protocol analysis or agents. **Availability monitoring**: up/down status (green/red) with alerts, tickets and uptime reports.
- **Configuration monitoring**: back up and restore device configs (a config may need matching firmware, so keep the old software), compare identical devices, alert on unapproved changes via change control.

## 3.3 Disaster Recovery
labs: incident-response
@notes
### Disaster Recovery
- **DRP (disaster recovery plan)** covers backups, offsite replication, cloud replacements and alternate sites, plus third parties (temporary facilities, recovery services).
- **RTO (recovery time objective)**: how long until service is back (aim near zero; web server example one hour). **RPO (recovery point objective)**: how much data (time) you can afford to lose, determined by backup or replication frequency (banking, patient data need very short RPO; website edits can tolerate hours). On a timeline: last good recovery point, outage, restored service. Outage minus last recovery point = RPO, outage to restoration = RTO.
- **MTTR (mean time to repair)**: average time to fix a failure. **MTBF (mean time between failures)**: expected life before failure (20 years for a firewall means fewer spares needed).
- **Site resiliency**: moving operations to another site and back later. **Cold site**: empty building, bring everything, cheapest, slowest. **Warm site**: some infrastructure (power, racks, perhaps hardware), bring data and finish setup. **Hot site**: near exact replica with current data (replication), switch quickly, most expensive.
- **Testing**: a **tabletop exercise** is a meeting where key people walk through a scenario (a day or two, cheap). **Validation tests** perform the actual failover steps for a scenario (building fire, regional evacuation), once or more a year. Document what worked and fix the gaps.

### Network Redundancy
- **Active-passive**: two devices, one active, one standby, constantly exchanging status. On failure the standby takes over. Config, session tables and routing tables must be kept in sync.
- **Active-active**: both devices pass traffic at the same time, using all capacity, and the survivor simply carries the load after a failure. Needs more engineering because the two directions of a flow might take different paths, so you must track flows and design routing carefully.

## 3.4 IP Services
labs: networking-tcp-ip-dhcp-nat-subnets, linux-server-admin-ubuntu
@notes
### DHCP
- History: manual config, then **BOOTP**, then **DHCP**. The four-step **DORA** exchange: **Discover** (client, source 0.0.0.0, broadcast to 255.255.255.255, UDP 68 to 67), **Offer** (server, broadcast, UDP 67 to 68), **Request** (client picks one offer, broadcast), **Acknowledge** (server confirms, client applies the settings). Everything is broadcast because the client has no IP yet.
- Broadcasts do not cross routers, so central DHCP servers use a **DHCP relay / helper** on the router. The relay turns the broadcast into a **unicast** to the DHCP server (source becomes the router's interface IP) and turns the reply back into a broadcast on the client subnet.

### Configuring DHCP
- A **scope** (per subnet): the address **pool/range**, **exclusions**, subnet mask, **lease duration** and **options** (DNS servers, default gateway, VoIP call server). Servers remember MAC-to-IP pairings and will often give you the same address back.
- **Reservation** (static DHCP, IP reservation): bind a MAC address to a fixed IP in the server, so printers and servers always get the same address and are still managed centrally.
- **Lease timers**: **T1 = 50 percent** of the lease: client tries to **renew** with the original server. **T2 = 87.5 percent (7/8)**: if that failed, the client **rebinds** with any DHCP server. Example, 8-day lease: T1 at 4 days, T2 at 7 days. Clients release their address on shutdown.
- **DHCP options**: numbered fields (up to 254) for extra settings, for example **option 129** call server IP, **option 135** HTTP proxy. The server must support the option.

### IPv6 and SLAAC
- DHCPv6 exists, but IPv6 hosts can also self-configure (**stateless**, no leases, no server). **NDP (neighbor discovery protocol)** replaces ARP and uses **multicast**, not broadcast. **SLAAC** steps: host sends a **router solicitation (RS)**, router answers with a **router advertisement (RA)** (the 64-bit prefix, prefix length, DNS and other parameters; routers also send **unsolicited RAs**). The host builds the **last 64 bits (interface ID)** from its MAC address (modified EUI-64: insert `ff:fe` in the middle) or randomizes it. **Duplicate address detection (DAD)** checks nobody else uses it. Result: a unique, routable address.

### An Overview of DNS
- DNS translates names to IPs. Hierarchy: root (`.`, 13 server clusters, over 1,000 servers), **TLDs** (.com, .org, .net, country codes like .us .uk), domains, hosts. A full name is an **FQDN** (www.example.com). Use redundant servers: **primary** (holds the editable zone) and **secondary** (read-only copy).
- **Local resolution**: the **hosts file** (Windows: `C:\Windows\System32\drivers\etc\hosts`, usually needs write permission changed) overrides DNS for testing or fixes. Some apps ignore it.
- **Forward lookup**: name to IP (`dig www.example.com`, `nslookup`). **Reverse lookup**: IP to name (`dig -x 1.2.3.4`). The reverse name can differ from the forward name (for example a CDN's name).
- **Authoritative** server = owns the zone. **Non-authoritative** = answered from a cache or secondary copy. **TTL** (seconds) controls how long caches keep an answer (300 = 5 minutes).
- **Recursive resolution**: the client (resolver) asks its local DNS server, which asks a **root server** (points to the .com servers), then the **TLD server** (points to the domain's name server), then the **authoritative server** (gives the IP), caches it and answers the client.
- **Security**: DNS is clear text and unauthenticated. **DNSSEC** digitally signs responses (authenticity and integrity, not secrecy). **DNS over TLS (DoT)** encrypts on **TCP 853**. **DNS over HTTPS (DoH)** encrypts inside HTTPS on **TCP 443** (looks like web traffic, many browsers use it by default).

### DNS Records
- **SOA** start of authority (zone info, serial, refresh/retry/expire). **A** hostname to IPv4. **AAAA** (quad-A) hostname to IPv6. **CNAME** alias to another name (needs a second lookup). **MX** mail exchanger for the domain (points at a name that needs an A record). **TXT** free text, used for **SPF** (which servers may send mail for you) and **DKIM** (public key to verify mail signatures). **NS** the domain's name servers. **PTR** reverse lookup (IP to name, stored in a reverse zone such as 23.168.192.in-addr.arpa).

### Time Protocols
- **NTP** (UDP 123): clients sync to servers; accurate to milliseconds (about 10 ms from a local server). Servers do not set their own time, a client component syncs them upstream. Many orgs run an internal NTP server. Critical for log correlation, and **Kerberos fails if clocks differ by more than 5 minutes** (feeding wrong time is a denial of service).
- **NTS (network time security)** authenticates NTP: TLS handshake with an **NTS key exchange server** gets a **cookie** that the client includes in NTP requests. **PTP (precision time protocol)**: hardware-based, **nanosecond** accuracy, for industrial uses.

## 3.5 Network Access
labs: vpn-tailscale, linux-server-admin-ubuntu
@notes
### VPNs
- A VPN encrypts traffic across a public network to a **VPN concentrator** (often the firewall). **Client-to-site**: VPN client software on a laptop, started manually or **always-on**. **Site-to-site**: concentrators at two sites build a permanent encrypted tunnel; users are unaware. **Clientless VPN**: runs in an HTML5 browser (web cryptography API), no software to install.
- **Full tunnel**: all client traffic goes through the VPN (corporate controls everything but it adds a detour for internet traffic). **Split tunnel**: only corporate-bound traffic uses the VPN, other traffic goes straight to the internet (more efficient, less visibility and protection).

### Remote Access
- **SSH** (TCP 22): encrypted remote terminal, replaces **Telnet** (TCP 23, clear). **RDP** for remote Windows desktops, **VNC** (uses the **RFB** protocol, many OSes) for graphical control. **API**: automate device management with the device's own language, with error handling, instead of scripts over CLI.
- **Console**: direct serial connection to a device (RJ45 serial, DB9, or USB-to-serial) with a text CLI. Works even when the network is down. **Jump server (jump box)**: a hardened, MFA-protected host you reach through VPN or SSH, then hop to internal devices. Keep it patched.
- **In-band management**: reach the device over the network via its management IP using SSH or a web GUI (sometimes a dedicated management interface). **Out-of-band management**: a path that does not use the production network: serial console/COM port, a separate management network, even a **modem on a phone line** or a **COM server** to dial in when everything else is down.

## 4.1 Network Security Concepts
labs: computer-networks, active-directory
@notes
### Security Concepts
- **Data in transit** (in motion) crosses a network; switches and routers only forward it, so protection comes from firewalls, IPS and **encryption (TLS, IPsec)**. **Data at rest** sits on storage; protect with **full disk, database, or file/folder encryption** plus **ACLs** set by the OS.
- **PKI** = policies and processes managing keys and certificates. A **certificate authority (CA)** signs certificates so anyone trusting the CA trusts them. Internal CAs sign for internal users and devices (public CA for the internet). A **web of trust** is the decentralized alternative: if A trusts B and B trusts C, A trusts C.
- **IAM** = identity and access management: authentication, authorization and auditing of who touches data. **Least privilege**: only the rights the job needs. **Role-based access control (RBAC)**: permissions attach to roles, users get roles (in Windows, via groups).
- **Geofencing / geographic restriction**: allow or deny based on location, found by IP (inaccurate), GPS, or the Wi-Fi network/access point.
- **Physical**: **CCTV** (motion detect, plate or face recognition, central recording), locks (key, deadbolt, PIN, RFID badge, biometrics); combine for multiple factors.

### Authentication
- **AAA**: identification (public, such as a username), **authentication** (prove it with private info), **authorization** (what you may access), **accounting** (log logins, logouts, failures). A VPN or switch sends credentials to an **AAA server**, which says approved or denied.
- **SSO**: log in once, use many resources, usually for about a day. Depends on the auth method.
- **RADIUS**: widely supported AAA protocol (VPN, 802.1X Wi-Fi, switches, firewalls). **LDAP**: read/write a directory (X.500 attributes: OU, org, location, domain). Containers and leaf objects form a tree; used by Active Directory, OpenDirectory, eDirectory. **SAML**: open XML standard for web SSO. Client hits a resource, is redirected to the identity provider, authenticates, gets a signed token and presents it to the resource. **TACACS+**: Cisco-origin AAA protocol, now open; separates AAA functions.
- **MFA** factors: something you **know**, **have**, **are**, somewhere you **are**. **TOTP**: time-based one-time password from a shared secret plus the clock (about 30 seconds), needs time sync.

### Security Technologies
- **Honeypot**: a decoy system to watch attackers. **Honeynet**: a whole decoy network (servers, workstations, routers, NAS).
- **Risk** = exposure to harm. **Vulnerability** = a weakness. **Exploit** = using a vulnerability. **Threat** = what could exploit it (agent, action, or accidents like fire or flood).
- **CIA triad**: **confidentiality** (encryption, access limits), **integrity** (unchanged data; hashes, digital signatures), **availability** (systems usable when needed).

### Regulatory Compliance
- Laws and standards bring fines or worse. **Data localization**: data on a country's citizens must stay inside it. **GDPR** (EU): protects personal data of EU residents (name, address, photo, email, bank, browsing); gives people control, including deletion. **PCI DSS** (an industry standard, not a law): six goals, secure network, protect cardholder data, vulnerability program, strong access control, monitor and test, security policy. Failing audits can end your right to process cards.

### Segmentation Enforcement
- Segment physically or with VLANs for **performance** and **security** (limit who talks to whom; PCI requires it for card data).
- **IoT** (sensors, cameras, doorbells) is often weakly secured: put it on its own network. **IIoT** and **SCADA/ICS** (large industrial control, real-time) and **OT** (grid, traffic, plants) need uptime and isolation. **Guest network**: internet only, no internal access, passphrase or login. **BYOD**: personal devices get a segmented work area (company data can be wiped on exit).

## 4.2 Attack Types
labs: network-traffic-analysis
@notes
### Denial of Service
- **DoS**: make a service unavailable, by overload, a software flaw, a distraction while another attack runs, or plain physical action (cut power, water leak). Accidents count: a **switching loop** without **STP** floods the network, and one huge download can saturate a small link.
- **DDoS**: many devices (a **botnet**) attack together. It is **asymmetric**: attackers with few resources beat big ones.
- **Reflection and amplification**: the attacker sends small spoofed requests (source = victim) to open servers; they answer the victim with far bigger replies. Protocols abused: **NTP, DNS, ICMP**. Example: a 28-byte DNS query with the `ANY` type returned about 1,300 bytes. Defenses: patching, rate limits, anti-spoofing filters, closing open resolvers, upstream scrubbing.

### VLAN Hopping
- VLANs separate traffic unless a router connects them. Two tricks cross without a router:
- **Switch spoofing**: the attacker pretends to be a switch; if the port auto-negotiates a **trunk** (DTP), they reach every VLAN on it. Fix: **disable trunk auto-negotiation**, set ports manually to access, and list the allowed VLANs on trunks.
- **Double tagging**: a frame with two 802.1Q tags. The first switch strips the tag that matches the **native VLAN** and forwards the frame, the next switch reads the second tag and drops it onto the target VLAN. Traffic is **one-way** (no replies), enough for DoS. Fix: don't put users in the native VLAN, change native VLAN from 1 to an unused ID, and tag the native VLAN.

### MAC Flooding
- A **MAC address** is 48 bits (6 bytes, hex); first 3 bytes = **OUI** (vendor), last 3 = NIC serial. The **burned-in address** is stored in ROM.
- A switch **learns source MACs** per port into a **MAC (CAM) table**; entries age out in about 5 minutes (STP also uses MACs). Frames for known MACs go out one port only; **unknown destinations are flooded** to all ports.
- **MAC flooding**: send many frames with random source MACs to fill the limited table; then all traffic floods like a **hub** and the attacker can sniff it. Fix: **port security** (limit MACs per port, sticky MACs, violation action).

### ARP and DNS Poisoning
- **Spoofing** = pretending to be another person/device (email, caller ID, IP, DNS). It enables **on-path** (man-in-the-middle) attacks.
- **ARP** has no authentication and accepts unsolicited replies. In **ARP poisoning** the attacker sends a reply "192.168.1.1 is at attacker-MAC", the victim caches it, and all its router traffic goes through the attacker (usually forwarded on, so nobody notices). Defenses: **dynamic ARP inspection (DAI)**, static entries, 802.1X.
- **DNS poisoning**: change records on the DNS server or forge responses in transit (often from an on-path position), or edit the client **hosts file** (which overrides DNS). Victims are sent to the attacker's server. Defenses: DNSSEC, patching, DoT/DoH, locked-down hosts file.

### Rogue Services
- **Rogue DHCP server**: DHCP has no authentication, so a fake server can hand out bad IPs, gateways or DNS (outage or on-path). Defenses: **DHCP snooping** (only trusted ports may answer), AD-authorized DHCP servers. If found, remove it and renew all leases.
- **Rogue access point**: an unauthorized AP plugged into the LAN (or OS Wi-Fi sharing). Find with wireless scans and walk-arounds; prevent with **802.1X (NAC)** on switch ports.
- **Evil twin**: malicious AP copying a real SSID/captive portal, often at higher power. Always use **VPN or HTTPS**.
- **On-path attack**: sits between two parties to read or change traffic. Examples: evil twin, ARP poisoning, session hijacking, HTTPS spoofing, Wi-Fi eavesdropping. Encryption limits the damage.

### Social Engineering
- **Phishing**: spoofed message to steal data. Check the sender domain, link target, spelling and graphics; open suspicious links only in an isolated VM, better, don't click.
- **Shoulder surfing**: watching a screen (also through windows, binoculars, or hijacked webcams). Use privacy filters, sit back to a wall, face screens away from windows.
- **Tailgating**: follow an authorized person through a door without their knowledge. **Piggybacking**: they let you in knowingly (hands full, "hold the door"). Prevent with **badges, one-at-a-time rules, access control vestibules (airlocks)**, and employees who challenge unbadged strangers.
- **Dumpster diving**: sorting through trash for names and documents. Prevent by locking or fencing bins, cameras, **shredding** or burning.

### Malware
- **Virus**: needs a human to spread. **Worm**: self-replicates over the network with no help (more dangerous, uses unpatched vulnerabilities). **Ransomware**: encrypts data and demands payment for the key. **Trojan**: disguised as something wanted. **Rootkit**: hides inside the OS, hard to detect or remove. **Keylogger**: records keystrokes and credentials. **Adware/spyware**: ads and spying for profit. **Bloatware**: unwanted preinstalled software (not malicious, wastes resources). **Logic bomb**: triggers on a date or event. **Botnet / bot**: remote-controlled infected hosts. **Backdoor**: hidden remote access.
- Delivery: links, pop-ups, **drive-by downloads**. Defense: patch OS and apps, don't click, backups.

## 4.3 Network Security Features

@notes
### Device Security
- **Close unused ports/services**: every listening service is an entry point (ports 0 to 65,535). Check with **nmap**; use a **firewall** to limit who can reach the ones you keep.
- **Change default credentials** on every switch, router and firewall; default admin logins are public.
- **Port security** (switches): limit the number of MACs per port or pin specific MACs; a violation usually **shuts the port down** and alerts the admin. Stops someone swapping in their own device.
- **Disable unused interfaces** (wall jacks, conference rooms) until needed.
- **NAC / 802.1X**: require authentication before a port or Wi-Fi network works.
- **MAC filtering**: allow or block by MAC. Weak, **security through obscurity**: MACs are easy to sniff and change.
- **Key management**: central console to create, track expiry, renew, revoke and report on certificates, SSL keys and SSH keys per user or service.

### Security Rules
- **ACL**: allow/deny list matching source and destination IP, port, protocol, time or application. Found on routers, firewalls and operating systems.
- **Firewall rules** are read **top to bottom, first match wins**: put specific rules first, general ones last. If nothing matches, the **implicit deny** blocks the traffic. Sample rule base: allow TCP 22, 80, 443, 3389 in; allow UDP 53 and 123 out; deny ICMP; implicit deny at the end.
- **URL filtering**: allow or block specific URLs or **categories**; combine with firewall rules so users can't bypass. **Content filtering** goes further: inspect content for leaked documents or financial data, unsafe content, malware (antivirus). Next-generation firewalls include both.
- **Screened subnet (DMZ)**: separate network for public services (web, mail) so the internet reaches them but not the internal LAN.
- **Zones**: group networks into **trusted/untrusted**, or inside, internet, server, database and screened subnet zones. Rules reference zones rather than IPs ("trusted to untrusted: allow", "untrusted to trusted: deny"). This is a **zone-based firewall**.

## 5.1 Troubleshooting

### Network Troubleshooting Methodology
- Steps in order: **1 identify the problem** (gather information, question users, identify symptoms, determine what changed, duplicate the problem if possible, approach multiple problems individually). **2 establish a theory of probable cause** (question the obvious; consider multiple approaches such as top-down or bottom-up through the OSI model, or divide and conquer). **3 test the theory**; if it fails, make a new theory or escalate. **4 establish a plan of action** and identify potential effects. **5 implement the solution** or escalate. **6 verify full system functionality** and implement preventive measures. **7 document** findings, actions and outcomes.
- Ask "what changed?" (cables moved, device powered off, config edits). Users plus switch and router metrics give the best picture. Labs help reproduce problems; split large problems into pieces.
- Start with quick, obvious causes (swap a cable). Eliminating variables helps: if the issue shows on two operating systems, the OS isn't the cause.
- Production changes go through **change control** with a **plan B, plan C and a rollback**. The troubleshooters and the team implementing the change may differ. Always confirm the fix with the users, discuss prevention, then record it in the help desk or knowledge base.

## 5.2 Physical Issues
labs: hardware-diagnostics-and-repair, computer-networks
@notes
### Cable Issues
- **Fiber mismatch**: single-mode (core about 9 microns, one light path) vs multimode (50 or 62.5 micron core, many paths), all with 125 micron cladding, so they look identical. Mixing them causes signal errors. Colors are not reliable; read the jacket print and document your fiber. Transceivers must also match the **wavelength** (850 nm multimode, 1310 nm single-mode).
- **Copper categories** (set by TIA, minimums come from IEEE): **1000BASE-T** needs Cat 5 up to **100 m**; **10GBASE-T** needs Cat 6 (UTP about **55 m**) or Cat 6A (100 m). **Bandwidth** = theoretical maximum; **throughput** = what you actually move. Wrong category means errors and slowdowns.
- **UTP vs STP**: STP has a shield (grounded) around the cable or each pair; use it near interference.
- **Crosstalk**: leaking between pairs. **NEXT** near-end, **FEXT** far-end, **alien** from other cables. **ACR** compares attenuation to near-end crosstalk, like signal to noise (higher is better). Fix: re-terminate, keep twists up to the connector, use Cat 6A with spacers.
- **EMI**: keep cables away from power lines, fluorescent lights, generators and fire systems; never break the shield. Respect **bend radius**, no staples, use Velcro ties, not tight plastic ones.
- **Attenuation**: loss of signal over distance (copper, fiber, Wi-Fi); explains length limits.
- **Bad terminations**: pins must match end to end (1-1, 2-2...). Wrong pins drop speed (1 Gb falls to 100 Mb), **reversed** pairs give no link, **crossed** pairs (half cross) appear as 1-3 and 3-1. Auto-MDIX may hide this, but terminate properly. Always test with a **cable tester**.

### Interface Issues
- Monitor with **SNMP** (standard counters in **MIB-II**, plus vendor MIBs). Watch **link status** (up/down), **utilization** and **errors**.
- Ethernet frame: preamble/SFD, destination MAC, source MAC, EtherType, payload, **FCS**. A bad FCS = **CRC error** (cable, interface, duplex or interference). **Runt** = under 64 bytes (collisions on half duplex). **Giant** = over 1,518 bytes (or over the configured jumbo size). **Drops** = no buffer room (congestion).
- **Error disabled**: the switch shut a port itself (flapping link, port security violation, errors). It stays down until an admin re-enables it. **Administratively down**: an admin turned it off. **Suspended**: incompatible configuration at once, for example **LACP** on one side only.

### Hardware Issues
- **PoE**: power on data wires. Source: **endspan** (PoE switch) or **midspan** (injector). Standards: **PoE 802.3af 15.4 W**, **PoE+ 802.3at 25.5 W**, **PoE++ 802.3bt** type 3 up to 51 W and type 4 up to 71.3 W (cameras, laptops). Check device class and the switch's **total PoE budget** (such as 200 W or 720 W).
- **Transceiver mismatches**: wavelength and fiber type must agree; labels are small and hidden once inserted.
- **Power budget**: transmit power (dBm) minus loss (distance, connectors, splices) = received power; it must be **above the receiver sensitivity**. Example: sensitivity -17 dBm; receiving -15 dBm is fine, -20 dBm is too weak.

## 5.3 Troubleshooting Network Services
labs: computer-networks, networking-tcp-ip-dhcp-nat-subnets
@notes
### Switching Issues
- Ethernet frames have no TTL, so a **switching loop** circulates forever and broadcast/multicast storms kill the network. **Spanning Tree Protocol (STP)** prevents them.
- STP switches exchange **BPDUs** (MAC multicast, hello **every 2 seconds**). Missing **three** hellos = link down and the topology is recomputed. A **root bridge** is elected: **lowest bridge ID** wins (settable from 0 to 61,440 in steps; ties broken by lowest MAC). Others pick a **root port** toward the root; **designated ports** forward; **blocked/discarding** ports break loops. Port states: **blocking/discarding, listening, learning, forwarding**, **disabled** (admin). Failures unblock ports automatically.
- **VLAN issues**: device has an IP but can't reach neighbors? Check the **access port's VLAN ID** on the switch.
- **ACLs**: if routing and VLANs look right but packets disappear, check ACLs on the path. Like firewall rules: first match, specific entries first, **implicit deny**, so an empty ACL on an interface blocks everything. Be careful editing ACLs on the interface you are managing through (you can lock yourself out).

### Routing and IP Issues
- Check the **routing table on every router** along the path and the **return path**. No route = packet dropped, often with **ICMP destination/host unreachable**. Compare with a network map.
- **Gateway of last resort** = default route, **0.0.0.0/0**, usually static (`ip route 0.0.0.0 0.0.0.0 10.10.50.2`). Routing table sources: directly connected, static, learned (RIP, OSPF, etc.).
- **Address pool exhaustion**: clients get **APIPA 169.254.x.x** (local only, nonroutable). Check the DHCP server or **IPAM**, enlarge the pool, **shorten the lease** on transient networks.
- **Incorrect IP, mask or gateway**: verify with the admin, packet capture, or other devices. Test in order: **ping self, ping gateway, ping beyond the gateway** (and traceroute).
- **Duplicate IPs**: static device inside a DHCP pool, overlapping scopes on two servers, or a rogue DHCP server. Modern OSes warn on conflict. Ping the address before assigning; if it answers, find it: ping, then **ARP table** for the MAC, then **switch MAC table** for the port. Capture DHCP offers to catch duplicate servers.

## 5.4 Performance Issues
labs: computer-networks
@notes
### Performance Issues
- **Congestion**: more traffic arrives than a link can send (two 1 Gb links into one 1 Gb uplink). Small buffers fill and packets are **dropped**. Fix: faster links, more links, or less traffic (QoS).
- **Bottleneck**: the slowest component limits everything (bus, CPU, storage, slowest link). Drill down: the example web transaction at about 1,500 to 1,750 ms was dominated by the database; a database fix cut it to about 500 ms.
- **Bandwidth (utilization)** percentage over time, **throughput** actual data moved; gather with the switch, **SNMP** or **NetFlow**.
- **Latency**: delay between request and response; measure at each hop with packet captures (microsecond resolution).
- **Packet loss/discards**: valid packets dropped by congestion or outage; corruption (bad cable, weak Wi-Fi) forces retransmission.
- **Jitter**: variation in the time between packets. Voice and live video need regular spacing; high jitter causes clicks and stutters.

### Wireless Issues
- **Interference and channels**: 2.4 GHz has only three non-overlapping channels in North America (**1, 6, 11**). Channel 8 would overlap 6 and 11. 5 GHz and 6 GHz have many more. Let APs auto-select channels; recheck manual ones.
- Best practices: **disable legacy/low-speed support**, lower output power on small areas, split big networks across APs on different channels, upgrade to newer standards.
- **Signal attenuation**: weaker with distance. Use a **Wi-Fi analyzer** and **heat map**; raise power (if supported), add a **higher-gain antenna**, keep coax runs short and undamaged. Run **site surveys** repeatedly (neighbors change).
- **Client disassociation**: older 802.11 management frames are unprotected, so an attacker can kick clients off (DoS). Look for deauth frames in a capture; newer standards (protected management frames) prevent it.
- **Roaming**: multiple APs with the **same SSID** must have **identical settings** and security, or roaming clients get dropped.

## 5.5 Tools and Protocols
labs: network-traffic-analysis, linux-command-line, networking-tcp-ip-dhcp-nat-subnets
@notes
### Software Tools
- **Protocol analyzer** (Wireshark): decodes captured frames from wired or wireless links. Devices can capture natively and export files. Some sites capture all packets to disk for later search.
- **nmap** (network mapper, an **active** scanner): finds hosts in a range (even with layer-2 scans on the same subnet, so rogue devices can't hide), **open ports**, **services and versions**, **OS** guesses, and runs scripts (NSE). Unexpected open ports (the example showed 22, 80, 443, 548 AFP, 2049 NFS) need investigation.
- **CDP** (Cisco proprietary) and **LLDP** (vendor-neutral, IEEE) are **discovery protocols**: neighbors announce name, addresses, port, native VLAN and software, so you learn the wiring and config without logging in.
- **Speed tests**: measure download and upload before and after a change and at different times of day. Test sites differ by distance and load; your ISP's own site is often the most accurate (also fast.com, speedtest.net).

### Command Line Tools
- **ping**: ICMP echo request/reply; shows reachability, TTL, round-trip time, loss. Ctrl+C prints statistics (continuous ping on Linux and macOS; Windows `-t`). First test on any problem.
- **traceroute** (`tracert` on Windows): maps the routers on the path by sending packets with TTL 1, 2, 3 and so on; each router answers **ICMP time exceeded**, revealing its IP and latency (three probes per hop). `*` means ICMP is filtered or lost. Compare traces to find where a path breaks. Windows uses ICMP echo; Linux and macOS default to UDP and can change the payload.
- **nslookup** (deprecated) and **dig**: query DNS directly (A, MX, TXT and more) and choose a server (`dig @1.1.1.1 example.com`). Several A records can exist for redundancy.
- **tcpdump** (Linux/macOS; WinDump on Windows): CLI packet capture with filters, saves **pcap** files for Wireshark.
- **netstat**: `-a` all connections and listeners, `-n` numeric (no DNS), `-b` (Windows) shows the executable, shows states (established, waiting, closing).
- **ipconfig** (Windows; `/all` adds MAC, DHCP, DNS), **ifconfig** (Linux/macOS, deprecated) and **ip address** (modern Linux) show IP settings.
- **arp -a**: local ARP cache of IP-to-MAC pairs (works on every OS). Pinging a host fills the entry; use the MAC to look it up in a switch's MAC table.

### Hardware Tools
- **Tone generator + inductive probe**: put an analog tone on a wire, hold the probe near cables to find the far end in a bundle. Many probes also test continuity.
- **Cable tester**: continuity only (pins 1 to 8 in order, shorts, opens, crossed wires); it doesn't certify a category. **Certifier** does the category tests.
- **Taps**: copy traffic to an analyzer. **Physical tap** (breaks the link at install; **passive** = unpowered, common on fiber; **active** = powered, regenerates the signal). **Port mirror / SPAN**: switch copies a port's traffic to another port; limited by the mirror port's bandwidth (a 2 Gb stream cannot fit a 1 Gb mirror), so use a tap for heavy links.
- **Wi-Fi analyzer**: shows channels, strengths, APs and interference; **spectrum analyzer** shows every signal on a range of frequencies (microwave ovens, non-Wi-Fi sources) and signal-to-noise ratio.
- **Visual fault locator (VFL)**: a fiber flashlight; light leaks out where the fiber is broken or bent too much.

### Basic Network Device Commands
- Syntax varies by vendor but the ideas match. Examples (Cisco-style): `show mac address-table`, `show ip route` (codes: **C** connected, **S** static, **R** RIP, plus a more specific route wins), `show interface` (up/down, line protocol, speed, duplex, MTU, CRC, drops, input/output errors, rates), `show running-config` (active config; `show startup-config` for stored), `show arp`, `show vlan`, `show power inline` (PoE use: for example 370 W capacity, 40 W used, 330 W free).

Command picker
Pick one command for each: (1) who is using TCP 443 on this PC, (2) MX records for example.com, (3) which switch port has MAC aa:bb:cc:dd:ee:ff, (4) is PoE power left on the switch.
@answer
(1) `netstat -ano` (or `-b`). (2) `dig example.com MX`. (3) `show mac address-table address aa:bb:cc:dd:ee:ff`. (4) `show power inline`.
