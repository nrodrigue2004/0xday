## 1.1 Operating Systems
labs: operating-systems
@notes
### Operating Systems Overview
- The OS sits between hardware and applications: it moves data between storage, memory and CPU, handles input and output, manages files, and ships its own maintenance utilities. Apps are written for one OS; a Windows executable will not run on Linux, though document formats (and web apps) move freely.
- **Windows**: biggest market share, huge hardware/software support, many editions (10, 11, Server). Downsides: the biggest malware target, and driver quality depends on each hardware vendor.
- **Linux**: free and open source, many distributions, runs on almost anything, community support only (no single vendor); newer hardware may lack drivers.
- **macOS**: Apple hardware only, polished, security-minded, tightly integrated; costs more and has less industry support.
- **Chrome OS**: Google, built on the Linux kernel, browser-centered, light, needs a network connection for most apps.
- **iPadOS**: a tablet version of iOS (Safari desktop browser, Sidecar second display, keyboard and multitasking). **iOS**: closed source, Apple hardware only; apps built with Apple's SDK on macOS and approved by Apple before the App Store. **Android**: open source, Linux-based, run by the Open Handset Alliance, many hardware makers, apps via Google Play and third-party stores.
- Watch **end of life** (each vendor sets its own) and keep systems patched.

### File Systems
- Partitions must be formatted with a file system before data is stored.
- **NTFS**: Windows default; compression, encryption, quotas, permissions. Linux/macOS read it (modern ones write too). **ReFS**: resilient, self-repairing, huge volumes, server-oriented, not widely deployed.
- **FAT32**: old, max volume 2 TB and file size 4 GB. **exFAT**: for flash drives, files over 4 GB, works across Windows, macOS, Linux.
- **ext4**: Linux and Android standard. **XFS**: high-performance, large-volume Linux file system with journaling and low fragmentation. **APFS**: Apple, tuned for SSDs, built-in encryption and snapshots (iOS, iPadOS, macOS).

## 1.2 Installing Operating Systems
labs: windows-deployment-and-drivers, secure-data-sanitization
@notes
### Boot Methods and Install Types
- **Boot sources**: bootable USB, **PXE** (network boot from a server), internal/external drives, internet-based install (minimal Linux installers, macOS Recovery, Windows Update), optical media or an **ISO image** (a full disk image file, common with VMs). Multi-boot lets you choose between OSes at startup.
- **Clean install**: wipes the partition and starts fresh. **In-place upgrade**: keep apps, data and settings. **Image deployment**: build one reference system, capture the image, apply to many. **Remote network install** from a share. **Recovery partition**: hidden partition with install files. **Repair installation**: reinstalls OS files but keeps user files. **Third-party drivers**: load them from the installer prompt when storage or network hardware is not detected.
- **Zero-touch deployment**: automated install that also applies company settings (domain join, mail), so a user can turn on a new laptop and wait.

### Partitions and Formatting
- A **partition** is a logical section of a drive; a formatted partition is a **volume** (Microsoft's term).
- **GPT** (GUID Partition Table): needs UEFI, up to 128 partitions, huge drive support (Windows caps at 256 TB), all partitions equal. **MBR**: legacy, 2 TB maximum, 4 primary partitions (only primary can boot, one marked active) plus one extended partition holding non-bootable logical drives. BIOS compatibility mode disables Secure Boot.
- Changing partitions can destroy data; back up first.
- **Quick format** only rebuilds the file table (fast, old data recoverable, default in Windows 10/11). **Full format** writes zeros across the disk (slow, more secure). diskpart can do full formats.

### Upgrading Windows
- Upgrade keeps applications, accounts and settings and is faster; a clean install removes everything. Neither is better, so choose per case and **back up first**. Start an upgrade from inside the running OS; start a clean install by booting the installation media.
- Check requirements first: memory, disk space, driver and app compatibility, license keys. Windows 11 needs **TPM 2.0**, **UEFI with Secure Boot**, a supported CPU and enough RAM. Use **PC Health Check**; view TPM with `tpm.msc` and Secure Boot state in System Information.
- **Life cycle**: monthly quality updates, feature updates every six months to a year, support usually 18 to 36 months (Microsoft Modern Lifecycle Policy).

## 1.3 Microsoft Windows
labs: operating-systems, group-policy, active-directory
@notes
### Windows Editions
- Core 2 covers **Windows 10 and Windows 11** (all in-support versions are in scope). There is no Windows 9. Windows 10 support for Home and Pro ended **14 Oct 2025**, but it is still seen in production. Windows 11 (Oct 2021) is **64-bit only**, new Start menu and taskbar, snap layouts, Teams integration, touch improvements and Copilot.
- **Home**: consumer. Microsoft account/OneDrive, Defender, no domain join, no BitLocker (Win 11 Home has **Device Encryption**, recovery key stored in the Microsoft account), no group policy, Remote Desktop **client only**, 128 GB RAM max (64-bit).
- **Pro**: business. Domain join, BitLocker, Remote Desktop **host and client**, group policy, Hyper-V, 2 TB RAM max.
- **Pro for Workstations** (Win 10): up to four CPUs, 6 TB RAM, ReFS.
- **Enterprise**: volume licensing, up to 6 TB RAM, AppLocker, BranchCache, granular UX control; MDM/MAM management (Win 11), ReFS.
- 32-bit Windows (Win 10 only) caps at **4 GB RAM**.
- **N editions** (Europe) ship without media player and multimedia tools; add the Media Feature Pack from Settings > Apps > Optional features.

### Enterprise Features
- **Active Directory Domain Services (AD DS)**: central, distributed database of users, computers, permissions; centralizes authentication. A **workgroup** manages each device separately (home). Domain-joined PCs get a standard locked-down desktop; at home you can customize freely.
- **Remote Desktop**: the RDP client runs on nearly any OS; the Remote Desktop service runs on Pro/Enterprise only.
- **EFS** encrypts chosen files/folders (part of NTFS); **BitLocker** is full-disk encryption (OS and data). Both help if a laptop is lost.
- **Group policy**: `gpedit.msc` for a single machine (local policy), `gpmc.msc` Group Policy Management Console for domains.

## 1.4 The Windows OS
labs: windows-admin-powershell, log-analysis
@notes
### Task Manager
- Open with **Ctrl+Shift+Esc**, Ctrl+Alt+Del, or right-click the taskbar. Tabs: **Processes** (running apps and background processes with CPU, memory, disk, network, GPU columns you can sort), **Performance** (60-second graphs), **Users** (connected users, can disconnect), **Startup** (enable or disable boot-time apps; disable groups to find a culprit), **Services** (start, stop, restart).

### Microsoft Management Console (mmc.exe)
- MMC starts empty; add **snap-ins** (File > Add/Remove Snap-in), save the console as a file, and reload it later.
- **Event Viewer** (`eventvwr.msc`): Application, Security, Setup, System logs; levels informational, warning, error, critical, audit success/failure; filter by level, source, user, computer.
- **Disk Management** (`diskmgmt.msc`): drives, partitions, file systems, drive letters; shrink, extend, mirror. Back up before changes; you can lose data.
- **Task Scheduler** (`taskschd.msc`): triggers, actions, conditions and settings; automate recurring jobs; folders for organization.
- **Device Manager** (`devmgmt.msc`): hardware by category; update, disable or uninstall drivers. Drivers are specific to the Windows version.
- **Certificate Manager** (`certmgr.msc`): view, add, remove certificates (trusted root CAs).
- **Local Users and Groups** (`lusrmgr.msc`): built-in Administrator and Guest, groups such as Administrators, Users, Backup Operators, Power Users.
- **Performance Monitor** (`perfmon.msc`): hundreds of counters over time, alerts, reports; lets you review a problem after it happened.
- **Group Policy**: `gpedit.msc` (local; computer configuration and user configuration, administrative templates) and `gpmc.msc` (domain).

### Additional Tools
- **System Information** (`msinfo32.exe`): read-only summary of hardware resources, components, software environment; also shows Secure Boot state.
- **Resource Monitor** (`resmon.exe`): real-time CPU, memory, disk, network detail per process.
- **System Configuration** (`msconfig.exe`): General (normal, diagnostic, selective startup), Boot (safe boot, no GUI, boot log), Services, Startup (moved to Task Manager), Tools.
- **Disk Cleanup** (`cleanmgr.exe`): removes temp files, downloads, recycle bin.
- **Defragment** (`dfrgui`, `defrag`): needed for HDDs only; SSDs do not need it.
- **Registry Editor** (`regedit.exe`): hives start with HKEY (Classes Root, Current User, Local Machine, Users, Current Config). Back up (export) a key before editing; run the .reg file to restore.

## 1.5 The Windows Command Line
labs: windows-admin-powershell, networking-tcp-ip-dhcp-nat-subnets
@notes
### Command Prompt Basics
- Open with `cmd`; some commands need an **elevated** prompt (Run as administrator, or **Ctrl+Shift+Enter** from search; you must be in Administrators).
- Help: `help`, `help dir`, or `dir /?`.
- Navigation: `dir` lists files; `cd`/`chdir` changes directory; `cd ..` goes up one; `md`/`mkdir` creates; `rd`/`rmdir` removes. Paths use backslashes and a drive letter (`C:\Users\name`). Tab autocompletes.

### Disk and File Commands
- **`chkdsk /f`** fixes file-system index errors; **`chkdsk /r`** also scans every sector (slow; includes /f). Needs admin; a locked system volume is checked at the next restart.
- **`format`**: initializes a partition with a file system (defaults to FAT32 if none given); erases the partition; admin only.
- **`diskpart`**: partition tool (`list disk`, `list volume`, `list partition`, format, etc.); needs admin.
- **`copy`**: `/v` verifies the copy, `/y` suppresses overwrite prompts (useful in batch files). **`robocopy`** (robust copy) has many more options: bandwidth throttling, retries after interruptions, subdirectories.
- **`sfc /scannow`**: System File Checker detects and repairs changed or corrupt core Windows files; details in cbs.log.

### System and Identity Commands
- `hostname`: the computer name (confirm you are on the right machine before a restart). `winver`: Windows version dialog. `whoami`: current user; `whoami /all` adds SID, groups and privileges.
- **`gpupdate /force`** forces a group policy refresh; **`gpresult /r`** shows the resultant set of policies (RSoP) applied to the user and computer.

### Network Commands
- **`ipconfig`**: IP, mask, gateway; `/all` adds hostname, DNS servers, DHCP, MAC. Also `/release`, `/renew`, `/flushdns`.
- **`ping`** (ICMP): tests reachability; reports replies, round-trip time, TTL, loss; default 4 packets. 
- **`netstat`**: connections and ports; `-a` all, `-b` shows executable (admin), `-n` numeric addresses. Columns: protocol, local address, foreign address, state (ESTABLISHED, CLOSE_WAIT...).
- **`nslookup`**: DNS queries; name to IP and IP to name; uses the default DNS server.
- **`net view \\server`** lists shares; **`net use H: \\server\share`** maps a drive; **`net user name /domain`** shows account details (active, password last set/expiry, groups).
- **`tracert`**: maps routers by sending packets with TTL 1, 2, 3...; each router decrements TTL and replies "time exceeded" at 0. TTL in IPv4 counts hops, not seconds. Firewalls that block ICMP hide hops.
- **`pathping`**: tracert first, then measures loss and round-trip time at every hop (takes minutes).

labs: windows-admin-powershell
@notes
### Control Panel
- Open by searching "control". Switch from Category to **large/small icons** to see every applet.
- **Internet Options** tabs: General (history), Security (zones: internet, intranet, trusted, restricted), Privacy (cookies, pop-up blocker), Content (certificates, autocomplete), Connections (VPN/dial-up, **proxy** under LAN Settings: automatic or manual), Programs (add-ons, defaults), Advanced.
- **Devices and Printers**: friendly front end for connected and network devices (printer properties) without Device Manager detail.
- **Programs and Features**: installed apps, uninstall/repair, and **Turn Windows features on or off** (e.g. IIS, Hyper-V, media features).
- **Network and Sharing Center**: connections, adapter status and properties, IPv4 properties (static, DHCP, DNS), "change adapter settings".
- **System**: edition, version, CPU, RAM, domain/workgroup; **Advanced system settings** > Performance Settings (visual effects, **virtual memory/paging file**), System Protection.
- **Windows Defender Firewall**: separate settings for domain, private and public/guest profiles; on by default.
- **Mail** applet only appears when a client such as Outlook is installed (accounts, data files, profiles).
- **Sound**: playback and recording devices, default device.
- **User Accounts**: local accounts, standard vs administrator, password, UAC settings, file-encryption certificates.
- **Device Manager**: add/remove devices; driver tabs General, Driver, Details, Events, Resources.
- **Indexing Options**: controls what Windows Search indexes; include or exclude folders and file types.
- **Administrative Tools / Windows Tools**: Computer Management, Task Scheduler, Registry Editor, etc.
- **File Explorer Options**: General (click behavior, privacy), View (hidden files, extensions), Search (system dirs, zip contents, file names vs contents).
- **Power Options**: plans; **Hibernate** saves memory to disk (no power needed); **Sleep/Standby** keeps state in RAM (low power draw); lid-close action, USB selective suspend, display timeout. **Fast Startup** is a hybrid hibernate, so Windows never fully shuts down; turn it off if you need a true shutdown.
- **Ease of Access**: magnifier, narrator, on-screen keyboard, high contrast.

### Settings App
- Newer single interface. **Time & Language**: set time automatically, time zone, language and region (**correct time matters because Active Directory/Kerberos needs it**). **Windows Update**: automatic updates, active hours. **Personalization**: colors, background, lock screen. **Apps**: install, uninstall, optional features. **Privacy & Security**: antivirus, firewall, data sharing, speech. **Bluetooth & Devices**: audio, printers, mouse, pen. **Network & Internet**: Ethernet, Wi-Fi, VPN, proxy, IP and DNS. **Gaming**: Game Bar. **Accounts**: Microsoft and local accounts, email, sign-in options such as PIN and MFA.

## 1.7 Windows Networking
labs: networking-tcp-ip-dhcp-nat-subnets, vpn-tailscale, active-directory
@notes
### Shares, Workgroups and Domains
- A **share** exposes a file, folder or printer on the network. Map a drive letter in File Explorer (Map network drive: `\\server\share`, reconnect at sign-in, different credentials) or with `net use H: "\\server\Share Name"` (quote names with spaces). A trailing **$** makes a share **hidden** (e.g. `ADMIN$`); it still works if you know the name. View shares in Computer Management > Shared Folders.
- **Workgroup**: standalone devices each with their own accounts (home). **Domain**: central Active Directory credentials and policies, managed by IT; needs **Pro or better** (not Home). Join via Settings > System > About > Domain or workgroup > Change, with domain credentials.
- **Share a printer**: Printer properties > Sharing tab > Share this printer.

### Windows Defender Firewall
- Always on by default; turn off only temporarily for troubleshooting (needs elevation). Settings per profile: turn on/off, **block all incoming connections**, notify on blocked apps.
- Allow an app through the firewall, or open **Windows Defender Firewall with Advanced Security**: inbound/outbound rules, connection security rules, monitoring. New rule types: Program, **Port**, Predefined, Custom. Example: block inbound TCP 80 on all profiles.

### IP Configuration
- **DHCP** is the default. Without DHCP or a static address Windows falls back to **APIPA 169.254.x.x** (link-local only, no internet). Use an **Alternate Configuration** tab (set when "obtain automatically" is selected) to supply a fallback static address instead.
- Static settings: **IP address, subnet mask, default gateway**, plus **DNS**. Or use a **DHCP reservation**. **Loopback 127.0.0.1** verifies the local IP stack.

### Network Connections
- Create via Network and Sharing Center or Settings > Network & Internet.
- **VPN**: encrypted tunnel from a client to a concentrator. Built-in client needs the server address; can add a smart card for MFA. Toggle from the system tray network icon.
- **Wi-Fi**: needs SSID, security type (WPA2/WPA3), encryption (AES, not old TKIP), and either **PSK** (personal) or **802.1X** enterprise authentication against a central server.
- **Wired**: usually fastest, so it is the default route. **WWAN**: cellular via built-in or USB modem, or phone tether/hotspot (may need vendor software).
- **Proxy**: intermediary that makes requests for you; set automatic or manual in Internet Options or Settings, with exceptions.
- **Network profiles**: **private** (trusted, sharing allowed) vs **public** (no sharing or inbound by default). **Metered connection** limits data use; set data limits.

## 1.9 Linux
labs: linux-command-line, linux-server-admin-ubuntu
@notes
### Linux Basics and Boot
- Linux is free, Unix-like, offered as many **distributions** (Ubuntu, Debian, Red Hat...). Community support; drivers for brand-new hardware can lag. A GUI is optional; most configuration is **text files**.
- **Boot**: BIOS/UEFI picks the boot device from its boot order > the **bootloader** (UEFI reads EFI files from the **EFI System Partition**) > the **kernel** (core of the OS, runs in kernel space; apps run in user space) > **systemd** starts and manages background services called **daemons**. The administrator account is **root**.
- Key files in `/etc`: **passwd** (users, UID, GID, home, shell; password field shows x), **shadow** (hashed passwords, readable only with elevated rights), **hosts** (name to IP; overrides DNS), **resolv.conf** (DNS servers), **fstab** (file system table of what mounts at boot).

### File and Permission Commands
- `ls` (list; `-l` details, `-a` hidden, `-la`), `pwd` (print working directory), `cd` (`cd ~` goes home), `man cmd` (manual page; q quits), pipe output to `more` to paginate.
- `mv src dst` moves **or renames**; `cp src dst` copies; `rm file` deletes (`-r` removes directories and contents).
- **chmod**: `r=4, w=2, x=1`. Three groups: **user (owner), group, others**. `chmod 744 file` = owner rwx, group r--, others r--. `ls -l` first column: type (`-` file, `d` directory) then rwx x3. Symbolic: `chmod u+x script.sh`, `chmod a-w first.txt` (u, g, o, a; `+` add, `-` remove).
- **chown**: `sudo chown jack file`, `sudo chown professor:backup file` (owner:group); needs elevation.
- **sudo** runs one command as superuser (preferred); **su** switches the whole session to root (`exit` to return).
- **grep text file** searches for text in files. **find** locates files by name: `find . -name "third.*"`.
- **fsck**: file system check (usually at boot, before mounting). **mount** lists mounts or mounts a device (like net use); pipe to grep to filter.
- **Package managers**: `sudo apt install wireshark` (Debian/Ubuntu); **dnf** (Red Hat/RPM, successor of YUM).

### Network and Diagnostics
- **`ip address`** (interfaces, IPs, MACs), `ip route` (routing table); also configure and enable/disable interfaces. Old `ifconfig` replaced.
- **`ping`**: Linux pings continuously until Ctrl+C (default 56 bytes), then prints a summary.
- **`curl URL`**: fetch raw HTML/data from a URL for scripting. **`dig name`**: DNS query (like nslookup), shows question/answer sections. **`traceroute`**: like tracert, uses TTL, 3 probes per hop.
- **`cat`**: show a file; `cat one two three > all.txt` concatenates. **`top`**: live processes and CPU/memory, plus load averages for 1, 5 and 15 minutes. **`ps`**: process snapshot (`ps -e` all processes; pipe to grep). **`df -h`**: free space per file system in human-readable units. **`du -h`**: space used by folders (find what is eating the disk). **`nano`**: simple terminal text editor (Ctrl+X to exit).

## 1.10 Installing Applications
labs: windows-deployment-and-drivers, operating-systems
@notes
### Requirements
- **32-bit vs 64-bit**: 32-bit addresses about 4 GB of memory; 64-bit addresses vastly more (about 17 billion GB theoretical). Drivers must match the OS bit width. A **64-bit OS runs 32-bit and 64-bit apps; a 32-bit OS cannot run 64-bit apps.** Windows stores 64-bit apps in `Program Files` and 32-bit in `Program Files (x86)`. Check System > About.
- **Graphics**: integrated (GPU in the CPU) vs a **dedicated/discrete** graphics card for 3D, video editing.
- **RAM**: requirement applies to the app alone, not the OS plus other apps; check Task Manager. **CPU speed** (GHz, cycles per second) and cores vary by workload. **Storage** space for the app and its data.
- **Licensing**: key, or a **hardware token** (USB dongle) for expensive niche software.

### Distribution
- Download from the **developer or official store**, not third-party sites. Physical media (USB, optical) for offline machines such as isolated data center systems. **ISO files** hold a full disk image with an ISO 9660 file system; mount to see contents.
- **Disk images** capture an OS plus patches, apps and settings for fast deployment, but hardware must match (VMs make this easy).

### Business Impact
- An installer runs with the **user's permissions**, so it can reach everything the user can. Untested apps can overwrite data, break other apps, slow systems, change the UI (retraining, workflow changes) or crash the machine. Test in a lab or **sandbox** first, and have a recovery plan.

## 2.1 Security Measures
labs: system-hardening-windows-linux, active-directory
@notes
### Physical Security
- **Bollards/barricades**: stop vehicles while letting people walk through. **Access control vestibule** (mantrap): small room between outside and inside; only one door opens at a time; staff check ID. **Badge readers**: RFID/NFC (older magnetic stripe); badges can also clock in and log guard rounds.
- **Video surveillance (CCTV)**: networked cameras to a central recorder; infrared at night; motion alerts; modern cameras read plates and recognize faces.
- **Alarms and sensors**: circuit sensors on doors, windows, fences; motion detection; **duress button** under a desk.
- **Locks**: conventional key and deadbolt; electronic PIN lock; token (RFID); biometric. Combine factors (badge + PIN + fingerprint). **Lock server racks and cabinets** (doors front and back, perforated for airflow).
- **Guards and badges**: security guard at reception checks ID. ID badges with photo, visitor badges, pre-registered **access lists**, and logs that create an **audit trail**. **Fences** (tall, sturdy, razor wire) form a perimeter. **Lighting** deters intruders and improves camera images. **Magnetometers** (metal detectors) find metal only, not ceramic.

### Physical Access Methods
- **Key fob**: RFID tag on a keychain, used like a badge. **Smart card**: stores a signed **certificate**; use with PIN or biometric; reader built into laptop or external USB. **Mobile digital key**: key on your phone (cars, hotels, offices), protected by phone unlock. Keep **physical keys** as backup, in a cabinet with sign-out and ID collateral.
- **Biometrics** store a mathematical template, not a picture: retina scan (very accurate; capillaries), fingerprint, palm scan, facial recognition (3D dot map, about 1-in-1-million false acceptance), voice recognition (weakest; changes with health; combine with other factors).

### Logical Security
- **Least privilege**: only the rights needed for the job. **Zero trust**: trust nothing by location; authenticate every user, device and app; internal MFA, encryption, segmentation, analytics.
- **ACL (access control list)**: allow/deny rules based on source or destination IP, TCP/UDP ports, protocol; also seen as file permissions on Windows and Linux.
- **MFA** factors: something you **know**, **have**, **are**, **somewhere you are**. Email confirmation links also act as a factor. **Authenticator apps and hardware tokens** generate codes. **SMS** codes are weak (SIM swap/number reassignment, social engineering of the carrier). **Voice-call** codes share the same flaw. **TOTP** (time-based one-time password) changes about every 30 seconds using a shared secret and synced clocks (Google Authenticator). **HOTP/OTP** codes are single-use from a list/counter.

### Authentication and Access
- **SAML**: open standard where the app redirects to an identity/authorization server; the client gets a signed token and presents it to the resource server. Fine for web, not designed for mobile apps. **SSO** (single sign-on) avoids repeated logins; sessions time out (often ~24 h) and the auth protocol must support it.
- **Just-in-time access**: temporary (ephemeral) admin credentials issued from a password vault so a stolen standard account has no admin rights. **PAM (privileged access management)** vaults, automates and audits admin and root accounts.
- **MDM (mobile device management)**: central control of company and BYOD phones/tablets: policies (lock screen, PIN), app control, separate company data partition, remote wipe of company data. **DLP (data loss prevention)**: detects and blocks sensitive data (SSNs, card numbers, medical records) leaving via endpoints, cloud, email, firewall. **IAM**: lifecycle, authentication, authorization and auditing of digital identities for people and devices. **Directory services** (Active Directory) are the single repository of users, groups, devices and permissions; help desks reset passwords there.

## 2.2 Windows Security
labs: system-hardening-windows-linux, group-policy, windows-admin-powershell
@notes
### Defender Antivirus
- Built in and on by default (Microsoft Defender Antivirus, in the **Windows Security** app > Virus & threat protection). Keep **real-time protection** on; only disable temporarily (UAC prompt appears). Settings include cloud-delivered protection, automatic sample submission, tamper protection, controlled folder access, exclusions. Update definitions via Protection updates > **Check for updates**.

### Windows Firewall
- Enable/disable per profile (domain, private, public) in Windows Security > Firewall & network protection (needs admin). **Block all incoming connections** overrides allowed-app rules (useful on public Wi-Fi). Configure firewall notifications; **Security providers** shows which AV/firewall is active (to spot third-party products).

### Authentication Settings
- **Local account** (on the PC), **Microsoft account** (cloud sync across devices), **domain account** (Active Directory). Default local accounts: Administrator, Guest (limited), Default; groups include Administrators, Backup Operators, Guests, Users, Power Users (legacy). Manage in Computer Management > Local Users and Groups.
- Login options: password, **PIN**, biometrics, SSO. **Passwordless** methods (Windows Hello, facial recognition, security keys) avoid weak or written-down passwords; the first login may still use a password.

### File Permissions
- **NTFS permissions** (local file system) vs **share permissions** (network access). When both apply, the **most restrictive wins**, and an explicit **deny** overrides allows. NTFS permissions are inherited by child folders and new files. **Explicit** permissions override inherited ones. Moving a file within the same volume keeps its original permissions.
- Example: NTFS Everyone full control but share Everyone read: a network user only gets read.

### Elevation and Encryption
- **Run as administrator** is explicit even for admins. **UAC (User Account Control)** prompts "Do you want to allow this app to make changes?" for admin tasks; levels range from always notify to never.
- **BitLocker** (FDE) encrypts a whole volume; **BitLocker To Go** protects USB drives. **EFS** encrypts selected files/folders on NTFS (not in Home) using your credentials; if the password is administratively reset, encrypted data can be lost, so keep backups.

### Active Directory
- **AD** is a centralized database of users, computers, shares and printers that provides authentication and permissions. **Domain controllers** host and replicate it (distributed). Computers must be explicitly **joined** by an administrator (Settings > System > About > Domain or workgroup, or PowerShell), then rebooted and logged in with domain credentials.
- **OUs (organizational units)** organize objects (by site, building, department) and are where policies attach. Manage with **Active Directory Users and Computers**: reset passwords, disable accounts, add to groups, **move** objects between OUs (which changes the policies they get).
- **Group Policy Objects (GPOs)** are created and linked in Group Policy Management; edit under user or computer configuration (e.g. Administrative Templates > Desktop to hide the Recycle Bin). `gpupdate /force` refreshes; some settings need logoff/logon.
- **Logon scripts** (User Configuration > Policies > Windows Settings > Scripts) can map drives (e.g. `net use G: \\server\share`). **Home folders** map a personal network drive (`\\server\home\%username%`). **Folder redirection** sends Documents, Desktop and Downloads to a server for backup, often paired with **offline files** for laptops.
- **Groups** assign permissions at scale: add users to groups instead of setting rights per user (e.g. Remote Desktop Users).

## 2.3 Wireless Security
labs: network-traffic-analysis, firewalls-pfsense
@notes
### Wireless Encryption
- Wireless traffic is in the air, so you need **authentication**, **encryption**, and a **Message Integrity Check (MIC)** to detect tampering. A wireless analyzer sees everything unencrypted.
- **WEP** (Wired Equivalent Privacy): broken. **WPA** (2002): stopgap using **TKIP** on existing hardware. **WPA2** (2004): **AES** encryption, needed newer access points, still common. **WPA3** (2018): stronger AES, safer initial key exchange, and encryption even on **open networks**.
- **Open system**: no password (coffee shop). **Personal mode**: WPA2/WPA3 with a **pre-shared key (PSK)** everyone uses. **Enterprise mode / 802.1X**: each user logs in with their own credentials checked against a central authentication database, so removing one user's account ends their wireless access.

### Authentication Methods
- Central auth servers (**AAA**: authentication, authorization, accounting) let VPN, switches, firewalls and Wi-Fi share the same credentials.
- **RADIUS**: widely supported, used for VPN, wireless 802.1X, network devices. **TACACS+**: Cisco-associated, open standard, more detailed responses. **Kerberos**: Windows domain protocol; authenticate once, get tickets from a ticket-granting service; mutual authentication that resists on-path and replay attacks. Non-Windows systems may need smart cards or SAML for SSO.
- Pick the one your infrastructure supports (VPN needs RADIUS, Cisco gear uses TACACS+, Windows uses Kerberos).
- **MFA factors** also include **something you do** (a signature). Costs vary: hardware tokens cost more than phone apps.

## 2.4 Malware
labs: malware-analysis, password-cracking-john
@notes
### Malware Types
- **Entry paths**: vulnerabilities (then a **backdoor**), malicious links, pop-ups, **drive-by downloads**, worms (rare). Patch OS and apps.
- **Trojan**: looks useful, runs with your rights. **Rootkit**: embeds in the OS and hides from scanners and Task Manager; **UEFI Secure Boot** (checks signatures) largely stops them; use rootkit-specific removers. **Virus**: needs a human to run it; spreads via files or USB. **Spyware**: watches activity; **keylogger** records keystrokes (plus mouse, screenshots). **Ransomware**: encrypts files and demands payment (backups are the defense). **Boot sector virus**: infects the bootloader; Secure Boot checks it. **Cryptominer**: hijacks CPU (even via JavaScript on a web page). **Stalkerware**: spyware installed by someone you know to track location, camera, mic. **Fileless malware**: runs only in memory, abusing PowerShell and a vulnerability, may add a registry autostart. **PUP (potentially unwanted program)**: bundled adware, toolbars, fake backup tools, hijacked search.

### Anti-malware Tools
- **WinRE (Windows Recovery Environment)**: boot from install media, or Shift+Restart, or Settings > Recovery > Advanced startup. Troubleshoot > Advanced options > Command Prompt, Startup Repair, UEFI firmware settings. Use it to remove malware, edit services, repair boot.
- **EDR** (endpoint detection and response): behavioral analysis and machine learning rather than signatures; root-cause data; can isolate, quarantine and roll back. **MDR** is EDR run by a third party, often an **MSSP**. **XDR** correlates endpoint, network and cloud data.
- Real-time **antivirus/anti-malware** with behavior detection. **Email gateway** (on-prem or cloud) scans mail for malicious links/attachments. **Software firewall** on each endpoint blocks inbound and outbound traffic, including malware calling a **command and control** server.
- **User training**: phishing simulations, posters, message boards, login banners, intranet docs, one-on-one training.
- **Remediation**: the only way to be sure malware is gone is **wipe and restore** from a known good backup or **image**; manual rebuild is slowest; keeping user data on a network share speeds reimaging.

## 2.5 Social Engineering and Attacks
labs: phishing-analysis, incident-response
@notes
### Social Engineering
- Attackers exploit people: pose as bullying customers, use news events (fake funeral links), spoofing, or personal data from LinkedIn/trash.
- **Phishing**: fake email linking to a spoofed login page; signs include unknown sender or domain, odd fonts, bad spelling, broken graphics, urgency. Never click email links; compare against the real site. **Vishing**: voice phishing (banks and police do not demand money by phone; hang up). **Smishing**: SMS phishing (fake tolls, "hi, how are you?"). **QR code phishing**: public QR codes can be swapped. **Spear phishing**: targeted at a group (e.g. executives, finance). **Whaling**: spear phishing aimed at the CEO or other top executives.
- **Shoulder surfing**: watching a screen (trains, coffee shops, binoculars, webcam); use awareness and **privacy filters**. **Tailgating**: following an authorized person through a door without consent. **Piggybacking**: authorized person knowingly lets you in ("hands full of donuts"); use no-piggyback policies and badge each time. **Impersonation**: pretending to be someone else (VP, help desk, vendor), often with details from **dumpster diving** (searching trash for phone lists, emails). Policies on caller verification help.

### Denial of Service
- **DoS** makes a service unavailable: overwhelm the server, trigger a flaw, cut power. Unintentional DoS: a **switch loop** without spanning tree, a big download using all bandwidth, a water leak. **DDoS** uses many systems, often a **botnet** of infected "zombies". Mitigate with firewall filtering, ISP DDoS protection, or a reverse-proxy service such as Cloudflare.

### On-Path Attacks
- Attacker sits between two devices to watch or alter traffic. **ARP poisoning/spoofing**: unsolicited ARP reply maps the router's IP to the attacker's MAC in the victim's ARP cache (ARP has no security). **On-path browser attack**: malicious proxy software in the browser steals logins. **Evil twin**: rogue access point with the same SSID (maybe a fake captive portal). Defend with HTTPS and a VPN on public networks.

### Zero-Day and Vulnerabilities
- **Zero-day**: previously unknown vulnerability with no patch. Track with **CVE** (Common Vulnerabilities and Exposures). Example: Log4j (found Dec 2021, code from 2013).
- **SOE (standard operating environment)**: tested, uniform, patched systems that are easier to secure; non-compliant devices are a risk (detect via AD policies, NGFW, scans). **Unpatched systems**: Microsoft **Patch Tuesday** is the second Tuesday of each month; a race between patching and exploit writers, so test and deploy fast and miss no devices. After troubleshooting, **re-enable** AV and firewall. **EOL** (end of life: no longer sold, still supported) vs **EOSL** (end of service life: no more patches); replace EOSL systems. **BYOD** needs MDM to separate corporate data and wipe it remotely.

### Password and Application Attacks
- Never store passwords in clear text. **Hashing** gives a fixed-length one-way fingerprint (SHA-256); tiny changes give very different hashes; it is not encryption. Linux hashes live in /etc/shadow.
- **Brute force**: try all combinations; **online** attacks get locked out, so attackers prefer **offline** attacks on a stolen hash file. **Dictionary attack**: common words and mutations (a to @, o to 0). Weak passwords: password, dragon, letmein, football.
- **Insider threat**: employees know where data is and bypass perimeter controls; can be bribed to plant ransomware. Use least privilege, monitoring, backups.
- **SQL injection**: user input changes the database query, e.g. `' OR 1=1; --` returns every row. Fix with input validation and parameterized queries. Other injections: HTML, XML, LDAP.
- **XSS (cross-site scripting)**: injected script (often JavaScript) runs in the victim's trusted session, can steal the session cookie. **Reflected** (via a link) vs **persistent/stored** (saved on a page for all visitors). Prevent: input validation, updates, avoid untrusted links.
- **Business email compromise (BEC)**: spoofed or compromised business email requesting wire changes, gift cards, payroll redirection; builds trust, uses urgency; look-alike domains (a brand name with a letter dropped). Verify by phone through a known number.
- **Supply chain attack**: compromise a vendor, hardware or software provider. Examples: Target breach via an HVAC vendor's VPN (flat network); counterfeit Cisco hardware; SolarWinds Orion malicious update signed and shipped to 18,000 customers. Defend with vendor audits, network segmentation, trusted suppliers, hardware verification, code signing.

## 2.6 Malware Removal
labs: incident-response, malware-analysis
@notes
### Malware Removal Process
- Best practice is to **wipe and reimage or replace**; manual removal is only to get a sick system running long enough to **rescue important documents** (you can never be 100% sure all malware is gone).
- **1. Identify symptoms**: AV alerts ("threats found"), slow boot, sluggishness, odd errors, pop-ups; research to confirm.
- **2. Quarantine the infected system**: disconnect/disable network, stop USB/removable media sharing. Don't back up malware to restore it later.
- **3. Disable System Restore** (temporarily): malware infects restore points; disabling deletes old restore points.
- **4. Remediate**: update the AV **engine and signatures** (signature updates may be blocked by the malware; download on another PC, copy via USB, boot to recovery), run scans, remove or quarantine files. If boot is affected, use **Safe Mode**; if that fails use **WinPE/Windows Recovery** (create your own with the Windows ADK) and repair boot records.
- **5. Reimage/reinstall** if needed using hardware-specific images; folder redirection keeps user data safe off the PC.
- **6. Prevent recurrence**: enable real-time protection and periodic scans, schedule signature updates (Task Scheduler if no built-in scheduler), keep Windows Update on, **re-enable System Restore** and create a fresh restore point.
- **7. Educate the user**: one-on-one training, posters, message boards, login message of the day, intranet page.

## 2.7 Security Best Practices
labs: system-hardening-windows-linux, group-policy
@notes
### Encryption and Passwords
- **Full-disk encryption** (BitLocker, data at rest), single file/folder encryption, encrypted USB drives. Keys come from the OS login or AD, so **back up encryption keys** too.
- **Password strength**: higher **entropy** (unpredictable): mix upper/lower case, numbers, symbols, avoid dictionary words; length 8+ and ideally long passphrases. **Password age/expiration** (30/60/90 days, shorter for critical systems) with **password history** to block reuse. **Change default credentials** (admin/admin on routers, firewalls).
- **BIOS/UEFI passwords**: **supervisor/admin** password blocks setting changes; **user** password is required to boot. Never blank.
- **Screen locks**: screensaver with password, auto-lock on inactivity (Personalization > Lock screen, screen timeout). **Cable locks** for laptops. Shield **PII** from viewers; use **privacy filters** and face the monitor away from walkways.
- **Password reuse** lets attackers pivot across sites; use unique passwords stored in a **password manager/vault** (encrypted, synced, business versions exist).

### Accounts and Services
- **Least privilege** via groups. **Login time restrictions**. **Disable the guest account** and disable interactive login for system accounts. **Failed-attempt lockout thresholds** stop online brute force (Windows machine lockout can reboot into BitLocker recovery). **Account expiration** for temp workers/contractors.
- **Autorun** (executes from removable media) was removed after Windows Vista; **Autoplay** only launches media (Settings > Bluetooth & devices > Autoplay: no action, open folder, ask).
- **Disable unneeded Windows services**: every running executable is potential attack surface.

## 2.9 Data Destruction

@notes
### Data Destruction
- **Physical destruction**: drill or hammer through platters, **shredder** (industrial), **degausser** (strong magnet; HDDs only, useless on SSD/flash), **incineration**.

## 2.10 SOHO Networks
labs: firewalls-pfsense, networking-tcp-ip-dhcp-nat-subnets
@notes
### Securing a SOHO Network
- **Change default admin credentials** (lists like routerpasswords.com make them easy to find). Use a strong password and MFA if available.
- **Filtering**: IP filtering and content filtering with an **allow list** (only listed traffic; most restrictive) or **deny list** (everything except listed). Content filters block URLs or categories (gambling, file sharing) and scan for malware.
- **Update firmware** on routers, firewalls and switches.
- **Placement**: all-in-one router/AP/switch/firewall near the ISP line; lock server gear in a secure room; mount APs high and central, but reachable.
- **UPnP (Universal Plug and Play)** lets apps reconfigure the router; usually **disable** it.
- **Screened subnet (DMZ)**: separate subnet for public-facing servers so the internal network stays protected.
- **Remote management**: disable internet-facing admin; restrict by IP if needed.
- **Wireless**: change default **SSID**; disabling SSID broadcast is only obscurity, not security. Use WPA2/WPA3 (Personal PSK at home, Enterprise 802.1X at work), let channels auto-select, use the **guest network** for visitors, IoT and labs. Always enable encryption.
- **Wired**: disable unused switch ports or wall jacks; use **802.1X network access control**.
- **Port forwarding** (destination/static NAT): public IP and port forwarded to a private server (e.g. 66.20.1.14 to 192.168.3.22), always on 24/7 and opens firewall holes; UPnP forwards are temporary.

## 2.11 Browser Security
labs: system-hardening-windows-linux, vpn-tailscale
@notes
### Browser Security
- Download browsers only from the **developer's official site**; verify the file **hash** (e.g. SHA-256 sums on download pages; use a hash tool) against the posted value. Mismatch means a modified or corrupted file.
- Keep the browser **updated** (auto update managers). **Extensions** have browser-level control: install from official stores (Chrome Web Store, Microsoft Store). Researchers found 24+ malicious Chrome extensions in March 2021 stealing credentials and keystrokes. Review the extension manager regularly.
- **Password managers/vaults**: encrypted, synchronized, unique logins per site so a leaked password can't be reused. Business vaults exist.
- **Certificate errors** ("connection not private"): expired certificate, wrong domain, **untrusted root CA** (try badssl.com), or wrong system date/time.
- **Pop-up blocker**: on by default; add exceptions per trusted site rather than disabling. 
- **Clear browsing data** (history, passwords, downloads, cookies, cache): clearing the cache is a common troubleshooting step for corrupt or stale pages. **Private/incognito mode** keeps no local history or cache, useful for troubleshooting and public computers.
- **Browser sync** (favorites, history, extensions, settings) via cloud login: convenient but stores data in the cloud. **Ad blockers** and tracking controls vary and are not 100% reliable.
- **Proxy**: sits between users and the internet, makes requests on their behalf; URL filtering, authentication, caching, malware inspection. **Explicit** proxy needs configuration (auto-detect or manual host:port such as proxy.example.com:8080 plus credentials); **transparent** proxy needs none. Proxy misconfiguration blocks internet access.
- **Secure DNS / DNS over HTTPS (DoH)** encrypts DNS queries; enable in browser advanced settings if the resolver supports it.

## 3.1 Troubleshooting Windows
labs: operating-systems, windows-admin-powershell, hardware-diagnostics-and-repair
@notes
### Stop Errors and Performance
- **BSOD / stop error**: the OS halts because of bad hardware, drivers or an app fault; reboot is required. Read the **stop code** (e.g. KERNEL_MODE_HEAP_CORRUPTION) or scan the QR code and look it up. If it won't reboot: **last known good**, **System Restore**, **driver rollback**, **Safe Mode**; reseat components and run **hardware diagnostics** (CPU, RAM).
- **Slow system**: Task Manager (per-app CPU/memory/disk/network; Performance tab shows the last 60 seconds). Then Windows Update (known bugs), free disk space, defrag (HDD only), laptop on battery throttles CPU/heat, malware scan after updating signatures.

### Boot Problems
- "**Operating system not found / missing OS**": a bootable disk with no OS is attached (remove it), or a dual-boot install replaced the bootloader.
- **Startup Repair** fixes common issues automatically (missing bootloader, moved Windows folder, boot looping into Safe Mode). **BCD** (Boot Configuration Database) replaced boot.ini; `bootrec /rebuildbcd` scans drives for Windows installs and re-adds them from the recovery command prompt.

### Services, Apps, Memory, USB
- **Device not working**: Device Manager (disable, update, roll back, uninstall driver).
- "**One or more services failed to start**": services.msc, start manually; check the logon account and **dependencies** (one must start first); run **SFC** for built-in services; reinstall app services as admin.
- **App crash with no message**: **Event Viewer** (filter by app); **Reliability Monitor** shows failures over time (one-off vs repeated). Last resort: uninstall/reinstall.
- **Low memory**: sort Task Manager by memory; **virtual memory/page file** (System > About > Advanced system settings > Performance > Advanced > Virtual memory) swaps RAM to disk.
- **USB controller resources exceeded**: each device uses **endpoints** (controllers support a limited number, e.g. 96 or 254). Move the device to another port/controller; match USB 2 devices to USB 2 controllers and USB 3 to USB 3.
- **Random failures with no message**: run full hardware diagnostics (vendor tools or UEFI diagnostics), **Windows Memory Diagnostic** overnight, `sfc /scannow`, malware scan.
- **Slow login with roaming profile**: profile downloads from the domain controller; WAN congestion or a failing local DC is the usual cause (domain admin fixes it).
- **Time drift**: set time automatically (Settings > Time & language > Date & time), set time zone, **Sync now**; keeps Kerberos and certificates working.

## 4.1 Documentation and Support Systems
labs: help-desk-ticketing-osticket
@notes
### Ticketing Systems
- The **help desk** takes calls, emails and texts, **triages** (priority, handle or hand off), assigns a ticket and monitors until resolved. Tickets document issues, assign them to teams (network, server), support reporting and resolution metrics.
- **Capture at creation**: user and contact person (often integrated with Active Directory; confirm details), device/asset, request type, summary, detailed description (symptoms, screenshots, next steps, callback notes), **category** (change request, hardware, onboarding, account), **severity/priority** (low to critical, based on role/department/impact), and **escalation** to specialists.
- Keep **progress notes** concise and time-stamped (who did what) and write **resolution details** so future techs can reuse them. **Link related tickets** to spot trends (e.g. 60 days of VPN errors justified an upgrade).

### Asset Management
- A central **inventory** lists mobile devices, laptops, desktops, network gear and modules with make, model, purchase date and owner. Used by support, finance (cost, depreciation, warranty), licensing (renewals) and audits.
- **Asset tag**: label with organization name, barcode or QR code and unique number tied to the database record. The central database is the **CMDB** (Configuration Management Database).
- **Procurement life cycle**: purchase request (budget, approvals) > purchasing negotiates with vendors (terms, maintenance, not only price) > **purchase order** > vendor ships > **invoice** > accounting pays.

### Document Types
- **Incident report**: what led up to, the incident, response; feeds the incident response plan and lessons learned.
- **Standard operating procedures (SOPs)**: downtime, power loss, software installation, testing, change control, who to contact.
- **Onboarding**: signed IT agreements/**AUP**, accounts, groups/permissions, equipment. **Offboarding**: collect hardware, handle data (backups, handoff, encryption keys), disable accounts.
- **SLA** (service level agreement): minimum service terms (e.g. under 4 hours unscheduled downtime a year, credit/penalty, technician dispatch, spare equipment on site). Internal SLAs also exist.
- **Knowledge base**: searchable technical articles (vendor like Microsoft or internal); integrates into help desk tickets.

## 4.2 Change Management
labs: help-desk-ticketing-osticket, virtualization-proxmox
@notes
### Why and Process
- Every change risks downtime. **Change management** standardizes frequency, duration, installation steps and **rollback**. Goals: avoid downtime, notify affected teams, prevent conflicting changes.
- **Request form**: purpose (why: features, bug fixes, performance, security patches), **scope** (3 users vs the core switch), date/time, affected systems, impact, **risk analysis** (risk of making AND of not making the change), **rollback plan**, **backup plan**, approvals.
- **Change control board** (all departments) approves, schedules or delays (e.g. retail change freeze Nov 15 to Jan 5). **Sponsor** funds it, **business customer** uses it, IT implements. **End-user acceptance** (users test and approve) closes the change; users are involved throughout.

### Change Types and Timing
- **Standard**: low risk, pre-approved, routine (replace a monitor). **Normal**: medium risk, full process (firewall rule, database upgrade, core switch replacement). **Emergency**: high risk, expedited (zero-day patch).
- **Maintenance window** (e.g. Sunday 2:00 AM, skipped if no changes) or on-demand time. **Change freeze** blocks everything except emergency changes.

### Plans and Testing
- **Rollback plan**: return to the original config (VM snapshot is easy; firmware may be impossible, so swap in equipment with old firmware). Always keep a **backup**.
- **Backup plan (plan B/C)**: alternate steps if the primary method fails, e.g. firewall update: download file beforehand, use USB, FTP or CLI console.
- **Sandbox testing**: separate test environment; test the upgrade and the rollback there. Consult experts who have done the change.

## 4.3 Backup and Recovery
labs: log-analysis, linux-server-admin-ubuntu
@notes
### Backup Types
- Plan around data size, backup type, media, location, software (for backup and restore) and frequency.
- **Full**: everything (OS, apps, documents); longest backup, biggest storage, simplest restore (one set).
- **Differential**: full first, then everything changed **since the last full**; grows daily. Restore = last full + **last differential** (two sets).
- **Incremental**: full first, then only changes **since the last backup of any kind**; smallest and fastest to take. Restore = full + **every incremental** in order (slowest restore).
- **Synthetic full**: assembles a full backup from the existing full and incremental/differential sets without re-transferring data; saves bandwidth and time; restores like a full.

| Type | Backup time | Restore time | Sets for restore |
|---|---|---|---|
| Full | High | Low | 1 |
| Differential | Moderate | Low-moderate | 2 |
| Incremental | Low | High | Full + all incrementals |
| Synthetic | Low | Low | 1 |

### Testing, Restores, Locations
- A backup is only proven by **recovery testing**: restore a sample file and compare to the original; **audit** the backup process regularly.
- **In-place restore** overwrites the original location (re-imaging). **Alternate location** restore keeps existing files and avoids overwriting newer data.
- **On-site**: fast, local, cheap. **Off-site**: survives fire or flood, depends on bandwidth. Most use both.
- **GFS (grandfather-father-son)**: monthly full (grandfather), weekly (father), daily incremental/differential (son); intervals can shift (hourly/daily/weekly).
- **3-2-1 rule**: **3** copies of data, on **2** different media types (disk, tape, NAS), **1** copy off-site (storage facility or cloud).

## 4.4 Safety
labs: hardware-diagnostics-and-repair
@notes
### ESD (Electrostatic Discharge)
- Static is harmless to people but not to silicon: you feel a discharge at about **3,500 V**, while components can be damaged by **100 V or less** (damage may not be noticed).
- Prevention: **humidity over 60%** (impractical), **self-ground** by touching the metal chassis, **anti-static wrist strap** clipped to bare metal of the device (breakaway snap), **anti-static pad/mat**, **anti-static bags** for storage and transport, handle components by the **edges**.
- **Unplug power** before opening (does not help with ESD but prevents shock). **Never connect yourself to a building's electrical ground** (it can be energized).
- Storage: HVAC regulated, about **50-80 °F (10-27 °C)**, low humidity (silica gel packs), original box or bubble wrap.

### Safety Procedures
- Disconnect power before opening PCs, printers, anything with a cord. Do not touch unfamiliar parts: **capacitors** store charge. Power supplies, displays and laser printers can hold **residual power**; replace the PSU as a unit, do not open it.
- **Grounding** sends fault current to ground; never remove ground pins; ground data center racks too.
- **Cable management**: tape or cover floor cables (trip hazard), bundle with Velcro or ties.
- **Lifting**: lift with your legs, not your back; use rack lifts.
- **Fire**: no water or foam in data centers (**FM-200, CO2, dry chemical**). Remove burning equipment from power first.
- **PPE**: safety goggles for chemicals and toner/battery work, **air filter mask** for toner dust.
- Know **health and safety laws, building/fire codes and environmental disposal rules**.

- **MSDS / SDS** (Material Safety Data Sheet, US **OSHA** requirement) accompanies hazardous products (toner, ink, batteries): ingredients, hazards, first aid, firefighting, disposal. Consult it for disposal guidance.

## 4.6 Privacy and Policies
labs: incident-response, digital-forensics
@notes
### Incident Response Basics
- **Chain of custody**: document every person who handles evidence; use sealed bags and hashes/digital signatures for integrity.
- **First response**: identify the issue (logs, witnesses, monitoring), report through the proper channel (including law enforcement where needed), preserve and collect data.
- **Imaging**: make a **bit-for-bit** copy of the entire drive (includes deleted data still on disk), with a **hardware write blocker** or booted software imaging tool; analyze the copy, not the original. Verify with hashes.
- **Document** the event summary, step-by-step acquisition process, analysis findings and conclusions (may be used in court).
- **Order of volatility** (collect most volatile first): CPU registers/cache > routing/ARP tables, process table, kernel statistics, memory > temporary file systems > disk > remote logging and monitoring data > physical configuration and network topology > backup tapes.

### Licensing, Agreements, Regulations
- **Licenses**: per-seat (one per user), **concurrent** (max simultaneous users), duration/subscription (expires), personal, **perpetual** (one-time cost), **corporate/site**. **FOSS** includes source you can modify; closed source does not.
- **EULA**: contract accepted at installation. **NDA**: confidentiality agreement, **unilateral** (one party) or **bilateral** (both).
- **PCI DSS**: credit card data. Six control objectives: secure network and systems, protect cardholder data, vulnerability management program, strong access control (MFA), regular monitoring and testing, information security policy.
- **PII** = data that identifies a person (breach example: OPM 2015, 21.5 million people). **PHI** = health data, regulated in the US by **HIPAA** (1996).
- **Data retention**: versioning, rollback period (e.g. 30 days) and legal retention (email, tax, financial records for years).
- **AUP** limits liability and defines acceptable use; **splash screen / login banner** informs or requires agreement ("as is" disclaimers, support hours).

## 4.9 Remote Access
labs: vpn-tailscale, linux-server-admin-ubuntu, windows-admin-powershell
@notes
### Remote Desktop and VPN
- **RDP** (Microsoft Remote Desktop Protocol, **TCP 3389**) has clients on all platforms. **VNC** uses **RFB** (Remote Frame Buffer), open source. Open remote desktop ports with weak passwords are brute-force targets; add MFA. Scammers also use remote tools: verify who is asking.
- **VPN**: encrypts traffic across public networks to a **VPN concentrator** (often in a next-gen firewall). Client software or OS built-in VPN. Use MFA at login.
- **SSH**: encrypted terminal, **TCP 22**; Telnet (TCP 23) is cleartext. Harden with **key pairs**, disable root login, disable passwords (certificate only), IP allow lists.

### Management Tools
- **RMM** (Remote Monitoring and Management): MSP console to patch, remotely connect, monitor and inventory many customers; a high-value target, so protect with **MFA, tight access and auditing**.
- **SPICE** (Simple Protocol for Independent Computing Environments): remote console for virtual machines with efficient graphics and shared clipboard/folders.
- **WinRM** (Windows Remote Management): send a script to a Windows host (needs authentication), run it remotely and receive results with no interactive session (e.g. Get-WmiObject Win32_Service).
- Third-party tools: screen sharing (GoToMyPC, TeamViewer), video conferencing (Zoom, WebEx), file sync (Dropbox, Box, Google Drive), endpoint management (Citrix Endpoint Management, ManageEngine Desktop Central). Always use MFA and limit to authorized users.

## 4.10 Artificial Intelligence
labs: log-analysis, siem-security-onion
@notes
### Using AI
- **AI** aims to learn, infer and reason like humans; **generative AI** creates text, images, audio and video from prompts. Integrated into search summaries, email summaries, image editors and translation.
- **Appropriate uses**: analyzing huge data sets such as logs for security issues, scripting and automation decisions, healthcare (MRI review, spotting dangerous drug interactions), real-time translation.
- **Inappropriate uses**: **fraud and deep fakes** (impersonating people), code nobody understands, claiming AI work as your own, **plagiarism** in school and uncited AI summaries.

### Risks and Limits
- **Bias**: models inherit bias from skewed or under-represented training data (Amazon dropped a resume AI that favored men). Review outputs.
- **Hallucination**: confident but wrong output (Google's demo claim about the James Webb telescope). 2024 fact-checking tests found accuracy figures such as 72.3%, 64.9% and 58.6% across tools, so always **verify**.
- **Public AI** (ChatGPT, Gemini): more data and maybe better accuracy, but anything entered may be retained or leaked (passwords, keys, PII). **Private AI**: built on the organization's own data, controlled model, limits breach scope but has less data.
- **Policy**: do not enter sensitive data, passwords, keys or customer information into public AI; follow company AI policy; hold humans accountable for outputs.
