Data protection starts with knowing what data you have, how sensitive it is, where it lives, and what state it is in. Only then can you choose the right control.

### Data types

- **Regulated data**: controlled by law or industry rules, so mishandling brings fines. Examples: health records (**HIPAA**), payment cards (**PCI DSS**), personal data of EU residents (**GDPR**), financial data.
- **Trade secrets**: information that gives a business an edge and is protected by secrecy (recipes, formulas, source code).
- **Intellectual property (IP)**: patents, copyrights, trademarks, designs.
- **Legal information**: contracts, case files, discovery.
- **Financial information**: accounts, statements, payment data.
- **Human-readable** data is directly understood by people (text, documents). **Non-human-readable** needs software to interpret (binary files, encoded or encrypted data, databases).

### Data classification

Classification labels data by sensitivity so the right protection applies. The scheme depends on the organization.

| Common labels | Meaning |
| --- | --- |
| **Public** | Safe to release; no harm |
| **Private / internal** | For internal use; low impact if leaked |
| **Sensitive** | Needs protection; loss would hurt |
| **Confidential** | Limited access; significant harm if exposed |
| **Restricted** | Tightest control; severe harm |
| **Critical** | Essential to operations; availability matters most |

Government labels you may see: **Unclassified, Confidential, Secret, Top Secret**.

**Roles:** the **data owner** decides classification and access (accountable). The **data steward** manages quality and metadata. The **data custodian** (usually IT) implements technical protection. The **data controller** decides why and how personal data is processed; the **data processor** processes it on the controller's behalf. A **data protection officer (DPO)** oversees privacy compliance.

### States of data

| State | Where it is | Typical protection |
| --- | --- | --- |
| **At rest** | Stored on disk, database, backup, USB | Full-disk/file/database encryption, access control, secure storage |
| **In transit (in motion)** | Moving across a network | TLS, IPsec/VPN, SSH, secure protocols |
| **In use** | Being processed in memory/CPU | Secure enclaves, memory protection, access controls, limiting exposure on screen |

A complete data protection plan covers all three.

### Data sovereignty and location

- **Data sovereignty**: data is subject to the laws of the country where it is stored. Cloud region choices can affect compliance.
- **Geolocation / geographic restrictions**: limit where data can be stored or accessed from (block access from certain countries, keep EU data in the EU).
- **Privacy regulations** (GDPR, CCPA) add requirements around consent, retention and breach notification.

### Methods to secure data

- **Geographic restrictions**: control by location (above).
- **Encryption**: converts data so only key holders can read it (at rest, in transit).
- **Hashing**: one-way fingerprint for integrity and password storage.
- **Masking**: hides part of a value while keeping format (`XXX-XX-1234`). Often used in test and support views.
- **Tokenization**: swaps sensitive data for a token; the real value sits in a secure vault.
- **Obfuscation**: makes data hard to understand (not strong security by itself).
- **Segmentation**: separate networks or databases for sensitive data so access is restricted.
- **Permission restrictions**: least privilege, role-based access, need to know.
- **Data loss prevention (DLP)**: policies and tools that detect and block sensitive data leaving (email, USB, cloud uploads).
- **Rights management / classification labels** that travel with the file.
- **Retention and disposal**: keep only what is needed, then destroy it securely (shredding, degaussing, wiping).

### More detail from the lessons

**Types and classes**

- **Regulated data** has rules set by a third party (card data under PCI standards) or by government law, which can dictate how long data is kept. **Trade secrets** are known only to the organization. **Intellectual property** is often visible but protected by **copyright and trademark law**. **Legal** records (court records, judge and attorney names) are often public, but parts hold private **PII** and live in separate systems. **Financial** data covers both company books and personal bank details.
- **Human-readable** (documents, spreadsheets) vs **non-human-readable** (encoded data, barcodes, images) vs **mixed** (a barcode with its digits printed underneath).
- Sensitivity differs: a license plate lookup is mild, medical history never accessible. Match controls: specific permissions, a stricter viewing process, or a **restricted network area**.
- **Proprietary** data is unique to the organization. **PII**: name, date of birth, mother's maiden name, biometrics, address. **PHI**: health status, healthcare records, even healthcare payments.
- Classification example set: **sensitive** (IP, PII, PHI), **confidential** (more sensitive, extra access), **public/unclassified** (government), **private/classified/restricted** (extra rights, maybe an **NDA**), and **critical** (must always be available, so plan uptime).

**States of data**

- **At rest** counts as at rest even if it is not encrypted. Add FDE, database or file/folder encryption, plus user and group permissions.
- **In transit (in motion)**: protect with a firewall or IPS (allow known good, block unusual) and with encryption such as **TLS** or a **site-to-site IPsec VPN**.
- **In use**: data in RAM or the CPU is usually **decrypted** since it must be processed, so attackers target it. **Target, November 2013**: code on every point-of-sale terminal pulled **110 million** card records from terminal memory, even though Target encrypted data in transit and at rest.
- **Data sovereignty**: data stored in a country follows that country's laws and court orders. **GDPR** (EU) requires data on EU citizens to be stored in the EU. Check rules for each geography you operate in.
- **Geolocation** uses **GPS**, **802.11** (matching visible SSIDs against wireless databases) and mobile provider data. Streaming services blocking foreign content is the everyday example. You can grant more data access when the user is inside the corporate building.

**Protecting data details**

- **Geographic restrictions** use IP subnet (good for known internal subnets, poor for mobile devices), GPS, and wireless data. **Geofencing** applies policy based on location (for example, only accessible inside corporate facilities).
- Data lives on devices, on networks and in CPU/memory, and each location can be attacked, so protect all of them.
- **Encryption** turns **plaintext** into **ciphertext** and needs the right implementation and key to decrypt. **Confusion** is the property that the ciphertext looks very different from the plaintext (PGP "Hello, world" demo).
- **Hashing**: message digest or fingerprint, cannot rebuild the data. Used for passwords, for download checks (Linux ISO hash next to the file), and with public key crypto in **digital signatures**. A **collision** is two inputs with the same hash, and algorithms with this problem were dropped. SHA-256: 256 bits, 64 hex characters; changing a period to an exclamation mark changes the entire hash.
- **Obfuscation**: developers obfuscate code to protect it (the code still works the same), and attackers use it to hide malicious scripts. Example: one line of PHP `echo "Hello, world"` turned into a longer valid PHP script that outputs the same.
- **Masking** hides part of data such as card numbers on receipts (last four shown); can shuffle, encrypt, or use asterisks. **Tokenization** replaces data with a **one-time token** (phone or smartwatch payment); no encryption or hashing needed and no way to derive the card number from the token. Flow: register the card on the phone, the **token service server** returns tokens, NFC sends a token at the store, and the store checks it with the token server.
- **Segmentation**: one big database means one breach exposes everything. Split data into separate databases with security matched to sensitivity (a name list needs less than health or financial data).
- **Permission restrictions** begin with **secure authentication** (password policy, extra factors) and continue with groups and file permissions after login.

### Exam traps

- **Masking** hides *display*; **tokenization** replaces *storage*; **encryption** is reversible with a key.
- **Owner** decides classification; **custodian** implements controls.
- **In use** data is the hardest to protect because it must be decrypted to be processed.
- Regulated data = legal requirement; **classification** = your own scheme. Both can apply.
- DLP is a detective *and* preventive technology for data leaving the organization.
