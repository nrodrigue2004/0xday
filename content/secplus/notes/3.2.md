Objective 3.2 is about where security devices go, how they behave when they fail, and how traffic gets protected as it moves.

### Secure infrastructure: placement and attributes

**Security zones** group systems by trust: internet (untrusted), a **DMZ / screened subnet** for public-facing servers, internal (trusted), and often a management network and a guest network. Rules between zones control what can talk to what.

**Attack surface** shrinks when you minimize exposed services and reduce connectivity between zones.

**Device attributes:**

| Attribute | Option A | Option B |
| --- | --- | --- |
| **Active vs passive** | **Active**: can block or change traffic | **Passive**: only observes and alerts |
| **Inline vs tap/monitor** | **Inline**: traffic flows *through* the device (can block). A failure may drop traffic | **Tap / SPAN port**: a copy of traffic goes to the device. No effect on flow, cannot block directly |
| **Failure mode** | **Fail-open**: on failure, traffic is allowed (keeps availability, loses security) | **Fail-closed**: on failure, traffic is blocked (keeps security, loses availability) |

> Choose by what matters more. A safety door fails open so people can escape. A firewall protecting sensitive data usually fails closed.

### Intrusion prevention

- **IDS** (intrusion detection system): detects and alerts; passive. **IPS** (intrusion prevention system): detects and blocks; inline.
- **Detection methods:** **signature-based** (known patterns, fast and accurate for known threats, misses new ones), **anomaly/behavior-based** (learns normal and flags deviations, catches unknown but more false positives), **heuristic**.
- **Network-based (NIDS/NIPS)** watch network traffic. **Host-based (HIDS/HIPS)** run on a single system and see local activity (files, processes, logs).
- Tune rules to reduce **false positives** (alert on benign) and **false negatives** (miss a real attack).

### Network appliances

- **Jump server (jump box / bastion host)**: a hardened intermediate host used to reach devices in a secure zone. Admins log into it first, which gives one monitored, controlled entry point.
- **Proxy server**: sits between users and the internet. **Forward proxy** filters and caches outbound web requests (content filtering, logging, anonymity). **Reverse proxy** sits in front of servers (hides them, load balances, terminates TLS).
- **Load balancer**: spreads traffic across servers for availability and scale; health-checks servers; can offload TLS.
- **Sensors and collectors**: devices that gather logs and network data for the SIEM.
- **Web application firewall (WAF)**: layer 7 filter for web apps (SQLi, XSS).
- **UTM** (unified threat management): firewall, IPS, antivirus, filtering and VPN in one appliance.
- **NGFW** (next-generation firewall): application-aware, user-aware, with deep packet inspection and integrated IPS.

### Port security

- **Port security** on a switch limits MAC addresses per port, shuts ports that violate the rule, and disables unused ports.
- **802.1X** is port-based network access control. A device must authenticate before the switch port or wireless association allows traffic. Three roles: **supplicant** (client), **authenticator** (switch/AP), **authentication server** (usually RADIUS). It uses **EAP** methods (EAP-TLS with certificates is strongest).
- **Network access control (NAC)** adds posture checks (patched? antivirus running?) and can quarantine noncompliant devices.
- **Loop protection (STP, BPDU guard)**, **DHCP snooping** (blocks rogue DHCP servers), **dynamic ARP inspection** (blocks ARP spoofing), **MAC filtering** (weak, easy to spoof).

### Firewall types

| Type | Works at | What it does |
| --- | --- | --- |
| **Packet filter / stateless** | Layer 3-4 | Allows or denies by IP, port, protocol; no memory of connections |
| **Stateful** | Layer 3-4 | Tracks connection state, so return traffic of an allowed session is permitted |
| **Proxy / application firewall** | Layer 7 | Terminates and re-creates the connection, can inspect content of specific protocols |
| **Next-generation firewall** | Layers 3-7 | Application identification, user identity, IPS, TLS inspection, threat feeds |
| **WAF** | Layer 7 (HTTP) | Protects web apps |
| **Host-based** | On the endpoint | Per-host rules |

- Rules are processed **top to bottom**; the first match wins. End with an **implicit deny**: anything not explicitly allowed is blocked. Place specific rules before general ones.
- **Network vs host firewall**, **hardware vs software**, **appliance vs virtual vs cloud** are all deployment variants.

### Secure communication and access

- **VPN**: encrypted tunnel over an untrusted network. **Remote-access** VPN (client to network) and **site-to-site** (network to network).
- **IPsec**: layer 3. **AH** gives integrity/authentication only; **ESP** gives encryption plus integrity. **Transport mode** protects the payload (host to host); **tunnel mode** wraps the whole original packet (gateway to gateway). **IKE** negotiates keys.
- **TLS** secures applications (HTTPS, email, VPN). **SSL VPNs** use TLS, work through firewalls on 443.
- **Split tunnel** sends only corporate traffic through the VPN; **full tunnel** sends everything (more control, more load).
- **Always-on VPN** reconnects automatically.
- **SD-WAN**: software-defined routing over multiple links (MPLS, broadband, LTE) with central policy.
- **SASE** (secure access service edge): delivers networking and security (SWG, CASB, ZTNA, firewall-as-a-service) from the cloud, so remote users and branches get consistent security.
- **Secure Shell (SSH)** for remote administration; **RDP** carries risk if exposed to the internet.
- **Tunneling** protocols encapsulate one protocol inside another (GRE, L2TP).

### More detail from the lessons

**Zones and attack surface**

- A security zone is a logical grouping by use or access type, not an IP range. Simple model: **trusted/internal** vs **untrusted/external**. Finer zones named things like inside, internet, servers, databases and **screened**. Rules then read clearly: trusted to untrusted allowed, untrusted to screened allowed, and untrusted straight to trusted usually blocked (only in special cases). Lesson diagram: internet, firewall, router, then internal mail, database and directory servers; a better design adds a screened zone.
- Other devices that help the design: **honeypots**, **jump servers**, **network sensors**, **load balancers**.
- Ways in (like a house with doors, windows and a basement): application code, open server ports, the authentication process, and **human error** (one mistaken firewall rule). All of them together are the **attack surface**; minimize it by auditing code, blocking ports and monitoring traffic in real time.
- **Connectivity**: secure network drops and cabling (physical and logical protection), because a tap can see all traffic, so add **application-level encryption**. Use **IPsec tunnels** site to site and a **VPN concentrator** for remote users.

**IPS**

- An IPS watches live traffic and blocks known exploits, buffer overflows and SQL injection. An IDS only alerts.
- **Inline devices can fail** (power loss, hardware, software bug). **Fail-open** keeps traffic flowing with no security checking. **Fail-closed** cuts the link. Most networks prefer fail-open but check the documentation for your device. Failure mode only matters when the device is **inline/active**.
- Layout example: internet, firewall, IPS, core switch. **Active monitoring** (inline) is the default config for IPS and can remove malicious traffic before it reaches the switch. Reasons to avoid it: fear of causing downtime or of blocking legitimate traffic.
- **Passive monitoring**: a **port mirror / SPAN (Switch Port Analyzer)** or a physical **network tap** sends a copy of the traffic to the IPS. It cannot cause an outage but cannot block in real time, so it behaves like an IDS.

**Appliances in detail**

- **Jump server**: a hardened device inside the network reachable from outside. Admins connect to it, then SSH onward (two-step). It must be tightly secured because compromising it gives access to everything behind it.
- **Proxy**: makes requests for users, can evaluate responses, **cache** (saving bandwidth), **URL filter** and **content scan**. **Explicit proxy** must be configured in the app or OS; **transparent proxy** is invisible to users. **NAT** is a simple form of proxy. An **application proxy** understands one protocol (HTTP proxy), and some handle several (HTTP, HTTPS, FTP).
- **Forward (internal) proxy**: users go to the internal proxy, which fetches from the internet and inspects the reply. **Reverse proxy**: sits in front of your web server for inbound traffic, drops malicious requests, and caches identical requests to speed responses and reduce server load.
- **Open proxy**: available to anyone, used to bypass controls. Unknown owner may inject ads or malicious code, so many organizations block them.
- **Load balancer** distributes load across a web server or database farm and gives **fault tolerance** (convergence is fast and mostly unnoticed). **Active/active** uses every server; **active/passive** keeps standby servers that take over (server A and B active, C and D standby; a failure promotes a standby). Extra features: **TCP offloading** (one persistent TCP session instead of one per user), **SSL/TLS offloading** (decrypt at the balancer using purpose-built hardware, send clear traffic to the servers, re-encrypt responses), **caching**, **prioritization**, and **content switching** (send certain request types to specific servers).
- **Sensors and collectors**: switches, routers, firewalls, IPS, authentication logs and web server logs generate stats; standalone sensors collect traffic stats too. A **collector** is the central database, which may be a vendor console or a **SIEM** that consolidates, correlates and compares data (example report: failed authentications and port scans).

**Port security and 802.1X**

- **EAP** is a framework used by many wired and wireless vendors. **802.1X** (port-based NAC) is the common integration: you cannot use a switch port until you authenticate. Back ends include **RADIUS, LDAP, TACACS+, Kerberos** (for example an Active Directory database through Kerberos or LDAP).
- Three parts: **supplicant** (client), **authenticator** (switch or AP), **authentication server**. Flow: the supplicant connects with no access, the authenticator sends an **EAP request**, the supplicant sends an **EAP response** with its identity, the authenticator forwards that to the authentication server, which asks for more details (credentials), the supplicant provides them, the authenticator relays them, and the server replies with success so the authenticator opens access.

**Firewalls in detail**

- Traditional network firewalls decide by **Layer 4** (TCP/UDP port). **NGFW** works at **Layer 7**. Firewalls can also be Layer 3 devices (routing, NAT, routing protocols) at the edge, and include a VPN.
- **UTM** (also called web security gateway or all-in-one security appliance): URL filtering, content inspection, malware blocking, spam filtering, CSU/DSU, routing and switching, firewall, IDS/IPS, bandwidth shaping (QoS) and VPN concentrator. Drawbacks: many only work at layer 4, and turning on many features **slows the device**.
- **NGFW** (also called application layer gateway, stateful multilayer inspection, deep packet inspection): full packet decode, identifies who, where, and the application. Example: allow Microsoft SQL Server regardless of port, allow viewing but not posting to Twitter, restrict YouTube, even if ports are similar. Includes a vulnerability list (acts like an IPS) and **URL categories** (block "gambling") or individual URLs (espn.com, yahoo.com).
- **WAF**: analyzes input to web apps over HTTP/HTTPS, blocks SQL injection, usually used with an NGFW, and is required by **PCI DSS** for card applications. A sample log shows time, date, ID, URL (index.cgi), service IP and port, client IP and country, and the attack name "SQL Injection in Parameter," blocked by a standard policy.

**Secure communication in detail**

- A **VPN concentrator** is the endpoint for encrypted connections; today often inside an NGFW, or software, with client software often built into the OS.
- IPsec packet structure: the original IP header and data are encrypted and wrapped with an **IPsec header and trailer**, then a **new IP header** points to the concentrator. The far end strips the outer layers and decrypts.
- **SSL/TLS VPN** runs over **TCP 443**, passes through most firewalls, and is used for **remote access** from a single device. It can use normal credentials (not forced to use certificates or shared passwords, though it can), can be browser-based with no client install, and can be **always on**. **IPsec site-to-site VPN** uses firewalls as endpoints, so devices need no extra software.
- **SD-WAN** was built for cloud access: instead of every site hauling traffic to a central data center and then out to the cloud (extra hops), the WAN adapts to reach cloud apps directly. **SASE** is described as the next generation of VPN: security services live in the cloud near the services, and **SASE clients** on every device (office, home, mobile) connect securely. Organizations often combine remote-access SSL VPNs, IPsec site-to-site VPNs, SD-WAN for connectivity and SASE for security.

### Exam traps

- **Inline = can block; tap/passive = can only alert.**
- **Fail-open** favors availability; **fail-closed** favors security.
- **IDS** doesn't block; **IPS** does.
- **802.1X** authenticates devices at the port; a firewall doesn't.
- **ESP** encrypts; **AH** doesn't.
- A jump server reduces exposure by giving admins a single controlled path.
