## trouble-no-internet
q: wifi connected but no internet | my internet is not working | cannot connect to the internet | no internet connection troubleshooting | why do i have no internet
a: Work from the bottom up. Check the cable or Wi-Fi link, then your IP (ipconfig or ip a; 169.254.x.x means DHCP failed), then ping the default gateway, then ping 8.8.8.8 (tests IP routing), then ping a name like example.com (tests DNS). The first step that fails is the problem. Rebooting the router fixes many ISP-side issues.
links: g:computer-networks u:comptia/netplus

## trouble-dns
q: why is my dns not resolving | dns not working | cannot resolve hostname | website not loading but ping by ip works | dns resolution failing
a: If ping 8.8.8.8 works but names fail, DNS is the problem. Check which resolver the machine uses (ipconfig /all or resolvectl status), test with nslookup or dig against another resolver (8.8.8.8 or 1.1.1.1), flush the cache (ipconfig /flushdns), check for a bad hosts file entry, and make sure the DNS server is up.
links: g:networking-tcp-ip-dhcp-nat-subnets m:networking-tcp-ip-dhcp-nat-subnets

## trouble-cannot-ping
q: why cant i ping a host | ping request timed out | ping not working | destination host unreachable | cannot ping server
a: Request timed out usually means the packet was dropped (firewall blocking ICMP, host down, wrong route). Destination host unreachable means no route or no ARP answer on the local network. Check IP and subnet, the default gateway, the target's firewall, and try a port test (nc -vz host 22). A failed ping alone doesn't prove the host is down.
links: g:computer-networks

## trouble-slow-network
q: why is my network slow | internet is slow troubleshooting | how to find the cause of a slow connection | network latency high | wifi is slow
a: Separate the causes: run a speed test on wired vs Wi-Fi, ping the gateway and an outside host for latency and loss, traceroute to find where delay starts, and check what is using bandwidth. Common causes are Wi-Fi interference, a congested link, a bad cable, DNS delay and a heavy download or backup.

## trouble-ip-conflict

a: A 169.254.x.x address means the machine couldn't reach a DHCP server and gave itself one. Check the cable or Wi-Fi, the DHCP server and scope. An IP conflict means two devices share one address: find it with arp -a, then fix the static assignment or DHCP reservation.

## trouble-ssh-refused
q: ssh connection refused | ssh connection timed out | cannot ssh into server | ssh permission denied publickey | why cant i ssh
a: Connection refused: the host answered but nothing listens on that port (sshd not running or wrong port). Timed out: packets are dropped (firewall, wrong IP, host down). Permission denied (publickey): the server rejected your key or user: check the key path, file permissions (chmod 600), the user, and authorized_keys. Use ssh -v for detail.
links: m:linux g:linux-server-admin-ubuntu

a: Refused means the target actively rejected the connection (no service on that port, or a reset). Timed out means no reply at all, so something is dropping the packets (firewall, routing, host off). The difference tells you where to look.

a: You authenticate to the KDC and get a ticket-granting ticket (TGT). To use a service you present the TGT and get a service ticket, then show that to the service. No password crosses the network after login. Attacks: Kerberoasting, golden ticket, pass the ticket.
links: g:active-directory u:pentest/ad-attacks

## concept-how-passwords-stored
q: how are passwords stored | how should passwords be stored | how does password hashing work | why are passwords salted
a: Properly: as a salted hash made with a slow function (bcrypt, scrypt, Argon2), never plain text or fast hashes. A salt is a random value added per password so identical passwords hash differently and rainbow tables fail.
links: b:cia-and-crypto

## concept-how-vpn
q: how does a vpn work | how does vpn encryption work | explain vpn tunneling
a: A VPN client encrypts packets and wraps them inside new packets sent to the VPN server (tunneling). The server decrypts and forwards them, so the local network only sees encrypted traffic to the VPN. Protocols: WireGuard, OpenVPN, IPsec.
links: b:vpns-and-tunnels g:vpn-tailscale

## concept-how-firewall
q: how does a firewall work | how do firewall rules work | what does a firewall do | firewall rule order
a: A firewall compares traffic to ordered rules (source, destination, port, protocol, action) and takes the first match, with an implicit deny at the end. Stateful firewalls track connections so replies are allowed back automatically.
links: g:firewalls-pfsense

## concept-how-ids
q: how does an ids detect attacks | signature vs anomaly detection | how does intrusion detection work
a: Signature-based IDS compares traffic to known attack patterns. Anomaly-based IDS learns normal behavior and flags deviations. Signatures are accurate for known attacks but miss new ones. Anomaly detection can find new ones but produces more false positives.
links: g:ids-snort

## concept-how-ransomware
q: how does ransomware work | how does ransomware spread | what does ransomware do
a: It gets in (phishing, exposed RDP, a vulnerability), gains privileges, spreads, often steals data, deletes backups, then encrypts files and demands payment. Defenses: patching, MFA, offline immutable backups, segmentation and EDR.
links: g:malware-analysis s:2.4

## concept-how-sqli
q: how does sql injection work | what is an example of sql injection | explain sql injection | how does sqli happen
a: When an app builds a query from user input, input like ' OR '1'='1 changes the query's logic. SELECT * FROM users WHERE name = '' OR '1'='1' returns every user. Parameterized queries stop this because input is never treated as SQL.
links: w:injection-and-xss

## concept-how-xss
q: how does xss work | what is an example of xss | explain cross site scripting | how does a stored xss attack work
a: An app puts user input into a page without encoding it, so an attacker's script runs in the victim's browser with the site's privileges: stealing sessions, acting as the user, or changing the page. Fix with context-aware output encoding and CSP.
links: w:injection-and-xss

## concept-how-buffer-overflow
q: how does a buffer overflow work | explain buffer overflow | what is a stack overflow attack | how does stack smashing work
a: A program copies more data into a fixed-size buffer than it holds. The extra bytes overwrite neighboring memory, such as the saved return address, so an attacker can redirect execution. Mitigations: canaries, ASLR, DEP, and safe functions.
