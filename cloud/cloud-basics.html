The cloud is someone else's computers rented by the second. What matters is who runs which layer, where it lives, how it is billed, and which half of the security job stays with you.

1simple2mid3complex+ref

01 simple // the idea in plain words

Cloud computing means renting compute, storage and networking from a provider (AWS, Microsoft Azure, Google Cloud) over the internet, on demand, and paying for what you use. You get a server in a minute instead of a purchase order in a month. The tradeoff: you now depend on the provider, and a wrong click can cost money or leak data.

The three service models differ in how much of the stack the provider runs:

  • IaaS (infrastructure as a service): you rent virtual machines, disks and networks. You patch the OS. Example: EC2, Azure Virtual Machines.
  • PaaS (platform as a service): you hand over code or a database and the provider runs the OS and runtime. Example: Elastic Beanstalk, Azure App Service, RDS.
  • SaaS (software as a service): you just use the finished app. Example: Microsoft 365, Gmail, Salesforce.

Shared responsibility model. The provider secures the cloud itself (buildings, hardware, hypervisor). You secure what you put in it (your data, accounts, configuration, and your guest OS on IaaS). Nearly every cloud breach is the customer's half: a public bucket, a leaked key, an over-permissive role.

Deployment models: public cloud (shared provider infrastructure), private cloud (dedicated to one organization), hybrid (on-premises plus cloud) and multi-cloud (more than one provider).

Two layers are always yours: data and identity. That is why IAM and data classification come first in every cloud framework.

Geography

  • Region: a geographic area containing multiple data centers (us-east-1 in AWS, East US in Azure). Pick for latency, price, and data-residency law.
  • Availability zone (AZ): one or more separate data centers inside a region with independent power and network. Spreading across AZs survives a data-center failure; spreading across regions survives a regional one.
  • Edge / CDN: cached copies near users (CloudFront, Azure Front Door).

The cloud properties you are tested on

On-demand self-service, broad network access, resource pooling, rapid elasticity (scale out and back in), measured service (metered billing). Add: scalability (handle growth), high availability (stay up through failures), fault tolerance (keep working through a component failure).

Money

Billing is metered: compute seconds, GB stored, GB transferred out (ingress is usually free, egress is not). Free tiers are time- or quota-limited, and terms change, so read the provider's current page before relying on one. Cost surprises usually come from things left running: idle VMs, unattached disks, elastic IPs, NAT gateways, and forgotten test environments.

03 complex // what the pros do

Security consequences of the model

  • Misconfiguration beats exploits. Every resource is an API object; a bad setting is exposed to the whole internet within seconds. The default question is "who can reach this and who can call this".
  • The control plane (APIs, console, CLI) manages resources and is guarded by identity. The data plane is the traffic to the running service. Compromise of the control plane (a stolen key) outranks nearly everything else.
  • Multi-tenancy: your VM shares hardware with strangers. Hypervisor escapes are rare, but side-channel and noisy-neighbor issues exist, and some regulations require dedicated hosts.
  • Compliance is inherited in part: providers publish audit reports (SOC 2, ISO 27001) for their half. You still have to prove yours.
  • Vendor lock-in and exit cost: proprietary services are fast to build with and slow to leave. Open formats, containers and infrastructure-as-code reduce it.

Infrastructure as code

Define resources in files (CloudFormation, ARM/Bicep, Terraform), review them in git, deploy them repeatably. Benefits: reproducible labs, drift detection, peer review of security settings, and one-command teardown, which matters for cost.

Pricing and architecture vocabulary

On-demand, reserved / savings plans (commit for a discount), spot / low-priority (cheap, can be reclaimed). Tags label resources by owner, project and environment so costs and incidents can be traced. A landing zone is a pre-built, governed multi-account setup. Well-architected frameworks (AWS Well-Architected, Azure Well-Architected) list the pillars: operational excellence, security, reliability, performance, cost, and sustainability.

Exam-flavored distinctions

  • Elasticity reacts to demand automatically; scalability is the ability to grow.
  • CASB sits between users and cloud apps to enforce policy; CSPM scans cloud configuration for risk; CWPP protects running workloads.
  • Serverless still has servers, you just do not manage them: the shared line moves up again.
